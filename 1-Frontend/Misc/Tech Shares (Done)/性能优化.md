## 二、复杂 JavaScript 执行优化

### 1. 另起线程

- 参考：`Web Workers`

```ts
// 主线程
const worker = new Worker(new URL("./worker.ts", import.meta.url).href)

worker.postMessage("")
worker.addEventListener("message", (event: MessageEvent<any>) => {
  // 执行结束
})

// worker.ts
self.addEventListener("message", (event: MessageEvent<any>) => {
  // 执行复杂代码
  self.postMessage("")
})
```

#### 1. 说明

- `worker` 与主线程通过 `postMessage` 通信。
- 传输参数受结构化克隆算法限制。
- `worker` 中无法访问 `window`，可使用 `self`。
- `worker` 中无法直接操作 DOM。

### 2. 函数切片

- 参考：生成器函数

```ts
// 复杂代码
function* complexCalculate() {
  let count = 0
  const start = performance.now()

  while (performance.now() - start <= 5000) {
    yield count++
  }

  return count
}

// 将复杂代码切片为异步函数
function timeSlice(): Promise<number> {
  return new Promise(resolve => {
    const iteratorFn = complexCalculate()

    const recursion = () => {
      const start = performance.now()
      let result: IteratorResult<unknown, number>

      do {
        result = iteratorFn.next()
      } while (!result.done && performance.now() - start < 16)

      if (result.done) {
        resolve(result.value)
      } else {
        requestAnimationFrame(recursion)
      }
    }

    recursion()
  })
}
```

#### 2. 说明

- 将原本的长任务切片成多个短任务。
- 切片时间越短，主线程阻塞越少，但整体执行效率通常会下降。

## 三、其他性能优化点

### 1. 避免不必要的响应式数据转换

#### 1. 数据整体无需响应

- 不使用响应式 API，直接声明普通数据。

#### 2. 数据部分无需响应

- `markRaw()`
- `shallowRef()`
- `shallowReactive()`

### 2. 动画与绘制

- 使用 CSS 动画或 `requestAnimationFrame` 绘制动画。
- 使用 `transform` 实现位移效果，减少回流和重绘。
- 合并 DOM 操作，避免频繁触发布局计算。
- 避免大型、复杂布局以及布局抖动。

### 3. 请求与事件

- 中断已经不需要的请求：`AbortController`
- 页面缓存后及时关闭侦听器。
- 高频操作做节流处理，例如滚动、移动事件。

### 4. 页面与组件层优化

- 按需加载与页面缓存。
- 让传给子组件的 `props` 尽量保持稳定。
- 使用 `v-once`、`v-memo` 减少不必要的渲染。
