# 清除浮动

## 一、一句话理解

清除浮动解决的不是“让元素别浮了”，而是“别再让浮动元素把父容器和后续布局带乱”。

---

## 二、为什么需要清除浮动

浮动元素会脱离标准文档流，因此父元素如果没有显式高度，可能无法被内部浮动子元素撑开，导致父元素高度塌陷，进而影响后续布局。

典型现象：

- 父元素背景颜色消失
- 后面的标准流元素上移
- 布局错位

---

## 三、清除浮动的本质

**清除浮动** 的本质，不是“取消浮动”，而是**消除浮动对子元素外部布局的影响**。

目标可以概括为一句话：

让父元素重新感知浮动子元素的高度。

> **注意**：如果父元素本身已经有明确高度，且布局不受影响，就不一定需要清除浮动。

---

## 四、`clear` 属性

`clear` 用来控制元素的某一侧是否允许出现浮动元素。

```css
clear: left;
clear: right;
clear: both;
```

| 值          | 说明                   |
| ----------- | ---------------------- |
| **`left`**  | 左侧不允许有浮动元素   |
| **`right`** | 右侧不允许有浮动元素   |
| **`both`**  | 两侧都不允许有浮动元素 |

实际开发中最常见的是：

```css
clear: both;
```

---

## 五、常见清除浮动方法

### 1. 额外标签法

也叫“隔墙法”，是在最后一个浮动元素后面额外插入一个块级元素，并给它加 `clear: both`。

```html
<div class="parent">
  <div class="left"></div>
  <div class="right"></div>
  <div class="clear"></div>
</div>
```

```css
.clear {
  clear: both;
}
```

#### 优缺点

| 维度     | 说明                         |
| -------- | ---------------------------- |
| **优点** | 思路直观，容易理解           |
| **缺点** | 增加无语义标签，结构不够干净 |

---

### 2. 父元素设置 `overflow`

给父元素设置 `overflow: hidden`、`auto` 或 `scroll`，常常可以触发新的格式化上下文，从而包裹内部浮动元素。

```css
.parent {
  overflow: hidden;
}
```

#### 优缺点

| 维度     | 说明                             |
| -------- | -------------------------------- |
| **优点** | 代码少，写法简单                 |
| **缺点** | 可能裁剪超出内容，不适合所有场景 |

---

### 3. `:after` 伪元素清除浮动

这是经典做法之一，通过在父元素末尾生成一个伪元素来完成清除。

```css
.clearfix::after {
  content: "";
  display: block;
  clear: both;
}
```

然后给父元素添加类名：

```html
<div class="parent clearfix">...</div>
```

#### 优缺点

| 维度     | 说明                           |
| -------- | ------------------------------ |
| **优点** | 不增加额外标签，结构更干净     |
| **缺点** | 对非常老的浏览器兼容处理更麻烦 |

---

### 4. 双伪元素法

这是更完整、更稳妥的一种写法，常见于老项目兼容方案中。

```css
.clearfix::before,
.clearfix::after {
  content: "";
  display: table;
}

.clearfix::after {
  clear: both;
}
```

在现代项目里，如果不考虑极老浏览器，通常单 `::after` 版本已经够用。

这也说明：清除浮动方法没有绝对唯一答案，关键看结构是否干净、是否会引入副作用。

---

## 六、快速排查思路

如果你怀疑页面是浮动没清干净，可以按这条线看：

1. 父元素背景是不是“没高度了”。
2. 后面的普通块元素是不是被顶上来了。
3. 浮动子元素后面有没有形成新的清除点。
4. 当前方案会不会因为 `overflow` 把内容裁掉。

---

## 七、现代开发中的建议

虽然要理解清除浮动，但现代布局里，很多原先依赖浮动的场景已经被 `flex` 和 `grid` 替代。

### 1. 仍需清除浮动的场景

- 维护老项目
- 阅读历史代码
- 某些经典图文混排或旧布局方案

### 2. 新项目更推荐

| 场景               | 推荐方式        |
| ------------------ | --------------- |
| **横向排列**       | `flex`          |
| **二维网格布局**   | `grid`          |
| **旧布局兼容维护** | 浮动 + 清除浮动 |

---

## 八、什么时候必须清除浮动

一般满足以下三个条件时，就要考虑清除浮动：

1. 父元素没有固定高度
2. 子元素使用了浮动
3. 后续布局受到了影响

---

## 九、小结

| 知识点                 | 结论                           |
| ---------------------- | ------------------------------ |
| **清除浮动本质**       | 消除浮动对外部布局的影响       |
| **最基础方法**         | 额外标签 + `clear: both`       |
| **常见简洁方案**       | 父元素 `overflow: hidden`      |
| **更推荐的结构化方案** | `::after` 伪元素清除浮动       |
| **现代替代思路**       | 新布局优先考虑 `flex` / `grid` |
