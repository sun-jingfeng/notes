# HTML5增强特性

## 一、这篇的主线

这几个主题虽然看起来分散，但本质上都在做一件事：

```text
让 HTML 不只是“摆结构”，而是更好地表达内容、承载媒体、改善输入体验。
```

可以这样理解：

1. 语义化标签解决“页面结构表达”。
2. 多媒体标签解决“原生音视频能力”。
3. 新增 `input` 类型和表单属性解决“输入体验和基础校验”。

---

## 二、HTML5 语义化标签

**语义化标签** 指标签本身就能表达结构和内容含义，而不只是“一个没有语义的盒子”。

### 2.1 常见语义化标签

| 标签          | 语义                   |
| ------------- | ---------------------- |
| **`header`**  | 页头、区块头部         |
| **`nav`**     | 导航区域               |
| **`main`**    | 页面主要内容           |
| **`article`** | 独立内容，如文章、帖子 |
| **`section`** | 一个主题分区           |
| **`aside`**   | 侧边栏、补充信息       |
| **`footer`**  | 页脚、区块尾部         |

### 2.2 示例

```html
<header>网站头部</header>
<nav>主导航</nav>
<main>
  <article>
    <section>文章内容</section>
  </article>
  <aside>相关推荐</aside>
</main>
<footer>页脚信息</footer>
```

### 2.3 为什么要语义化

| 价值           | 说明                         |
| -------------- | ---------------------------- |
| **结构更清晰** | 代码可读性更强               |
| **利于 SEO**   | 搜索引擎更容易理解页面结构   |
| **利于无障碍** | 屏幕阅读器更容易识别页面区域 |

### 2.4 和 `div` 的区别怎么理解

`div` 本身没有明确语义，更像一个通用容器；而 `header`、`nav`、`main`、`article` 这些标签，自带结构含义。

| 写法                       | 含义清晰度           |
| -------------------------- | -------------------- |
| **`<div class="header">`** | 依赖类名推断         |
| **`<header>`**             | 标签本身就能表达语义 |

### 2.5 一个常见误区

语义化不是“把所有 `div` 都机械替换掉”，而是让标签含义和内容结构对应起来。

### 2.6 一个实战判断标准

如果这个区域换个标签不会影响“内容本身的语义”，那就不要为了“看起来高级”强行套语义标签。

## 三、HTML5 多媒体标签

HTML5 提供了原生音视频能力，最常见的是 `video` 和 `audio`。

### 3.1 视频标签 `video`

```html
<video controls width="300" poster="./cover.jpg">
  <source src="movie.mp4" type="video/mp4" />
  <source src="movie.ogg" type="video/ogg" />
  您的浏览器暂不支持 video 标签。
</video>
```

### 3.2 音频标签 `audio`

```html
<audio controls>
  <source src="music.mp3" type="audio/mpeg" />
  <source src="music.ogg" type="audio/ogg" />
  您的浏览器暂不支持 audio 标签。
</audio>
```

### 3.3 常见属性对比

| 属性                   | 作用         |
| ---------------------- | ------------ |
| **`controls`**         | 显示播放控件 |
| **`autoplay`**         | 自动播放     |
| **`muted`**            | 静音         |
| **`loop`**             | 循环播放     |
| **`poster`**           | 视频封面     |
| **`preload`**          | 预加载策略   |
| **`width` / `height`** | 设置显示尺寸 |

### 3.4 使用注意事项

1. 自动播放常受浏览器限制。
2. `autoplay + muted` 更容易成功自动播放。
3. 视频通常优先提供 `mp4`，音频通常优先提供 `mp3`。
4. 需要兼顾加载性能时，要考虑 `preload` 策略。

### 3.5 多媒体标签和第三方播放器的边界

原生 `video`、`audio` 解决的是“具备播放能力”，但复杂业务经常还要补：

1. 自定义控件。
2. 封面、海报、清晰度切换。
3. 错误提示和加载状态。
4. 权限控制或试看逻辑。

### 3.6 一个实战提醒

音视频标签解决的是“播放能力”，不等于就自动拥有完整播放器体验。很多业务场景仍然需要自定义控件、封面、错误处理和加载状态。

## 四、HTML5 新增的 input 类型

HTML5 扩展了很多 `input` 类型，让浏览器能提供更合适的输入体验。

### 4.1 常见类型

| 类型         | 作用     |
| ------------ | -------- |
| **`email`**  | 邮箱输入 |
| **`url`**    | 网址输入 |
| **`number`** | 数字输入 |
| **`tel`**    | 电话输入 |
| **`search`** | 搜索输入 |
| **`date`**   | 日期选择 |
| **`time`**   | 时间选择 |
| **`range`**  | 滑块选择 |
| **`color`**  | 颜色选择 |
| **`file`**   | 文件上传 |

### 4.2 示例

```html
<input type="number" />
<input type="tel" />
<input type="search" />
<input type="date" />
```

### 4.3 它们带来的好处

1. 移动端可弹出更合适的键盘。
2. 浏览器可提供基础输入校验。
3. 用户输入体验更自然。

### 4.4 一个边界认知

这些类型能优化体验，但不能替代真正的业务校验和服务端校验。

### 4.5 怎么选更合理

| 需求             | 推荐类型           | 原因                     |
| ---------------- | ------------------ | ------------------------ |
| **邮箱输入**     | `email`            | 浏览器可做基础格式校验   |
| **手机号输入**   | `tel`              | 移动端常弹出更合适键盘   |
| **数字范围输入** | `number` / `range` | 交互更符合数据类型       |
| **日期时间选择** | `date` / `time`    | 浏览器会尽量提供原生控件 |
| **文件上传**     | `file`             | 直接接入文件选择流程     |

### 4.6 兼容性怎么看

即使浏览器不完全支持某种类型，它通常也会退化成普通文本输入框，所以前端仍要准备：

1. 兜底校验逻辑。
2. 格式提示。
3. 服务端最终校验。

## 五、HTML5 常见表单属性

HTML5 还增强了表单控件的属性能力。

### 5.1 常见属性

| 属性               | 作用                         |
| ------------------ | ---------------------------- |
| **`placeholder`**  | 占位提示                     |
| **`required`**     | 必填                         |
| **`autofocus`**    | 页面加载后自动聚焦           |
| **`autocomplete`** | 自动补全                     |
| **`pattern`**      | 正则校验规则                 |
| **`multiple`**     | 支持多值，例如多文件、多邮箱 |
| **`min` / `max`**  | 最小值 / 最大值              |
| **`step`**         | 步长                         |

### 5.2 示例

```html
<input type="text" placeholder="请输入用户名" required autofocus />
<input type="number" min="1" max="100" step="1" />
<input type="file" multiple />
```

### 5.3 修改 placeholder 样式

```css
input::placeholder {
  color: pink;
}
```

### 5.4 使用这些属性时要注意什么

1. `required`、`pattern` 只能做基础前端拦截。
2. `autofocus` 不宜滥用，否则会影响页面进入体验。
3. `autocomplete` 在登录、搜索等场景通常很有价值。
4. `multiple` 往往需要配合后端接口能力一起考虑。

### 5.5 原生校验和业务校验的边界

HTML5 表单属性能做的是“基础体验增强”和“基础拦截”，不能替代：

1. 更复杂的业务规则校验。
2. 联动校验。
3. 服务端最终校验。

也就是说，前端原生校验是第一层，不是最后一层。

---

## 六、语义化、多媒体、表单增强之间的关系

可以把它们统一理解为 HTML5 对网页基础能力的三次升级：

| 方向         | 升级点                     |
| ------------ | -------------------------- |
| **结构表达** | 用更有语义的标签描述页面   |
| **媒体承载** | 原生支持音视频播放         |
| **输入体验** | 更丰富的输入类型与校验属性 |

---

## 七、小结

1. 语义化标签让页面结构更清晰，也更利于 SEO 和无障碍。
2. `video` 和 `audio` 让网页具备原生音视频播放能力，但复杂播放体验仍需业务层补充。
3. HTML5 扩展的 `input` 类型能显著提升输入体验，尤其在移动端。
4. `placeholder`、`required`、`pattern` 等属性可以增强表单交互和基础校验，但不能替代服务端校验。
5. 学这一篇时，重点不是记住所有标签和属性，而是理解 HTML5 为什么要让页面“更有语义、更有能力、更好输入”。
