# 浏览器与骨架标签

## 一、一句话理解

这篇真正要建立的是两个基础认知：页面最终是浏览器在解释执行，而 HTML 骨架就是浏览器理解页面的起点。

---

## 二、常见浏览器与内核

## 一、常见浏览器与内核

浏览器表面上看是“打开网页的软件”，底层真正负责解析 HTML、CSS、JavaScript 并完成渲染的，是浏览器内核（更准确地说是渲染引擎与相关运行时组件）。

### 1. 常见浏览器

| 浏览器                           | 常见内核 / 引擎 |
| -------------------------------- | --------------- |
| **Chrome**                       | Blink           |
| **Edge（Chromium）**             | Blink           |
| **Safari**                       | WebKit          |
| **Firefox**                      | Gecko           |
| **国内大多数 Chromium 系浏览器** | Blink           |

> **注意**：现代前端开发中，很多国内浏览器本质上也是基于 Chromium，因此渲染行为通常更接近 Chrome / Edge。

### 2. 为什么前端要关注浏览器内核

| 原因             | 说明                                 |
| ---------------- | ------------------------------------ |
| **兼容性差异**   | 某些 CSS / JS 特性支持情况不同       |
| **调试环境选择** | 大多数前端调试会优先用 Chrome / Edge |
| **性能表现**     | 不同浏览器在渲染、脚本执行上会有差异 |

## 三、HTML 骨架是什么

HTML 骨架是一个网页最基础的结构模板，通常由文档声明、`html`、`head`、`body` 等标签组成。

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Document</title>
  </head>
  <body></body>
</html>
```

VS Code 中输入 `!` 后按 Tab，通常就能快速生成这份基础骨架。

---

## 四、骨架标签逐项说明

### 1. `<!DOCTYPE html>`

**文档类型声明**，用于告诉浏览器：当前页面按 **HTML5 标准** 解析。

| 作用             | 说明                                         |
| ---------------- | -------------------------------------------- |
| **声明文档类型** | 告诉浏览器使用哪种 HTML 标准                 |
| **避免怪异模式** | 不写可能导致浏览器进入兼容模式，渲染结果异常 |

> **注意**：`<!DOCTYPE html>` 不是普通 HTML 标签，而是文档声明。

### 2. `<html lang="zh-CN">`

`html` 是整个文档的根元素，`lang` 用来标识页面主要语言。

```html
<html lang="zh-CN"></html>
```

| 值          | 含义     |
| ----------- | -------- |
| **`zh-CN`** | 简体中文 |
| **`en`**    | 英文     |
| **`ja`**    | 日文     |

它的主要作用不是“限制页面只能显示某种语言”，而是帮助：

- 搜索引擎理解页面语言
- 浏览器和辅助技术做更准确的语音朗读和语义处理

### 3. `<head>`

`head` 中放的是页面元信息，不直接显示在页面主体中。

常见内容包括：

- 字符编码
- 页面标题
- 视口设置
- 样式文件引入
- SEO 信息

### 4. `<meta charset="UTF-8">`

用于声明字符编码，防止中文乱码。

```html
<meta charset="UTF-8" />
```

| 编码        | 说明                         |
| ----------- | ---------------------------- |
| **`UTF-8`** | 通用性最强，现代项目默认首选 |
| **`GBK`**   | 中文编码，旧项目中较常见     |

> **注意**：现代开发中统一使用 `UTF-8` 最稳妥，避免出现乱码和跨平台问题。

### 5. `<meta name="viewport">`

控制移动端视口，影响页面在手机上的缩放和布局。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

| 配置                     | 说明                 |
| ------------------------ | -------------------- |
| **`width=device-width`** | 视口宽度等于设备宽度 |
| **`initial-scale=1.0`**  | 初始缩放比例为 1     |

这是移动端页面几乎必写的一项配置。

### 6. `<title>`

用于设置浏览器标签页标题。

```html
<title>我的第一个网页</title>
```

### 7. `<body>`

`body` 中放的是页面真正展示给用户的内容，例如：

- 文本
- 图片
- 表单
- 列表
- 组件结构

## 五、一个更完整的基础模板

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="description" content="页面描述" />
    <title>首页</title>
  </head>
  <body>
    <h1>欢迎来到我的网站</h1>
  </body>
</html>
```

## 六、常见注意事项

| 问题                      | 说明               |
| ------------------------- | ------------------ |
| **漏写 `DOCTYPE`**        | 可能进入兼容模式   |
| **字符编码不统一**        | 容易出现乱码       |
| **移动端没写 `viewport`** | 页面显示和缩放异常 |
| **`title` 不规范**        | 影响可读性和 SEO   |

---

## 七、小结

| 知识点         | 结论                         |
| -------------- | ---------------------------- |
| **浏览器内核** | 决定页面解析与渲染行为       |
| **HTML 骨架**  | 页面最基本的结构模板         |
| **`DOCTYPE`**  | 声明 HTML5 文档类型          |
| **`charset`**  | 声明字符编码，通常用 `UTF-8` |
| **`viewport`** | 控制移动端视口               |
