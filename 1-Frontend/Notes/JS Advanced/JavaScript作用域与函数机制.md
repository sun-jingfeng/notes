# JavaScript作用域与函数机制

## 一、这篇怎么串起来理解

这几个知识点并不是彼此独立的，它们共同回答了 3 类问题：

| 主题组                           | 回答的问题                                      |
| -------------------------------- | ----------------------------------------------- |
| **作用域、作用域链、闭包、提升** | 变量为什么能访问到，为什么有时又访问不到        |
| **参数、默认值、剩余参数、解构** | 函数如何更清晰地接收和拆分数据                  |
| **箭头函数**                     | 函数写法为什么变了，`this` 和参数行为有什么差异 |

## 二、作用域

作用域规定了变量能够被访问的范围。离开这个范围，变量通常就不能再被访问。

JavaScript 中常见的作用域有：

1. 全局作用域。
2. 函数作用域。
3. 块级作用域。

### 2.1 全局作用域

```js
const appName = "demo"

function logName() {
  console.log(appName)
}
```

全局变量几乎任何地方都能访问，但副作用也最大，容易造成命名冲突和污染。

### 2.2 函数作用域

```js
function sum(a, b) {
  const result = a + b
  console.log(result)
}

sum(1, 2)
// console.log(result)
```

### 2.3 块级作用域

```js
if (true) {
  const age = 18
  console.log(age)
}

// console.log(age)
```

`if`、`for`、`while`、独立花括号代码块都能形成块级作用域。

### 2.4 `var`、`let`、`const` 的区别

| 关键字  | 是否有块级作用域 | 是否允许重复声明 | 是否允许重新赋值 | 是否必须初始化 |
| ------- | ---------------- | ---------------- | ---------------- | -------------- |
| `var`   | 否               | 是               | 是               | 否             |
| `let`   | 是               | 否               | 是               | 否             |
| `const` | 是               | 否               | 否               | 是             |

### 2.5 一个实战结论

1. 默认优先 `const`。
2. 需要重新赋值时用 `let`。
3. 除非维护旧代码，否则尽量不要主动写 `var`。

## 三、作用域链

当在当前作用域中找不到某个变量时，JavaScript 会沿着外层作用域一层层往上查找，这条查找路径就叫 **作用域链**。

```js
const a = 1

function outer() {
  const b = 2

  function inner() {
    const c = 3
    console.log(a, b, c)
  }

  inner()
}
```

查找顺序可以理解为：

```text
当前作用域 -> 外层作用域 -> 更外层作用域 -> 全局作用域
```

规则是：

1. 优先查找当前作用域。
2. 当前没有，再往父级作用域找。
3. 找到就停止。
4. 一直到全局还找不到，就报错。

## 四、闭包

### 4.1 什么是闭包

闭包可以简单理解为：**函数在外部执行时，依然能够访问其定义时所在作用域中的变量。**

```js
function createCounter() {
  let count = 0

  return function () {
    count++
    console.log(count)
  }
}

const counter = createCounter()
counter()
counter()
```

### 4.2 闭包的价值

1. 让外部可以访问函数内部变量。
2. 实现数据私有化。
3. 避免全局变量污染。

### 4.3 常见场景

1. 计数器。
2. 柯里化函数。
3. 模块内部私有状态。
4. 事件处理器里保留外部变量。

### 4.4 使用闭包时要注意什么

闭包不是坏东西，但如果滥用，可能让本来应该被释放的变量继续留在内存里。

判断标准通常是：

1. 它是不是在保存必要状态。
2. 它是不是在无意义地长期持有大对象。

## 五、预解析与提升

很多资料会把它叫“预解析”，更准确地说，是变量声明和函数声明在编译阶段的处理机制。

### 5.1 `var` 的变量提升

```js
console.log(message) // undefined
var message = "hello"
```

这不等于“值也被提前”，更像这样：

```js
var message
console.log(message)
message = "hello"
```

### 5.2 `let` 和 `const`

```js
// console.log(age)
let age = 18
```

`let` 和 `const` 也会被登记到当前作用域，但在声明前不能访问，这段区域通常被称为 **暂时性死区**。

### 5.3 函数声明与函数表达式

```js
sayHi()

function sayHi() {
  console.log("hi")
}
```

函数声明可以在定义前调用。

```js
// sayHello()

const sayHello = function () {
  console.log("hello")
}
```

函数表达式不会像函数声明那样可直接提前调用。

### 5.4 开发建议

1. 不要依赖提升写代码。
2. 变量先声明再使用。
3. 优先使用 `let` 和 `const`。

## 六、参数

### 6.1 形参与实参

```js
function sum(a, b) {
  return a + b
}

sum(1, 2)
```

1. `a`、`b` 是形参。
2. `1`、`2` 是实参。

### 6.2 默认参数

```js
function greet(name = "游客") {
  console.log("你好，" + name)
}
```

如果调用时没有传值，或显式传入 `undefined`，就会使用默认值。

### 6.3 `arguments` 与剩余参数

```js
function showArgs() {
  console.log(arguments)
}
```

注意：

1. `arguments` 不是数组。
2. 箭头函数中没有 `arguments`。

```js
function sum(...nums) {
  return nums.reduce((total, item) => total + item, 0)
}
```

剩余参数的优势是：

1. 拿到的是真数组。
2. 语义更清晰。
3. 更适合现代写法。

### 6.4 参数相关的一个实战建议

如果参数个数多、含义不直观，通常更推荐用对象参数，再配合解构，让调用和维护更清晰。

## 七、箭头函数

箭头函数是 ES6 提供的更简洁的函数写法。

### 7.1 基本语法

```js
const add = (a, b) => {
  return a + b
}
```

```js
const double = n => n * 2
```

### 7.2 和普通函数的区别

| 对比项           | 普通函数   | 箭头函数       |
| ---------------- | ---------- | -------------- |
| `this`           | 调用时决定 | 继承外层作用域 |
| `arguments`      | 有         | 没有           |
| 能否作为构造函数 | 可以       | 不可以         |

### 7.3 一个典型例子

```js
const obj = {
  name: "Tom",
  normal() {
    console.log(this.name)
  },
  arrow: () => {
    console.log(this.name)
  },
}
```

箭头函数更适合作为回调、小函数，而不是对象方法或构造函数的替代品。

### 7.4 什么时候优先用箭头函数

1. 简短回调。
2. 需要继承外层 `this` 的内部函数。
3. 函数式链式调用中的小处理函数。

### 7.5 什么时候不要滥用箭头函数

1. 对象方法。
2. 构造函数。
3. 明确依赖动态 `this` 的事件处理器。

## 八、解构赋值

解构赋值本质上是更简洁的赋值写法，常见于数组和对象。

### 8.1 数组解构

```js
const arr = [10, 20, 30]
const [a, b, c] = arr
```

可以跳过某些位置：

```js
const [first, , third] = [1, 2, 3]
```

也可以设置默认值：

```js
const [x = 0, y = 0] = [5]
```

### 8.2 对象解构

```js
const user = {
  name: "Tom",
  age: 18,
}

const { name, age } = user
```

### 8.3 重命名与默认值

```js
const { name: userName, gender = "unknown" } = user
```

### 8.4 常见使用场景

1. 函数返回值拆分。
2. 提取接口返回数据。
3. 组件参数解构。
4. 从配置对象中读取选项。

### 8.5 一个边界提醒

解构可以提升可读性，但层级过深时也会让代码难懂。嵌套太复杂时，分步取值通常更稳妥。

---

## 九、小结

1. 作用域决定变量的可访问范围，作用域链决定变量如何向外查找。
2. 闭包的本质是“函数带着定义时环境一起工作”，重点是合理保存状态。
3. 提升和暂时性死区解释了为什么有些变量能提前访问、有些不能。
4. 默认参数、剩余参数和解构让函数接口表达更清晰。
5. 箭头函数最大的价值不是“写得短”，而是更明确的 `this` 和更适合回调的语义。
