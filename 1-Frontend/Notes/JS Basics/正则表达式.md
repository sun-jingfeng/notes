# 正则表达式

## 一、什么是正则表达式

正则表达式是用于描述字符串匹配规则的一套语法。它最常见的用途有：

1. 表单校验。
2. 字符串查找。
3. 文本替换。
4. 内容提取。

它的核心不是“记住所有符号”，而是能把一个字符串规则准确表达出来。

---

## 二、如何创建正则

### 2.1 字面量写法

```js
const reg = /abc/
```

### 2.2 构造函数写法

```js
const reg = new RegExp("abc")
```

### 2.3 什么时候用哪种

1. 规则写死时，优先字面量。
2. 规则需要动态拼接时，用 `RegExp` 构造函数。

例如：

```js
const keyword = "abc"
const reg = new RegExp(keyword, "i")
```

---

## 三、常用方法

### 3.1 `test()`

```js
;/abc/.test("xxabcxx") // true
```

返回布尔值，适合做“是否匹配”的判断。

### 3.2 `exec()`

```js
;/abc/.exec("xxabcxx")
```

匹配成功时返回数组，失败时返回 `null`，适合做“提取匹配结果”。

### 3.3 `match()`、`replace()`、`split()`

正则也经常和字符串方法搭配使用：

```js
"a1b2c3".match(/\d/g)
"a1b2c3".replace(/\d/g, "_")
"a-b-c".split(/-/)
```

---

## 四、元字符分类

为了方便学习，可以把正则里的元字符分成这几类：

1. 位置边界。
2. 字符集合。
3. 预定义类。
4. 量词。
5. 分组与选择。
6. 转义符。
7. 修饰符。

---

## 五、位置边界

### 5.1 `^`

匹配字符串开始位置。

### 5.2 `$`

匹配字符串结束位置。

### 5.3 精确匹配

```js
console.log(/^abc$/.test("abc")) // true
console.log(/^abc$/.test("xabc")) // false
```

如果 `^` 和 `$` 同时出现，通常表示整串必须完全符合规则。

---

## 六、字符集合与预定义类

### 6.1 中括号 `[]`

表示“匹配其中任意一个字符”。

```js
;/[abc]/
```

### 6.2 范围写法

```js
const lower = /[a-z]/
const upper = /[A-Z]/
const digit = /[0-9]/
```

### 6.3 取反写法

```js
;/[^a-z]/
```

放在中括号开头的 `^` 表示取反，不是开始边界。

### 6.4 预定义类

| 写法 | 含义                   |
| ---- | ---------------------- |
| `\d` | 数字，等价于 `[0-9]`   |
| `\D` | 非数字                 |
| `\w` | 字母、数字、下划线     |
| `\W` | 非 `\w`                |
| `\s` | 空白字符               |
| `\S` | 非空白字符             |
| `.`  | 除换行外的任意单个字符 |

示例：

```js
;/^\d{6}$/.test("123456")
```

---

## 七、量词

量词用于控制前一个规则重复多少次。

| 写法    | 含义        |
| ------- | ----------- |
| `*`     | 0 次或多次  |
| `+`     | 1 次或多次  |
| `?`     | 0 次或 1 次 |
| `{m}`   | 恰好 m 次   |
| `{m,n}` | m 到 n 次   |
| `{m,}`  | 至少 m 次   |

示例：

```js
;/^\d{6,12}$/
```

表示长度为 6 到 12 位的纯数字。

### 7.1 贪婪与非贪婪

默认情况下，量词通常是**贪婪匹配**，会尽可能多地吃字符。

```js
"<div>123</div><p>456</p>".match(/<.*>/)
```

这往往会匹配过头。

如果想尽量少匹配，可以写成**非贪婪**：

```js
"<div>123</div><p>456</p>".match(/<.*?>/g)
```

这是实战里非常高频的一个边界点。

---

## 八、分组、捕获与或关系

### 8.1 分组 `()`

用于把多个规则作为一个整体处理。

```js
;/(ab)+/
```

### 8.2 或关系 `|`

```js
;/(Java|HTML|CSS)/
```

表示匹配 `Java`、`HTML`、`CSS` 其中之一。

### 8.3 捕获分组

```js
const result = /(\d{4})-(\d{2})-(\d{2})/.exec("2026-03-17")
```

这时通常可以拿到：

1. 完整匹配结果。
2. 第一个括号匹配结果。
3. 第二个括号匹配结果。
4. 第三个括号匹配结果。

它非常适合做结构化提取。

---

## 九、转义符

有些字符在正则里本身有特殊含义，如果想匹配它本身，就要转义。

```js
const reg = /\/\//
```

这个规则表示匹配字符串里的 `//`。

常见需要转义的字符有：

1. `.`
2. `*`
3. `+`
4. `?`
5. `(` `)`
6. `[` `]`
7. `{` `}`
8. `\`
9. `/`

---

## 十、修饰符

修饰符写在正则末尾，用来控制匹配行为。

| 修饰符 | 含义       |
| ------ | ---------- |
| `i`    | 忽略大小写 |
| `g`    | 全局匹配   |
| `m`    | 多行匹配   |

示例：

```js
;/abc/gi
```

### 10.1 `g` 的一个易错点

全局匹配会影响某些方法的行为，尤其是配合 `exec()` 循环匹配时，会依赖内部状态继续往后找。

所以要知道：

1. `g` 不只是“多找几个”。
2. 它还会改变匹配过程中的状态推进方式。

---

## 十一、常见业务示例

### 11.1 手机号

```js
;/^1[3-9]\d{9}$/
```

### 11.2 用户名

```js
;/^[a-zA-Z0-9_]{4,16}$/
```

### 11.3 去掉字符串两端空白

```js
str.replace(/^\s+|\s+$/g, "")
```

### 11.4 提取日期

```js
;/(\d{4})-(\d{2})-(\d{2})/
```

### 11.5 匹配简单 URL 前缀

```js
;/^https?:\/\//
```

---

## 十二、容易踩的坑

1. `.` 默认不能匹配换行。
2. `^` 在中括号外表示开头，在中括号里开头表示取反。
3. `g` 修饰符会影响某些方法的匹配行为。
4. 贪婪匹配很容易把内容吃多。
5. 正则适合描述规则，不适合处理非常复杂的语言结构。

### 12.1 一个实战建议

如果规则已经复杂到“自己都快读不懂”，就该考虑：

1. 先拆分处理。
2. 或者改用普通字符串逻辑。
3. 不要为了“全用一个正则解决”而牺牲可维护性。

---

## 十三、小结

1. 正则表达式是字符串规则描述工具。
2. 学习重点是边界、字符集合、量词、分组、修饰符。
3. `test` 适合判断，`exec` 更适合提取。
4. 贪婪与非贪婪、捕获分组、`g` 修饰符行为，是从“会写”到“真会用”的关键。
5. 真正熟练的核心不是背模板，而是能把自然语言规则翻译成正则，并知道什么时候不该硬上正则。
