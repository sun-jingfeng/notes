# 函数重载

## 一、一句话理解

函数重载解决的核心问题是：同一个函数支持多种调用方式时，如何让调用方仍拿到足够精确的类型结果。

---

## 二、什么是函数重载

**函数重载** 指同一个函数名可以声明多组不同的参数和返回值签名，让 TypeScript 在调用时根据传入参数推导出更精确的结果类型。

一句话理解：

**同一个函数有多种合法调用方式，但每种方式的返回值类型可能不同。**

---

## 三、为什么需要函数重载

如果只写联合类型，往往会导致返回值也变成笼统联合，调用方拿不到精确结果。

### 3.1 不使用重载

```ts
function toArray(value: string | number): string[] | number[] {
  if (typeof value === "string") {
    return value.split("")
  }

  return value.toString().split("").map(Number)
}

const arr1 = toArray(123)
const arr2 = toArray("abc")
```

此时：

1. `arr1` 的类型是 `string[] | number[]`
2. `arr2` 的类型也是 `string[] | number[]`

这显然不够精确。

### 3.2 使用重载后

```ts
function toArray(value: string): string[]
function toArray(value: number): number[]
function toArray(value: string | number) {
  if (typeof value === "string") {
    return value.split("")
  }

  return value.toString().split("").map(Number)
}

const arr1 = toArray(123)
const arr2 = toArray("abc")
```

此时：

1. `arr1` 能被推导为 `number[]`
2. `arr2` 能被推导为 `string[]`

这就是函数重载最大的价值：**让调用方得到更精确的类型体验。**

---

## 四、函数重载的基本结构

函数重载通常由两部分组成：

1. **重载签名**：提供给外部看的多组调用方式。
2. **实现签名**：真正的函数实现。

```ts
function fn(value: string): string[]
function fn(value: number): number[]
function fn(value: string | number) {
  // 真实实现
}
```

### 4.1 一个关键规则

**实现签名必须兼容所有重载签名。**

所以实现函数的参数通常会写得更宽泛，例如：

1. `string | number`
2. `any`
3. `unknown`

其中：

1. `any` 最宽松，但不安全。
2. `unknown` 更安全，但需要额外类型判断。
3. `联合类型` 往往是最常用的折中方案。

---

## 五、函数类型中的重载

函数重载不只可以写在 `function` 声明里，也可以写成调用签名。

### 5.1 调用签名写法

```ts
type Fn = {
  (name: string): void
  (age: number): void
}

const fn: Fn = () => {}
```

### 5.2 对象方法中的重载

```ts
type Obj = {
  fn(name: string): void
  fn(age: number): void
}

const obj: Obj = {
  fn() {},
}
```

这类写法常见于：

1. 接口定义
2. 对象工具集
3. 某些库的 API 声明

---

## 六、交叉类型也能表达“多个调用方式”

```ts
type Fn = ((p: number) => number) &
  ((p: string) => string) &
  ((p: boolean) => boolean)
```

这种写法本质上也能表达“同一个函数支持多种入参和返回值组合”。

### 6.1 但为什么平时更常写重载

因为 `function` 重载的可读性通常更高，也更符合“一个函数有多种签名”的直觉。

---

## 七、函数重载的几个重要规则

### 7.1 重载签名必须连续写在一起

### 7.2 实现签名不能只兼容其中一部分

### 7.3 导出规则要一致

要么都导出，要么都不导出。

```ts
export function toArray(value: string): string[]
export function toArray(value: number): number[]
export function toArray(value: string | number) {
  return typeof value === "string"
    ? value.split("")
    : value.toString().split("").map(Number)
}
```

---

## 八、为什么 `Parameters` / `ReturnType` 看重载时只取最后一个

这是一个非常容易踩坑的点。

```ts
type Fn = {
  (name: string): string
  (age: number): number
  (male: boolean): boolean
}

type Par = Parameters<Fn>
type Ret = ReturnType<Fn>
```

结果通常会取**最后一个签名**：

1. `Par` 是 `[male: boolean]`
2. `Ret` 是 `boolean`

### 8.1 为什么会这样

因为在类型系统内部，重载函数最后会落到“最后一个兼容签名”上进行提取。

### 8.2 实际意义

如果你希望工具类型保留更完整的信息，不能简单依赖 `Parameters` / `ReturnType` 对重载函数做提取。

---

## 九、什么时候该用函数重载

适合使用重载的场景：

1. 参数个数不同。
2. 参数类型不同。
3. 不同入参对应不同返回值。
4. 你希望调用者拿到精确提示。

例如：

1. `get(id: number)` 返回单条数据。
2. `get(ids: number[])` 返回数组数据。
3. `format(value: Date)` 和 `format(value: number)` 返回不同格式结果。

---

## 十、什么时候不该滥用重载

如果只是参数稍有差异，但返回值没有实质区别，可能直接写联合类型更简单。

例如：

```ts
function print(value: string | number) {
  console.log(value)
}
```

这种就没必要强行写重载。

### 10.1 一个判断标准

如果不用重载会让调用方类型明显变差，就考虑重载；否则先选更简单的联合类型写法。

这也是一个很实用的工程判断：重载是为调用体验服务的，不是为了让声明看起来更复杂。

---

## 十一、小结

1. 函数重载的价值是让同一函数支持多种调用方式，并给调用方更精确的返回类型。
2. 重载由“多个重载签名 + 一个实现签名”组成。
3. 实现签名必须兼容所有重载签名。
4. 调用签名、对象方法、交叉类型都可以表达类似重载效果。
5. `Parameters` 和 `ReturnType` 处理重载函数时通常只看最后一个签名，这一点要特别注意。
