# 字符串类型题目

## 一、一句话理解

**字符串类型题** 本质上是在类型系统里做“字符串模式匹配、递归拆解、结果累积和重新拼装”。

这类题表面上像是在做 `trim`、`split`、`replace`、路径生成、命名转换，实际上核心都离不开同一套模板：

1. 先用模板字符串类型匹配目标结构。
2. 匹配成功后把字符串拆成几段。
3. 对剩余部分继续递归。
4. 用累积器保存中间结果，最后再统一返回。

---

## 二、这类题的核心不是“背答案”

字符串类型题本质上是在练 4 件事：

| 能力                 | 常见写法                             |
| -------------------- | ------------------------------------ |
| **按字符拆字符串**   | ``T extends `${infer F}${infer R}``` |
| **递归处理剩余部分** | 递归传入 `R`                         |
| **累积结果**         | 额外增加 `Result` 参数               |
| **字符串重组**       | `${A}${B}`                           |

所以很多题虽然表面不同，底层套路其实一样。

---

## 三、最基础的模板：拆一个字符

字符串类型题最常见的起手式：

```ts
type SplitOnce<T extends string> = T extends `${infer F}${infer R}`
  ? [F, R]
  : never
```

它表示：

1. 把第一个字符提取为 `F`
2. 剩余部分提取为 `R`
3. 如果拆不出来，说明字符串为空

这个模板是很多题的基础。

## 四、取首字符 / 尾字符

### 3.1 取首字符

```ts
type GetFirstChar<T extends string> = T extends `${infer F}${string}`
  ? F
  : never

type T1 = GetFirstChar<"sun">
type T2 = GetFirstChar<"">
```

思路很简单：只要能拆出第一个字符，就把它返回。

### 3.2 取尾字符

取尾字符比取首字符难一点，因为模板字符串更适合从前往后拆，所以通常用递归把“当前字符”不断往后传。

```ts
type GetLastChar<
  T extends string,
  LastChar extends string = "",
> = T extends `${infer First}${infer Rest}`
  ? GetLastChar<Rest, First>
  : LastChar

type T1 = GetLastChar<"abc">
type T2 = GetLastChar<"">
```

这里的 `LastChar` 就是累积器。

做这类题时，一个很重要的判断是：

1. 如果你只需要“看第一段”，通常一次匹配就够了。
2. 如果你需要“知道最后那一段”，通常就得递归走完整个字符串。

## 五、字符串和元组之间互转

### 4.1 字符串转元组

```ts
type StringToTuple<
  T extends string,
  Result extends string[] = [],
> = T extends `${infer Left}${infer Right}`
  ? StringToTuple<Right, [...Result, Left]>
  : Result

type T1 = StringToTuple<"abc.CDE">
```

套路是：

1. 每次拆一个字符。
2. 放进结果数组。
3. 递归处理剩余字符串。

### 4.2 元组转字符串

```ts
type TupleToString<T extends any[], Result extends string = ""> = T extends [
  infer Left,
  ...infer Right,
]
  ? TupleToString<Right, `${Result}${Left & (string | number | boolean)}`>
  : Result

type T = TupleToString<["a", 3, "b", true]>
```

这题和上面正好反过来：一个在“拆字符串拼元组”，一个在“拆元组拼字符串”。

这类题特别值得熟，因为它本质上是在训练你理解：

1. 字符串递归和元组递归只是载体不同。
2. 真正稳定的套路是“拆当前项 + 递归剩余项 + 累积结果”。

## 六、重复、切分、计数类题目

### 5.1 重复字符串

```ts
type RepeatString<
  Str extends string,
  Count extends number,
  Counter extends any[] = [],
  Result extends string = "",
> = Counter["length"] extends Count
  ? Result
  : RepeatString<Str, Count, [...Counter, unknown], `${Result}${Str}`>
```

这类题常见套路是：

1. 用数组长度模拟数字递增。
2. 每次递归向结果里多拼一个字符串。

### 5.2 字符串 `split`

```ts
type SplitString<
  Str extends string,
  Separator extends string,
  Result extends string[] = [],
> = Str extends `${infer Left}${Separator}${infer Right}`
  ? SplitString<Right, Separator, [...Result, Left]>
  : [...Result, Str]
```

关键点：找到分隔符后，把左边放进结果，再继续处理右边。

### 5.3 字符串长度

```ts
type LengthOfString<
  Str extends string,
  Counter extends any[] = [],
> = Str extends `${infer _}${infer Right}`
  ? LengthOfString<Right, [...Counter, unknown]>
  : Counter["length"]
```

因为类型系统里不能直接像运行时那样取字符串长度，所以通常借助数组长度来计数。

这几类题经常一起出现，原因是它们都依赖两个通用技巧：

1. 用 `Counter extends any[] = []` 模拟数字增长。
2. 用 `Result` 保存每轮递归产生的新结果。

## 七、命名转换类题目

这类题在业务里很实用，比如组件事件名、接口字段转换、样式键名转换。

### 6.1 大驼峰 / 小驼峰转短横线

```ts
type KebabCase<
  Str extends string,
  Result extends string = "",
> = Str extends `${infer Left}${infer Right}`
  ? Left extends Lowercase<Left>
    ? KebabCase<Right, `${Result}${Left}`>
    : KebabCase<Right, `${Result}-${Lowercase<Left>}`>
  : Result extends `-${infer R}`
    ? R
    : Result
```

思路是：

1. 遇到大写字母就补 `-`。
2. 同时把当前字符转成小写。
3. 最后处理首字符可能多出来的 `-`。

### 6.2 短横线转驼峰

```ts
type CamelCase<Str extends string> = Str extends `${infer Left}-${infer Right}`
  ? `${Left}${Capitalize<CamelCase<Right>>}`
  : Str
```

思路是：找到 `-`，把后半段首字母大写再继续递归。

这类题比前面的难点不在递归，而在“边界修正”：

1. 首字符前面是否会多拼一个连接符。
2. 连续分隔符怎么处理。
3. 大小写转换发生在拼接前还是拼接后。

## 八、搜索与替换类题目

### 7.1 `includes`

```ts
type Includes<Str extends string, Inc extends string> = Str extends ""
  ? Inc extends ""
    ? true
    : false
  : Str extends `${string}${Inc}${string}`
    ? true
    : false
```

### 7.2 `trim`

```ts
type Trim<Str extends string> = Str extends ` ${infer Result}`
  ? Trim<Result>
  : Str extends `${infer Result} `
    ? Trim<Result>
    : Str
```

### 7.3 `replace`

```ts
type Replace<
  Str extends string,
  Rep extends string,
  Tar extends string,
> = Rep extends ""
  ? `${Tar}${Str}`
  : Str extends `${infer Left}${Rep}${infer Right}`
    ? Replace<`${Left}${Tar}${Right}`, Rep, Tar>
    : Str
```

这几类题的共同点是：

1. 先匹配目标片段。
2. 匹配到后拆成“左 + 目标 + 右”。
3. 再决定返回布尔、裁剪结果或重组结果。

写这类题时，最容易忽略的是“空串边界”：

1. 被查找串如果是空字符串，要不要直接返回。
2. 替换目标如果允许空字符串，递归可能失控。
3. 首尾空格、连续空格往往需要多轮递归才能清理干净。

## 九、路径与对象键名生成类题目

### 8.1 生成对象访问路径

```ts
type RemoveFirst<
  Str extends string,
  Rem extends string,
> = Str extends `${Rem}${infer Right}` ? Right : Str

type ObjectAccessPaths<
  Obj extends object,
  Result extends string = "",
  Key = keyof Obj,
> = Key extends keyof Obj
  ? Obj[Key] extends object
    ? ObjectAccessPaths<Obj[Key], `${Result}.${Key & string}`>
    : RemoveFirst<`${Result}.${Key & string}`, ".">
  : never
```

这里的关键点有两个：

1. `Key extends keyof Obj` 会触发分发，分别处理每个键。
2. 每深入一层对象，就把路径多拼上一段。

这类题常用于：

1. 表单字段路径推导。
2. i18n key 路径推导。
3. 配置项路径提示。

### 8.2 根据短横线事件名生成组件事件类型

```ts
type CamelCase<Str extends string> = Str extends `${infer Left}-${infer Right}`
  ? `${Left}${Capitalize<CamelCase<Right>>}`
  : Str

type ComponentEmitsType<Obj extends object> = {
  [Key in keyof Obj as `on${Capitalize<CamelCase<Key & string>>}`]: Obj[Key] extends (
    this: infer This,
    ...args: infer Args
  ) => any
    ? (this: This, ...args: Args) => void
    : Obj[Key]
}
```

这题综合用了：

1. 模板字符串类型
2. 键名重映射 `as`
3. `Capitalize`
4. `infer` 提取函数参数

属于典型综合题。

这一类题通常是字符串题里最接近真实开发的：

1. 表单字段路径补全。
2. 组件事件名推导。
3. 国际化 key 提示。
4. 配置项访问路径约束。

## 十、做字符串类型题时的通用套路

### 9.1 先判断这题属于哪一类

1. 提取某一段。
2. 统计数量。
3. 拆分和重组。
4. 命名转换。
5. 路径生成。

### 9.2 再选对应模板

| 题型       | 常见模板                     |
| ---------- | ---------------------------- |
| 拆字符串   | `${infer F}${infer R}`       |
| 找分隔符   | `${infer L}${Sep}${infer R}` |
| 递归计数   | `Counter extends any[] = []` |
| 累积字符串 | `Result extends string = ""` |
| 累积元组   | `Result extends any[] = []`  |

### 9.3 最后再考虑边界条件

例如：

1. 空字符串怎么处理。
2. 分隔符为空字符串时怎么处理。
3. 首字符是否需要特殊修正。
4. 是否会触发条件类型分发。

### 10.4 做题时最值得优先问自己的三个问题

1. 我现在要匹配的是“单字符”、"固定分隔符"，还是“前后两段结构”？
2. 这题需要返回单个字符串、布尔值，还是元组 / 联合类型？
3. 中间结果是用字符串累积更自然，还是用元组累积更稳定？

很多字符串类型题卡住，不是因为不会写递归，而是因为一开始没有选对“匹配模板”和“累积器形态”。

### 10.5 真实开发里怎么快速判断

| 场景                     | 优先思路                                              |
| ------------------------ | ----------------------------------------------------- |
| **只判断是否包含某模式** | 优先写成 ``Str extends `${string}${X}${string}```     |
| **要按分隔符拆分**       | 优先写成 ``Str extends `${infer L}${Sep}${infer R}``` |
| **要逐字符扫描**         | 优先写成 ``Str extends `${infer F}${infer R}```       |
| **要做数量统计**         | 额外引入 `Counter extends any[] = []`                 |
| **要不断生成新字符串**   | 额外引入 `Result extends string = ""`                 |
| **要收集多个片段**       | 额外引入 `Result extends any[] = []`                  |

---

## 十一、小结

1. 字符串类型题的底层核心是“模板字符串匹配 + 递归 + 累积器”。
2. 取首尾、`split`、`trim`、`replace`、命名转换，本质上都是同一套思路的不同变形。
3. 遇到复杂题时，先拆成“如何匹配、如何递归、如何保存结果”三个问题。
4. 真正有价值的不是记某一道题，而是记住可复用的模板。
