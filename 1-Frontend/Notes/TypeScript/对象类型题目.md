# 对象类型题目

## 一、一句话理解

对象类型题的核心，不是炫复杂技巧，而是熟练把条件类型、映射类型、`keyof` 和 `infer` 组合起来解决对象结构判断与重组问题。

---

## 二、这类题目的意义

这类题通常来自 `type-challenges` 一类的类型体操练习，核心目标不是“背答案”，而是训练你对这些能力的理解：

1. 条件类型。
2. 分发行为。
3. `infer` 推断。
4. 映射类型。
5. `keyof`、`Omit`、`Exclude` 等工具类型组合。

这篇不追求收录所有题，而是保留几道代表性题目和思路。

---

## 三、获取对象中的可选属性

### 1. 目标

从对象类型中取出所有可选属性名，组成联合类型。

### 2. 实现

```ts
type OptionalKeys<Obj extends object, Key = keyof Obj> = Key extends keyof Obj
  ? Omit<Obj, Key> extends Obj
    ? Key
    : never
  : never

type T1 = OptionalKeys<{
  foo: number | undefined
  bar?: string
  name?: string
  flag: boolean
}> // "bar" | "name"
```

### 3. 思路

如果删掉某个键后，剩余结构仍然能赋给原对象类型，说明这个键不是必须的。

---

## 四、获取对象中的必选属性

### 1. 实现

```ts
type RequiredKeys<Obj extends object, Key = keyof Obj> = Key extends keyof Obj
  ? Omit<Obj, Key> extends Obj
    ? never
    : Key
  : never

type T1 = RequiredKeys<{
  foo: number | undefined
  bar?: string
  name?: string
  flag: boolean
}> // "foo" | "flag"
```

### 2. 思路

和可选属性题是相反方向：删掉之后如果不再兼容，说明它是必选属性。

## 五、判断是不是 `never`

### 1. 经典写法

```ts
type IsNever<T> = [T] extends [never] ? true : false

type T1 = IsNever<never> // true
type T2 = IsNever<string> // false
type T3 = IsNever<undefined> // false
type T4 = IsNever<any> // false
```

### 2. 为什么要加方括号

为了避免条件类型分发，否则 `never` 会出现特殊行为，导致判断失真。

## 六、判断是不是 `any`

### 1. 一种常见写法

```ts
type IsAny<T> = unknown extends T
  ? [T] extends [number]
    ? true
    : false
  : false

type T1 = IsAny<string> // false
type T2 = IsAny<any> // true
type T3 = IsAny<unknown> // false
type T4 = IsAny<never> // false
```

### 2. 核心点

`any` 在类型系统里非常特殊，很多普通判断方式都会被它“吞掉”，所以需要额外技巧处理。

---

## 七、判断是不是空对象类型

### 1. 示例实现

```ts
type IsEmptyObj<T> = keyof T extends never
  ? unknown extends T
    ? false
    : number extends T
      ? true
      : false
  : false
```

### 2. 为什么这题会绕

因为 `{}`、`object`、`unknown`、`any` 这些类型本身就容易混淆，所以判断“空对象”时经常需要做特殊分支处理。

这类题的重点不在结果，而在于你是否真正理解这些类型之间的差异。

尤其是 `{}`、`object`、`unknown`、`any` 这几类一混进来，很多直觉都会失效。

## 八、联合类型转交叉类型

这是类型体操里的经典题。

### 1. 正确写法

```ts
type UnionToIntersection<T> = (T extends any ? (p: T) => void : never) extends (
  p: infer P,
) => any
  ? P
  : never

type T1 = UnionToIntersection<{ a: string } | { b: number } | { c: boolean }>
```

结果等价于：

```ts
{ a: string } & { b: number } & { c: boolean }
```

### 2. 为什么这样能成立

关键在于：

1. `T extends any` 触发分发。
2. 把联合成员放进函数参数位置。
3. 再利用参数逆变把联合“收缩”为交叉。

---

## 九、联合类型转元组类型

这类题通常难度更高，核心是先从联合中“抽出一个成员”，再递归构造元组。

### 1. 典型实现

```ts
type FindUnionOne<T> = (
  (T extends any ? (p: (p: T) => void) => void : never) extends (
    p: infer P,
  ) => any
    ? P
    : never
) extends (p: infer P) => any
  ? P
  : never

type UnionToTuple<T, Result extends any[] = []> = [T] extends [never]
  ? Result
  : UnionToTuple<Exclude<T, FindUnionOne<T>>, [FindUnionOne<T>, ...Result]>
```

### 2. 要注意的一点

联合类型本身是无序的，所以这类题虽然能构造元组，但顺序往往依赖推导细节，不适合把顺序当成绝对语义。

这也是为什么这类题更适合拿来练推导过程，而不是拿来承诺稳定顺序。

---

## 十、做题时的通用判断路径

1. 先判断题目是在“筛键”“改键”“改值”还是“重组整体结构”。
2. 再看有没有联合分发在暗中影响结果。
3. 如果结果很怪，优先检查 `any`、`never`、空对象相关类型是不是混进来了。

---

## 十一、总结

1. 对象类型题目的核心不是炫技，而是练习条件类型、映射类型和 `infer`。
2. `OptionalKeys`、`RequiredKeys`、`IsNever`、`IsAny` 都是高频代表题。
3. `UnionToIntersection` 是理解类型体操的重要分水岭。
4. 遇到这类题，优先先想“类型在判断时有没有分发”。
5. 真正学会之后，你写复杂工具类型时会轻松很多。
