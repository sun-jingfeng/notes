# 数组类型题目

## 一、一句话理解

数组类型题的本质，不是记某一题答案，而是熟练使用“元组拆解 + 递归 + 累积器 + 长度计数”这四套模板。

---

## 二、数组类型题在练什么

数组类型题本质上是在练：**如何用元组递归模拟数组操作。**

最常见的基础能力有 4 类：

| 能力               | 常见写法                                         |
| ------------------ | ------------------------------------------------ |
| **取头尾元素**     | `[infer F, ...infer R]`、`[...infer R, infer L]` |
| **递归遍历元组**   | `T extends [infer L, ...infer R] ? ... : ...`    |
| **累积结果**       | `Result extends any[] = []`                      |
| **用长度模拟数字** | `Counter["length"]`                              |

所以做题时，重点不是记住某个答案，而是看懂“拆头、拆尾、递归、累积”这套模式。

---

## 三、最基础的元组操作

### 3.1 取长度

```ts
type LengthOfTuple<T extends any[]> = T["length"]
```

这道题最基础，因为元组长度本身就是字面量数字。

```ts
type T1 = LengthOfTuple<[1, 2, 3]>
type T2 = LengthOfTuple<[]>
type T3 = LengthOfTuple<number[]>
```

注意：

1. 元组长度通常能得到具体数字。
2. 普通数组长度通常只能得到 `number`。

### 3.2 取第一个元素

```ts
type FirstItem<T extends any[]> = T[0]
```

### 3.3 取最后一个元素

不能写成运行时代码那种减法形式：

```ts
// type LastItem<T extends any[]> = T[T["length" - 1]]
```

因为类型系统里不能这样直接做索引运算。

常见写法是元组解构：

```ts
type LastItem<T extends any[]> = T extends [...any[], infer Last] ? Last : never
```

如果想兼容普通数组：

```ts
type LastItem<T extends any[]> = T extends [...any[], infer Last]
  ? Last
  : T extends Array<infer Every>
    ? Every
    : never
```

## 四、模拟数组基础方法

### 4.1 `shift`

```ts
type Shift<T extends any[]> = T extends [any, ...infer R] ? R : never
```

思路：丢掉第一个元素，保留剩余部分。

### 4.2 `push`

```ts
type Push<T extends any[], Item> = [...T, Item]
```

这类题很简单，因为元组展开本身就能表达“尾部新增”。

---

## 五、递归重组类题目

### 5.1 反转数组

```ts
type ReverseTuple<T extends any[], Result extends any[] = []> = T extends [
  infer L,
  ...infer R,
]
  ? ReverseTuple<R, [L, ...Result]>
  : Result
```

这题的本质是：

1. 每次取出头部元素。
2. 放到结果数组最前面。
3. 继续处理剩余部分。

### 5.2 数组拍平

```ts
type Flat<T extends any[]> = T extends [infer L, ...infer R]
  ? L extends any[]
    ? [...Flat<L>, ...Flat<R>]
    : [L, ...Flat<R>]
  : []
```

这题体现的是：

1. 先遍历数组。
2. 如果当前元素还是数组，就递归展开。
3. 否则直接保留。

## 六、用数组长度模拟数字

类型系统里不能像运行时那样自然做 `i + 1`，所以很多题会借助数组长度模拟数字累加。

### 6.1 根据长度生成数组

```ts
type Repeat<
  T,
  Count extends number,
  Result extends any[] = [],
> = Result["length"] extends Count ? Result : Repeat<T, Count, [...Result, T]>
```

思路是：

1. 结果数组长度没到 `Count`。
2. 就继续往结果数组里加一个 `T`。
3. 长度到了就结束递归。

这个套路在 `slice`、`splice`、字符串长度、重复字符串等题里都很常见。

## 七、过滤与查找类题目

### 7.1 `filter`

```ts
type Filter<T extends any[], F, Result extends any[] = []> = T extends [
  infer L,
  ...infer R,
]
  ? [L] extends [F]
    ? Filter<R, F, [...Result, L]>
    : Filter<R, F, Result>
  : Result
```

这里有个关键点：

为什么写 `[L] extends [F]`，而不是 `L extends F`？

因为前者可以避免分发条件类型带来的意外结果，尤其在 `any` 参与时更稳定。

### 7.2 `findIndex`

这类题通常也会借助“数组长度累积器”记录当前位置。

```ts
type FindIndex<T extends any[], F, Counter extends any[] = []> = T extends [
  infer L,
  ...infer R,
]
  ? [L] extends [F]
    ? Counter["length"]
    : FindIndex<R, F, [...Counter, unknown]>
  : never
```

如果需要精确相等比较，通常还会配合额外的 `IsEqual` 工具类型。

## 八、数组转对象类题目

### 8.1 元组转枚举对象

```ts
type TupleToEnum<T extends readonly PropertyKey[], UseIndex = false> = {
  readonly [Key in T[number]]: UseIndex extends true
    ? FindIndex<T extends any[] ? T : never, Key>
    : Key
}
```

这题综合用了：

1. `T[number]` 取出元组元素联合。
2. 映射类型遍历联合键。
3. 条件类型决定值是自身还是索引。

## 九、`slice` / `splice` 这类偏综合题

### 9.1 `slice` 的思路

这类题通常会拆成两步：

1. 先跳过前 `Start` 个元素。
2. 再收集到 `End` 位置为止。

示意写法：

```ts
type Slice<
  T extends any[],
  Start extends number,
  End extends number = T["length"],
  Skipped extends any[] = [],
  Result extends any[] = [],
> = T extends [infer L, ...infer R]
  ? Skipped["length"] extends Start
    ? [...Skipped, ...Result]["length"] extends End
      ? Result
      : Slice<R, Start, End, Skipped, [...Result, L]>
    : Slice<R, Start, End, [...Skipped, unknown], Result>
  : Result
```

这里最关键的是：

1. `Skipped` 负责模拟当前游标。
2. `Result` 负责收集最终片段。

### 9.2 `splice` 的思路

`splice` 一般会更复杂，因为它要同时处理：

1. 起始位置。
2. 删除数量。
3. 插入内容。

如果只是理解套路，可以先记住：

**本质上就是“切成前半段 + 删除段 + 后半段”，再把插入内容拼回去”。**

例如：

```ts
type Splice<
	T extends any[],
	Start extends number,
	DeleteCount extends number,
	Insert extends any[] = []
> = [...Slice<T, 0, Start>, ...Insert, ...Slice<T, Start + DeleteCount>]
```

实际纯类型实现里因为不能直接写 `Start + DeleteCount`，通常需要继续用数组长度模拟数字，这就是它难的地方。

所以这类题一旦感觉复杂，先别急着写完整实现，先把“游标”“结果”“剩余输入”三部分拆清楚。

## 十、做数组类型题的通用套路

### 10.1 先判断是“取元素”还是“改结构”

1. 取元素：优先考虑 `infer` 头尾拆分。
2. 改结构：优先考虑递归 + `Result`。
3. 涉及数字下标：优先考虑数组长度计数。

### 10.2 高频模板

| 题型     | 常用模板                                      |
| -------- | --------------------------------------------- |
| 取头部   | `[infer F, ...infer R]`                       |
| 取尾部   | `[...infer R, infer L]`                       |
| 递归遍历 | `T extends [infer L, ...infer R] ? ... : ...` |
| 计数     | `Counter extends any[] = []`                  |
| 累积结果 | `Result extends any[] = []`                   |

### 10.3 注意边界情况

1. 空元组怎么处理。
2. 普通数组和元组是否都要兼容。
3. 是否会被 `any` 触发分发。
4. 返回 `never`、`[]`、`undefined` 哪个更合理。

---

## 十一、做题时最值得优先问自己的三个问题

1. 这题是在“取元素”，还是在“改结构”。
2. 需不需要递归，如果需要，递归时谁是剩余输入、谁是累积结果。
3. 题目里的数字位置能不能直接表达，还是要靠数组长度模拟。

---

## 十二、小结

1. 数组类型题本质上是“用元组递归模拟数组操作”。
2. 头尾拆分、递归遍历、结果累积、长度计数，是最核心的四套基本功。
3. `filter`、`flat`、`reverse`、`slice`、`splice` 本质上都能拆回这些基础模板。
4. 学这类题时，优先记套路，不要只记某一道题的最终写法。
