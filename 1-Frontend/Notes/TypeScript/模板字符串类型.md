# 模板字符串类型

## 一、一句话理解

模板字符串类型的核心价值，不只是“在类型里拼字符串”，而是把字符串规则本身变成可推导、可校验的类型约束。

---

## 二、什么是模板字符串类型

模板字符串类型可以理解为：**把 JavaScript 里的模板字符串写法搬到了类型系统中，用来拼接、约束、匹配字符串类型。**

最基本的例子：

```ts
type Name = "Sun"
type SayHi = `hi, ${Name}`
```

此时：

```ts
type SayHi = "hi, Sun"
```

它的本质是：**根据已有的字面量类型，生成新的字符串字面量类型。**

---

## 三、模板字符串类型最核心的价值

1. 组合字符串字面量。
2. 约束字符串格式。
3. 从字符串中提取片段。
4. 配合映射类型批量生成键名。

在 TypeScript 高级类型里，它非常常见。

---

## 四、联合类型会自动展开

这是模板字符串类型最重要的特性之一。

### 4.1 单个联合类型展开

```ts
type Direction = "top" | "right" | "bottom" | "left"
type AllMargin = `margin-${Direction}`
```

结果是：

```ts
type AllMargin = "margin-top" | "margin-right" | "margin-bottom" | "margin-left"
```

### 4.2 多个联合类型组合

```ts
type Prop = "margin" | "padding"
type Value = "100px" | "200px"
type Style = `${Prop}: ${Value}`
```

结果会做笛卡尔积展开：

```ts
type Style =
  | "margin: 100px"
  | "margin: 200px"
  | "padding: 100px"
  | "padding: 200px"
```

这也是为什么模板字符串类型很适合生成成批的字符串规则。

---

## 五、与泛型结合使用时的限制

### 5.1 为什么直接写会报错

```ts
// type SaySomething<T> = `hi, ${T}`
```

这是因为模板字符串插槽中的类型，必须能落到可字符串化的那几个基础类型范围内。

### 5.2 常见写法一：直接约束泛型

```ts
type SaySomething<T extends string | number | boolean> = `hi, ${T}`

type T1 = SaySomething<"Sun">
type T2 = SaySomething<123>
type T3 = SaySomething<true>
```

### 5.3 常见写法二：通过交叉类型收窄

```ts
type SaySomething<T> = `hi, ${T & string}`

type T1 = SaySomething<"Sun">
type T2 = SaySomething<123>
```

这里的效果是：

1. 如果 `T` 能兼容 `string`，就继续拼接。
2. 如果不能兼容，就得到 `never`。

---

## 六、字面量类型和宽泛类型的区别

### 6.1 字面量类型会得到确定结果

```ts
type T = `hi, ${"Sun"}`
```

结果是：

```ts
type T = "hi, Sun"
```

### 6.2 宽泛类型不会收敛成某个具体字符串

```ts
type T = `hi, ${string}`
```

它表示的是“所有符合 `hi, xxx` 结构的字符串”，而不是某一个具体值。

所以要记住：

1. **字面量类型** 会得到具体结果。
2. **宽泛类型** 会得到模式化字符串类型。

---

## 七、模板字符串类型可以用来约束格式

### 7.1 约束固定前缀

```ts
type NumKey = `num${number}`

const list: NumKey[] = ["num0", "num1", "num2"]
```

### 7.2 约束命名规则

```ts
type InnerKey = `inner_${string}`

const keys: InnerKey[] = ["inner_data1", "inner_data2"]
```

这类写法在前端工程里非常常见，例如：

1. 事件名约束。
2. className 约束。
3. 路由 key、缓存 key、埋点 key 约束。

---

## 八、和 `infer` 结合时可以做字符串匹配

模板字符串类型不只是“拼接”，还可以“拆解”。

```ts
type GetFirstName<T extends string> = T extends `${infer F} ${string}`
  ? F
  : never

type T1 = GetFirstName<"Sun Jingfeng">
```

这里的逻辑是：

1. 如果字符串能匹配 `名字 + 空格 + 其他内容`
2. 就把前半段提取成 `F`
3. 最终得到名字部分

这类写法是后面很多字符串题的基础。

---

## 九、字符串相关内置工具类型

TypeScript 提供了几个高频字符串工具类型。

| 工具类型              | 作用       |
| --------------------- | ---------- |
| **`Uppercase<T>`**    | 全部转大写 |
| **`Lowercase<T>`**    | 全部转小写 |
| **`Capitalize<T>`**   | 首字母大写 |
| **`Uncapitalize<T>`** | 首字母小写 |

示例：

```ts
type T1 = Uppercase<"sun">
type T2 = Lowercase<"SUN">
type T3 = Capitalize<"sun">
type T4 = Uncapitalize<"SUN">
```

这些工具常和模板字符串类型组合使用，例如：

1. 批量生成事件名。
2. 驼峰 / 短横线命名转换。
3. 构造带前缀的对象键名。

---

## 十、实际开发中的常见场景

### 10.1 生成事件名

```ts
type EventName<T extends string> = `on${Capitalize<T>}`
```

### 10.2 生成 CSS 属性名

```ts
type Direction = "top" | "right" | "bottom" | "left"
type MarginKey = `margin-${Direction}`
```

### 10.3 约束路径和标识符格式

```ts
type CacheKey = `user:${string}`
type RouteName = `page-${string}`
```

---

## 十一、真实开发里怎么快速判断

| 需求                           | 更适合的能力              |
| ------------------------------ | ------------------------- |
| **批量生成规则化字符串联合**   | 模板字符串类型            |
| **把旧键名映射成新键名**       | 模板字符串类型 + 键重映射 |
| **从字符串结构里提取一段信息** | 模板字符串类型 + `infer`  |
| **只是普通自由字符串**         | 不一定需要模板字符串类型  |

---

## 十二、小结

1. 模板字符串类型本质上是“在类型层拼接和匹配字符串”。
2. 联合类型放进模板字符串中会自动展开。
3. 它既能生成字符串，也能用 `infer` 拆解字符串。
4. 搭配 `Uppercase`、`Capitalize` 等工具类型，可以做很多命名转换。
5. 它是字符串类型题、事件命名、键名映射、格式约束里的核心基础。
