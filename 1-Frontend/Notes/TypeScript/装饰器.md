# 装饰器

## 一、一句话理解

装饰器的核心不是“加一个语法糖”，而是用声明式方式给类和成员附加元数据或增强逻辑。

---

## 二、什么是装饰器

装饰器本质上是一个函数，用来给类或类成员附加额外行为。

它常被用在：

1. 元数据收集。
2. 依赖注入。
3. 路由注册。
4. 参数校验。
5. AOP 风格增强。

---

## 三、使用前要知道的事

TypeScript 里的装饰器要特别注意版本背景。

### 1. 历史上的实验性装饰器

很多旧教程说的都是 TypeScript 的实验性装饰器，需要：

```json
{
  "compilerOptions": {
    "experimentalDecorators": true
  }
}
```

### 2. 现代语义与旧教程差异

近年 JavaScript 标准装饰器语义已经推进，TypeScript 也在逐步支持新的装饰器模型。

所以你在学习时要先确认：

1. 当前项目使用的是旧装饰器语义还是新语义。
2. 教程代码是否和你的 TS 版本一致。

这篇主要先以**常见旧教程语义**做理解，因为很多现存资料和框架示例仍然基于这一套。

这里最重要的不是背参数顺序，而是先确认“你看到的示例到底属于哪一代装饰器语义”。

---

## 四、类装饰器

类装饰器作用在类本身。

### 1. 基本示例

```ts
function Decorator(target: any) {
  target.type = "人类"
  target.prototype.age = 20
}

@Decorator
class People {}

console.log((People as any).type)
console.log((new People() as any).age)
```

### 2. 可以返回新类覆盖原类

```ts
function Overwrite<T extends new (...args: any[]) => any>(target: T) {
  return class extends target {
    eat() {
      console.log("child eat")
    }
  }
}

@Overwrite
class Person {
  eat() {
    console.log("parent eat")
  }
}
```

如果装饰器返回了一个新类，原类会被替换。

---

## 五、多个装饰器的执行顺序

```ts
function Decorator1(target: any) {
  target.type = "人类 1"
}

function Decorator2(target: any) {
  target.type = "人类 2"
}

@Decorator2
@Decorator1
class People {}
```

一个常见记忆方式是：

1. 先从上往下读取。
2. 再从下往上执行。

因此，离类更近的装饰器通常先执行。

---

## 六、方法装饰器

方法装饰器可以读取或修改方法描述符。

### 1. 基本签名

```ts
function Enum(target: any, key: string, descriptor: PropertyDescriptor) {}
```

### 2. 参数含义

| 参数         | 含义         |
| ------------ | ------------ |
| `target`     | 类的原型     |
| `key`        | 方法名       |
| `descriptor` | 属性描述对象 |

### 3. 修改可枚举性

```ts
function Enum(target: any, key: string, descriptor: PropertyDescriptor) {
  descriptor.enumerable = true
}

class Animal {
  @Enum
  eat() {}
}
```

### 4. 包装原方法

```ts
function Log(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value

  descriptor.value = function (...args: any[]) {
    console.log("before")
    const result = original.call(this, ...args)
    console.log("after")
    return result
  }
}
```

这种写法很适合做日志、埋点、耗时统计。

也就是说，方法装饰器最常见的价值，是在不改业务调用方式的前提下包一层通用增强。

---

## 七、属性装饰器

属性装饰器可以作用在实例属性上。

```ts
function Mark(target: any, key: string) {}

class People {
  @Mark
  name = "Sun"
}
```

### 1. 注意点

属性装饰器通常拿不到属性初始化值本身，它更常用于：

1. 记录元数据。
2. 做标记。
3. 配合其他反射库使用。

---

## 八、访问器装饰器

访问器装饰器作用在 `getter` / `setter` 上。

```ts
function ToUpper(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.set

  descriptor.set = function (newVal: string) {
    original?.call(this, newVal.toUpperCase())
  }
}

class People {
  private _name = "Sun"

  @ToUpper
  set name(newVal: string) {
    this._name = newVal
  }

  get name() {
    return this._name
  }
}
```

这类装饰器适合做输入规整、权限控制、缓存处理。

---

## 九、参数装饰器

参数装饰器作用在方法参数上。

```ts
function Params(target: any, key: string, index: number) {}

class People {
  play(@Params value: string) {}
}
```

### 1. 参数含义

1. `target`：类原型。
2. `key`：参数所在的方法名。
3. `index`：参数位置索引。

参数装饰器常用于：

1. 标记必填参数。
2. 标记路由参数。
3. 做依赖注入信息采集。

---

## 十、装饰器工厂

如果装饰器需要传参，通常会写成“返回装饰器函数”的形式。

```ts
function Enum(isEnum: boolean) {
  return function (target: any, key: string, descriptor: PropertyDescriptor) {
    descriptor.enumerable = isEnum
  }
}

class Animal {
  @Enum(true)
  eat() {}
}
```

这种形式通常叫**装饰器工厂**。

---

## 十一、`reflect-metadata`

很多装饰器高级玩法会配合 `reflect-metadata` 使用。

```ts
import "reflect-metadata"

const REQUIRED_KEY = Symbol("REQUIRED_KEY")

function Required() {
  return (target: any, prop: string) => {
    const requiredKeys = Reflect.getMetadata(REQUIRED_KEY, target) ?? []
    Reflect.defineMetadata(REQUIRED_KEY, [...requiredKeys, prop], target)
  }
}
```

### 1. 它常见的价值

1. 存储元数据。
2. 配合依赖注入框架。
3. 做校验规则收集。
4. 做控制器、路由、参数映射。

很多后端或框架型代码里的装饰器体系，本质上都离不开元数据能力。

---

## 十二、真实开发里什么时候值得用装饰器

| 场景                                     | 是否适合   |
| ---------------------------------------- | ---------- |
| **框架层元数据收集、依赖注入、路由注册** | 很适合     |
| **日志、埋点、权限、缓存等通用增强**     | 适合       |
| **普通业务函数里零散加点逻辑**           | 不一定值得 |
| **团队对装饰器语义和版本不统一**         | 要谨慎     |

---

## 十三、总结

1. 装饰器本质是函数，用来给类和成员附加行为。
2. 常见装饰器类型包括类、方法、属性、访问器、参数装饰器。
3. 如果装饰器返回新类，就会替换原类。
4. 现代 TypeScript 中要先区分你看到的是旧实验性装饰器还是新标准装饰器语义。
5. 学装饰器时，重点是理解“增强”和“元数据”，而不是死记参数顺序。
