# 赋值兼容性

## 一、一句话理解

赋值兼容性讨论的核心，不是两个类型名字像不像，而是“源值能不能至少满足目标类型要求”。

---

## 二、什么是赋值兼容性

赋值兼容性说的是：**一个类型的值，能不能赋给另一个类型的变量。**

TypeScript 是结构类型系统，所以很多时候它更关心“结构是否满足要求”，而不是“名字是不是一样”。

---

## 三、对象的赋值兼容性

对于对象来说，可以先记住一个常见原则：

**目标类型要求的属性，只要源值都有，就通常可以赋值。**

```ts
let obj1 = {
  a: 123,
  b: 123,
}

let obj2 = {
  a: 123,
  b: 123,
  c: 123,
}

obj1 = obj2 // 允许
// obj1.c // 报错
```

### 1. 为什么反过来不行

```ts
// obj2 = obj1 // 报错
```

因为 `obj2` 需要 `c`，而 `obj1` 没有。

### 2. 一个直观理解

可以理解成：

1. 你要求我至少有 `a`、`b`。
2. 我不仅有 `a`、`b`，还有 `c`。
3. 那我当然能满足你。

---

## 四、函数的赋值兼容性

函数兼容性主要看两部分：

1. 参数。
2. 返回值。

### 1. 参数兼容

```ts
let fn1 = (p1: number, p2: number) => 123
let fn2 = (p1: number) => 123

fn1 = fn2 // 常见情况下允许
// fn2 = fn1 // 不允许
```

### 2. 如何理解

当把 `fn2` 赋给 `fn1` 时，可以理解为：

1. 外界调用时可能会给两个参数。
2. 但 `fn2` 只用第一个参数，也还能正常工作。

不过这块在不同配置、回调场景、`strictFunctionTypes` 下会有更细的差异，初学阶段先掌握大原则即可。

所以函数兼容性最重要的不是背规则，而是知道参数位置和返回值位置的判断方向并不完全一样。

### 3. 返回值兼容

返回值一般遵循“返回更具体的，可以赋给返回更宽泛的”。

```ts
let fa: () => number | string
let fb: () => number

fa = fb // 允许
// fb = fa // 不允许
```

因为 `number` 可以放进 `number | string`，但反过来不行。

---

## 五、类的赋值兼容性

TypeScript 中类的兼容性，很多时候也遵循结构类型规则。

### 1. 普通属性情况下

```ts
class A {
  key1 = 123
  key2 = 123
}

class B {
  key1 = 123
  key2 = 123
  key3 = 123
}

const obj: A = new B()
```

这是允许的，因为 `B` 至少具备 `A` 所需的全部结构。

### 2. `private` / `protected` 会改变情况

```ts
class A {
  private key1 = 123
}

class B {
  private key1 = 123
}

// const obj: A = new B() // 报错
```

为什么？

因为带有 `private` 或 `protected` 成员时，兼容性不再只是看“长得像不像”，而会带上一点“声明来源是否一致”的限制。

这让类的兼容性在这类场景下更接近名义类型系统。

---

## 六、基础类型的赋值兼容性

相同类型之间当然兼容。

```ts
type T1 = number
type T2 = number

const data1: T1 = 123
const data2: T2 = data1
```

### 1. 为什么看起来不同但其实一样

因为 TypeScript 更关心底层表示的类型结构，而不是别名名字本身。

---

## 七、品牌类型（Branded Type）思路

有时候你希望两个底层一样的类型不要互相赋值，比如：

1. 用户 ID
2. 订单 ID

它们本质上都可能是 `number`，但语义不同。

这时可以借助“品牌类型”做区分。

```ts
class AddType<S> {
  private _type!: S
}

type NewType<T, S extends string> = T & AddType<S>

type UserId = NewType<number, "UserId">
type OrderId = NewType<number, "OrderId">

const userId = 123 as UserId
// const orderId: OrderId = userId // 报错
```

### 1. 用途

这类技巧适合在大型系统里避免“同底层类型但不同语义”的误传。

---

## 八、赋值兼容性的本质

从更高层看，赋值兼容性本质上是在回答这个问题：

**源值提供的信息，是否至少能满足目标类型的要求。**

### 1. 结构类型系统的一个特征

TypeScript 不是主要靠“名字相同”来判断兼容，而是主要靠“结构满足要求”来判断。

这也是它和很多传统强名义类型语言的一个明显差异。

---

## 九、真实开发里怎么快速判断

| 场景                           | 该先看什么                     |
| ------------------------------ | ------------------------------ |
| **对象能不能赋值**             | 目标要求的字段源值是否都具备   |
| **函数能不能赋值**             | 参数和返回值方向是否兼容       |
| **两个类长得很像却不能赋值**   | 是否有 `private` / `protected` |
| **底层类型一样但语义不能混用** | 是否需要品牌类型               |

---

## 十、总结

1. TypeScript 的赋值兼容性核心是“目标需要的结构，源值是否都能提供”。
2. 对象通常遵循“属性多的可以赋给属性少的”。
3. 函数兼容性要分别看参数和返回值。
4. 类在只有普通属性时接近结构兼容，但遇到 `private` / `protected` 会更严格。
5. 品牌类型是一种实用技巧，用来区分底层相同但语义不同的值。
