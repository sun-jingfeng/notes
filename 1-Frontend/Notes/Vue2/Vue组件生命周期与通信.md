# Vue组件生命周期与通信

## 一、这篇的主线

这一篇其实覆盖了 Vue 组件开发里的三条主线：

| 主线     | 回答的问题                          |
| -------- | ----------------------------------- |
| 生命周期 | 组件在什么阶段适合做什么事          |
| 数据共享 | 组件之间的数据应该怎么流动          |
| `ref`    | 什么时候需要直接拿 DOM 或子组件实例 |

---

## 二、组件的生命周期

生命周期指的是一个组件从创建、挂载、更新到销毁的完整过程。

生命周期函数是 Vue 在这些关键阶段自动调用的钩子函数，开发者可以在对应时机写初始化、请求数据、清理定时器等逻辑。

### 2.1 常见生命周期钩子

| 钩子            | 阶段         | 常见用途                     |
| --------------- | ------------ | ---------------------------- |
| `beforeCreate`  | 实例初始化前 | 很少直接使用                 |
| `created`       | 实例创建完成 | 初始化数据、发请求           |
| `beforeMount`   | 挂载前       | 很少直接使用                 |
| `mounted`       | 挂载完成     | 操作 DOM、发起依赖界面的逻辑 |
| `beforeUpdate`  | 更新前       | 更新前观察旧 DOM 状态        |
| `updated`       | 更新后       | 依赖更新后 DOM 的操作        |
| `beforeDestroy` | 销毁前       | 清理定时器、解绑事件         |
| `destroyed`     | 销毁后       | 组件已被移除                 |

### 2.2 生命周期的常见理解

1. `created` 时数据已经准备好了，但 DOM 还没挂载。
2. `mounted` 时可以安全访问页面上的真实 DOM。
3. 组件销毁前要记得清理副作用，例如定时器、全局事件、订阅。

### 2.3 一个实战判断标准

1. 只依赖数据、不依赖 DOM 的初始化逻辑，常放 `created`。
2. 必须等页面节点出来才能做的事，常放 `mounted`。
3. 清理副作用，常放 `beforeDestroy`。

### 2.4 一个高频排错点

如果你发现 DOM 取不到、第三方库初始化报空，第一时间先看是不是把依赖真实节点的逻辑写到了 `created` 里。

## 三、组件之间的数据共享

项目中最常见的组件关系主要有：

1. 父子关系。
2. 兄弟关系。

不同关系，数据通信方式也不同。

### 3.1 父组件向子组件传值

父传子使用 `props`。

`props` 的本质是父组件传入的数据接口。子组件应把 `props` 当作只读数据，不要直接修改。

### 3.2 子组件向父组件传值

子传父使用自定义事件，也就是 `$emit`。

```js
this.$emit("update-count", 100)
```

### 3.3 兄弟组件之间的数据共享

在 Vue2 中，兄弟组件常见方案是：

1. 父组件中转。
2. EventBus。

父组件中转更清晰，也更容易维护：

```text
A 子组件 emit -> 父组件改数据 -> 父组件 props 给 B 子组件
```

EventBus 更像轻量方案：

```js
bus.$emit("share-data", { name: "张三" })
bus.$on("share-data", handler)
```

### 3.4 各种通信方式怎么选

| 场景               | 更适合                        |
| ------------------ | ----------------------------- |
| 父传子             | `props`                       |
| 子传父             | `$emit`                       |
| 兄弟组件           | 父级中转优先，必要时 EventBus |
| 跨很多层或全局共享 | Vuex / 统一状态管理           |

### 3.5 一个边界提醒

EventBus 适合小型项目或临时通信；组件越来越多时会让数据流变得不清晰。大型项目更常用统一状态管理。

### 3.6 组件通信怎么快速判断

| 场景               | 更推荐   |
| ------------------ | -------- |
| 父传子             | `props`  |
| 子传父             | `$emit`  |
| 兄弟组件少量中转   | 父级中转 |
| 临时跨组件广播     | EventBus |
| 全局共享和复杂状态 | Vuex     |

## 四、`ref` 引用

`ref` 用于获取 DOM 元素或子组件实例的引用。

Vue 实例上有一个 `$refs` 对象，里面收集了模板中所有带 `ref` 的引用。

### 4.1 使用 `ref` 获取 DOM 元素

```html
<input ref="ipt" />
```

```js
this.$refs.ipt.focus()
```

### 4.2 使用 `ref` 获取组件实例

```html
<Child ref="childRef" />
```

```js
this.$refs.childRef.sayHi()
```

如果 `ref` 绑定的是组件，那么 `$refs.xxx` 拿到的是子组件实例；如果绑定的是普通标签，则拿到的是 DOM 元素。

### 4.3 什么时候该用 `ref`

1. 聚焦输入框。
2. 读取真实尺寸。
3. 调用子组件公开方法。

### 4.4 什么时候不要滥用 `ref`

如果本来可以用 `props`、事件和响应式数据流解决，就不要把 `ref` 当成常规通信方案。

### 4.5 一个真实判断标准

如果你的需求是“拿值、传值、同步状态”，先想 `props` / `$emit` / Vuex；如果你的需求是“拿 DOM、调焦点、读尺寸、调用子组件公开方法”，再考虑 `ref`。

## 五、`ref` 和条件渲染、`$nextTick`

如果某个元素受 `v-if` 控制，那么它可能还没渲染出来，此时直接访问 `$refs` 可能拿不到对应元素。

```js
this.inputVisible = true

this.$nextTick(() => {
  this.$refs.ipt.focus()
})
```

`this.$nextTick(cb)` 表示等 DOM 更新完成后，再执行回调函数。

这在下面几类场景特别常见：

1. 切换 `v-if` 后立刻获取新 DOM。
2. 更新列表后读取最新高度。
3. 打开弹窗后自动聚焦输入框。

### 5.1 一个核心理解

数据改了，不代表 DOM 已经立刻改完；`$nextTick` 解决的是“等视图真正更新后再操作”。

### 5.2 一个典型组合

```text
改响应式数据
  -> 视图进入异步更新队列
  -> DOM 更新完成
  -> $nextTick 回调执行
```

只要出现“刚改完数据就立刻读 DOM”的需求，就应该先想到这个链路。

## 六、生命周期、通信、ref 的配合思路

| 场景                | 推荐做法            |
| ------------------- | ------------------- |
| 组件创建后请求数据  | `created`           |
| 组件挂载后操作 DOM  | `mounted`           |
| 父传子              | `props`             |
| 子传父              | `$emit`             |
| 兄弟通信            | 父级中转 / EventBus |
| 获取 DOM 或组件实例 | `ref`               |
| 等 DOM 更新后再操作 | `$nextTick`         |

---

## 七、小结

1. 生命周期描述的是组件从创建到销毁的整个过程，重点要分清 `created`、`mounted`、`beforeDestroy` 这几个高频钩子。
2. Vue 的组件通信优先走清晰的数据流：父传子用 `props`，子传父用 `$emit`，兄弟通信优先父级中转。
3. `ref` 适合处理 DOM 和组件实例引用，不适合作为常规数据通信主通道。
4. `v-if`、异步更新和 DOM 操作一起出现时，通常要想到 `$nextTick`。
5. 学这一篇时，重点不是分别记 3 块知识点，而是理解“组件在不同阶段如何正确拿数据、传数据、操作 DOM”。
