# DOM编程基础与事件回调

## 一、一句话理解

这篇真正要建立的是一条 DOM 编程主线：函数被交给事件或异步时机执行，再在对应上下文里安全地操作节点、样式和业务数据。

---

## 二、这篇的主线

这篇实际上在讲 DOM 编程最常见的一条链路：

```text
写函数 -> 把函数交给事件或定时器 -> 在回调里操作节点、样式和数据属性
```

所以这些主题虽然分散，但在真实代码里经常一起出现。

---

## 三、具名函数与匿名函数

### 3.1 具名函数

具名函数就是有明确名字的函数。

```js
function sum(a, b) {
  return a + b
}
```

### 3.2 匿名函数

匿名函数本身没有函数名，常见于函数表达式、回调等场景。

```js
const sum = function (a, b) {
  return a + b
}
```

### 3.3 区别

| 对比项     | 具名函数声明       | 函数表达式               |
| ---------- | ------------------ | ------------------------ |
| 是否有名字 | 有                 | 常见写法中没有显式函数名 |
| 调用时机   | 通常可在声明前调用 | 必须先赋值后调用         |

### 3.4 一个实战建议

1. 复用逻辑、调试定位更重要的函数，更适合具名函数。
2. 一次性回调、小范围逻辑，匿名函数更常见。

### 3.5 一个真实选择标准

如果你已经明确这段函数后续需要解绑事件、复用逻辑、单独测试或看报错堆栈，通常就别再图省事写成匿名函数。

## 四、回调函数

如果把函数 A 作为参数传给函数 B，并在 B 的内部适时调用 A，那么 A 就叫回调函数。

```js
function handle(callback) {
  callback()
}

handle(function () {
  console.log("我是回调函数")
})
```

### 4.1 常见场景

| 场景     | 说明                  |
| -------- | --------------------- |
| 事件监听 | 事件触发时执行回调    |
| 定时器   | 时间到了执行回调      |
| 数组遍历 | 如 `forEach` 中的函数 |
| 异步请求 | 请求完成后执行回调    |

```js
setTimeout(function () {
  console.log("1 秒后执行")
}, 1000)
```

### 4.2 一个理解重点

回调的本质不是“写在函数里”，而是“由别的时机控制它何时执行”。

### 4.3 一个常见误区

回调不等于异步。事件监听、数组遍历、函数封装里都可能出现回调，只是执行时机由外部控制。

### 4.4 做回调题或看业务代码时先问什么

1. 这个函数是谁来调用。
2. 它什么时候被调用。
3. 调用时会传什么参数。
4. 它里面的 `this` 是谁。

---

## 五、`this` 环境对象

`this` 表示函数运行时所处的环境对象。

### 5.1 粗略判断规则

谁调用，`this` 就大概率指向谁。

```js
const obj = {
  name: "张三",
  sayHi() {
    console.log(this)
  },
}

obj.sayHi()
```

### 5.2 直接调用函数

```js
function test() {
  console.log(this)
}

test()
```

在浏览器非严格模式下，直接调用时 `this` 通常指向 `window`；严格模式下通常是 `undefined`。

### 5.3 事件回调里的 `this`

```js
button.addEventListener("click", function () {
  console.log(this)
})
```

普通函数写法中，这里的 `this` 通常指向当前绑定事件的元素。

### 5.4 一个边界提醒

如果换成箭头函数，它不会自己生成 `this`，而是继承外层上下文，这一点在事件回调里很容易踩坑。

### 5.5 普通函数和箭头函数怎么选

| 场景                            | 更常见的选择 |
| ------------------------------- | ------------ |
| **需要事件元素本身作为 `this`** | 普通函数     |
| **明确希望继承外层 `this`**     | 箭头函数     |
| **对象方法依赖调用者**          | 普通函数更稳 |

### 5.6 一个排错提醒

事件回调里如果 `this` 突然不是你预期的元素，第一时间先看有没有把普通函数改成箭头函数，或者有没有在别的地方通过 `call`、`bind`、`apply` 改过调用方式。

## 六、事件监听

事件监听就是让程序去检测某个事件是否发生，一旦发生，就执行对应逻辑。

```js
const btn = document.querySelector("button")

btn.addEventListener("click", function () {
  console.log("按钮被点击了")
})
```

### 6.1 事件监听三要素

| 要素     | 说明                   |
| -------- | ---------------------- |
| 事件源   | 哪个元素触发事件       |
| 事件类型 | 什么行为，如 `click`   |
| 回调函数 | 事件发生后执行什么逻辑 |

### 6.2 `addEventListener` 和 L0 事件的区别

| 写法                 | 特点                           |
| -------------------- | ------------------------------ |
| `onclick = fn`       | 简单，但可维护性和扩展性较弱   |
| `addEventListener()` | 更灵活，可配合捕获、移除等能力 |

真实业务里通常优先 `addEventListener()`。

### 6.3 事件委托意识

如果很多相似子元素都要绑定点击事件，真实业务里通常会考虑事件委托，而不是给每个节点单独绑一遍监听器。

## 七、查找节点

### 7.1 常用方法

| 方法                              | 作用                     |
| --------------------------------- | ------------------------ |
| `document.getElementsByTagName()` | 根据标签名查找多个元素   |
| `document.querySelector()`        | 根据选择器查找第一个元素 |
| `document.querySelectorAll()`     | 根据选择器查找所有元素   |

```js
const firstItem = document.querySelector(".item")
const allItems = document.querySelectorAll(".item")
```

### 7.2 伪数组

像 `querySelectorAll()` 返回的结果，通常是类数组对象。

| 特点               | 说明                    |
| ------------------ | ----------------------- |
| 有下标             | 可以通过 `[0]` 访问     |
| 有 `length`        | 可以遍历                |
| 不一定有真数组方法 | 比如不一定能直接 `push` |

### 7.3 一个选择建议

1. 需要第一个匹配结果，用 `querySelector()`。
2. 需要按 CSS 选择器批量查找，用 `querySelectorAll()`。
3. 老写法的标签 / 类名 / id 查询要会看，但新代码通常更偏向统一使用选择器 API。

### 7.4 一个维护性提醒

查找节点时，真正重要的不只是“能不能查到”，还包括：

1. 选择器是否稳定。
2. 是否容易被结构调整影响。
3. 查询范围是否应该收敛到某个父容器内。

## 八、更新元素样式

### 8.1 直接写 `style`

```js
box.style.width = "200px"
box.style.backgroundColor = "pink"
```

适合修改少量样式。

### 8.2 `cssText`

```js
box.style.cssText = "width: 200px; height: 100px; background: pink;"
```

适合一次写多条样式，但会让样式字符串集中在 JS 中，维护性一般。

### 8.3 `className` / `classList`

```js
box.classList.add("active")
box.classList.remove("active")
box.classList.toggle("active")
```

### 8.4 三种方式对比

| 方式      | 适用场景             |
| --------- | -------------------- |
| `style`   | 改少量单个样式       |
| `cssText` | 一次覆盖多条内联样式 |
| 类名切换  | 最适合真实业务开发   |

一个实战结论：状态切换类样式，通常优先类名切换，而不是在 JS 里堆一长串内联样式。

### 8.5 类名切换、内联样式、读计算样式怎么分工

| 需求                   | 更推荐               |
| ---------------------- | -------------------- |
| 业务状态切换           | `classList`          |
| 少量临时样式修正       | `style`              |
| 一次性覆盖很多内联样式 | `cssText`            |
| 读取最终生效样式       | `getComputedStyle()` |

## 九、获取元素样式

可以通过 `getComputedStyle()` 获取元素最终生效的样式。

```js
const style = window.getComputedStyle(box)
console.log(style.width)
console.log(style.getPropertyValue("background-color"))
```

### 9.1 `style` 和 `getComputedStyle()` 的区别

| 方式                 | 拿到的是什么         |
| -------------------- | -------------------- |
| `element.style`      | 当前元素的内联样式   |
| `getComputedStyle()` | 最终计算后的生效样式 |

### 9.2 一个容易误解的点

如果样式来自外部样式表，直接读 `element.style.xxx` 往往拿不到；这时就该用 `getComputedStyle()`。

另外，读样式是“读最终结果”，不代表适合把它当成业务状态源反复依赖。

## 十、自定义属性

除了标签标准属性外，开发者还可以通过 `data-*` 的形式扩展自定义属性。

```html
<div data-info="user" data-login-name="zhangsan"></div>
```

### 10.1 使用价值

| 价值           | 说明                 |
| -------------- | -------------------- |
| 存储额外数据   | 方便 JS 读取业务标识 |
| 不污染标准属性 | 结构更清晰           |

### 10.2 JavaScript 读取方式

```js
const box = document.querySelector("div")

console.log(box.dataset.info)
console.log(box.dataset.loginName)
```

### 10.3 规则

| 规则                       | 说明                                    |
| -------------------------- | --------------------------------------- |
| HTML 中必须以 `data-` 开头 | 如 `data-info`                          |
| JS 中通过 `dataset` 访问   | 不写 `data-`                            |
| 多单词转驼峰               | `data-login-name` → `dataset.loginName` |

### 10.4 一个实际用途

列表点击、事件委托、埋点标识、状态标记等场景里，`data-*` 都很常见。

### 10.5 `dataset`、`getAttribute()`、业务状态存储怎么选

| 需求                   | 更推荐                       |
| ---------------------- | ---------------------------- |
| 读写 `data-*` 业务标识 | `dataset`                    |
| 访问任意原始属性字符串 | `getAttribute()`             |
| 存复杂运行时状态       | 不要硬塞 DOM，优先业务状态层 |

`data-*` 适合挂轻量标识，不适合把复杂对象状态都塞进 DOM 结构里。

---

## 十一、把这些知识点串成真实开发链路

```text
先定义函数
  -> 把函数交给事件或其他时机调用
  -> 在回调里结合 this / 节点查找 / data-* 判断当前操作对象
  -> 再通过 classList 或样式更新界面
```

---

## 十二、小结

1. 具名函数和匿名函数的差别，不只是有没有名字，还影响复用和调试体验。
2. 回调函数的本质是“执行时机交给别人决定”。
3. `this`、事件监听和回调经常一起出现，理解它们的关系很重要。
4. 改样式时真实业务通常优先类名切换，读样式时要分清 `style` 和 `getComputedStyle()`。
5. `data-*` 是 DOM 编程里非常实用的业务数据挂载方式。
