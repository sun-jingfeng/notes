# 拖拽交互与滚动控制

## 一、一句话理解

拖拽和滚动都属于“位置变化”相关能力，但拖拽更关注用户交互中的移动与投放，滚动更关注视口和内容区域之间的位置关系。

---

## 二、先分清两种拖拽思路

前端里说“拖拽”，常见其实有两条路：

| 方案                       | 核心能力                              | 适合场景                            |
| -------------------------- | ------------------------------------- | ----------------------------------- |
| **原生 Drag and Drop API** | 浏览器提供 `dragstart`、`drop` 等事件 | PC 端拖入、拖出、简单排序、文件拖放 |
| **鼠标 / 手势模拟拖拽**    | 自己监听坐标变化                      | 自定义拖拽、复杂排序、移动端拖拽    |

这篇主要讲的是浏览器原生拖拽 API。

要先知道：原生拖拽在 PC 端更常见，但在移动端兼容性和交互体验通常不如自定义手势方案。

### 2.1 真实开发里怎么快速判断

| 需求                           | 更推荐                 |
| ------------------------------ | ---------------------- |
| PC 端文件拖入、简单拖放        | 原生 Drag and Drop API |
| 移动端拖拽、复杂排序、吸附跟手 | pointer / touch 方案   |
| 需要统一跨端体验               | 自定义手势拖拽         |

原生拖拽最适合“浏览器已经帮你定义好交互语义”的场景，不适合把它硬当成万能拖拽引擎。

---

## 三、原生拖拽的基本流程

实现一次最简单的拖拽放置，通常有这几步：

1. 给元素开启拖拽能力。
2. 在拖拽开始时记录当前被拖元素或数据。
3. 在目标区域里允许放置。
4. 在放下时执行 DOM 或数据更新。

```html
<div class="box">
  <span draggable="true">1</span>
  <span draggable="true">2</span>
  <span draggable="true">3</span>
</div>

<div class="target"></div>
```

```js
const items = document.querySelectorAll(".box span")
const target = document.querySelector(".target")

let current = null

items.forEach(item => {
  item.addEventListener("dragstart", event => {
    current = event.target
  })
})

target.addEventListener("dragover", event => {
  event.preventDefault()
})

target.addEventListener("drop", () => {
  if (current) {
    target.appendChild(current)
  }
})
```

## 四、拖拽相关属性和事件

### 1. `draggable`

要让元素支持原生拖拽，需要设置 `draggable="true"`。

```html
<div draggable="true">可拖拽元素</div>
```

### 2. 常见拖拽事件

| 事件            | 说明                   |
| --------------- | ---------------------- |
| **`dragstart`** | 开始拖拽时触发         |
| **`drag`**      | 拖拽过程中持续触发     |
| **`dragenter`** | 进入可放置区域时触发   |
| **`dragover`**  | 在目标区域上方持续触发 |
| **`dragleave`** | 离开目标区域时触发     |
| **`drop`**      | 放下时触发             |
| **`dragend`**   | 拖拽结束时触发         |

关键点：如果目标元素想接收 `drop`，通常必须在 `dragover` 中执行 `event.preventDefault()`。

### 3. `dataTransfer`

在很多拖拽场景中，不一定直接传 DOM 节点，也可以通过 `event.dataTransfer` 携带字符串数据。

```js
item.addEventListener("dragstart", event => {
  event.dataTransfer.setData("text/plain", event.target.dataset.id)
})

target.addEventListener("drop", event => {
  const id = event.dataTransfer.getData("text/plain")
  console.log(id)
})
```

这在跨容器传值、文件拖入、列表排序里都很常见。

### 4. 一个边界提醒

`dataTransfer` 更适合传轻量标识、文本信息或文件数据，不适合承载复杂状态管理本身。

更稳的做法通常是：

1. 拖拽时只传 `id`、类型、来源容器这类关键信息。
2. 真实的数据修改仍然交给业务状态层处理。

## 五、拖拽实战里的高频问题

| 问题                 | 常见原因                 | 处理思路                                 |
| -------------------- | ------------------------ | ---------------------------------------- |
| **`drop` 不触发**    | 忘了 `preventDefault()`  | 在 `dragover` 中放开默认限制             |
| **拖到目标区没反应** | 没保存当前拖拽对象或数据 | 在 `dragstart` 里明确记录                |
| **视觉反馈差**       | 没做进入、离开状态处理   | 用 `dragenter`、`dragleave` 切换高亮样式 |
| **移动端体验差**     | 原生拖拽不适合触屏       | 换手势库或用 pointer/touch 方案          |

什么时候不建议用原生拖拽：

- 需要移动端稳定支持。
- 需要复杂吸附、排序动画、拖拽边界控制。
- 需要精确跟随手指或鼠标坐标。

### 5.1 一个实战判断标准

如果你的需求里已经出现下面这些关键词，通常就该考虑放弃原生拖拽：

1. 拖拽排序动画。
2. 吸附到网格或边界。
3. 跨端统一手感。
4. 跟手预览和精确位置控制。

## 六、滚动相关 API

滚动通常分两种：页面整体滚动和局部容器滚动。

| 场景             | 说明                                         |
| ---------------- | -------------------------------------------- |
| **页面整体滚动** | 常操作 `window` 或根滚动容器                 |
| **局部容器滚动** | 常操作某个具体元素，比如弹窗内容区、表格区域 |

### 1. `scrollTo()`

让页面或元素滚动到指定位置。

```js
container.scrollTo({
  top: 300,
  left: 0,
  behavior: "smooth",
})
```

### 2. `scrollBy()`

基于当前位置继续滚动一段距离。

```js
container.scrollBy({
  top: 100,
  behavior: "smooth",
})
```

### 3. `scrollIntoView()`

让某个元素进入可视区域。

```js
targetElement.scrollIntoView({
  behavior: "smooth",
  block: "start",
})
```

常见场景：

- 锚点跳转
- 表单校验失败后滚到错误项
- 列表定位到当前选中项

### 4. 一个高频误区

`scrollIntoView()` 很省心，但它滚动的是“最近的可滚动祖先容器”，不是你想象中的任何容器都会一起动。

所以遇到滚动位置不对时，要先搞清楚：

1. 当前真正发生滚动的是页面，还是内部容器。
2. 目标元素是不是被某个局部滚动容器包住了。

## 七、滚动位置相关概念

### 1. 页面滚动

页面级常见读法：

```js
console.log(window.scrollY)
console.log(window.scrollX)
```

### 2. 容器滚动

局部滚动容器常见读法：

```js
console.log(container.scrollTop)
console.log(container.scrollLeft)
```

理解这组 API 很重要，因为“滚动没生效”经常不是方法错了，而是你滚错了对象。

### 3. 排查滚动没生效的常用顺序

1. 先确认真正可滚动的是哪个对象。
2. 再确认目标容器有没有固定高度和 `overflow`。
3. 再看是不是被 `position: fixed`、路由切换或异步渲染时机影响了。
4. 最后再排查平滑滚动配置和浏览器兼容差异。

---

## 八、页面滚动和容器滚动怎么选

| 需求                       | 推荐对象                    | 原因               |
| -------------------------- | --------------------------- | ------------------ |
| **回到页面顶部**           | `window` 或根滚动容器       | 控制整页视口       |
| **弹窗内部回到顶部**       | 弹窗内容元素                | 页面本身不该被带动 |
| **错误项自动出现**         | 目标元素 `scrollIntoView()` | 更省心             |
| **虚拟列表或表格区域滚动** | 具体内容容器                | 只控制局部区域     |

在路由场景中，像 `vue-router` 的 `scrollBehavior` 通常处理的是页面级滚动，而不是组件内部的滚动容器。

## 九、滚动事件的性能问题

滚动事件触发频率很高，如果每次都执行重逻辑，很容易卡顿。

常见优化方式：

1. 节流。
2. 防抖。
3. 配合 `requestAnimationFrame()`。
4. 尽量避免在滚动回调里频繁强制读取布局信息。

### 9.1 一个补充提醒

如果只是想判断元素是否进入视口，很多场景下 `IntersectionObserver` 会比手写高频 `scroll` 监听更省心，也更不容易把性能问题写进业务代码里。

一个简单例子：

```js
let ticking = false

window.addEventListener("scroll", () => {
  if (ticking) return

  ticking = true

  requestAnimationFrame(() => {
    console.log(window.scrollY)
    ticking = false
  })
})
```

## 十、常见应用场景

### 1. 拖拽

- 拖入上传区
- 简单卡片排序
- 把元素从一个容器移到另一个容器

### 2. 滚动

- 返回顶部
- 吸顶导航
- 锚点定位
- 表单错误项定位
- 长列表滚动定位

## 十一、小结

1. 拖拽先分清是原生 Drag and Drop，还是自定义手势拖拽，两者解决的问题并不一样。
2. 原生拖拽更适合 PC 端简单拖放和文件拖入，不适合复杂跨端交互。
3. 滚动相关 API 的关键不是记方法名，而是先分清“谁在滚”。
4. 排查这类问题时，目标对象、容器结构、触发时机和性能约束往往比 API 本身更重要。

| 知识点           | 结论                                           |
| ---------------- | ---------------------------------------------- |
| **原生拖拽前提** | 元素需要 `draggable="true"`                    |
| **放置关键**     | `dragover` 中执行 `preventDefault()`           |
| **数据传递**     | 可结合 `dataTransfer` 使用                     |
| **滚动核心 API** | `scrollTo()`、`scrollBy()`、`scrollIntoView()` |
| **实战重点**     | 先确认滚动对象，再做性能优化                   |
