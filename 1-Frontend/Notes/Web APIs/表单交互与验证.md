# 表单交互与验证

## 一、这篇的主线

这一篇真正的主线是“用户输入的完整链路”：

```text
用户输入 -> 浏览器提供输入能力 -> 前端校验 -> 读取数据 -> 监听过程事件 -> 最终提交
```

把这条链路建立起来，表单项、校验、事件这些知识点就不会显得零散。

---

## 二、HTML 表单项

除了最基础的文本输入框，表单还支持很多不同的输入类型。

### 2.1 常见 `input` 类型

| 类型     | 作用     |
| -------- | -------- |
| `number` | 数字输入 |
| `url`    | 网址输入 |
| `email`  | 邮箱输入 |
| `date`   | 日期选择 |
| `tel`    | 电话输入 |
| `range`  | 滑块选择 |
| `color`  | 颜色选择 |
| `file`   | 文件上传 |

```html
<input type="email" />
<input type="number" min="1" max="100" step="1" />
<input type="file" />
```

### 2.2 它们的价值

这些类型能让浏览器提供更合适的输入体验，例如：

1. 移动端弹出更适合的键盘。
2. 浏览器做一层基础校验。
3. 一些控件直接带选择能力。

### 2.3 一个选择标准

只要浏览器已经提供了更语义化的输入类型，就尽量不要全部退回普通 `text` 输入框。

---

## 三、原生表单验证

浏览器本身提供了一些基础表单验证能力。

### 3.1 常见方式

| 属性 / 类型    | 作用             |
| -------------- | ---------------- |
| `type="email"` | 基础邮箱格式校验 |
| `type="url"`   | 基础网址格式校验 |
| `required`     | 必填             |
| `pattern`      | 自定义正则规则   |
| `novalidate`   | 关闭原生校验     |

```html
<form>
  <input type="email" required />
  <input type="text" pattern="^1[3-9]\d{9}$" />
  <button type="submit">提交</button>
</form>
```

### 3.2 原生校验、JS 校验、服务端校验怎么分工

| 方式            | 更适合                       |
| --------------- | ---------------------------- |
| 原生校验        | 第一层基础规则和输入约束     |
| JavaScript 校验 | 复杂交互、联动规则、即时提示 |
| 服务端校验      | 最终安全校验和可信判断       |

### 3.3 一个重要认知

原生校验很方便，但它主要解决的是基础输入正确性。真实业务里，通常仍然需要 JavaScript 校验和服务端校验配合。

### 3.4 一个实用补充

原生表单能力里还有一组很常用的方法：

```js
form.checkValidity()
form.reportValidity()
```

可以把它们理解成：

1. `checkValidity()` 用来判断当前表单是否通过原生校验。
2. `reportValidity()` 除了判断，还会触发浏览器原生提示。

## 四、表单数据怎么取

### 4.1 文本输入框

```js
const username = document.querySelector("input").value
```

### 4.2 单选框和复选框

```js
const checked = document.querySelector("input[type=checkbox]").checked
```

### 4.3 关键属性对比

| 属性       | 作用           |
| ---------- | -------------- |
| `value`    | 表单值         |
| `checked`  | 是否选中       |
| `selected` | 下拉项是否选中 |
| `disabled` | 是否禁用       |

### 4.4 一个常见坑

单选框、复选框如果没写 `value`，提交时默认值通常是 `on`。

### 4.5 文件上传是个例外

文件域的数据读取和普通文本值不同，通常会配合 `files` 和 `FormData` 处理，而不是只取 `value`。

## 五、表单交互事件

### 5.1 焦点事件

| 事件    | 含义           |
| ------- | -------------- |
| `focus` | 获取焦点时触发 |
| `blur`  | 失去焦点时触发 |

常见用途：

1. 输入时高亮边框。
2. 失焦时触发校验。
3. 展示或隐藏辅助提示。

### 5.2 输入相关事件

`input`：用户输入过程中实时触发，适合联想搜索、实时校验、字数统计。

`change`：值真正发生变化并确认后触发，例如失焦或下拉选完。

| 事件     | 触发时机               |
| -------- | ---------------------- |
| `input`  | 用户输入过程中实时触发 |
| `change` | 值完成变更后触发       |

### 5.3 键盘事件

| 事件       | 含义                                   |
| ---------- | -------------------------------------- |
| `keydown`  | 按键按下时触发                         |
| `keyup`    | 按键抬起时触发                         |
| `keypress` | 历史上用于字符输入，现代场景已较少推荐 |

```js
document.addEventListener("keydown", function (event) {
  console.log(event.key)
})
```

现代开发里通常更推荐 `event.key` 或 `event.code`，因为语义更清晰。

### 5.4 提交事件 `submit`

```js
const form = document.querySelector("form")

form.addEventListener("submit", function (event) {
  event.preventDefault()
  console.log("阻止默认提交，改为前端接管")
})
```

最常见的触发方式：

1. 点击 `type="submit"` 的按钮。
2. 某些输入框回车提交。

### 5.5 真实开发里怎么配合验证时机

| 时机     | 更适合做什么                 |
| -------- | ---------------------------- |
| `focus`  | 展示提示、预热输入引导       |
| `input`  | 实时反馈、字数统计、轻量校验 |
| `blur`   | 单项格式校验                 |
| `submit` | 最终提交前总校验             |

---

## 六、这些事件怎么配合使用

真实表单里，常见流程通常是：

```text
focus 时给提示
input 时做实时反馈
blur 时做单项校验
submit 时做最终校验并提交
```

这也是为什么表单事件不能孤立去记，它们对应的是用户输入过程的不同阶段。

---

## 七、表单的其他常见属性

### 7.1 `autofocus`

页面加载后让某个表单项自动获取焦点。

### 7.2 `autocomplete`

控制浏览器是否记录和联想历史输入。

```html
<input type="text" autocomplete="off" />
```

### 7.3 一个实际建议

`autofocus` 虽然方便，但不要滥用，否则可能影响页面初始体验；`autocomplete` 也不能一刀切关闭，要看业务是否真的涉及隐私或安全输入。

---

## 八、小结

1. 不同 `input` 类型可以提升输入体验和基础校验能力，优先使用更语义化的输入类型。
2. 原生表单验证适合做第一层校验，但不能替代 JavaScript 与服务端校验。
3. 表单值读取要重点掌握 `value`、`checked`、`selected` 这些核心属性，并知道文件上传是例外场景。
4. 焦点事件、输入事件、键盘事件、提交事件分别对应用户输入链路里的不同阶段。
5. 学这篇时，重点是把“用户输入的全过程”串起来理解，而不是分散记事件名和属性名。
6. 更稳的表单方案通常是：语义化输入类型 + 原生第一层校验 + JS 交互校验 + 服务端最终校验。
