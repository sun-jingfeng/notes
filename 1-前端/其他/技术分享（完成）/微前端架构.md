## 一、业务场景

### 1. 需求描述

- 一个项目由多个相对独立的部分组成。
- 每个独立部分都需要单独部署。
- 某些子项目可能是已经运行多年的存量系统，需要平滑接入。

### 2. 示例

- 父项目
- 子项目：强对流预警
- 子项目：雷达单站
- 子项目：雷达三维
- 子项目：评估检验
- 子项目：个例复盘

## 二、基于 iframe 的解决方案

### 1. 父子通信方式

- 本地存储：要求同源，适合存取统一 token key 等简单共享信息。
- 全局数据：要求同源，父项目将公共能力挂到 `window` 上，子项目直接读取。
- 事件通信：可结合 `window.postMessage` 处理消息通知类场景。

### 2. 父项目注入全局数据

```ts
window.globalData = {
  headerHeight,
  tokenKey,
  parentRouter: router,
  loginPath,
  redirectKey,
  ElMessage,
}
```

### 3. 子项目读取全局数据

```ts
export let iframeGlobalData: Window["globalData"]

try {
  iframeGlobalData = window.top?.globalData
} catch (error) {
  console.error(error)
}
```

### 4. 类型声明

```ts
/// <reference types="vue-router" />

interface Window {
  globalData?: {
    headerHeight: number
    tokenKey: string
    parentRouter: import("vue-router").Router
    loginPath: string
    redirectKey: string
    ElMessage: import("element-plus/es/utils").SFCInstallWithContext<
      import("element-plus").Message
    >
  }
}
```

### 5. 子项目页面标题高度

- 单独部署时，使用自己的页面标题高度。
- 嵌入父项目时，使用父项目统一的页面标题高度，保证父项目标题可以完整覆盖子项目标题。

```ts
const headerHeight = `${iframeGlobalData?.headerHeight ?? 60}px`
```

### 6. 子项目登录系统与 token

- 单独部署时，使用自己的登录系统与 token key。
- 父子结构中，复用父项目登录系统，并统一使用父项目的 token key。

```ts
export const tokenKey = iframeGlobalData?.tokenKey ?? "token-tjgz-warning"
```

### 7. 跳转到登录页

- 单独部署时，子项目跳转到自己的登录页。
- 嵌入父项目时，交由父项目路由完成登录跳转，并携带重定向参数。

```ts
router.beforeEach(to => {
  if (getToken()) {
    if (to.path === loginPath) {
      return "/"
    }
    return true
  }

  if (to.path === loginPath) {
    return true
  }

  if (iframeGlobalData) {
    const parentRouter = iframeGlobalData.parentRouter
    const parentRoute = parentRouter.currentRoute.value

    parentRouter.push({
      path: loginPath,
      query:
        parentRoute?.path === "/" ? {} : { [redirectKey]: parentRoute?.path },
    })

    return true
  }

  return {
    path: loginPath,
    query: to.path === "/" ? {} : { [redirectKey]: to.path },
  }
})
```

### 8. 请求拦截器

```ts
instance.interceptors.response.use(
  response => {
    if (
      +response.data.code === 200 ||
      (response.status === 200 && response.data instanceof Blob)
    ) {
      return response.data
    }

    const rawRouter = iframeGlobalData?.parentRouter ?? router
    const currentPath = rawRouter.currentRoute.value.path

    if (+response.data.code === 401 && currentPath !== loginPath) {
      removeToken()
      rawRouter.push({
        path: loginPath,
        query: currentPath === "/" ? {} : { [redirectKey]: currentPath },
      })
    }

    return Promise.reject(response.data)
  },
  error => Promise.reject(error),
)
```

### 9. ElMessage 复用

- 子项目自己的 `ElMessage` 可能会被父项目的页面标题挡住。
- 因此在父子结构中，优先复用父项目提供的 `ElMessage`。

```ts
export const getElMessage = () => iframeGlobalData?.ElMessage ?? ElMessage
```

## 三、同源独立部署与缓存问题

### 1. nginx 配置

#### 1. 父项目

```nginx
location /tjgz/ {
  alias /home/bgdb/nowcastings/tjgz/;
  try_files $uri $uri/ /tjgz/index.html;
}
```

#### 2. 子项目

```nginx
location /tjgz-warning/ {
  alias /home/bgdb/nowcastings/tjgz-warning/;
  try_files $uri $uri/ /tjgz-warning/index.html;
  add_header Cache-Control no-cache;
}
```

### 2. 子项目设置协商缓存验证

#### 1. 发现问题

- 子项目重新部署后，单独访问时页面会自动更新。
- 但通过父项目中的 `iframe` 访问时不会自动更新，必须手动清缓存后才生效。

#### 2. 问题原因

- 响应头返回了 `Etag`、`Last-Modified`，但未明确设置 `Cache-Control`。
- 浏览器直接访问时，通常会携带 `Cache-Control: max-age=0`，从而触发协商缓存验证。
- `iframe` 访问时未必会主动要求校验资源，可能直接命中强缓存。
- 结果就是：直接访问能及时更新，`iframe` 场景却可能读到旧资源。

#### 3. 解决方案

- 在子项目响应头中显式添加 `Cache-Control: no-cache`，强制走协商缓存。
- 调试子项目日志时，记得取消勾选控制台里的 `Selected context only`。

## 四、微前端框架选择

### 1. 微前端概念

- 微前端借鉴了微服务的思路，将一个庞大的前端应用拆分成多个独立、可单独开发、运行、部署的小型应用。
- 这些小型应用最终再被组合成一个完整系统，或者用于整合多个历史上互不关联的系统。

### 2. iframe 的缺陷

- 父子项目非同源部署时通信不便。
- 父子项目 URL 不同步，刷新后子项目状态容易丢失。
- DOM 结构不共享，原生硬隔离难以突破。
- 每次加载子应用都要重建浏览器上下文，性能开销偏大。

### 3. 主流框架对比

| 框架         | 特点                               | 建议           |
| ------------ | ---------------------------------- | -------------- |
| `single-spa` | 上手难度最大，集成成本高           | 不建议优先使用 |
| `qiankun`    | 上手难度较大，且与 Vite 兼容性一般 | 不建议优先使用 |
| `micro-app`  | 上手简单，接入成本低               | 最建议使用     |
| `wujie`      | 上手简单，体验较好                 | 建议使用       |
