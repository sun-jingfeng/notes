# 什么是Ajax、Ajax的优点、Ajax的应用场景、区别Ajax和浏览器请求、请求方式、jQuery中封装的Ajax方法、network工具使用

## 一、一句话理解

Ajax 的核心意义不是“发一个请求”，而是让页面在不整体跳转的前提下，按需向服务端取数据、提交数据，再把结果局部更新到当前界面。

---

## 二、什么是 Ajax

**Ajax（Asynchronous JavaScript And XML）** 是一种在**不刷新整页**的前提下，与服务器进行数据交互的技术。

虽然名字里有 XML，但现代前端开发中更常见的数据格式通常是 **JSON**。

### 1. Ajax 的基本链路

```text
前端发起请求
  -> 服务器处理请求
  -> 返回数据
  -> JavaScript 处理结果
  -> 局部更新页面
```

### 2. Ajax 的本质

Ajax 不是一种单独语言，也不是单独框架，而是下面几类能力的组合：

| 组成                               | 作用                       |
| ---------------------------------- | -------------------------- |
| **JavaScript**                     | 组织请求逻辑、处理响应结果 |
| **XMLHttpRequest / fetch / axios** | 发送网络请求               |
| **DOM 操作**                       | 把返回数据渲染到页面上     |

---

## 三、为什么 Ajax 会成为前端核心能力

只要需求是“页面不要跳走，但数据要变”，Ajax 基本就会出现。

| 价值             | 说明                                   |
| ---------------- | -------------------------------------- |
| **局部更新页面** | 不需要整页刷新，交互更流畅             |
| **反馈更快**     | 用户操作后能更快看到结果               |
| **前后端解耦**   | 页面结构和数据接口可以分离             |
| **适合异步交互** | 搜索建议、分页加载、表单校验都很依赖它 |

一个更贴近业务的理解：Ajax 让页面从“整页切换”变成“局部刷新”，这是现代前端交互体验的重要基础。

---

## 四、Ajax 常见应用场景

| 场景           | 说明                       |
| -------------- | -------------------------- |
| **搜索建议**   | 输入关键词时实时提示候选项 |
| **用户名校验** | 注册时检查用户名是否已存在 |
| **无刷新分页** | 点击分页按钮时只更新列表   |
| **聊天消息**   | 周期拉取或实时更新消息     |
| **数据面板**   | 根据筛选条件异步加载数据   |

一个简单例子：

```js
input.addEventListener("input", async function () {
  const keyword = this.value
  const response = await fetch(`/api/search?keyword=${keyword}`)
  const data = await response.json()
  renderList(data)
})
```

这段代码体现的不是某个 API 写法，而是一种典型模式：

```text
监听用户输入
  -> 发请求拿结果
  -> 用返回结果更新当前页面
```

## 五、Ajax 请求和浏览器默认请求有什么区别

### 1. 浏览器默认请求

浏览器会在这些场景自动发请求：

1. 地址栏输入网址并回车。
2. 点击超链接。
3. 提交表单。

这类请求通常伴随页面跳转或刷新。

### 2. Ajax 请求

Ajax 请求由 JavaScript 主动发起，通常不会让整个页面刷新。

| 对比项           | 浏览器默认请求     | Ajax 请求           |
| ---------------- | ------------------ | ------------------- |
| **发起方式**     | 浏览器默认行为     | JavaScript 主动发起 |
| **页面是否刷新** | 往往会刷新或跳转   | 通常不刷新整页      |
| **适用场景**     | 页面导航、整页跳转 | 局部更新、异步交互  |

### 3. 一个很重要的边界

“是否刷新整页”不是 HTTP 协议决定的，而是浏览器如何处理这次请求决定的。

也就是说：

- 同样都是 HTTP 请求。
- 浏览器默认请求更偏页面导航。
- Ajax 更偏数据交互。

## 六、常见请求方式怎么理解

| 请求方式   | 典型语义 | 常见场景               |
| ---------- | -------- | ---------------------- |
| **GET**    | 获取资源 | 查询列表、获取详情     |
| **POST**   | 提交数据 | 登录、注册、创建数据   |
| **PUT**    | 整体更新 | 更新用户资料、更新资源 |
| **PATCH**  | 局部更新 | 修改部分字段           |
| **DELETE** | 删除资源 | 删除评论、删除商品     |

学习阶段很多项目会把接口都写成 `GET` 或 `POST`，但从语义和可维护性看，最好让“请求方式”和“行为”尽量对应。

## 七、jQuery 中封装的 Ajax 方法

jQuery 在学习阶段很常用，因为它把底层 `XMLHttpRequest` 封装得更简单。

### 1. 常见方法

| 方法           | 作用                   |
| -------------- | ---------------------- |
| **`$.get()`**  | 发送 GET 请求          |
| **`$.post()`** | 发送 POST 请求         |
| **`$.ajax()`** | 通用 Ajax 方法，最灵活 |

### 2. `$.get()`

```js
$.get("/api/user", { id: 1 }, function (res) {
  console.log(res)
})
```

### 3. `$.post()`

```js
$.post(
  "/api/login",
  {
    username: "tom",
    password: "123456",
  },
  function (res) {
    console.log(res)
  },
)
```

### 4. `$.ajax()`

```js
$.ajax({
  url: "/api/books/4",
  type: "DELETE",
  success(res) {
    console.log(res)
  },
  error(err) {
    console.log(err)
  },
})
```

### 5. 常见配置项

| 配置项         | 说明               |
| -------------- | ------------------ |
| **`url`**      | 请求地址           |
| **`type`**     | 请求方式           |
| **`data`**     | 请求参数           |
| **`success`**  | 成功回调           |
| **`error`**    | 失败回调           |
| **`dataType`** | 期望返回的数据类型 |

实际理解：

- `$.get()`、`$.post()` 适合快速发简单请求。
- `$.ajax()` 适合要控制更多细节的场景。

现代项目里更常见的是 `fetch` 或 `axios`，但理解 jQuery Ajax 很有助于掌握 Ajax 基础思想。

---

## 八、一个完整的 Ajax 示例

```html
<ul class="book-list"></ul>

<script>
  $.get("/api/books", function (res) {
    const html = res.data
      .map(book => `<li>${book.bookname} - ${book.author}</li>`)
      .join("")

    $(".book-list").html(html)
  })
</script>
```

这段代码体现了 Ajax 最经典的链路：

1. 发请求拿数据。
2. 处理返回结果。
3. 局部更新页面内容。

## 九、Network 面板怎么用来排查 Ajax

浏览器开发者工具中的 **Network** 面板，是排查 Ajax 问题最核心的工具之一。

### 1. 常见筛选项

| 选项          | 说明            |
| ------------- | --------------- |
| **All**       | 查看所有请求    |
| **Fetch/XHR** | 查看 Ajax 请求  |
| **Doc**       | HTML 文档请求   |
| **JS**        | JavaScript 文件 |
| **CSS**       | 样式文件        |
| **Img**       | 图片资源        |

### 2. 排查时重点看什么

| 检查项                     | 说明                       |
| -------------------------- | -------------------------- |
| **Request URL**            | 请求地址对不对             |
| **Request Method**         | 请求方式对不对             |
| **Status Code**            | 状态码是否正常             |
| **Headers**                | 请求头和响应头是否符合预期 |
| **Query String / Payload** | 参数有没有传对             |
| **Response / Preview**     | 返回数据格式是否正确       |

### 3. 一个实战排查顺序

1. 请求有没有发出去。
2. 地址和方法对不对。
3. 参数有没有传错。
4. 后端返回的是成功还是错误。
5. 前端是不是拿到数据后没正确处理。

这个顺序很重要，因为很多人一上来就怀疑代码逻辑，实际上问题可能只是 URL 写错或者参数没带上。

## 十、jQuery Ajax、fetch、axios 怎么看

| 方案            | 特点                     |
| --------------- | ------------------------ |
| **jQuery Ajax** | 学习成本低，老项目常见   |
| **fetch**       | 浏览器原生现代接口       |
| **axios**       | 封装更完善，业务项目常见 |

可以这样理解这个演进：

- jQuery Ajax 更像历史主力方案。
- `fetch` 是浏览器原生现代能力。
- `axios` 是现代业务里很常见的工程化封装方案。

## 十一、小结

| 知识点             | 结论                                          |
| ------------------ | --------------------------------------------- |
| **Ajax 的本质**    | 用 JavaScript 主动发请求并局部更新页面        |
| **核心价值**       | 不整页刷新也能完成数据交互                    |
| **和默认请求区别** | 默认请求偏导航，Ajax 偏数据交互               |
| **学习主线**       | 发请求、看结果、更新页面、用 Network 排查     |
| **方案演进**       | 可先学 jQuery Ajax，再理解 `fetch` 和 `axios` |
