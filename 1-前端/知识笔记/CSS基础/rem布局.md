# rem 布局

## 一、一句话理解

`rem` 布局的本质，是把页面尺寸统一挂到根字号上，让整套视觉尺寸能随屏幕宽度按比例缩放。

---

## 二、为什么要学 rem 布局

在移动端开发里，屏幕宽度差异很大，如果只使用固定 `px`，文字和盒子尺寸往往难以自适应。

`rem` 布局的核心目标，是让尺寸能随着屏幕宽度变化而整体缩放。

常见移动端适配方案包括：

| 方案                  | 说明                   |
| --------------------- | ---------------------- |
| **媒体查询 + rem**    | 早期常见方案           |
| **flexible.js + rem** | 曾经非常流行           |
| **vw / vh**           | 现代更常见，心智更直接 |

---

## 三、什么是 rem

`rem` 是相对长度单位，表示相对于根元素 `html` 的 `font-size`。

```css
html {
  font-size: 16px;
}

.box {
  width: 10rem;
}
```

此时 `10rem = 160px`。

### 1. `em` 和 `rem` 的区别

| 单位      | 相对谁                           |
| --------- | -------------------------------- |
| **`em`**  | 相对于当前元素自身或父级文字环境 |
| **`rem`** | 相对于根元素 `html` 的字号       |

因此，`rem` 更适合做整站统一缩放。

---

## 四、媒体查询基础

媒体查询用于根据设备特征应用不同样式。

```css
@media (min-width: 375px) {
  body {
    background-color: #f5f5f5;
  }
}
```

### 1. 常见条件

| 条件                            | 说明         |
| ------------------------------- | ------------ |
| **`width`**                     | 视口宽度     |
| **`min-width`**                 | 最小宽度     |
| **`max-width`**                 | 最大宽度     |
| **`height`**                    | 视口高度     |
| **`min-height` / `max-height`** | 高度范围判断 |

实际移动端开发里，最常见的是 `min-width` 和 `max-width`。

---

## 五、媒体查询与 rem 的结合思路

如果只使用媒体查询去逐项改所有元素尺寸，会造成 CSS 大量重复。

更合理的做法是：

1. 媒体查询只负责修改 `html` 的 `font-size`
2. 其他元素统一使用 `rem`

### 1. 错误思路：每个元素都写媒体查询

```css
@media (width: 400px) {
  header {
    height: 20px;
  }
}

@media (width: 500px) {
  header {
    height: 25px;
  }
}
```

这种方式代码冗余很大。

### 2. 更合理的思路：只改根字号

```css
@media (width: 400px) {
  html {
    font-size: 40px;
  }
}

@media (width: 500px) {
  html {
    font-size: 50px;
  }
}
```

然后业务元素统一写成 `rem`：

```css
.header {
  height: 1rem;
}
```

---

## 六、常见 rem 适配写法

### 1. 区间写法

```css
@media (min-width: 0) and (max-width: 320px) {
  html {
    font-size: 32px;
  }
}

@media (min-width: 375px) and (max-width: 414px) {
  html {
    font-size: 37.5px;
  }
}
```

### 2. 递增写法

```css
@media (min-width: 320px) {
  html {
    font-size: 32px;
  }
}

@media (min-width: 375px) {
  html {
    font-size: 37.5px;
  }
}

@media (min-width: 414px) {
  html {
    font-size: 41.4px;
  }
}
```

> **注意**：如果只使用 `min-width` 或只使用 `max-width`，媒体查询书写顺序非常重要。

## 七、flexible.js 思路

`flexible.js` 曾经是移动端 `rem` 适配的常用方案之一。

### 1. 核心思路

把视口宽度按比例换算成根字号，例如：

视口宽度 ÷ 10 = `html` 的 `font-size`

如果视口宽度是 `375px`，那么根字号就是 `37.5px`。

这样：

```text
1rem = 37.5px
```

### 2. 价值

开发时只要关心把设计稿尺寸换算成 `rem` 即可。

但它也带来一个成本：开发者需要始终记得“真实尺寸不是直接写出来的，而是通过根字号间接换算出来的”。

---

## 八、px 转 rem 的换算

假设设计稿宽度是 `750px`，而实际开发常以 `375px` 逻辑宽度为基准：

1. 先把设计稿尺寸除以 2，得到逻辑像素
2. 再除以根字号，得到 rem 值

例如：

设计稿宽度 `346px`：

```text
346 ÷ 2 = 173
173 ÷ 37.5 ≈ 4.61rem
```

因此可以写：

```css
width: 4.61rem;
```

---

## 九、px 转 rem 工具

在过去的工作流里，常会使用编辑器插件自动把 `px` 转成 `rem`。

### 1. 作用

| 作用             | 说明         |
| ---------------- | ------------ |
| **减少手算成本** | 自动换算     |
| **统一换算基准** | 降低人工误差 |

不过在现代项目中，如果团队已经改用 `vw`、设计 token 或构建工具自动转换，就不一定还需要单独依赖这类插件。

所以这些工具的价值更像是过渡期提效，而不是长期一定要保留的核心依赖。

## 十、vw / vh 与 rem 的关系

### 1. 基本概念

| 单位     | 含义          |
| -------- | ------------- |
| **`vw`** | 视口宽度的 1% |
| **`vh`** | 视口高度的 1% |

```text
1vw = 视口宽度的 1%
1vh = 视口高度的 1%
```

### 2. 为什么现在更常用 vw

因为移动端很多自适应，本质上都是围绕视口宽度进行缩放，而 `vw` 天然就是相对视口宽度，不需要再绕到 `html font-size`。

### 3. 什么时候 rem 仍然有价值

| 场景                   | 说明                      |
| ---------------------- | ------------------------- |
| **老项目维护**         | 很多历史项目仍是 rem 方案 |
| **根字号统一缩放设计** | 整体缩放逻辑明确          |
| **配合设计系统**       | 某些设计体系仍基于 rem    |

---

## 十一、真实项目里怎么选

| 场景                          | 更适合的方案           |
| ----------------------------- | ---------------------- |
| **维护历史移动站**            | rem 往往改动成本更低   |
| **新项目只做宽度自适应**      | `vw` 通常更直接        |
| **已有成熟 px 转 rem 工具链** | rem 依然可行           |
| **团队对根字号换算不熟**      | 优先选心智更直观的方案 |

一个实战判断是：如果团队每次写样式都要频繁手算和来回换算，说明这套方案的心智成本已经偏高。

---

## 十二、小结

| 知识点               | 结论                       |
| -------------------- | -------------------------- |
| **rem 相对谁**       | 相对 `html` 的 `font-size` |
| **rem 核心价值**     | 让整体尺寸按根字号缩放     |
| **媒体查询角色**     | 常用于动态设置根字号       |
| **flexible.js 思路** | 视口宽度按比例换成根字号   |
| **现代替代方案**     | `vw` 往往更直接            |
