# HTML 列表

## 一、一句话理解

HTML 列表的重点不是把内容“排成一行一列”，而是用合适的语义表达“并列关系、顺序关系、解释关系”。

---

## 二、为什么列表很重要

很多初学者会把列表理解成“带圆点的内容”，但在实际开发里，列表更重要的价值是语义：

- 导航菜单本质上是一组并列入口。
- 操作步骤本质上是一组有顺序的阶段。
- 术语解释本质上是标题和说明的对应关系。

所以列表标签选得对，页面结构会更清晰，也更利于维护和理解。

HTML 中常见三类列表：

| 类型         | 标签               | 适用场景                   |
| ------------ | ------------------ | -------------------------- |
| **无序列表** | `ul` + `li`        | 菜单、导航、功能点、标签组 |
| **有序列表** | `ol` + `li`        | 操作步骤、排行榜、流程说明 |
| **描述列表** | `dl` + `dt` + `dd` | 术语解释、问答、字段说明   |

---

## 三、无序列表 `ul`

无序列表表示各项之间是并列关系，不强调先后顺序。

```html
<ul>
  <li>首页</li>
  <li>产品</li>
  <li>关于我们</li>
</ul>
```

| 特点                     | 说明                       |
| ------------------------ | -------------------------- |
| **默认带项目符号**       | 浏览器通常显示圆点         |
| **语义上表示并列项**     | 不强调谁先谁后             |
| **`ul` 内应直接放 `li`** | 不要直接塞纯文本或杂乱结构 |

常见场景：

- 顶部导航
- 侧边菜单
- 商品卖点
- 标签列表

### 1. 为什么导航常用 `ul`

导航并不是“只是看起来一排按钮”，它本质上是一组并列的入口，所以用 `ul` 表达更符合语义。

---

## 四、有序列表 `ol`

有序列表表示内容存在明确顺序。

```html
<ol>
  <li>注册账号</li>
  <li>填写资料</li>
  <li>提交审核</li>
</ol>
```

| 特点                     | 说明                   |
| ------------------------ | ---------------------- |
| **默认带序号**           | 浏览器自动编号         |
| **强调前后顺序**         | 顺序被打乱会影响理解   |
| **结构要求与 `ul` 类似** | `ol` 内也应直接放 `li` |

常见场景：

- 教程步骤
- 安装流程
- 排名榜单
- 操作说明

### 1. 什么时候该选 `ol`

只要“前后顺序会影响含义”，就优先考虑 `ol`。比如注册流程、烹饪步骤、安装步骤，用 `ul` 就不够准确。

---

## 五、描述列表 `dl`

描述列表用于“标题 + 解释”的结构，不强调顺序，而强调对应关系。

```html
<dl>
  <dt>HTML</dt>
  <dd>用于描述网页结构的标记语言。</dd>
  <dd>是前端开发的基础之一。</dd>
</dl>
```

| 标签     | 作用               |
| -------- | ------------------ |
| **`dl`** | 描述列表容器       |
| **`dt`** | 名词、标题项       |
| **`dd`** | 对 `dt` 的解释说明 |

规则：

| 规则                            | 说明         |
| ------------------------------- | ------------ |
| **`dl` 内主要放 `dt` 和 `dd`**  | 保持结构清晰 |
| **一个 `dt` 可以对应多个 `dd`** | 很常见       |

常见场景：

- FAQ 问答
- 术语解释
- 商品参数说明
- 表单字段说明

### 1. 为什么不用 `ul` 代替 `dl`

因为 `ul` 表示的是“并列项”，而 `dl` 表示的是“说明关系”。语义不同，后续阅读和维护的理解成本也不同。

---

## 六、三种列表怎么选

| 需求                     | 推荐标签 | 原因         |
| ------------------------ | -------- | ------------ |
| **一组并列入口或功能点** | `ul`     | 强调并列关系 |
| **一组有先后顺序的步骤** | `ol`     | 强调顺序关系 |
| **标题和解释一一对应**   | `dl`     | 强调说明关系 |

选择列表标签时，不要只看视觉样式，要先看内容语义。

---

## 七、实际开发中的常见写法

### 1. 菜单导航

```html
<ul class="nav">
  <li><a href="#">首页</a></li>
  <li><a href="#">产品</a></li>
  <li><a href="#">联系</a></li>
</ul>
```

### 2. 操作步骤

```html
<ol>
  <li>选择商品</li>
  <li>填写地址</li>
  <li>确认支付</li>
</ol>
```

### 3. 术语说明

```html
<dl>
  <dt>HTTP</dt>
  <dd>超文本传输协议。</dd>
  <dt>HTTPS</dt>
  <dd>在 HTTP 基础上加入加密能力。</dd>
</dl>
```

---

## 八、开发中的注意事项

| 问题                              | 说明                             |
| --------------------------------- | -------------------------------- |
| **不要为了样式滥用列表**          | 列表首先表达语义，不只是为了排版 |
| **`ul` 和 `ol` 内不要直接写文本** | 应该放在 `li` 中                 |
| **不要把所有重复内容都写成列表**  | 先判断是不是并列、顺序、说明关系 |
| **默认样式通常会被重置**          | 圆点、缩进、外边距常会被统一清掉 |

常见重置写法：

```css
ul,
ol {
  margin: 0;
  padding: 0;
  list-style: none;
}
```

这里要注意：样式上去掉圆点，并不代表语义也消失了。它仍然是列表。

---

## 九、小结

| 知识点            | 结论                                   |
| ----------------- | -------------------------------------- |
| **无序列表 `ul`** | 表示并列关系，常用于导航、菜单、功能点 |
| **有序列表 `ol`** | 表示顺序关系，常用于步骤、排行、流程   |
| **描述列表 `dl`** | 表示说明关系，常用于术语和问答         |
| **选择原则**      | 优先看内容语义，再考虑样式实现         |
