# JavaScript表达式与流程控制

## 一、一句话理解

这一组知识点看起来分散，但它们其实都在解决同一个问题：代码到底怎么计算、按什么顺序执行、出问题时怎么定位、重复逻辑该怎么写。

---

## 二、先补上赋值运算符

赋值运算符用于给变量赋值，或者基于当前值继续修改。

```js
let num = 10
num = 20
num += 5
num -= 2
num *= 3
num /= 2
num %= 3
```

| 运算符 | 含义         |
| ------ | ------------ |
| `=`    | 直接赋值     |
| `+=`   | 加后再赋值   |
| `-=`   | 减后再赋值   |
| `*=`   | 乘后再赋值   |
| `/=`   | 除后再赋值   |
| `%=`   | 取余后再赋值 |

这类运算符常和循环、计数、累计求和一起出现。

## 三、一元运算符

### 1. 什么是一元运算符

一元运算符只需要一个操作数。

常见的一元运算符：

- `++`
- `--`
- `!`
- `typeof`

### 2. 自增和自减

```js
let num = 1
num++
++num
num--
--num
```

真正容易出错的地方，不是“记不住有这个符号”，而是前置和后置在表达式中的执行时机。

### 3. 前置和后置的区别

前置自增：先加，再参与表达式。

```js
let a = 1
let b = ++a

console.log(a) // 2
console.log(b) // 2
```

后置自增：先参与表达式，再加。

```js
let a = 1
let b = a++

console.log(a) // 2
console.log(b) // 1
```

### 4. 使用建议

| 场景                 | 建议                         |
| -------------------- | ---------------------------- |
| **单独一行递增变量** | 前置和后置差异通常不大       |
| **参与复杂表达式**   | 尽量避免，容易读错           |
| **业务代码**         | 优先写得清楚，不追求花哨写法 |

例如下面这种写法虽然能跑，但可读性很差：

```js
let total = price * count++
```

更清晰的写法通常是拆开：

```js
let total = price * count
count += 1
```

## 四、运算符优先级

运算符优先级决定表达式先算哪一部分。

### 1. 常见规律

1. 小括号优先级最高。
2. 一元运算通常高于二元运算。
3. 算术运算通常高于比较运算。
4. 比较运算通常高于逻辑与、逻辑或。

### 2. 典型例子

```js
console.log(1 + 2 * 3) // 7
console.log((1 + 2) * 3) // 9
console.log(!true || false) // false
console.log(3 > 2 && 2 > 1) // true
```

### 3. 实际开发建议

不要把表达式写成“必须背优先级表才能读懂”的样子。

| 情况                       | 建议                   |
| -------------------------- | ---------------------- |
| **表达式一眼能看懂**       | 可以不额外加括号       |
| **表达式稍复杂**           | 主动加括号，提高可读性 |
| **逻辑运算与比较运算混用** | 优先加括号，避免歧义   |

优先级本来是帮助计算机的，不是用来考验读代码的人。

## 五、断点调试

### 1. 为什么断点比一直打日志更高效

`console.log()` 能看到结果，但不容易看清过程；断点调试可以直接看到每一步执行到了哪、变量值怎么变化、条件为什么成立或不成立。

尤其适合：

- 分支判断出错
- 循环次数异常
- 某个变量在中途被改了
- 函数调用链太长

### 2. 基本使用流程

在浏览器 DevTools 中：

1. 打开开发者工具。
2. 进入 `Sources` 面板。
3. 找到对应脚本文件。
4. 点击行号设置断点。
5. 刷新页面或重新触发代码。

### 3. 常见调试操作

| 操作     | 作用                       |
| -------- | -------------------------- |
| 单步跳过 | 执行当前行，不进入函数内部 |
| 单步进入 | 进入函数内部继续看         |
| 单步跳出 | 跳出当前函数               |
| 继续执行 | 直接运行到下一个断点       |

### 4. `debugger`

也可以在代码中直接写断点：

```js
let num = 10
debugger
console.log(num)
```

执行到 `debugger` 时，程序会暂停。

### 5. 调试循环时重点看什么

调试循环不要只盯着打印结果，重点看三件事：

1. 初始值是不是对的。
2. 条件是不是会在某一刻变成 `false`。
3. 变化量是不是每次都真的在更新。

## 六、循环

循环用于重复执行一段逻辑。

循环最核心的三个要素：

1. 初始值
2. 继续条件
3. 变化量

只要这三件事有一件写错，就容易出现死循环、少循环、或多循环。

### 1. `while` 循环

```js
let i = 1

while (i <= 5) {
  console.log(i)
  i++
}
```

特点：先判断，再执行。

适用场景：

- 条件驱动的重复执行
- 不方便把初始化、条件、变化量写在一行时

### 2. `do...while` 循环

```js
let i = 1

do {
  console.log(i)
  i++
} while (i <= 5)
```

特点：先执行一次，再判断条件，所以至少执行一次。

### 3. `for` 循环

```js
for (let i = 1; i <= 5; i++) {
  console.log(i)
}
```

特点：初始化、条件、变化量写在一起，最适合计数型循环。

### 4. 三种循环对比

| 循环         | 特点         | 常见场景         |
| ------------ | ------------ | ---------------- |
| `while`      | 先判断再执行 | 条件型循环       |
| `do...while` | 至少执行一次 | 先做一次再判断   |
| `for`        | 结构紧凑     | 计数型循环最常见 |

## 七、循环中的控制语句

### 1. `break`

`break` 用来立即结束当前循环。

```js
for (let i = 1; i <= 10; i++) {
  if (i === 5) {
    break
  }
  console.log(i)
}
```

### 2. `continue`

`continue` 用来跳过本次循环，直接进入下一次。

```js
for (let i = 1; i <= 5; i++) {
  if (i === 3) {
    continue
  }
  console.log(i)
}
```

区别：

- `break` 是“整个循环到这里就结束”。
- `continue` 是“这一次先跳过，后面继续”。

## 八、常见问题与排查思路

| 问题                     | 常见原因                   | 怎么查                   |
| ------------------------ | -------------------------- | ------------------------ |
| **循环停不下来**         | 条件始终成立，变化量没更新 | 看条件和变量变化         |
| **结果多 1 次或少 1 次** | 边界条件写错               | 检查 `<`、`<=`、初始值   |
| **计算结果异常**         | 前置后置混用、优先级误判   | 加括号、拆表达式、打断点 |
| **逻辑分支不符合预期**   | 运算顺序和预想不同         | 用断点逐步看每一步结果   |

## 九、小结

| 知识点           | 结论                                   |
| ---------------- | -------------------------------------- |
| **一元运算符**   | 最常见的是自增、自减、逻辑非、`typeof` |
| **前置和后置**   | 一个先变后用，一个先用后变             |
| **运算符优先级** | 不确定时主动加括号                     |
| **断点调试**     | 最适合理解执行过程和排查循环、分支问题 |
| **循环**         | 先盯住初始值、条件、变化量这三个核心点 |
