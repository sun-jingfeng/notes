# 比较、逻辑、分支

## 一、一句话理解

这篇真正要掌握的不是几个运算符长什么样，而是程序如何根据条件判断走向不同分支。

---

## 二、比较运算符

比较运算符用于判断两个值之间的关系，结果一定是布尔值，即 `true` 或 `false`。

| 运算符 | 含义                         |
| ------ | ---------------------------- |
| `>`    | 左边是否大于右边             |
| `<`    | 左边是否小于右边             |
| `>=`   | 左边是否大于或等于右边       |
| `<=`   | 左边是否小于或等于右边       |
| `==`   | 值是否相等，会发生隐式转换   |
| `===`  | 类型和值都相等               |
| `!=`   | 值是否不相等，会发生隐式转换 |
| `!==`  | 类型或值不相等               |

### 1. `==` 和 `===` 的区别

```js
console.log(1 == "1") // true
console.log(1 === "1") // false
```

原因是 `==` 会尝试做隐式类型转换，而 `===` 不会。

真实开发中，通常优先使用 `===` 和 `!==`，这样判断更准确。

### 2. 字符串比较

字符串比较本质上是按字符编码逐位比较。

```js
console.log("a" > "b") // false
console.log("abc" > "abb") // true
```

规则可以简单理解为：从左到右逐位比较，遇到不同字符时停止。

### 3. 特殊值 `NaN`

`NaN` 表示“不是一个有效数字”。

```js
console.log(NaN == NaN) // false
console.log(NaN === NaN) // false
console.log(isNaN(NaN)) // true
```

注意：`NaN` 不等于任何值，包括它自己。

### 4. 小数比较的注意点

```js
console.log(0.1 + 0.2 === 0.3) // false
```

这是因为浮点数存在精度问题，所以不要轻易直接比较小数是否完全相等。

## 三、逻辑运算符

逻辑运算符通常用来组合多个条件。

| 运算符 | 含义                 |
| ------ | -------------------- | --- | ------------------------ |
| `&&`   | 与，左右都为真才为真 |
| `      |                      | `   | 或，只要有一个为真就为真 |
| `!`    | 非，取反             |

### 1. 基本用法

```js
console.log(true && true) // true
console.log(true && false) // false
console.log(true || false) // true
console.log(!true) // false
```

### 2. 逻辑与 `&&`

只有左右两边都为真，结果才为真。

```js
const age = 20
const hasId = true

console.log(age >= 18 && hasId) // true
```

### 3. 逻辑或 `||`

只要左右两边有一个为真，结果就为真。

```js
const isAdmin = false
const isOwner = true

console.log(isAdmin || isOwner) // true
```

### 4. 逻辑非 `!`

逻辑非会把真值变假，把假值变真。

```js
console.log(!true) // false
console.log(!false) // true
console.log(!!"hi") // true
```

`!!值` 经常被用来快速把一个值转换成布尔值。

逻辑运算符在真实开发里经常不只是做数学意义上的真假判断，还会参与默认值兜底和条件执行。

---

## 四、短路运算

短路只会出现在 `&&` 和 `||` 中。

### 1. `&&` 的短路

如果左边已经是 `false`，整体结果一定是 `false`，右边就没必要再执行了。

```js
console.log(false && fn())
```

### 2. `||` 的短路

如果左边已经是 `true`，整体结果一定是 `true`，右边也没必要再执行了。

```js
console.log(true || fn())
```

### 3. 返回值不是布尔值的情况

`&&` 和 `||` 返回的是“最后一个被执行的表达式值”，不一定非得是布尔值。

```js
console.log(1 && 2) // 2
console.log(0 && 2) // 0
console.log("hello" || 0) // hello
console.log("" || "默认值") // 默认值
```

### 4. 常见应用

```js
function greet(name) {
  const finalName = name || "游客"
  console.log("你好，" + finalName)
}
```

不过在现代代码中，如果你只想处理 `null` 和 `undefined`，通常会更推荐空值合并运算符 `??`。

## 五、条件分支

条件分支的作用是根据不同条件执行不同代码。

### 1. 单分支 `if`

```js
if (score >= 60) {
  console.log("及格")
}
```

条件成立时执行大括号中的代码，不成立则跳过。

### 2. 双分支 `if...else`

```js
if (score >= 60) {
  console.log("及格")
} else {
  console.log("不及格")
}
```

### 3. 多分支 `if...else if...else`

```js
if (score >= 90) {
  console.log("优秀")
} else if (score >= 80) {
  console.log("良好")
} else if (score >= 60) {
  console.log("及格")
} else {
  console.log("不及格")
}
```

### 4. 布尔转换规则

`if` 判断里不一定非得写布尔值，JavaScript 会把表达式结果隐式转换成布尔值。

常见假值包括：

1. `false`
2. `0`
3. `""`
4. `null`
5. `undefined`
6. `NaN`

除了这些，绝大多数值都可以看作真值。

## 六、`switch` 语句

`switch` 适合处理“同一个变量对应多个固定值”的场景。

```js
const day = 3

switch (day) {
  case 1:
    console.log("星期一")
    break
  case 2:
    console.log("星期二")
    break
  case 3:
    console.log("星期三")
    break
  default:
    console.log("未知日期")
}
```

### 1. `switch` 的特点

1. `case` 判断本质上是全等比较。
2. `break` 用于结束当前 `switch`。
3. 如果没有 `break`，可能发生穿透。

### 2. 穿透示例

```js
const num = 1

switch (num) {
  case 1:
    console.log("one")
  case 2:
    console.log("two")
}
```

上面会输出：

```js
one
two
```

因为 `case 1` 命中后没有 `break`，会继续往下执行。

## 七、三元表达式

三元表达式是双分支 `if...else` 的简写形式。

语法：

```js
条件 ? 表达式1 : 表达式2
```

示例：

```js
const age = 20
const result = age >= 18 ? "成年" : "未成年"
console.log(result)
```

### 1. 适用场景

1. 根据条件快速取值。
2. 简单双分支逻辑。

### 2. 不适用场景

如果逻辑很复杂，仍然建议使用普通 `if...else`，否则可读性会下降。

三元表达式更适合“取值”，不适合承载大段流程控制。

---

## 八、条件判断的选择建议

| 场景                 | 推荐写法                 |
| -------------------- | ------------------------ |
| 单一条件成立才执行   | `if`                     |
| 两种结果二选一       | `if...else` 或三元表达式 |
| 多条件连续判断       | `if...else if...else`    |
| 单变量匹配多个固定值 | `switch`                 |

一个常见经验是：写条件判断时，先追求可读，再追求短。

---

## 九、总结

1. 比较运算符的结果一定是布尔值。
2. 开发中通常优先使用 `===` 和 `!==`，避免隐式类型转换带来的歧义。
3. 逻辑运算符除了做条件组合，还经常利用短路机制做默认值处理。
4. `if`、`switch`、三元表达式都属于条件分支，只是适用场景不同。
5. 写条件判断时，可读性通常比“写得短”更重要。
