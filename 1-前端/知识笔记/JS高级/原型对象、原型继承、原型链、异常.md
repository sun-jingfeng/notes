# 原型对象、原型继承、原型链、异常

## 一、这篇的主线

这一篇前半部分在讲 JavaScript 对象系统的底层机制，后半部分在讲错误处理。

可以拆成两组来学：

| 主题组                         | 核心问题                                 |
| ------------------------------ | ---------------------------------------- |
| **原型对象、原型继承、原型链** | 对象的方法为什么能共享，继承为什么能成立 |
| **异常**                       | 程序出错时如何中断、捕获和显式抛错       |

---

## 二、原型对象

每个构造函数都有一个 `prototype` 属性，这个属性指向的对象就叫 **原型对象**。

```js
function Person() {}

console.log(Person.prototype)
```

原型对象最重要的价值是：**让多个实例共享同一份方法**。

```js
function Person(name) {
  this.name = name
}

Person.prototype.sayHi = function () {
  console.log("Hi, 我是" + this.name)
}
```

如果把 `sayHi` 写到构造函数内部，那么每 `new` 一次都会创建一个新函数；挂到原型对象上则所有实例共享一份。

### 2.1 一个经验结论

1. 每个实例自己的数据，通常写在构造函数里。
2. 需要多个实例共享的方法，通常写在原型对象上。

---

## 三、构造函数、实例、原型的关系

先记住这 3 个关系：

| 关系                   | 说明                   |
| ---------------------- | ---------------------- |
| `构造函数.prototype`   | 指向原型对象           |
| `原型对象.constructor` | 指回构造函数           |
| `实例.__proto__`       | 指向构造函数的原型对象 |

```js
function Person() {}

const p = new Person()

console.log(Person.prototype.constructor === Person) // true
console.log(p.__proto__ === Person.prototype) // true
```

`__proto__` 主要用于理解原理，实际开发中不建议在业务代码里频繁直接操作它。

## 四、属性和方法的查找规则

当访问一个对象成员时，JavaScript 会这样查找：

1. 先找实例自身。
2. 实例没有，再找原型对象。
3. 原型对象没有，再继续向上找。
4. 最终找到 `Object.prototype` 还没有，就返回 `undefined`。

```js
function Person(name) {
  this.name = name
}

Person.prototype.sayHi = function () {
  console.log("Hi, 我是" + this.name)
}
```

### 4.1 同名成员的优先级

如果实例和原型对象上有同名成员，优先使用实例自己的成员。

```js
function Person() {
  this.sayHi = function () {
    console.log("实例方法")
  }
}

Person.prototype.sayHi = function () {
  console.log("原型方法")
}
```

### 4.2 一个实战意义

理解查找规则后，就更容易解释：

1. 为什么对象能直接调用原型上的方法。
2. 为什么实例属性可以覆盖原型属性。
3. 为什么原型污染会影响整个类型的实例。

## 五、原型继承

继承的本质是 **复用代码**。

例如 `Chinese`、`Japanese`、`American` 都是“人”的一种，它们可以共享人的共性方法，例如 `walk()`、`sleep()`。

### 5.1 原型继承示例

```js
function Person() {}

Person.prototype.walk = function () {
  console.log("会走路")
}

function Chinese(name) {
  this.name = name
}

Chinese.prototype = Object.create(Person.prototype)
Chinese.prototype.constructor = Chinese
```

这里的核心含义是：`Chinese` 实例能够沿着原型链访问 `Person.prototype` 上的方法。

### 5.2 为什么推荐 `Object.create`

旧写法常见：

```js
Chinese.prototype = new Person()
```

现代更推荐：

```js
Chinese.prototype = Object.create(Person.prototype)
```

原因：

1. 更纯粹，只建立原型链关系。
2. 不会多执行一次父构造函数。

### 5.3 组合继承的常见形式

如果既想继承父类实例属性，又想继承父类原型方法，常见写法是：

```js
function Person(name) {
  this.name = name
  this.arms = 2
}

Person.prototype.walk = function () {
  console.log(this.name + " 会走路")
}

function Chinese(name, language) {
  Person.call(this, name)
  this.language = language
}

Chinese.prototype = Object.create(Person.prototype)
Chinese.prototype.constructor = Chinese
```

这里：

1. `Person.call(this, name)` 负责继承实例属性。
2. `Object.create(Person.prototype)` 负责继承原型方法。

## 六、原型链

原型链可以理解为：对象通过原型不断向上连接后形成的一条查找链路。

```text
p
  -> Person.prototype
    -> Object.prototype
      -> null
```

### 6.1 原型链的作用

1. 支撑属性和方法的逐层查找。
2. 支撑 JavaScript 的继承机制。
3. 解释为什么对象能调用 `toString()`、`hasOwnProperty()` 等方法。

### 6.2 常见判断方式

```js
function Person() {}
const p = new Person()

console.log(p instanceof Person) // true
console.log(p instanceof Object) // true
console.log(Person.prototype.isPrototypeOf(p)) // true
```

### 6.3 原型链和 class 的关系

即使写成 `class`，方法共享和继承查找的底层机制本质上仍然离不开原型链。

## 七、异常

异常就是程序运行时出现的错误或非预期情况。

例如：

```js
console.log(a) // ReferenceError
```

### 7.1 `try...catch`

当一段代码可能报错时，可以用 `try...catch` 捕获错误，避免程序直接中断。

```js
try {
  console.log(a)
} catch (error) {
  console.log("代码执行出错：", error.message)
}
```

### 7.2 `finally`

`finally` 中的代码无论是否报错，通常都会执行。

```js
try {
  console.log("开始执行")
} catch (error) {
  console.log(error)
} finally {
  console.log("收尾逻辑")
}
```

### 7.3 `throw`

除了系统自动抛错，也可以手动抛出异常。

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error("除数不能为 0")
  }

  return a / b
}
```

### 7.4 什么时候该主动抛错

1. 参数明显非法。
2. 业务前提被破坏。
3. 当前函数无法继续安全执行。

### 7.5 一个实战提醒

异常处理的目标不是“把所有错误吞掉”，而是：

1. 在合适层级捕获。
2. 补充上下文。
3. 让错误可定位、可恢复或可上报。

---

## 八、小结

1. 原型对象负责方法共享，原型链负责属性和方法的逐层查找。
2. 原型继承的核心价值是复用代码，`Object.create()` 是更干净的建立方式。
3. `class` 是更现代的语法表达，但底层依然建立在原型机制之上。
4. 异常处理依赖 `try...catch...finally` 和 `throw`，重点是把错误和正常流程分开管理。
5. 学这一篇时，前半部分要理解对象机制，后半部分要理解错误处理边界，不要混成一个知识点硬记。
