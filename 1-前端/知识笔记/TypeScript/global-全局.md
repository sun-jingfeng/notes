# global 全局

## 一、一句话理解

`declare global` 解决的是: 当前文件已经是模块了，但你又确实需要给整个项目的全局作用域补类型。

---

## 二、什么是 `declare global`

在 TypeScript 中，如果你处于一个**模块文件**里，但又想往全局作用域补充类型，就可以使用：

```ts
declare global {
  // 在这里声明全局类型
}
```

它解决的问题是：**模块默认有自己的作用域，普通声明不会自动影响整个项目，但有时我们又确实想补一个全局类型。**

---

## 三、为什么普通声明不行

### 2.1 模块中的声明默认是局部的

```ts
type T = string

export {}
```

这时 `T` 只在当前模块内可见。

如果在另一个模块中使用：

```ts
let name: T
```

就会报错，因为另一个模块并不知道这个 `T`。

### 2.2 根本原因

只要文件里出现了 `import` 或 `export`，这个文件就会被视为模块。模块作用域下的类型声明不会自动泄漏到全局。

---

## 四、`declare global` 的基本写法

```ts
declare global {
  type T = string
}

export {}
```

这里的 `export {}` 很关键，它的作用是：

1. 明确告诉 TS 这是一个模块文件。
2. 避免当前文件本身被当作脚本文件处理。

声明后，其他模块中就可以直接使用：

```ts
let name: T
```

---

## 五、它常用来做什么

### 4.1 声明全局工具类型

```ts
declare global {
  type ID = string | number
}

export {}
```

### 4.2 扩展全局对象类型

比如扩展 `Window`：

```ts
declare global {
  interface Window {
    __APP_ENV__: "dev" | "prod"
  }
}

export {}
```

### 4.3 给第三方脚本注入的全局变量补类型

例如某个 SDK 会往 `window` 上挂属性，这时就很适合用 `declare global` 做补充声明。

---

## 六、和 `declare module` 的区别

| 写法                 | 作用对象   |
| -------------------- | ---------- |
| **`declare global`** | 全局作用域 |
| **`declare module`** | 某个模块   |

简单理解：

1. 想补全局，就用 `declare global`
2. 想补某个包或模块声明，就用 `declare module`

---

## 七、真实开发里怎么判断该不该全局化

| 场景                                         | 是否适合用 `declare global` |
| -------------------------------------------- | --------------------------- |
| **项目里很多地方都要直接使用同一个全局类型** | 可以考虑                    |
| **扩展 `Window` / `globalThis`**             | 很常见                      |
| **只在局部业务里使用的类型**                 | 不建议做全局                |
| **只是某个模块内部的约束**                   | 更适合局部导出导入          |

全局声明最容易犯的错误不是不会写，而是把本来局部的问题做成全局污染。

---

## 八、使用时的注意事项

1. 不要轻易把太多类型做成全局，容易造成命名污染。
2. 全局声明越多，越不利于定位类型来源。
3. 如果某个类型只在一小块业务中使用，优先局部导出导入，而不是全局声明。

---

## 九、小结

1. 模块中的普通类型声明默认不会影响其他模块。
2. `declare global` 可以在模块文件里补充全局类型。
3. 它最常见的用途是扩展 `Window`、声明全局工具类型、补第三方脚本注入变量的类型。
4. `declare global` 解决的是“全局作用域补类型”，`declare module` 解决的是“给模块补类型”。
5. 全局声明应谨慎使用，避免把局部问题做成全局污染。
