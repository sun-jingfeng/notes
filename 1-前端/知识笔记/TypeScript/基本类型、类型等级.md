# 基本类型、类型等级

## 一、一句话理解

这篇真正要解决的不是“把类型名背下来”，而是理解不同类型到底能装什么值、值域谁宽谁窄、为什么能赋值或不能赋值。

---

## 二、TypeScript 中的基本类型

TypeScript 的类型系统是在 JavaScript 值的基础上增加了一层静态约束，用来提前发现错误。

常见基本类型包括：

| 类型        | 示例            |
| ----------- | --------------- |
| `string`    | `"Tom"`         |
| `number`    | `18`、`3.14`    |
| `boolean`   | `true`、`false` |
| `symbol`    | `Symbol("id")`  |
| `bigint`    | `123n`          |
| `null`      | `null`          |
| `undefined` | `undefined`     |

示例：

```ts
const userName: string = "Sun"
const age: number = 20
const male: boolean = true
const token: symbol = Symbol("token")
const big: bigint = 9007199254740993n
```

### 1. 小写类型和包装类型

```ts
const s1: string = "abc"
const s2: String = new String("abc")
```

这里要区分：

1. `string`、`number`、`boolean` 是日常最常用的原始类型写法。
2. `String`、`Number`、`Boolean` 更接近包装对象类型。

真实项目中，通常优先使用小写类型，而不是 `String` 这种包装对象写法。

---

## 三、字面量类型

字面量类型表示“值只能是某几个固定值”。

```ts
let direction: "top" | "right" | "bottom" | "left" = "top"
```

这类类型经常和联合类型配合，用来约束配置项、组件属性、状态值。

### 1. 典型场景

1. 按钮尺寸：`"small" | "middle" | "large"`
2. 请求状态：`"idle" | "loading" | "success" | "error"`
3. 方向值、主题值、开关值等有限集合

---

## 四、`object`、`Object`、`{}` 的区别

这是 TypeScript 初学者最容易混淆的一组概念。

### 1. `object`

`object` 表示非原始类型，通常可以接收对象、数组、函数。

```ts
let value: object

value = {}
value = []
value = () => {}
// value = 1 // 报错
// value = "abc" // 报错
```

### 2. `Object`

`Object` 范围更宽，接近“除 `null` 和 `undefined` 外的大多数值”。

```ts
const data1: Object = "Sun"
const data2: Object = 20
const data3: Object = true
const data4: Object = { name: "Sun" }
```

但它表达能力很弱，实际开发中一般不推荐用来精确描述业务结构。

### 3. `{}`

`{}` 也不是“空对象”的最佳表达方式，它同样可以接受很多非空原始值。

```ts
const a: {} = "Sun"
const b: {} = 20
const c: {} = true
const d: {} = { name: "Sun" }
```

### 4. 实际建议

| 场景               | 推荐                  |
| ------------------ | --------------------- |
| 描述普通对象结构   | `type` / `interface`  |
| 只想表示“非原始值” | `object`              |
| 完全未知数据       | `unknown`             |
| 键值对象           | `Record<string, xxx>` |

不要把 `Object` 和 `{}` 当成“通用安全对象类型”。

---

## 五、`null` 与 `undefined`

当 `strictNullChecks` 开启时，`null` 和 `undefined` 不能随便赋值给其他类型。

```ts
let str: string = "abc"
// str = null // 报错
// str = undefined // 报错
```

这也是现代 TypeScript 项目里最常见的配置方式。

### 1. 为什么这很重要

因为它能帮助你在编译阶段发现“值可能为空”的问题，避免运行时错误。

```ts
function printName(name?: string) {
  if (name !== undefined) {
    console.log(name.toUpperCase())
  }
}
```

## 六、`void`

`void` 通常用于描述“函数没有返回值”这一情况。

```ts
function logMessage(message: string): void {
  console.log(message)
}
```

### 1. 注意点

1. `void` 主要用于函数返回值。
2. 它不表示“什么都没有的万能类型”。
3. 在回调类型中也很常见。

```ts
type Handler = () => void
```

---

## 七、`never`

`never` 表示“不可能有值”的类型。

典型场景有两个：

### 1. 函数永远不会正常结束

```ts
function throwError(message: string): never {
  throw new Error(message)
}

function loopForever(): never {
  while (true) {}
}
```

### 2. 穷尽性校验

```ts
type Status = "idle" | "loading" | "success"

function assertNever(value: never): never {
  throw new Error("Unexpected value: " + value)
}

function getText(status: Status) {
  switch (status) {
    case "idle":
      return "空闲"
    case "loading":
      return "加载中"
    case "success":
      return "成功"
    default:
      return assertNever(status)
  }
}
```

如果以后 `Status` 新增成员，但 `switch` 没同步处理，TypeScript 就会提示你。

---

## 八、`any`

`any` 表示放弃类型检查。

```ts
let something: any
something = []
something()
something.xxx
```

### 1. 特点

1. 几乎可以执行任意操作。
2. 类型检查会被绕开。
3. 容易把错误一路传染下去。

### 2. 使用建议

能不用就尽量不用，尤其不要把业务核心类型直接写成 `any`。

`any` 最大的问题不是“不优雅”，而是它会把后续一整段类型检查一起带松。

---

## 九、`unknown`

`unknown` 可以理解为“更安全的 `any`”。

```ts
let value: unknown

// value.toUpperCase() // 报错

if (typeof value === "string") {
  value.toUpperCase()
}
```

### 1. 为什么更安全

因为在真正操作它之前，必须先做类型缩小。

### 2. 适合场景

1. 接收外部接口数据。
2. `try...catch` 里的错误值。
3. 暂时不知道具体结构的数据。

---

## 十、类型等级与可赋值关系

TypeScript 里常说“类型等级”，本质上是在讨论：**一个类型能不能赋值给另一个类型。**

一个便于初学者理解的简化结论是：

```text
never < 字面量类型 < 基础类型 < 更宽泛的类型
```

例如：

```ts
type T1 = 123 extends number ? true : false // true
type T2 = "abc" extends string ? true : false // true
type T3 = never extends string ? true : false // true
```

### 1. 需要注意的地方

`any` 和 `unknown` 都比较特殊：

1. `any` 更像是关闭检查。
2. `unknown` 更像是“所有值都可以先放进来，但要先缩小再使用”。

它们不能简单粗暴地和普通类型放在一条绝对线性等级里理解。

### 2. 一个实用理解方式

| 类型       | 理解                       |
| ---------- | -------------------------- |
| `never`    | 最窄，根本不会有值         |
| 字面量类型 | 比如 `"top"`、`123`        |
| 基础类型   | 比如 `string`、`number`    |
| `unknown`  | 可接收任意值，但不能直接用 |
| `any`      | 放弃检查，最不安全         |

## 十一、真实开发里最常见的几个选择题

| 场景                             | 更推荐的类型          |
| -------------------------------- | --------------------- |
| **明确就是字符串、数字、布尔值** | 基础类型              |
| **只有几个固定可选值**           | 字面量类型 / 联合类型 |
| **接收未知外部数据**             | `unknown`             |
| **描述普通对象结构**             | `type` / `interface`  |
| **只想表示非原始值**             | `object`              |
| **临时跳过检查**                 | `any`，但要谨慎       |

---

## 十二、总结

1. TypeScript 的基本类型建立在 JavaScript 值之上，但多了静态约束。
2. `object`、`Object`、`{}` 含义并不一样，业务里通常不该滥用 `Object` 和 `{}`。
3. `any` 虽然方便，但会削弱类型系统；`unknown` 更适合处理未知值。
4. `never` 常用于“不会发生的情况”和穷尽性校验。
5. 学这篇时，关键不是背名词，而是理解“值域大小”和“可赋值关系”。
