# TypeScript条件类型与分发机制

## 一、一句话理解

条件类型的核心是在类型层做分支判断，而分发条件类型的关键是先想清楚：你要判断的是联合里的每个成员，还是整个联合类型本身。

---

## 二、什么是条件类型

**条件类型** 是 TypeScript 中基于条件判断来返回不同类型结果的一种类型表达式。

一句话理解：

```ts
T extends U ? X : Y
```

它在类型层面上，作用很像 JavaScript 里的三元表达式。

---

## 三、最基础的写法

```ts
type ResStatus<T> = T extends 200 | 201 | 204 | 206 ? "success" : "fail"

type Status1 = ResStatus<200> // "success"
type Status2 = ResStatus<300> // "fail"
```

### 1. 这段代码怎么读

如果 `T` 能赋值给 `200 | 201 | 204 | 206`，就返回 `"success"`，否则返回 `"fail"`。

---

## 四、条件类型和泛型组合

条件类型通常和泛型一起使用，这样它才能根据传入的类型动态变化。

```ts
type Conditional<T, U> = T extends U ? true : false

type R1 = Conditional<"abc", string> // true
type R2 = Conditional<"abc", number> // false
```

### 1. 它适合做什么

1. 判断类型之间的关系。
2. 根据入参类型推导返回值类型。
3. 生成更智能的工具类型。

---

## 五、根据泛型控制返回值类型

```ts
type FormatReturnValue<T> = T extends string
  ? string
  : T extends number
    ? number
    : never

function sum<T extends string | number>(a: T, b: T): FormatReturnValue<T> {
  return (a as any) + (b as any)
}

const r1 = sum(1, 2) // number
const r2 = sum("a", "b") // string
```

### 1. 为什么这里用了 `never`

因为除了 `string` 和 `number` 以外，这个类型不打算支持其他情况。

### 2. 为什么实现里用了 `as any`

因为 TypeScript 的泛型参数在函数实现阶段并不会自动帮你证明“这里一定可以直接做 `+` 运算”，所以示例里用类型断言简化实现。

---

## 六、判断两个类型是否相等

条件类型还常用来做“类型级比较”。

```ts
type NoDistribute<T> = T & {}

type IsEqual<T, U, Success, Fail> =
  NoDistribute<T> extends U
    ? NoDistribute<U> extends T
      ? Success
      : Fail
    : Fail

type T1 = IsEqual<1 | 2, 2 | 1, true, false> // true
type T2 = IsEqual<any, unknown, true, false> // true
```

### 1. 这里的关键点

为了避免联合类型分发带来的干扰，通常会先把类型包一层。

---

## 七、什么是分发条件类型

当条件类型的左侧是 **裸类型参数**，并且传入的是联合类型时，TypeScript 会对联合类型的每个成员分别计算，然后再把结果合并。

### 1. 示例

```ts
type SelectType<T> = T extends number ? true : false

type T1 = SelectType<number | string> // true | false -> boolean
```

这相当于：

```ts
type T1 = SelectType<number> | SelectType<string>
```

### 2. 为什么叫“分发”

因为联合类型被拆开后，分别进入条件判断，再把结果联合回来。

---

## 八、分发成立的条件

分发通常要同时满足这些条件：

1. 使用了条件类型。
2. 左侧是裸类型参数，例如 `T`。
3. 传入的是联合类型。

### 1. 什么叫裸类型参数

这些通常会触发分发：

```ts
T extends U ? X : Y
```

这些通常不会直接按分发处理：

```ts
[T] extends [U] ? X : Y
T[] extends U[] ? X : Y
```

---

## 九、分发带来的典型问题

有时候你本来想判断“整个联合类型是否是另一个类型的子集”，结果却因为分发得到不符合预期的结果。

```ts
type UnionAssets<T, U> = T extends U ? true : false

type T1 = UnionAssets<1 | 2 | 3, 1 | 2> // boolean
```

为什么是 `boolean`：

1. `1 extends 1 | 2` -> `true`
2. `2 extends 1 | 2` -> `true`
3. `3 extends 1 | 2` -> `false`
4. 最终合并成 `true | false`，也就是 `boolean`

---

## 十、如何避免分发

### 1. 用非裸类型包起来

```ts
type UnionAssets<T, U> = [T] extends [U] ? true : false

type T2 = UnionAssets<1 | 2 | 3, 1 | 2> // false
```

### 2. 也可以主动包一层工具类型

```ts
type NoDistribute<T> = T & {}

type UnionAssets<T, U> = NoDistribute<T> extends U ? true : false

type T3 = UnionAssets<1 | 2 | 3, 1 | 2> // false
```

### 3. 什么时候要避免分发

当你要判断的是“整体是否满足关系”，而不是“联合成员逐个是否满足关系”时。

---

## 十一、`any` 和 `never` 的特殊表现

### 1. `any`

```ts
type T = any extends number ? true : false // boolean
```

`any` 在条件类型中往往表现得比较特殊，容易得到更宽泛的结果。

### 2. `never`

```ts
type T1 = never extends never ? true : false // true

type IsNever<T> = T extends never ? true : false
type T2 = IsNever<never> // never
```

### 3. 为什么 `IsNever<never>` 不是 `true`

因为这里的 `T` 是裸类型参数，`never` 会触发“空联合分发”，最终结果还是 `never`。

如果要稳定判断 `never`，更常见写法是：

```ts
type IsNever<T> = [T] extends [never] ? true : false

type T3 = IsNever<never> // true
```

---

## 十二、条件类型的常见应用场景

1. 根据入参决定返回值类型。
2. 过滤联合类型中的某些成员。
3. 判断类型是否满足约束。
4. 编写更通用的工具类型。

### 1. 典型例子

```ts
type OnlyString<T> = T extends string ? T : never

type Result = OnlyString<string | number | boolean> // string
```

这里就利用了分发，把联合类型中的 `string` 成员筛出来。

---

## 十三、真实开发里怎么快速判断

| 问题                                       | 更该先想什么                               |
| ------------------------------------------ | ------------------------------------------ |
| **想按不同类型返回不同结果**               | 条件类型                                   |
| **想筛掉联合中的某些成员**                 | 分发条件类型                               |
| **想判断整个联合是否满足条件**             | 先包一层，避免分发                         |
| **结果为什么突然变成 `boolean` / `never`** | 检查是否发生分发、是否遇到 `any` / `never` |

---

## 十四、总结

1. 条件类型是 TypeScript 在类型层面做条件判断的核心机制。
2. 它常和泛型组合，用来写动态变化的类型结果。
3. 分发条件类型的关键在于：左侧是裸类型参数，并且传入联合类型。
4. 当你不希望联合类型被拆开计算时，要把类型包起来，避免分发。
5. 学这一篇时，重点不是背术语，而是先分清“我是想逐个判断联合成员，还是想整体判断一个联合类型”。
