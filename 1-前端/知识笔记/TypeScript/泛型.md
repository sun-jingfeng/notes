# 泛型

## 一、一句话理解

泛型的核心价值不是“语法更复杂”，而是在复用代码时尽量保留调用处的真实类型信息。

---

## 二、什么是泛型

**泛型（Generics）** 是 TypeScript 提供的一种参数化类型机制，用来在“类型安全”和“复用能力”之间取得平衡。

**核心思想：** 先不把类型写死，而是把类型当作参数传进来，等真正使用时再指定。

| 写死类型           | 泛型                   |
| ------------------ | ---------------------- |
| 只能服务某一种类型 | 能服务多种类型         |
| 复用性较差         | 复用性强               |
| 类型信息容易丢失   | 可保留调用处的真实类型 |

```ts
function identity<T>(value: T): T {
  return value
}

const num = identity<number>(100)
const str = identity("hello")
```

> 💡 大多数场景下，TypeScript 可以自动推断泛型参数，所以 `<number>` 往往可以省略。

## 三、泛型函数

### 1. 基本写法

```ts
function identity<T>(value: T): T {
  return value
}
```

这里的 `T` 就是类型变量，表示“调用时再决定的具体类型”。

### 2. 根据长度和内容创建数组

```ts
const getArray = <T>(times: number, value: T): T[] => {
  return Array.from({ length: times }, () => value)
}

const res1 = getArray<string>(3, "a")
const res2 = getArray(2, 100)
```

| 调用方式               | 返回值类型 |
| ---------------------- | ---------- |
| **`getArray(3, 'a')`** | `string[]` |
| **`getArray(2, 100)`** | `number[]` |

### 3. 元组交换

```ts
type Swap = <T, U>(arr: [T, U]) => [U, T]

const swap: Swap = arr => [arr[1], arr[0]]

const result = swap([123, "abc"])
// result: [string, number]
```

## 四、泛型为什么有价值

如果不用泛型，很多函数只能写成 `any`：

```ts
function identity(value: any): any {
  return value
}
```

这样虽然“能用”，但会丢掉类型信息。

```ts
const value = identity("hello")
value.toUpperCase() // 类型系统无法精准提示
```

改成泛型后，类型信息会从参数传递到返回值：

```ts
function identity<T>(value: T): T {
  return value
}

const value = identity("hello")
value.toUpperCase() // 有完整类型提示
```

## 五、在类型别名和接口中使用泛型

### 1. 响应数据结构

```ts
type ApiResponse<T = unknown> = {
  code: number
  data: T
  message?: string
}

function getDataList<T>(): ApiResponse<T> {
  throw new Error("示例函数")
}

const res = getDataList<string[]>()
```

此时 `res.data` 的类型就是 `string[]`。

### 2. 泛型接口

```ts
type Box<T> = {
  value: T
}

const box1: Box<number> = { value: 100 }
const box2: Box<string> = { value: "hello" }
```

## 六、在类中使用泛型

```ts
class MyList<T> {
  private arr: T[] = []

  add(value: T) {
    this.arr.push(value)
  }

  get(index: number): T | undefined {
    return this.arr[index]
  }
}

const list = new MyList<number>()
list.add(123)
// list.add('a') // ❌ 报错：string 不能赋给 number
```

| 优势                 | 说明                          |
| -------------------- | ----------------------------- | ---------- |
| **约束成员类型一致** | `MyList<number>` 中只能放数字 |
| **返回值类型明确**   | `get()` 返回 `number          | undefined` |

## 七、泛型约束

### 1. 约束泛型只能是某些类型

```ts
const handle = <T extends number | string>(value: T): T => value

handle(1)
handle("a")
// handle(true) // ❌ boolean 不满足约束
```

### 2. 约束泛型必须具有某个属性

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length
}

getLength([])
getLength("abc")
getLength(() => {})
// getLength(1) // ❌ number 没有 length
```

### 3. 用一个泛型约束另一个泛型

```ts
function getValue<T extends object, U extends keyof T>(obj: T, key: U) {
  return obj[key]
}

const obj = { a: 1, b: 2, c: 3 }
const value = getValue(obj, "b")
```

这里 `U extends keyof T` 的意思是：第二个参数只能是第一个参数对象已有的 key。

## 八、泛型默认值

泛型可以指定默认类型，在调用方不显式传入时自动使用。

```ts
type Union<T = string> = T

type T1 = Union
type T2 = Union<number>
```

| 类型     | 结果     |
| -------- | -------- |
| **`T1`** | `string` |
| **`T2`** | `number` |

## 九、泛型传递时的写法建议

在回调函数场景下，通常更推荐把泛型放在“类型别名本身”上，而不是把回调单独声明成泛型函数。

### 1. 推荐写法

```ts
type Callback<T> = (item: T) => void
type ForEach = <T>(arr: T[], callback: Callback<T>) => void

const forEach: ForEach = (arr, callback) => {
  arr.forEach(item => {
    callback(item)
  })
}

forEach(["a", "b", "c"], item => {
  console.log(item) // item: string
})
```

### 2. 不推荐写法

```ts
type Callback = <T>(item: T) => void
type ForEach = <T>(arr: T[], callback: Callback) => void
```

这种写法中，回调自己的泛型和外层数组的泛型没有绑定好，类型推导会变差。

## 十、什么时候该用泛型，什么时候别硬上

| 场景                                       | 是否适合用泛型 |
| ------------------------------------------ | -------------- |
| **函数逻辑一致，但入参与返回值类型要联动** | 很适合         |
| **容器类、响应包装、工具函数**             | 很适合         |
| **只有单一明确类型，不存在复用需求**       | 不一定需要     |
| **为了炫技把简单类型写得过于抽象**         | 不推荐         |

一个很实用的判断是：如果不用泛型就得写 `any`，而且会丢掉关键类型关系，那就值得考虑泛型。

## 十一、常见面试点与注意事项

| 问题                           | 说明                                     |
| ------------------------------ | ---------------------------------------- |
| **泛型和 `any` 的区别**        | 泛型保留类型关系，`any` 直接放弃类型检查 |
| **泛型什么时候写显式参数**     | 推断不出来、或者想手动指定时写           |
| **`extends` 在泛型里表示什么** | 表示约束，不一定是类继承                 |
| **泛型并不会运行时存在**       | 只在编译期参与类型检查                   |

## 十二、小结

| 知识点         | 结论                                     |
| -------------- | ---------------------------------------- |
| **泛型本质**   | 类型参数化                               |
| **最常见场景** | 泛型函数、泛型类型别名、泛型接口、泛型类 |
| **泛型约束**   | 用 `extends` 限制可传入的类型            |
| **默认类型**   | 可通过 `T = 默认类型` 指定               |
| **实际价值**   | 在复用代码时保留精确类型信息             |
