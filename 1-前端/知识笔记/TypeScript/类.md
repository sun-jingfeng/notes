# 类

## 一、一句话理解

TypeScript 里的类，不只是写面向对象语法，更重要的是把“实例长什么样、哪些成员能访问、哪些规则必须遵守”描述清楚。

---

## 二、为什么要学类

TypeScript 中的类既是运行时的 JavaScript 语法，也是类型系统里描述实例结构的一种方式。

```ts
class Person {}

const person: Person = new Person()
```

类适合用来表达：

1. 实例对象的结构。
2. 继承关系。
3. 面向对象建模。

---

## 三、类的基本写法

### 1. 属性需要先声明

```ts
class Circle {
  x: number
  y: number

  constructor(x: number, y: number = 100) {
    this.x = x
    this.y = y
  }
}
```

在 `strictPropertyInitialization` 等严格配置下，实例属性通常需要：

1. 在声明处初始化。
2. 或在构造函数中完成赋值。

### 2. 参数属性简写

```ts
class Animal {
  constructor(
    public name: string,
    public age: number,
  ) {}
}
```

这种写法会自动把参数提升为实例属性。

---

## 四、访问修饰符

TypeScript 提供了常见的访问控制修饰符。

| 修饰符      | 可访问范围         |
| ----------- | ------------------ |
| `public`    | 类内部、子类、外部 |
| `protected` | 类内部、子类       |
| `private`   | 仅类内部           |

### 1. `public`

```ts
class Animal {
  constructor(
    public name: string,
    public age: number,
  ) {}
}

const cat = new Animal("Tom", 10)
console.log(cat.name, cat.age)
```

`public` 是默认值，即使不写，很多成员也按公开成员处理。

### 2. `protected`

```ts
class Animal {
  constructor(
    protected name: string,
    public age: number,
  ) {}
}

class Cat extends Animal {
  rename() {
    this.name = "Orange"
  }
}
```

外部不能直接访问 `protected` 成员，但子类可以。

### 3. `private`

```ts
class Animal {
  constructor(
    private name: string,
    public age: number,
  ) {}

  getName() {
    return this.name
  }
}
```

`private` 成员只能在当前类内部使用，子类和外部都不能直接访问。

---

## 五、`readonly`

`readonly` 表示属性只能在初始化阶段赋值，之后不能再改。

```ts
class Animal {
  constructor(
    public readonly name: string,
    public age: number,
  ) {}
}

const cat = new Animal("White", 10)
// cat.name = "Black" // 报错
```

### 1. 注意点

1. `readonly` 可以和 `public`、`protected`、`private` 组合使用。
2. 构造函数里属于初始化阶段，因此允许赋值。

---

## 六、继承 `extends`

类可以通过 `extends` 继承父类。

```ts
class Animal {
  constructor(public name: string) {}

  say() {
    console.log("animal")
  }
}

class Cat extends Animal {
  catchMouse() {
    console.log(this.name + " 抓老鼠")
  }
}
```

### 1. `super`

子类构造函数中调用父类构造函数要用 `super()`。

```ts
class Cat extends Animal {
  constructor(
    name: string,
    public age: number,
  ) {
    super(name)
  }
}
```

---

## 七、方法重写

子类可以重写父类方法，但要遵守类型兼容规则。

```ts
class Animal {
  say(): string {
    return "animal"
  }
}

class Cat extends Animal {
  say(): string {
    return "cat"
  }
}
```

### 1. 一个核心点

如果父类方法返回值类型明确，子类重写时不能随便改成不兼容的返回类型。

---

## 八、构造函数访问控制

构造函数本身也可以使用访问修饰符。

### 1. `protected constructor`

```ts
class Animal {
  protected constructor() {}
}

class Mouse extends Animal {
  constructor() {
    super()
  }
}

// new Animal() // 报错
new Mouse()
```

这表示：

1. 父类不能直接实例化。
2. 但仍然可以被继承。

### 2. `private constructor`

```ts
class Singleton {
  private constructor() {}
  static instance = new Singleton()

  static getInstance() {
    return this.instance
  }
}
```

这表示：

1. 不能直接 `new`。
2. 不能被继承。
3. 很适合实现单例模式。

---

## 九、抽象类 `abstract`

抽象类可以作为“模板父类”，自身不能直接实例化。

```ts
abstract class Person {
  abstract eat(): void
}

class Teacher extends Person {
  eat(): void {
    console.log("eat")
  }
}
```

### 1. 规则

1. 抽象类不能被直接实例化。
2. 抽象方法只能写在抽象类中。
3. 非抽象子类必须实现抽象方法。

### 2. 适用场景

适合描述“有统一规范，但具体实现交给子类”的场景。

---

## 十、类与接口的关系

类可以实现接口。

```ts
interface Speakable {
  name: string
  speak(): void
}

class Person implements Speakable {
  constructor(public name: string) {}

  speak(): void {
    console.log("hello")
  }
}
```

这说明：

1. 接口负责描述规范。
2. 类负责提供实现。

这也是 TypeScript 里很典型的一条分工：接口更像约束，类更像具体实现。

---

## 十一、真实开发里怎么判断要不要用类

| 场景                           | 是否适合用类     |
| ------------------------------ | ---------------- |
| **明确存在实例、状态和方法**   | 适合             |
| **需要继承、封装、访问控制**   | 适合             |
| **只是普通数据对象或配置结构** | 不一定需要       |
| **更偏函数式工具处理**         | 往往不用类也可以 |

不要为了“像 Java”而强行用类，关键还是看建模是否真的需要实例语义。

---

## 十二、总结

1. TypeScript 的类同时参与运行时和类型系统。
2. `public`、`protected`、`private`、`readonly` 是类中最常用的修饰符。
3. 继承、重写、抽象类构成了类体系的核心。
4. 构造函数访问控制常用于限制实例化方式，例如单例模式。
5. 学这部分时，关键不是语法堆砌，而是理解“封装、继承、约束”这三件事。
