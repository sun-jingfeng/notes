# 类型别名、接口

## 一、一句话理解

`type` 和 `interface` 不是非此即彼的竞争关系，它们更像两种不同侧重点的建模工具。

---

## 二、类型别名和接口的定位

在 TypeScript 中，`type` 和 `interface` 都能描述类型结构，但它们并不完全等价。

一个够用的理解方式是：

| 工具        | 更常见用途                                       |
| ----------- | ------------------------------------------------ |
| `type`      | 联合类型、交叉类型、函数类型、工具类型、映射类型 |
| `interface` | 对象结构、类的约束、可扩展的 API 形状            |

### 1. 不是“谁更高级”

它们更多是侧重点不同，而不是谁全面替代谁。

---

## 三、类型别名 `type`

类型别名本质上是给一个类型起名字。

### 1. 基本用法

```ts
type Direction = "top" | "right" | "bottom" | "left"

let direction: Direction = "top"
```

### 2. 适合描述联合类型

```ts
type Status = "idle" | "loading" | "success" | "error"
```

### 3. 适合描述函数类型

```ts
type AddFn = (a: number, b: number) => number
```

### 4. 通过交叉类型组合

```ts
type Animal = {
  name: string
}

type Bear = Animal & {
  honey: boolean
}

const bear: Bear = {
  name: "Sun",
  honey: true,
}
```

### 5. 特点

1. 适合表达复杂类型计算。
2. 不能像接口那样靠“重名声明”自动合并。
3. 在工具类型场景里更常见。

---

## 四、接口 `interface`

接口更偏向描述“对象长什么样”。

### 1. 基本用法

```ts
interface Person {
  name: string
  age: number
  male?: boolean
}

const person: Person = {
  name: "abc",
  age: 20,
}
```

### 2. 为什么很多对象结构喜欢用接口

因为接口天然更适合扩展、实现、声明合并，尤其在大型项目和公共类型定义里更常见。

---

## 五、接口扩展 `extends`

接口可以通过 `extends` 继承其他接口。

```ts
interface Speakable {
  name: string
}

interface SpeakChinese extends Speakable {
  age: number
}

const speak: SpeakChinese = {
  name: "Sun",
  age: 20,
}
```

### 1. 作用

1. 复用已有结构。
2. 逐层扩展类型。
3. 让领域模型更清晰。

---

## 六、接口声明合并

接口支持重名声明，TypeScript 会自动合并它们。

```ts
interface IBox {
  width: string
}

interface IBox {
  height: string
}

const box: IBox = {
  width: "100px",
  height: "100px",
}
```

### 1. 声明合并的注意点

1. 重名接口的同名属性类型必须一致。
2. 如果一个导出、一个不导出，会报错。
3. 这也是接口能做全局扩展的重要基础。

声明合并是接口非常有代表性的特性，但也意味着它更适合公共协议、库扩展这类明确需要可扩展性的场景。

### 2. 同名属性类型冲突

```ts
interface IBox {
  width: string
}

// interface IBox {
//   width: number // 报错
// }
```

---

## 七、接口扩展全局类型

接口可以用于增强全局对象或内置对象类型。

### 1. 扩展 `Window`

```ts
interface Window {
  globalData: string
}

window.globalData = "abc"
```

### 2. 扩展内置对象

```ts
interface String {
  double(): string
}

String.prototype.double = function (this: string) {
  return this + this
}

"abc".double() // abcabc
```

不过这类扩展要谨慎，避免污染全局环境。

---

## 八、接口被类实现 `implements`

接口还可以作为类的约束。

```ts
interface Speakable {
  name: string
  speak(): void
}

interface SpeakChinese {
  speakChinese(): void
}

class Speak implements Speakable, SpeakChinese {
  name = "Sun"

  speak(): void {}

  speakChinese(): void {}
}
```

### 1. 作用

1. 约束类必须具备哪些成员。
2. 让类遵守统一协议。
3. 方便面向接口编程。

---

## 九、`type` 和 `interface` 的差异总结

| 对比项       | `type`   | `interface`    |
| ------------ | -------- | -------------- |
| 描述对象结构 | 可以     | 可以           |
| 描述联合类型 | 更擅长   | 不直接支持     |
| 描述交叉类型 | 更擅长   | 依赖 `extends` |
| 声明合并     | 不支持   | 支持           |
| 类实现       | 间接可以 | 非常常见       |

### 1. 一个实用经验

1. 复杂类型运算优先考虑 `type`。
2. 面向对象结构、公共 API、类约束优先考虑 `interface`。
3. 团队里最重要的不是“绝对统一”，而是使用习惯前后一致。

---

## 十、真实项目里怎么快速判断

| 需求                                 | 更常见选择  |
| ------------------------------------ | ----------- |
| **联合类型、交叉类型、工具类型组合** | `type`      |
| **对象结构协议、类实现约束**         | `interface` |
| **需要声明合并或扩展全局类型**       | `interface` |
| **只是想给复杂类型起别名**           | `type`      |

---

## 十一、总结

1. `type` 和 `interface` 都能描述类型，但适合的场景并不完全一样。
2. `type` 更适合联合、交叉、函数、映射等复杂类型表达。
3. `interface` 更适合对象结构、类实现、声明合并和全局扩展。
4. 实际开发中两者经常并存，不必强行二选一。
5. 学这篇的关键是理解“类型复用”和“结构扩展”的思路。
