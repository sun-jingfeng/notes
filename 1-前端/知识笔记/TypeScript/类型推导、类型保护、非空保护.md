# 类型推导、类型保护、非空保护

## 一、一句话理解

这三部分合起来，其实都在回答一个问题：TypeScript 是怎么一步步确认“这个值现在到底是什么”的。

---

## 二、这三个知识点的关系

这三个概念看起来分散，其实都在解决同一个核心问题：

**让 TypeScript 更准确地知道“这个值现在到底是什么类型”。**

| 主题         | 解决的问题                               |
| ------------ | ---------------------------------------- |
| **类型推导** | TS 如何自动推断类型                      |
| **类型保护** | TS 如何在分支里缩小类型范围              |
| **非空保护** | TS 如何确认某值不是 `undefined` / `null` |

---

## 三、类型推导

### 2.1 变量初始化时的推导

最常见的推导来自赋值语句。

```ts
let name = "abc"
let age = 20
let male = true
let some
```

推导结果通常是：

```ts
name: string
age: number
male: boolean
some: any
```

所以：

```ts
name = 123
```

会报错，因为 `name` 已经被推断成了 `string`。

### 2.2 一个实用习惯

遇到复杂类型时，可以先写出一个“真实初始值”，让 TS 推导，再把推导结果提取出来当成正式类型。

这比完全手写复杂对象类型更高效。

---

## 四、函数返回值推导

如果函数没有显式标注返回值，TS 会根据 `return` 内容推断。

```ts
function fn() {
  return 123
}
```

此时返回值会被推断为 `number`。

### 3.1 什么时候建议显式写返回值

1. 公共函数或导出函数。
2. 逻辑复杂、返回分支较多的函数。
3. 想稳定函数契约，避免后续改动把返回值类型带偏。

---

## 五、上下文类型推导

类型推导不一定只发生在“右边推左边”，也可能由上下文反向约束。

```ts
type Fn = (p1: number, p2: string) => void

const fn: Fn = (p1, p2) => {
  p1
  p2
}
```

这里 `p1` 和 `p2` 的类型不是手写的，而是由 `Fn` 这个上下文自动推导出来的。

这类现象叫做：**上下文类型推导**。

---

## 六、泛型推导

### 5.1 为什么需要泛型推导

如果函数参数和返回值都写成 `any`，调用方就拿不到有效类型信息。

### 5.2 示例一：提取对象值组成的数组

不使用泛型时：

```ts
function values(obj: any): any[] {
  const result = []

  for (const key in obj) {
    result.push(obj[key])
  }

  return result
}
```

这样返回值只能是 `any[]`。

改成泛型后：

```ts
function values<T extends object>(obj: T): T[keyof T][] {
  const result = [] as T[keyof T][]

  for (const key in obj) {
    result.push(obj[key as keyof T])
  }

  return result
}

const arr = values({ name: "abc", age: 20 })
```

此时 `arr` 会被推导为：

```ts
(string | number)[]
```

### 5.3 示例二：对象 map

```ts
function mapObject<T extends object, U>(
  obj: T,
  callback: (item: T[keyof T], key: keyof T) => U,
) {
  const result = {} as Record<keyof T, U>

  for (const key in obj) {
    result[key] = callback(obj[key], key)
  }

  return result
}
```

这个例子里，TS 会同时推导：

1. `T` 是传入对象的结构。
2. `U` 是回调返回值类型。
3. 最终结果对象会保留原键名，但值类型统一变为 `U`。

### 5.4 泛型推导的核心价值

**把调用处真实传入的信息，向函数内部和返回值传播。**

## 七、类型保护

### 6.1 什么是类型保护

类型保护指的是：通过某种判断，让 TS 在某个分支里把联合类型缩小成更具体的类型。

例如：

```ts
function fn(value: string | number) {
  if (typeof value === "string") {
    value.toUpperCase()
  } else {
    value.toFixed(2)
  }
}
```

在不同分支里，`value` 的类型会被自动缩小。

---

## 八、常见类型保护方式

### 7.1 `typeof`

适合判断基础类型。

```ts
function fn(value: string | number) {
  if (typeof value === "string") {
    value
  } else {
    value
  }
}
```

### 7.2 `instanceof`

适合区分类实例。

```ts
class Person {}
class Dog {}

function fn(value: Person | Dog) {
  if (value instanceof Person) {
    value
  } else {
    value
  }
}
```

### 7.3 `in`

适合通过属性是否存在来区分对象联合类型。

```ts
type T1 = { name: string }
type T2 = { age: number }

function fn(value: T1 | T2) {
  if ("name" in value) {
    value
  } else {
    value
  }
}
```

### 7.4 判别字段比较

当联合类型里有稳定字面量字段时，推荐使用判别联合。

```ts
type T1 = {
  name: string
  type: "1"
}

type T2 = {
  age: number
  type: "2"
}

function fn(value: T1 | T2) {
  if (value.type === "1") {
    value
  } else {
    value
  }
}
```

这是业务代码里最稳、最清晰的一种缩小方式。

在真实项目里，如果联合类型是你自己设计的，优先给它加稳定判别字段，后续缩小会轻松很多。

### 7.5 `Array.isArray`

```ts
function fn(value: string | string[]) {
  if (Array.isArray(value)) {
    value
  } else {
    value
  }
}
```

## 九、自定义类型保护 `is`

当内置判断方式不够用时，可以自己定义类型保护函数。

```ts
function isString(value: string | number): value is string {
  return typeof value === "string"
}

function fn(value: string | number) {
  if (isString(value)) {
    value
  } else {
    value
  }
}
```

### 8.1 为什么它重要

因为真实业务里的判断通常会更复杂，自定义类型保护可以把“判断逻辑”和“类型缩小结果”一起封装起来。

### 8.2 常见用途

1. 接口返回值校验。
2. 树结构节点类型判断。
3. 组件 props 或事件对象分类。

---

## 十、非空保护

### 9.1 什么是非空保护

当一个值可能是 `undefined` 或 `null` 时，需要在使用前先让 TS 确认它已经有值。

```ts
function fn(num?: number) {
  num

  num = num || 0
  num
}
```

这里在赋默认值之后，`num` 会被缩小成 `number`。

### 9.2 在同一控制流里有效

```ts
function fn(num?: number) {
  num = num || 0

  if (true) {
    num
  }
}
```

在同一函数、同一控制流分析范围内，这种非空缩小通常是有效的。

### 9.3 为什么不能随便跨函数作用域

```ts
function fn(num?: number) {
  num = num || 0

  function fn2() {
    num
  }
}
```

因为进入新的函数作用域后，TS 不能简单假设外层变量状态永远不变。

它会重新保守地看待这个值。

---

## 十一、非空保护和非空断言的区别

| 方式             | 含义                               | 是否更安全 |
| ---------------- | ---------------------------------- | ---------- |
| **非空保护**     | 通过判断或赋默认值让 TS 推断出非空 | 更安全     |
| **非空断言 `!`** | 直接告诉 TS 这里一定不为空         | 风险更高   |

例如：

```ts
const ele = document.getElementById("app")

if (ele) {
  ele.style.color = "red"
}
```

通常比：

```ts
const ele = document.getElementById("app")
ele!.style.color = "red"
```

更稳妥。

---

## 十二、实际开发建议

1. 能依赖推导时就不要重复手写类型。
2. 公共函数和边界函数建议显式标注返回值。
3. 联合类型优先通过判别字段、`in`、`typeof`、`instanceof` 来做缩小。
4. 非空值优先用判断和默认值处理，少直接滥用 `!`。

可以把这篇的主线理解成：优先让 TS 自己推出来，其次用安全判断帮助它缩小，最后才是不得已时用断言。

---

## 十三、小结

1. 类型推导让 TS 能从赋值、上下文、返回值和泛型中自动获得类型信息。
2. 类型保护让联合类型在分支里被缩小成更具体的类型。
3. 自定义 `is` 类型保护适合复杂业务判断。
4. 非空保护依赖控制流分析，在同一作用域里最有效。
5. 和直接使用 `!` 相比，基于判断的非空保护通常更稳妥。
