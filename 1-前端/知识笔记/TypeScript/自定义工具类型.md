# 自定义工具类型

## 一、为什么要写自定义工具类型

TypeScript 内置了很多工具类型，比如 `Pick`、`Omit`、`Partial`、`ReturnType`，但真实项目里经常还需要针对业务场景再封装一层。

常见目标包括：

1. 提取接口返回值。
2. 让某些字段可选或只读。
3. 根据值类型筛选键或对象。
4. 合并、覆盖、裁剪对象结构。
5. 表达互斥关系或更严格的业务约束。

一句话概括：**自定义工具类型的价值，不在于炫技，而在于把重复的类型操作抽成可复用能力。**

---

## 二、接口返回值相关工具

### 2.1 封装通用接口返回结构

```ts
type IResponseData<T> = {
  code: string
  data: T
  msg?: string
}
```

这个类型适合描述接口统一返回格式，例如：

```ts
type UserRes = IResponseData<{
  name: string
  age: number
}>
```

### 2.2 从接口函数里提取真正的数据类型

```ts
type IPickResponse<T extends (...args: any[]) => any> =
  ReturnType<T> extends Promise<IResponseData<infer R>> ? R : unknown
```

它的思路是：

1. 先拿到函数返回值 `ReturnType<T>`。
2. 判断它是不是 `Promise<IResponseData<...>>`。
3. 如果是，就用 `infer` 提取真正的业务数据类型。

### 2.3 典型场景

```ts
async function getUser() {
  return {
    code: "200",
    data: { name: "Tom", age: 18 },
  } as IResponseData<{ name: string; age: number }>
}

type UserData = IPickResponse<typeof getUser>
```

这样 `UserData` 就能直接拿到 `{ name: string; age: number }`。

## 三、`Compute`

### 3.1 作用

`Compute` 常用于把复杂交叉结构“展开”，让编辑器悬浮提示更好看。

```ts
type Compute<T extends object> = {
  [K in keyof T]: T[K]
}
```

### 3.2 为什么常用

很多类型经过 `&`、映射、工具类型嵌套后，提示会比较抽象，`Compute` 可以帮助把结果拍平展示。

### 3.3 键名重映射示例

```ts
type PrefixKeys<T extends object> = {
  [K in keyof T as `key_${K & string}`]: T[K]
}

type Obj = {
  a: string
  b: number
  c: boolean
}

type T1 = PrefixKeys<Obj>
```

这里体现了映射类型里的 `as` 键名重映射能力。

## 四、`IsEqual`

### 4.1 基础版

```ts
type IsEqual<T, U, Success = true, Fail = false> = [T] extends [U]
  ? [U] extends [T]
    ? Success
    : Fail
  : Fail
```

### 4.2 作用

用于比较两个类型是否相等，常见于：

1. 类型体操。
2. 过滤键。
3. 判断工具类型分支。

### 4.3 为什么加 `[]`

为了避免条件类型分发，保证比较更稳定。

## 五、让指定字段变为可选

```ts
type PartialOptional<T extends object, K extends keyof T> = Partial<
  Pick<T, K>
> &
  Omit<T, K>

type Obj = {
  name: string
  age: number
  male: boolean
}

type T1 = Compute<PartialOptional<Obj, "name">>
```

### 5.1 思路

1. 先把需要改造的字段 `Pick` 出来。
2. 对它们做 `Partial`。
3. 再和剩余字段 `Omit` 合并。
4. 最后可用 `Compute` 让结果更易读。

## 六、按值类型筛选键

### 6.1 取出值等于指定类型的键

```ts
type PickOrOmitKeysByValueType<
  T extends object,
  U,
  Pick extends boolean = true,
> = {
  [K in keyof T]: IsEqual<
    Pick,
    true,
    IsEqual<T[K], U, K, never>,
    IsEqual<T[K], U, never, K>
  >
}[keyof T]
```

### 6.2 示例

```ts
type Obj = {
  name: string
  age: number
  male: boolean
  address: string
}

type T1 = PickOrOmitKeysByValueType<Obj, string>
type T2 = PickOrOmitKeysByValueType<Obj, string, false>
```

这里：

1. `T1` 会得到字符串值对应的键。
2. `T2` 会得到非字符串值对应的键。

## 七、按值类型筛选对象

```ts
type PickByValueType<T extends object, U> = {
  [K in keyof T as T[K] extends U ? K : never]: T[K]
}

type Obj = {
  name: string
  age: number
  male: boolean
}

type T = PickByValueType<Obj, string | number>
```

它会得到：

```ts
{
  name: string
  age: number
}
```

### 7.1 和“筛选键”的区别

1. 筛选键得到的是联合类型。
2. 筛选对象得到的是新对象结构。

## 八、对象交集、差集、覆盖

### 8.1 取对象交集键

```ts
type ObjectInter<T extends object, U extends object> = Pick<
  T,
  Extract<keyof T, keyof U>
>
```

表示只保留两边共同拥有的键，值以第一个对象为准。

### 8.2 取对象差集

```ts
type ObjectDiff<T extends object, U extends object> = Omit<T, keyof U>
```

表示删除 `T` 中和 `U` 重复的键。

### 8.3 用第二个对象覆盖第一个对象

```ts
type CoverObj<T extends object, U extends object> = {
  [K in keyof T]: K extends keyof U ? U[K] : T[K]
}
```

如果 `U` 中有同名键，就让它覆盖 `T` 的类型。

### 8.4 这组工具什么时候有用

1. 合并接口响应结构。
2. 扩展组件 props。
3. 做 DTO、表单数据、视图模型转换。

---

## 九、对象互斥类型

### 9.1 为什么普通联合不够

```ts
type Obj1 = { a: string }
type Obj2 = { b: string }
type Obj3 = { c: string }

type T = Obj1 | Obj2 | Obj3
```

这并不是真正互斥，因为：

```ts
const obj: T = {
  a: "",
  b: "",
  c: "",
}
```

依然可能成立。

### 9.2 借助 `never` 做互斥

```ts
type OrObj<T extends object, U extends object> =
  | (T & { [K in Exclude<keyof U, keyof T>]?: never })
  | (U & { [K in Exclude<keyof T, keyof U>]?: never })
```

### 9.3 作用

可以表达“要么这一组字段生效，要么另一组字段生效，但不能混着来”。

这在表单配置、组件 props、状态分支里都很有用。

---

## 十、小结

1. 自定义工具类型的价值在于把重复的类型操作抽成可复用能力。
2. `IResponseData`、`IPickResponse` 适合接口返回结构场景。
3. `Compute`、`IsEqual` 是很多高级工具类型的基础积木。
4. 根据值类型筛选键、筛选对象，是业务类型设计里的高频需求。
5. 对象交集、差集、覆盖、互斥，属于很实用的一组对象工具能力。
6. 学这篇时，重点不是记住所有名字，而是看懂每个工具类型背后的组合思路。
