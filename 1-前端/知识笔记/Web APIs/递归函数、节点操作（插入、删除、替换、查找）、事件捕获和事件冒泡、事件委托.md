# 递归函数、节点操作、事件捕获与冒泡、事件委托

| 主线                | 核心问题                                 |
| ------------------- | ---------------------------------------- |
| **递归 + 节点操作** | 如何一层层处理结构化数据和 DOM 节点      |

## 二、递归函数

如果一个函数在内部调用自己，并通过条件控制结束，那么这个函数就是递归函数。

```js
function countDown(num) {
  if (num <= 0) {
    return
  }

  console.log(num)
  countDown(num - 1)
}
```

### 2.1 递归的三个关键点

| 关键点         | 说明                           |
| -------------- | ------------------------------ |
| 调用自身       | 函数内部再次调用自己           |
| 重复执行       | 每次调用通常处理一个更小的问题 |
| 必须有结束条件 | 否则会死循环或栈溢出           |

### 2.2 递归与循环的关系

递归本质上也是一种重复执行方式，简单场景通常可以用循环替代，但树结构遍历、目录遍历、嵌套 DOM 处理等问题用递归往往更自然。

### 2.3 一个判断标准

如果问题天然就是“父子嵌套、一层套一层”的结构，递归通常比手写多层循环更顺手。

## 三、节点操作

节点操作通常围绕 4 类行为：

1. 插入。
2. 删除。
3. 替换。
4. 查找关系。

### 3.1 插入节点

插入节点通常分两步：

1. 创建节点。
2. 把节点插入到页面中。

```js
const li = document.createElement("li")
li.innerText = "新项目"

const list = document.querySelector("ul")
list.appendChild(li)
```

### 3.2 克隆节点

```js
const newNode = li.cloneNode(true)
```

| 参数    | 说明                       |
| ------- | -------------------------- |
| `true`  | 连同后代节点一起克隆       |
| `false` | 只克隆当前节点，不包含后代 |

### 3.3 删除节点

```js
const ul = document.querySelector("ul")
const li = document.querySelector("li")

ul.removeChild(li)
```

现代浏览器中，也常直接使用：

```js
li.remove()
```

### 3.4 替换节点

```js
const oldNode = document.querySelector(".old")
const newNode = document.createElement("div")
newNode.innerText = "新的内容"

oldNode.parentNode.replaceChild(newNode, oldNode)
```

### 3.5 常见 DOM 操作怎么选

| 操作                         | 更适合         |
| ---------------------------- | -------------- |
| `appendChild()`              | 追加到末尾     |
| `insertBefore()`             | 插到指定节点前 |
| `replaceChild()`             | 明确做节点替换 |
| `removeChild()` / `remove()` | 删除节点       |

### 3.6 一个现实提醒

有些简单场景会直接用 `innerHTML` 改结构，但它本质是重新解析 HTML 字符串，已有子节点和事件关系可能被整体替换掉。

## 四、查找节点关系

### 4.1 父节点

```js
console.log(node.parentNode)
```

### 4.2 子节点

| 属性         | 说明                         |
| ------------ | ---------------------------- |
| `childNodes` | 所有子节点，包含文本、注释等 |
| `children`   | 只包含元素节点               |

### 4.3 兄弟节点

| 属性                     | 说明                           |
| ------------------------ | ------------------------------ |
| `previousSibling`        | 上一个兄弟节点，可能是文本节点 |
| `previousElementSibling` | 上一个兄弟元素节点             |
| `nextSibling`            | 下一个兄弟节点，可能是文本节点 |
| `nextElementSibling`     | 下一个兄弟元素节点             |

### 4.4 `nodeName`

```js
console.log(node.nodeName)
```

元素节点通常返回大写标签名，例如 `DIV`、`LI`。

### 4.5 一个易错点

在真实页面里，空白换行也可能形成文本节点，所以如果你只关心元素，通常优先看 `children`、`nextElementSibling` 这一类 API。

## 五、什么是事件流

事件流指的是事件从触发到结束时，在 DOM 树中的传播过程。

通常会涉及两个阶段：

| 阶段     | 方向               |
| -------- | ------------------ |
| 捕获阶段 | 从外到内，从父到子 |
| 冒泡阶段 | 从内到外，从子到父 |

默认开发中更常接触到的是冒泡阶段。

---

## 六、事件捕获与事件冒泡

### 6.1 事件冒泡

当某个元素触发事件后，事件会继续向上层父元素传播，这就是冒泡。

```js
child.addEventListener("click", function () {
  console.log("child")
})

parent.addEventListener("click", function () {
  console.log("parent")
})
```

### 6.2 事件捕获

```js
parent.addEventListener(
  "click",
  function () {
    console.log("capture")
  },
  true,
)
```

`addEventListener` 的第三个参数传 `true`，表示在捕获阶段触发。

### 6.3 事件对象里两个很重要的点

1. `event.target`：真正触发事件的元素。
2. `event.currentTarget`：当前正在执行监听器的元素。

这两个概念在事件委托里尤其重要。

### 6.4 注意点

| 说明         | 结论                       |
| ------------ | -------------------------- |
| 默认监听阶段 | 冒泡阶段                   |
| L0 事件      | 只有冒泡概念，没有捕获配置 |
| 捕获使用频率 | 一般低于冒泡               |

---

## 七、阻止事件传播

如果不希望事件继续传播，可以阻止事件流动。

```js
child.addEventListener("click", function (event) {
  event.stopPropagation()
})
```

### 7.1 常见鼠标移入移出事件

| 事件                        | 是否冒泡 |
| --------------------------- | -------- |
| `mouseover` / `mouseout`    | 会冒泡   |
| `mouseenter` / `mouseleave` | 不会冒泡 |

在很多交互场景下，`mouseenter` / `mouseleave` 更稳定。

## 八、事件委托

事件委托是把子元素的事件统一绑定到父元素上，利用事件冒泡来处理的一种技巧。

### 8.1 为什么要用

| 场景               | 优势                       |
| ------------------ | -------------------------- |
| 列表项很多         | 不必给每个子元素单独绑事件 |
| 子元素是动态新增的 | 新节点也能被统一处理       |

### 8.2 典型写法

```js
const list = document.querySelector("ul")

list.addEventListener("click", function (event) {
  if (event.target.nodeName === "LI") {
    console.log("点击了列表项")
  }
})
```

### 8.3 核心思路

1. 事件绑定在父元素上。
2. 通过 `event.target` 找到真正触发的元素。
3. 再根据标签名、类名或属性做判断。

### 8.4 事件委托的边界

它很适合 click、列表操作这类场景，但并不是所有事件都适合委托。比如某些不冒泡事件、对单个元素强依赖的精细交互，就不一定适合统一代理。

---

## 九、小结

1. 递归适合天然分层、嵌套的问题，前提是必须有结束条件。
2. DOM 操作重点是分清插入、删除、替换和关系查找各自解决什么问题。
3. 事件流包含捕获和冒泡两个阶段，日常开发大多数逻辑都建立在冒泡之上。
4. `event.target` 和 `event.currentTarget` 是理解事件委托的关键。
5. 事件委托的核心价值是减少绑定数量并兼容动态节点，但也要注意适用边界。
