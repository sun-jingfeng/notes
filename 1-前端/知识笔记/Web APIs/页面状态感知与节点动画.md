# 页面状态感知与节点动画

## 一、这篇的主线

这篇虽然主题很多，但都围绕“页面什么时候可用、元素现在是什么状态、如何按时间驱动变化”这条主线。

可以分成 3 组理解：

| 主题组                         | 解决的问题                         |
| ------------------------------ | ---------------------------------- |
| **滚动 / 加载**                | 页面和资源什么时候进入某种状态     |
| **节点大小 / 位置 / 卷起距离** | 元素当前到底有多大、在哪、滚了多少 |
| **定时器 / 动画**              | 代码如何按时间驱动视觉变化         |

---

## 二、滚动事件 `scroll`

滚动事件用来监听页面或元素滚动位置的变化。

### 2.1 基本写法

```js
window.addEventListener("scroll", function () {
  console.log(window.scrollY)
})
```

### 2.2 可以监听谁

| 监听对象   | 场景                   |
| ---------- | ---------------------- |
| `window`   | 监听页面整体滚动       |
| `document` | 某些历史写法中也会使用 |
| 具体元素   | 监听某个可滚动容器     |

```js
const panel = document.querySelector(".panel")

panel.addEventListener("scroll", function () {
  console.log(panel.scrollTop)
})
```

### 2.3 常见用途

1. 返回顶部按钮显示隐藏。
2. 吸顶导航。
3. 懒加载。
4. 无限滚动。

### 2.4 一个实战提醒

`scroll` 是高频事件，如果每次触发都做重计算、查布局、改 DOM，很容易卡顿。

所以真实项目里常配合：

1. 节流。
2. `requestAnimationFrame()`。
3. 被动监听等优化思路。

### 2.5 排查滚动逻辑时先问什么

1. 真正在滚的是页面，还是局部容器。
2. 回调里有没有做高频读写布局。
3. 当前需求更适合滚动监听，还是更适合 `IntersectionObserver`。

## 三、加载事件 `load`

```js
window.addEventListener("load", function () {
  console.log("页面及资源已加载完成")
})
```

### 3.1 `load` 的含义

它表示页面以及相关外部资源都已经加载完成，例如：

1. 图片。
2. 样式文件。
3. 脚本文件。
4. 其他带路径的资源。

### 3.2 和 `DOMContentLoaded` 的区别

| 事件               | 触发时机                 |
| ------------------ | ------------------------ |
| `DOMContentLoaded` | DOM 结构解析完成         |
| `load`             | DOM 和外部资源都加载完成 |

如果你只关心 DOM 可操作，通常更早的 `DOMContentLoaded` 更合适；如果你要确保图片尺寸等资源可用，`load` 更稳。

### 3.3 真实开发里怎么选

| 需求                             | 更推荐               |
| -------------------------------- | -------------------- |
| DOM 一解析完就开始绑事件         | `DOMContentLoaded`   |
| 依赖图片、视频、外链资源实际尺寸 | `load`               |
| 工程化框架组件内部逻辑           | 通常交给框架生命周期 |

## 四、节点大小

前端里最常用的节点尺寸属性有三组：

1. `clientWidth` / `clientHeight`
2. `offsetWidth` / `offsetHeight`
3. `scrollWidth` / `scrollHeight`

### 4.1 对比关系

| 属性          | 包含内容                      |
| ------------- | ----------------------------- |
| `clientWidth` | 内容区 + `padding`            |
| `offsetWidth` | 内容区 + `padding` + `border` |
| `scrollWidth` | 内容区 + `padding` + 溢出内容 |

### 4.2 怎么选

1. 关心可见内容区域大小，常看 `clientWidth`。
2. 关心元素占位总宽高，常看 `offsetWidth`。
3. 关心内容是否溢出、实际可滚动内容有多大，常看 `scrollWidth`。

### 4.3 一个容易混淆的点

这些属性拿到的是数字结果，适合直接用于计算，不需要自己去掉 `px`。

### 4.4 三组尺寸属性怎么快速判断

| 关心点             | 更常看                         |
| ------------------ | ------------------------------ |
| 可视内容区大小     | `clientWidth` / `clientHeight` |
| 元素占位总尺寸     | `offsetWidth` / `offsetHeight` |
| 实际滚动内容总尺寸 | `scrollWidth` / `scrollHeight` |

## 五、节点位置

### 5.1 `offsetTop` / `offsetLeft`

```js
const box = document.querySelector(".box")

console.log(box.offsetTop)
console.log(box.offsetLeft)
```

它们表示元素相对于最近已定位祖先元素的位置。

### 5.2 `offsetParent`

```js
console.log(box.offsetParent)
```

这个属性可以帮助你确认 `offsetTop` 和 `offsetLeft` 到底是相对谁在计算。

### 5.3 `getBoundingClientRect()`

```js
const rect = box.getBoundingClientRect()
console.log(rect.top, rect.left, rect.width, rect.height)
```

它返回元素相对于浏览器视口的位置和大小。

### 5.4 两类位置 API 的差异

| API                        | 更偏向       |
| -------------------------- | ------------ |
| `offsetTop` / `offsetLeft` | 相对布局链路 |
| `getBoundingClientRect()`  | 相对当前视口 |

### 5.5 什么时候更适合用 `getBoundingClientRect()`

1. 判断元素是否进入视口。
2. 做拖拽、碰撞检测。
3. 计算浮层、弹层、提示框位置。

### 5.6 一个排错提醒

如果你发现位置计算“时准时不准”，通常优先排查：

1. 当前参考系到底是视口还是定位祖先。
2. 页面是否已经滚动。
3. 元素是否发生了 `transform`、缩放或动态布局变化。

## 六、节点卷起位置

### 6.1 `scrollTop` / `scrollLeft`

```js
const panel = document.querySelector(".panel")

console.log(panel.scrollTop)
panel.scrollTop = 100
```

它们表示元素内容已经滚过去了多少距离。

### 6.2 页面整体滚动位置怎么拿

现代场景里经常用：

```js
console.log(window.scrollY)
console.log(document.documentElement.scrollTop)
```

### 6.3 一个常见组合判断

当你想判断“是否滚动到底部”时，常常会一起看：

1. `scrollTop`
2. `clientHeight`
3. `scrollHeight`

也就是：

```text
卷起距离 + 可视高度 是否接近 总内容高度
```

### 6.4 一个真实使用边界

“是否到底部”这类判断不要过度依赖绝对相等，实际项目里通常会保留一个误差范围，避免因为小数、缩放或浏览器差异导致临界值抖动。

## 七、延迟函数 `setTimeout`

```js
const timer = window.setTimeout(function () {
  console.log("延迟执行")
}, 1000)
```

### 7.1 它的特点

1. 延迟一段时间后执行一次。
2. 即使传 `0`，也不会立刻插队执行。
3. 仍然要等当前同步任务执行完才会轮到它。

### 7.2 清除延迟函数

```js
window.clearTimeout(timer)
```

### 7.3 为什么时间不一定绝对准确

因为定时器到点后只是“进入待执行队列”，真正执行还要等主线程空出来。

### 7.4 `setTimeout` 和 `setInterval` 的区别

| 定时器          | 特点           |
| --------------- | -------------- |
| `setTimeout()`  | 延迟执行一次   |
| `setInterval()` | 按间隔重复执行 |

### 7.5 为什么有时会用 `setTimeout` 模拟 `setInterval`

因为递归式 `setTimeout` 更容易控制每一次执行的节奏，避免任务堆积。

```js
function run() {
  console.log("执行一次")
  setTimeout(run, 1000)
}

setTimeout(run, 1000)
```

### 7.6 什么时候更适合递归 `setTimeout`

1. 每次执行耗时不稳定。
2. 需要根据上一次结果决定是否继续。
3. 不希望任务积压在队列里越堆越多。

## 八、JavaScript 动画

JavaScript 动画的本质，是在一段时间内持续修改元素样式或状态，从而形成视觉变化。

### 8.1 传统思路

```js
const box = document.querySelector(".box")
let left = 0

const timer = setInterval(() => {
  left += 5
  box.style.transform = `translateX(${left}px)`

  if (left >= 200) {
    clearInterval(timer)
  }
}, 16)
```

### 8.2 这种方式的问题

1. 节奏不一定和浏览器刷新同步。
2. 页面卡顿时更容易掉帧。
3. 频繁操作布局相关属性时性能更差。

### 8.3 `requestAnimationFrame()`

```js
const box = document.querySelector(".box")
let left = 0
let frameId = 0

function move() {
  left += 5
  box.style.transform = `translateX(${left}px)`

  if (left < 200) {
    frameId = requestAnimationFrame(move)
  }
}

frameId = requestAnimationFrame(move)
```

它会尽量和浏览器下一帧渲染节奏对齐，通常比手写 `setInterval()` 更平滑。

停止方式：

```js
cancelAnimationFrame(frameId)
```

### 8.4 一个性能建议

做动画时优先改：

1. `transform`
2. `opacity`

尽量少直接频繁改会触发布局重算的属性。

### 8.5 真实开发里怎么判断用什么动画方案

| 需求                       | 更推荐                    |
| -------------------------- | ------------------------- |
| 纯展示过渡、状态切换       | CSS 动画 / 过渡           |
| 需要逐帧控制               | `requestAnimationFrame()` |
| 只想每隔一段时间做一次任务 | 定时器                    |

---

## 九、小结

1. `scroll` 解决的是“滚动状态变化”，但它是高频事件，通常要考虑优化。
2. `load` 与 `DOMContentLoaded` 的核心区别在于是否要等外部资源一起完成。
3. 节点大小和位置相关 API 的关键在于分清“可视区域、占位尺寸、溢出内容、相对谁计算”。
4. `setTimeout()` 和 `setInterval()` 都不是绝对精准计时器，本质仍受事件循环影响。
5. JavaScript 动画更推荐使用 `requestAnimationFrame()`，并优先操作 `transform`、`opacity` 这类更友好的属性。
