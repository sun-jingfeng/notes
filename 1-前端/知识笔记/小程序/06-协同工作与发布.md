# 微信小程序协同工作和发布

## 一、为什么小程序项目需要协同机制

小程序虽然前端比重高，但真正的业务项目依然会涉及多角色协作，不是开发者单独写完就结束。

常见参与角色包括：

1. 产品。
2. 设计。
3. 前端开发。
4. 后端开发或云开发负责人。
5. 测试。
6. 项目管理。

---

## 二、常见团队分工

| 角色         | 主要职责                     |
| ------------ | ---------------------------- |
| **产品**     | 需求梳理、原型设计、流程定义 |
| **设计**     | 视觉稿、交互方案、设计规范   |
| **开发**     | 页面实现、接口联调、功能落地 |
| **测试**     | 功能测试、边界测试、回归测试 |
| **项目管理** | 节奏推进、风险控制、发布协调 |

### 1. 你要有的项目意识

真正影响项目质量的，往往不是“某个 API 会不会用”，而是协作链路是否清晰、交付边界是否明确。

---

## 三、微信平台权限管理

微信小程序平台本身提供了成员与权限管理能力，目的是让多人团队在同一个小程序项目下协作。

### 1. 为什么权限管理重要

因为不同角色并不应该拥有完全相同的权限，比如：

1. 有人只需要开发权限。
2. 有人只需要查看数据。
3. 有人负责提交审核和发布。

### 2. 管理目标

1. 降低误操作风险。
2. 保证发布口统一。
3. 让责任边界更清楚。

---

## 四、小程序常见版本类型

| 版本类型       | 说明                           |
| -------------- | ------------------------------ |
| **开发版本**   | 开发者上传的工作版本           |
| **体验版本**   | 给测试、产品、业务侧体验的版本 |
| **审核中版本** | 已提交平台审核，等待审核结果   |
| **线上版本**   | 已正式发布给用户使用的版本     |

### 1. 怎么理解这四层

可以简单理解为：

```text
开发版本 → 体验版本 → 审核中版本 → 线上版本
```

### 2. 一个重要原则

不要拿某个开发者本地自测代码直接当正式发布依据，中间一定要有体验和审核环节。

---

## 五、团队协作时的代码管理

实际项目里，代码协作通常还是离不开 Git。

### 1. 一个常见分支思路

```text
main / master      主分支
dev                日常开发集成分支
feature/*          功能分支
release/*          发布准备分支
hotfix/*           紧急修复分支
```

### 2. 一个典型流程

1. 从主干切功能分支。
2. 功能完成后合并到开发分支。
3. 测试通过后整理发布分支。
4. 提交体验版、审核版。
5. 审核通过后发布线上。

### 3. 为什么要这样做

因为它能把“开发中的不稳定代码”和“准备发布的稳定代码”分开。

---

## 六、发布前检查清单

这是最容易被忽略、但最影响线上质量的部分。

### 1. 基础配置

1. 域名是否已经配置。
2. 线上接口是否已部署。
3. HTTPS 是否可用。
4. 环境变量是否切到正式环境。

### 2. 功能与兼容

1. 登录流程是否正常。
2. 授权拒绝路径是否处理。
3. 页面跳转是否完整。
4. 关键设备场景是否验证。

### 3. 性能与稳定性

1. 图片和资源体积是否可控。
2. 接口失败是否有兜底。
3. 服务端负载是否评估。
4. 云函数 / 云数据库权限是否正确。

---

## 七、用户体验视角下的发布标准

上线不只是“功能能跑”，还要看用户体验是否合格。

### 1. 高频检查项

1. 导航是否清晰。
2. 流程是否符合用户预期。
3. 等待时是否有反馈。
4. 异常提示是否明确。
5. 文案是否准确自然。
6. 页面风格是否统一。

### 2. 一个实用判断标准

如果用户在关键路径上经常不知道“接下来该点哪”或“现在发生了什么”，那就说明还没达到可以发布的体验标准。

---

## 八、小程序码的作用

小程序发布后，平台会提供对应的小程序码，用于线上线下传播。

### 1. 常见用途

1. 海报投放。
2. 门店物料。
3. 活动页导流。
4. 线下扫码即用场景。

### 2. 价值

小程序码本质上是微信生态里的业务入口，它不只是“一个二维码”，而是用户增长链路的一部分。

---

## 九、总结

1. 小程序项目同样需要完整的多人协作机制。
2. 微信平台的成员权限、版本流转、审核发布构成了平台级交付流程。
3. Git 分支管理负责代码协作，平台版本管理负责交付与上线。
4. 发布前要重点检查环境配置、接口可用性、授权流程、异常路径和用户体验。
5. 真正稳定的上线，不是“能提交审核”，而是“团队协作、版本管理、体验质量都已经准备好”。
