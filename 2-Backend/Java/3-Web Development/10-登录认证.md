## 一、登录认证概述

### 1.1 认证 vs 授权

| 概念                    | 定义         | 解决的问题   |
| ----------------------- | ------------ | ------------ |
| **认证 Authentication** | 验证用户身份 | 你是谁？     |
| **授权 Authorization**  | 确定用户权限 | 你能做什么？ |

**处理流程：** 用户请求 → 认证（验证身份）→ 授权（检查权限）→ 访问资源

### 1.2 常见认证方案对比

| 特性         | Session | JWT        | OAuth 2.0  |
| ------------ | ------- | ---------- | ---------- |
| **状态**     | 有状态  | 无状态     | 无状态     |
| **存储**     | 服务端  | 客户端     | 客户端     |
| **分布式**   | 需共享  | 天然支持   | 天然支持   |
| **主动失效** | 容易    | 需黑名单   | 取决于实现 |
| **适用场景** | 传统Web | API/移动端 | 第三方登录 |

### 1.3 完整认证流程

**请求处理链路：** 客户端 → Filter/拦截器 → Controller → Service

**Token 校验流程：**

1.  获取请求 URL
2.  判断是否为白名单路径（如 `/login`）→ 是则放行
3.  从请求头获取 Token
4.  判断 Token 是否存在 → 不存在返回 401
5.  检查 Token 是否在黑名单 → 在则返回 401
6.  解析验证 Token → 失败返回 401
7.  设置用户上下文，放行请求

```java
    public Result<Void> handleException(Exception e) {
        log.error("系统异常: ", e);
        return Result.error("系统繁忙，请稍后再试");
    }
}
```

## 三、JWT 认证实战

### 3.1 JWT 结构

JWT 由三部分组成，各部分用 `.` 分隔，均经过 Base64URL 编码（编码而非加密，可被任意解码）。安全性完全依赖 Signature——服务端用密钥对前两部分做签名，任何篡改都会导致验签失败。

    eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMDAxIn0.xxx
          Header               Payload          Signature

| 部分          | 说明                 | 内容示例                                                                  |
| ------------- | -------------------- | ------------------------------------------------------------------------- |
| **Header**    | 元数据（签名算法）   | `{"alg": "HS256", "typ": "JWT"}`                                          |
| **Payload**   | 声明（用户数据）     | `{"sub": "1001", "username": "admin", "exp": 1234567890}`                 |
| **Signature** | 签名（防止篡改）     | `HMACSHA256(base64url(header) + "." + base64url(payload), secretKey)`     |

### 3.3 JWT 工具类

```java
package com.example.utils;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.ExpiredJwtException;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import jakarta.annotation.PostConstruct;
import lombok.Getter;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;

@Slf4j
@Component
public class JwtUtils {

    @Value("${jwt.secret}")
    private String secret;

    @Getter
    @Value("${jwt.access-expiration}")
    private Long accessExpiration;

    @Getter
    @Value("${jwt.refresh-expiration}")
    private Long refreshExpiration;

    private SecretKey key;

    @PostConstruct
    public void init() {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
    }

    // ==================== 生成 Token ====================

    /**
     * 生成 Access Token
     */
    public String generateAccessToken(Long userId, String username) {
        return buildToken(userId, username, accessExpiration);
    }

    /**
     * 生成 Refresh Token
     */
    public String generateRefreshToken(Long userId, String username) {
        return buildToken(userId, username, refreshExpiration);
    }

    private String buildToken(Long userId, String username, Long expiration) {
        Date now = new Date();
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .claim("username", username)
                .issuedAt(now)
                .expiration(new Date(now.getTime() + expiration))
                .signWith(key)
                .compact();
    }

    // ==================== 解析 Token ====================

    /**
     * 解析 Token，获取 Claims
     */
    public Claims parseToken(String token) {
        return Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }

    /**
     * 获取用户ID
     */
    public Long getUserId(String token) {
        return Long.parseLong(parseToken(token).getSubject());
    }

    /**
     * 获取用户名
     */
    public String getUsername(String token) {
        return parseToken(token).get("username", String.class);
    }

    // ==================== 验证 Token ====================

    /**
     * 验证 Token 是否有效
     */
    public boolean validate(String token) {
        try {
            parseToken(token);
            return true;
        } catch (ExpiredJwtException e) {
            log.debug("Token 已过期: {}", e.getMessage());
        } catch (JwtException e) {
            log.debug("Token 无效: {}", e.getMessage());
        } catch (Exception e) {
            log.debug("Token 解析失败: {}", e.getMessage());
        }
        return false;
    }

    /**
     * 判断 Token 是否已过期
     */
    public boolean isExpired(String token) {
        try {
            return parseToken(token).getExpiration().before(new Date());
        } catch (Exception e) {
            return true;
        }
    }

    /**
     * 获取 Token 剩余有效期（秒）
     * 用于登出时设置黑名单过期时间
     */
    public long getRemainExpiration(String token) {
        try {
            Date expiration = parseToken(token).getExpiration();
            long remain = (expiration.getTime() - System.currentTimeMillis()) / 1000;
            return Math.max(0, remain);
        } catch (Exception e) {
            return 0;
        }
    }
}
```

**认证服务：**

```java
package com.example.service;

import com.example.dto.LoginRequest;
import com.example.dto.LoginResponse;
import com.example.entity.User;
import com.example.exception.BusinessException;
import com.example.repository.UserRepository;
import com.example.utils.JwtUtils;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class AuthService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtUtils jwtUtils;
    private final CaptchaService captchaService;
    private final LoginAttemptService loginAttemptService;

    /**
     * 用户登录
     */
    public LoginResponse login(LoginRequest request) {
        String username = request.getUsername();

        // 1. 检查账号是否被锁定
        if (loginAttemptService.isLocked(username)) {
            throw new BusinessException("账号已被锁定，请15分钟后再试");
        }

        // 2. 验证码校验（失败3次及以上需要验证码）
        int remainingAttempts = loginAttemptService.getRemainingAttempts(username);
        if (remainingAttempts <= 2) {
            if (request.getCaptchaKey() == null || request.getCaptchaCode() == null) {
                throw new BusinessException("请输入验证码");
            }
            if (!captchaService.validate(request.getCaptchaKey(), request.getCaptchaCode())) {
                throw new BusinessException("验证码错误");
            }
        }

        // 3. 查询用户并验证密码
        User user = userRepository.findByUsername(username);
        if (user == null || !passwordEncoder.matches(request.getPassword(), user.getPassword())) {
            loginAttemptService.recordFailure(username);
            int remaining = loginAttemptService.getRemainingAttempts(username);
            throw new BusinessException("用户名或密码错误，剩余尝试次数：" + remaining);
        }

        // 4. 检查账号状态
        if (user.getStatus() != 1) {
            throw new BusinessException("账号已被禁用");
        }

        // 5. 登录成功，清除失败记录
        loginAttemptService.clearFailures(username);

        // 6. 生成Token并返回
        return buildLoginResponse(user);
    }

    /**
     * 刷新Token
     */
    public LoginResponse refresh(String refreshToken) {
        // 1. 验证 Refresh Token
        if (!jwtUtils.validate(refreshToken)) {
            throw new BusinessException(HttpServletResponse.SC_UNAUTHORIZED, "Refresh Token 无效或已过期");
        }

        // 2. 获取用户信息
        Long userId = jwtUtils.getUserId(refreshToken);
        User user = userRepository.findById(userId)
                .orElseThrow(() -> new BusinessException("用户不存在"));

        // 3. 检查账号状态
        if (user.getStatus() != 1) {
            throw new BusinessException("账号已被禁用");
        }

        // 4. 生成新Token
        return buildLoginResponse(user);
    }

    /**
     * 构建登录响应
     */
    private LoginResponse buildLoginResponse(User user) {
        return LoginResponse.builder()
                .accessToken(jwtUtils.generateAccessToken(user.getId(), user.getUsername()))
                .refreshToken(jwtUtils.generateRefreshToken(user.getId(), user.getUsername()))
                .expiresIn(jwtUtils.getAccessExpiration() / 1000)
                .user(LoginResponse.UserInfo.builder()
                        .id(user.getId())
                        .username(user.getUsername())
                        .nickname(user.getNickname())
                        .build())
                .build();
    }
}
```

### 3.5 Token 黑名单服务

登出时将 Token 写入 Redis 黑名单，每次请求校验阶段检查 Token 是否已失效。Redis Key 为 `token:blacklist:{token}`，TTL 与 Token 剩余有效期一致，到期后自动删除，无需额外清理逻辑。

```java
package com.example.service;

import lombok.RequiredArgsConstructor;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Service
@RequiredArgsConstructor
public class TokenBlacklistService {

    private final StringRedisTemplate redisTemplate;
    private static final String PREFIX = "token:blacklist:";

    /**
     * 将Token加入黑名单
     * @param token Token
     * @param expireSeconds Token剩余有效期（秒）
     */
    public void add(String token, long expireSeconds) {
        redisTemplate.opsForValue().set(
                PREFIX + token,
                "1",
                expireSeconds,
                TimeUnit.SECONDS
        );
    }

    /**
     * 检查Token是否在黑名单中
     */
    public boolean contains(String token) {
        return Boolean.TRUE.equals(redisTemplate.hasKey(PREFIX + token));
    }
}
```

### 3.6 JWT 主动失效（改密码场景）

JWT 一旦签发便无法主动吊销，生命周期由 `exp` 字段决定。用户改密码后，已签发的旧 Token 在过期前仍然合法，是 JWT 无状态特性带来的经典安全问题。

**三种解决方案对比：**

| 方案                         | 原理 | 优点 | 缺点 |
| ---------------------------- | ---- | ---- | ---- |
| **Redis 黑名单**             | 改密码时将当前请求的 Token 写入黑名单，每次请求查一次黑名单 | 实现直接 | 只能拦截发起改密码时携带的那一个 Token，其他设备的旧 Token 无法覆盖；每次请求多一次 Redis I/O |
| **Token 版本号（推荐）**     | 用户表加 `token_version` 字段，改密码时自增；Token payload 携带版本号，验证时与 DB 值比对 | 一次操作使所有设备的旧 Token 同时失效；无额外存储；版本号比对可复用已有 DB 查询 | 每次请求需查库，破坏纯无状态 |
| **短有效期 + Refresh Token** | Access Token 设置极短有效期（如 5 分钟），改密码时从 Redis 删除 Refresh Token | 无需主动吊销 Access Token，到期自动失效 | 实现最复杂；Refresh Token 本身也需持久化管理 |

> 推荐 **Token 版本号** 方案：改密码等于全局注销，一次 DB 字段自增使所有设备的旧 Token 同时失效，无需额外引入存储结构。实际项目中通常搭配较短的 Access Token 有效期（如 2 小时），进一步缩短旧 Token 的存活窗口。如果系统同时使用了 Refresh Token，改密码时还需将该用户的 Refresh Token 从 Redis 中删除，否则旧 Refresh Token 仍可换取携带新版本号的 Access Token。

## 四、请求拦截与认证

### 4.1 Filter vs Interceptor 对比

| 对比项              | Filter                 | Interceptor              |
| ------------------- | ---------------------- | ------------------------ |
| **规范**            | Servlet 规范           | Spring MVC 规范          |
| **执行时机**        | DispatcherServlet 之前 | DispatcherServlet 之后   |
| **能否获取Handler** | 不能                   | 能                       |
| **依赖注入**        | 需特殊处理             | 原生支持                 |
| **适用场景**        | 编码、跨域、通用过滤   | 认证、权限、日志         |
| **异常处理**        | 必须手动设置响应       | 可抛异常由全局处理器捕获 |

> 💡 两种方式二选一，推荐使用 Interceptor。Filter 在 DispatcherServlet 之前执行，`@ControllerAdvice` 无法捕获其抛出的异常，需手动设置响应；Interceptor 在 Spring MVC 内部执行，可直接抛出自定义异常由全局处理器统一处理。

### 4.3 方式一：Filter 实现

```java
package com.example.filter;

import com.example.common.Result;
import com.example.context.UserContext;
import com.example.service.TokenBlacklistService;
import com.example.utils.JwtUtils;
import com.fasterxml.jackson.databind.ObjectMapper;
import jakarta.servlet.*;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;

import java.io.IOException;
import java.util.Set;

@Component
@RequiredArgsConstructor
public class AuthFilter implements Filter {

    private final JwtUtils jwtUtils;
    private final TokenBlacklistService blacklistService;
    private final ObjectMapper objectMapper;

    /** 白名单路径 */
    private static final Set<String> WHITE_LIST = Set.of(
            "/auth/login",
            "/auth/refresh",
            "/captcha"
    );

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                         FilterChain chain) throws IOException, ServletException {
        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse res = (HttpServletResponse) response;

        // 1. 放行 OPTIONS 预检请求（CORS）
        if ("OPTIONS".equalsIgnoreCase(req.getMethod())) {
            chain.doFilter(request, response);
            return;
        }

        // 2. 白名单放行
        String uri = req.getRequestURI();
        if (isWhiteListed(uri)) {
            chain.doFilter(request, response);
            return;
        }

        // 3. 获取并校验 Token
        String token = extractToken(req);
        if (token == null) {
            sendError(res, HttpServletResponse.SC_UNAUTHORIZED, "未登录");
            return;
        }

        // 4. 检查黑名单
        if (blacklistService.contains(token)) {
            sendError(res, HttpServletResponse.SC_UNAUTHORIZED, "Token已失效，请重新登录");
            return;
        }

        // 5. 解析Token并设置上下文
        try {
            UserContext.setUserId(jwtUtils.getUserId(token));
            UserContext.setUsername(jwtUtils.getUsername(token));
            chain.doFilter(request, response);
        } catch (Exception e) {
            sendError(res, HttpServletResponse.SC_UNAUTHORIZED, "Token无效或已过期");
        } finally {
            UserContext.clear();
        }
    }

    private boolean isWhiteListed(String uri) {
        return WHITE_LIST.contains(uri);
    }

    private String extractToken(HttpServletRequest request) {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return header.substring(7);
        }
        return null;
    }

    private void sendError(HttpServletResponse response, int code, String message)
            throws IOException {
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write(objectMapper.writeValueAsString(Result.error(code, message)));
    }
}
```

## 五、密码安全

### 5.1 BCrypt 加密配置

**BCrypt** 是专为密码存储设计的自适应哈希算法。每次加密时自动生成随机盐值（salt），因此相同明文每次的哈希结果均不同，验证时必须使用 `matches()` 方法而非字符串直接比较。计算成本由 `strength` 参数控制（默认 10），`strength` 每增加 1，计算时间翻倍，可随硬件升级而提高破解难度。相比 MD5/SHA 等通用哈希算法，BCrypt 对暴力破解和彩虹表攻击的抵抗力显著更强。

```java
package com.example.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

**使用方式：**

```java
    }
}
```

```java
package com.example.validation;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

public class PasswordValidator implements ConstraintValidator<StrongPassword, String> {

    private int min;
    private int max;

    @Override
    public void initialize(StrongPassword annotation) {
        this.min = annotation.min();
        this.max = annotation.max();
    }

    @Override
    public boolean isValid(String password, ConstraintValidatorContext context) {
        if (password == null) {
            return false;
        }
        return password.length() >= min
                && password.length() <= max
                && password.matches(".*[A-Z].*")   // 包含大写字母
                && password.matches(".*[a-z].*")   // 包含小写字母
                && password.matches(".*\\d.*");    // 包含数字
    }
}
```

### 5.3 登录失败次数限制

使用 Redis 对每个用户名维护一个失败计数器（Key：`login:attempt:{username}`）。每次登录失败时计数器自增，首次自增时设置 TTL（15分钟）；达到上限（5次）后账号进入锁定状态，锁定期内所有登录请求直接拒绝；登录成功后删除计数器。TTL 到期后计数器自动清除，账号自动解锁，无需定时任务介入。

```java
package com.example.service;

import lombok.RequiredArgsConstructor;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Service
@RequiredArgsConstructor
public class LoginAttemptService {

    private final StringRedisTemplate redisTemplate;

    private static final String PREFIX = "login:attempt:";
    private static final int MAX_ATTEMPTS = 5;      // 最大尝试次数
    private static final int LOCK_MINUTES = 15;     // 锁定时间（分钟）

    /**
     * 记录登录失败
     */
    public void recordFailure(String username) {
        String key = PREFIX + username;
        Long attempts = redisTemplate.opsForValue().increment(key);
        if (attempts != null && attempts == 1) {
            // 首次失败，设置过期时间
            redisTemplate.expire(key, LOCK_MINUTES, TimeUnit.MINUTES);
        }
    }

    /**
     * 检查账号是否被锁定
     */
    public boolean isLocked(String username) {
        String key = PREFIX + username;
        String value = redisTemplate.opsForValue().get(key);
        return value != null && Integer.parseInt(value) >= MAX_ATTEMPTS;
    }

    /**
     * 登录成功，清除失败记录
     */
    public void clearFailures(String username) {
        redisTemplate.delete(PREFIX + username);
    }

    /**
     * 获取剩余尝试次数
     */
    public int getRemainingAttempts(String username) {
        String key = PREFIX + username;
        String value = redisTemplate.opsForValue().get(key);
        if (value == null) {
            return MAX_ATTEMPTS;
        }
        return Math.max(0, MAX_ATTEMPTS - Integer.parseInt(value));
    }
}
```

### 6.1 图形验证码

**工作流程：** 前端请求 `/captcha` → 后端生成验证码并存入 Redis（Key：`captcha:{key}`，TTL 5分钟）→ 返回 `{key, image}`（image 为 Base64）→ 前端渲染图片 → 用户输入验证码 → 登录请求携带 `captchaKey + captchaCode` → 后端校验后删除 Redis Key（一次性使用，防重放）。

```java
package com.example.service;

import com.wf.captcha.SpecCaptcha;
import lombok.RequiredArgsConstructor;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.Map;
import java.util.UUID;
import java.util.concurrent.TimeUnit;

@Service
@RequiredArgsConstructor
public class CaptchaService {

    private final StringRedisTemplate redisTemplate;
    private static final String PREFIX = "captcha:";
    private static final int EXPIRE_MINUTES = 5;

    /**
     * 生成图形验证码
     * @return key: 验证码标识, image: Base64图片
     */
    public Map<String, String> generate() {
        // 生成验证码：宽130px，高48px，4个字符
        SpecCaptcha captcha = new SpecCaptcha(130, 48, 4);
        String code = captcha.text().toLowerCase();
        String key = UUID.randomUUID().toString().replace("-", "");

        // 存入Redis，5分钟过期
        redisTemplate.opsForValue().set(PREFIX + key, code, EXPIRE_MINUTES, TimeUnit.MINUTES);

        Map<String, String> result = new HashMap<>();
        result.put("key", key);
        result.put("image", captcha.toBase64());
        return result;
    }

    /**
     * 校验验证码
     */
    public boolean validate(String key, String code) {
        if (key == null || code == null) {
            return false;
        }
        String redisKey = PREFIX + key;
        String stored = redisTemplate.opsForValue().get(redisKey);
        redisTemplate.delete(redisKey);  // 一次性使用
        return code.toLowerCase().equals(stored);
    }
}
```

### 6.2 短信验证码

使用两个 Redis Key 分别管理：`sms:code:{phone}` 存储验证码（TTL 5分钟），`sms:limit:{phone}` 控制发送频率（TTL 60秒）。发送时先检查限频 Key 是否存在，存在则拒绝；验证时取出后立即删除，确保每个验证码只能使用一次。

```java
package com.example.service;

import com.example.exception.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.security.SecureRandom;
import java.util.concurrent.TimeUnit;

@Service
@RequiredArgsConstructor
public class SmsService {

    private final StringRedisTemplate redisTemplate;

    private static final String CODE_PREFIX = "sms:code:";
    private static final String LIMIT_PREFIX = "sms:limit:";
    private static final int CODE_EXPIRE_MINUTES = 5;
    private static final int LIMIT_SECONDS = 60;

    /**
     * 发送短信验证码
     */
    public void send(String phone) {
        // 1. 检查发送频率（60秒内只能发一次）
        if (Boolean.TRUE.equals(redisTemplate.hasKey(LIMIT_PREFIX + phone))) {
            throw new BusinessException("发送太频繁，请60秒后再试");
        }

        // 2. 生成6位数字验证码（SecureRandom 保证随机性，不可预测）
        String code = String.format("%06d", new SecureRandom().nextInt(1000000));

        // 3. 调用短信服务商API发送（示例）
        // smsClient.send(phone, "您的验证码是：" + code + "，5分钟内有效");

        // 4. 存储验证码，5分钟有效
        redisTemplate.opsForValue().set(CODE_PREFIX + phone, code, CODE_EXPIRE_MINUTES, TimeUnit.MINUTES);

        // 5. 设置发送间隔限制，60秒
        redisTemplate.opsForValue().set(LIMIT_PREFIX + phone, "1", LIMIT_SECONDS, TimeUnit.SECONDS);
    }

    /**
     * 校验短信验证码
     */
    public boolean validate(String phone, String code) {
        if (phone == null || code == null) {
            return false;
        }
        String stored = redisTemplate.opsForValue().get(CODE_PREFIX + phone);
        if (code.equals(stored)) {
            redisTemplate.delete(CODE_PREFIX + phone);  // 验证成功后删除
            return true;
        }
        return false;
    }
}
```

## 七、权限控制（RBAC）

**RBAC（Role-Based Access Control，基于角色的访问控制）** 是最常见的权限模型。用户不直接关联权限，而是通过角色间接获得权限：

    用户（User）→ 用户角色关联（sys_user_role）→ 角色（Role）→ 角色权限关联（sys_role_permission）→ 权限（Permission）

这种设计将权限管理收敛到角色层面——调整某类用户的权限时只需修改角色所关联的权限，无需逐个更新用户记录，维护成本低。

### 7.1 数据库设计

```sql
-- 用户表
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL COMMENT '用户名',
    password VARCHAR(100) NOT NULL COMMENT '密码（BCrypt加密）',
    nickname VARCHAR(50) COMMENT '昵称',
    status TINYINT DEFAULT 1 COMMENT '状态：1正常 0禁用',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 角色表
CREATE TABLE sys_role (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    code VARCHAR(50) UNIQUE NOT NULL COMMENT '角色编码',
    name VARCHAR(50) NOT NULL COMMENT '角色名称',
    description VARCHAR(200) COMMENT '描述'
);

-- 权限表
CREATE TABLE sys_permission (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    code VARCHAR(100) UNIQUE NOT NULL COMMENT '权限编码，如 user:list',
    name VARCHAR(50) NOT NULL COMMENT '权限名称',
    type TINYINT COMMENT '类型：1菜单 2按钮'
);

-- 用户-角色关联表
CREATE TABLE sys_user_role (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, role_id)
);

-- 角色-权限关联表
CREATE TABLE sys_role_permission (
    role_id BIGINT NOT NULL,
    permission_id BIGINT NOT NULL,
    PRIMARY KEY (role_id, permission_id)
);

-- 示例数据
INSERT INTO sys_role (code, name) VALUES ('admin', '管理员'), ('user', '普通用户');
INSERT INTO sys_permission (code, name, type) VALUES 
    ('user:list', '用户列表', 2),
    ('user:add', '添加用户', 2),
    ('user:update', '编辑用户', 2),
    ('user:delete', '删除用户', 2);
```

**根据用户 ID 查询权限编码：**

RBAC 模型中用户与权限之间没有直接关联，需要经过“用户 → 角色 → 权限”两层关联表才能完成映射，因此 SQL 需联查三张表：

```sql
SELECT DISTINCT p.code
FROM sys_permission p
INNER JOIN sys_role_permission rp ON p.id = rp.permission_id
INNER JOIN sys_user_role ur       ON rp.role_id = ur.role_id
WHERE ur.user_id = #{userId}
```

1. `sys_user_role`：通过 `user_id` 找出该用户拥有的所有 `role_id`
2. `sys_role_permission`：通过 `role_id` 找出这些角色对应的所有 `permission_id`
3. `sys_permission`：通过 `permission_id` 取出最终的权限编码 `code`

`DISTINCT` 用于去重——同一个权限可能被多个角色同时持有，若用户身兼多个角色，该权限会出现多行，`DISTINCT` 确保结果集中每个权限编码只出现一次。

**AOP 切面：**

```java
package com.example.aspect;

import com.example.annotation.Logical;
import com.example.annotation.RequirePermission;
import com.example.context.UserContext;
import com.example.exception.AuthenticationException;
import com.example.exception.BusinessException;
import com.example.service.PermissionService;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;
import org.springframework.stereotype.Component;

import java.util.Arrays;
import java.util.Set;

@Aspect
@Component
@RequiredArgsConstructor
public class PermissionAspect {

    private final PermissionService permissionService;

    @Before("@annotation(requirePermission)")
    public void checkPermission(RequirePermission requirePermission) {
        // 1. 获取当前用户
        Long userId = UserContext.getUserId();
        if (userId == null) {
            throw new AuthenticationException("未登录");
        }

        // 2. 获取用户权限
        Set<String> userPermissions = permissionService.getPermissionsByUserId(userId);

        // 3. 校验权限
        String[] required = requirePermission.value();
        Logical logical = requirePermission.logical();

        boolean hasPermission;
        if (logical == Logical.AND) {
            hasPermission = Arrays.stream(required).allMatch(userPermissions::contains);
        } else {
            hasPermission = Arrays.stream(required).anyMatch(userPermissions::contains);
        }

        if (!hasPermission) {
            throw new BusinessException(HttpServletResponse.SC_FORBIDDEN, "无权访问");
        }
    }
}
```

### 7.3 权限服务（带缓存）

```java
package com.example.service;

import com.example.mapper.PermissionMapper;
import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

import java.util.Collections;
import java.util.List;
import java.util.Set;
import java.util.concurrent.TimeUnit;
import java.util.stream.Collectors;

@Slf4j
@Service
@RequiredArgsConstructor
public class PermissionService {

    private final PermissionMapper permissionMapper;
    private final StringRedisTemplate redisTemplate;
    private final ObjectMapper objectMapper;

    private static final String PREFIX = "user:permissions:";
    private static final long EXPIRE_HOURS = 2;

    /**
     * 获取用户权限（带缓存）
     */
    public Set<String> getPermissionsByUserId(Long userId) {
        String key = PREFIX + userId;

        // 1. 先查缓存
        try {
            String cached = redisTemplate.opsForValue().get(key);
            if (cached != null) {
                return objectMapper.readValue(cached, new TypeReference<Set<String>>() {});
            }
        } catch (Exception e) {
            log.warn("读取权限缓存失败: {}", e.getMessage());
        }

        // 2. 查数据库
        Set<String> permissions = permissionMapper.selectPermissionCodesByUserId(userId);
        if (permissions == null) {
            permissions = Collections.emptySet();
        }

        // 3. 写入缓存
        try {
            redisTemplate.opsForValue().set(
                    key,
                    objectMapper.writeValueAsString(permissions),
                    EXPIRE_HOURS,
                    TimeUnit.HOURS
            );
        } catch (Exception e) {
            log.warn("写入权限缓存失败: {}", e.getMessage());
        }

        return permissions;
    }

    /**
     * 清除用户权限缓存（修改用户角色后调用）
     */
    public void clearUserCache(Long userId) {
        redisTemplate.delete(PREFIX + userId);
    }

    /**
     * 清除角色相关用户的权限缓存（修改角色权限后调用）
     */
    public void clearRoleCache(Long roleId) {
        List<Long> userIds = permissionMapper.selectUserIdsByRoleId(roleId);
        if (userIds != null && !userIds.isEmpty()) {
            List<String> keys = userIds.stream()
                    .map(id -> PREFIX + id)
                    .collect(Collectors.toList());
            redisTemplate.delete(keys);
        }
    }
}
```

## 八、Spring Security 集成（@PreAuthorize 方案）

### 8.1 方案对比

| 对比项           | 自定义方案（ThreadLocal + AOP）            | Spring Security 方案                             |
| ---------------- | ------------------------------------------ | ------------------------------------------------ |
| **认证载体**     | ThreadLocal `UserContext`                  | `SecurityContextHolder`                          |
| **权限校验**     | 自定义 `@RequirePermission` + AOP          | `@PreAuthorize("hasAuthority('xxx')")`           |
| **用户加载**     | 手动查数据库写入 UserContext               | 实现 `UserDetailsService`，框架自动加载          |
| **Filter 写法**  | 继承任意 Filter，手动判断放行              | 继承 `OncePerRequestFilter`，写入 SecurityContext |
| **外部依赖**     | 无额外依赖                                 | `spring-boot-starter-security`                   |
| **灵活度**       | 高，完全自主控制                           | 中，需理解 Spring Security 拦截链                |
| **适合场景**     | 小型项目、已有认证体系                     | 中大型项目、需要标准化安全配置                   |

**实现 UserDetailsService，从数据库加载用户和权限：**

```java
package com.example.security;

import com.example.entity.User;
import com.example.exception.AuthenticationException;
import com.example.mapper.PermissionMapper;
import com.example.repository.UserRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.stereotype.Service;

import java.util.Set;

@Service
@RequiredArgsConstructor
public class UserDetailsServiceImpl implements UserDetailsService {

    private final UserRepository userRepository;
    private final PermissionMapper permissionMapper;

    @Override
    public UserDetails loadUserByUsername(String userId) {
        // userId 作为 username（登录后以 userId 为主键查询）
        User user = userRepository.findById(Long.parseLong(userId))
                .orElseThrow(() -> new AuthenticationException("用户不存在"));

        // 查询该用户的所有权限编码
        Set<String> permissions = permissionMapper.selectPermissionCodesByUserId(user.getId());

        return new LoginUser(user.getId(), user.getUsername(), user.getPassword(), permissions);
    }
}
```

### 8.4 JWT 认证 Filter

继承 `OncePerRequestFilter`，解析 Token 后将认证信息写入 `SecurityContextHolder`：

```java
package com.example.security;

import com.example.service.TokenBlacklistService;
import com.example.utils.JwtUtils;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;

@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtUtils jwtUtils;
    private final UserDetailsServiceImpl userDetailsService;
    private final TokenBlacklistService blacklistService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String token = extractToken(request);

        if (token != null && jwtUtils.validate(token) && !blacklistService.contains(token)) {
            String userId = String.valueOf(jwtUtils.getUserId(token));
            UserDetails userDetails = userDetailsService.loadUserByUsername(userId);

            // 将认证信息写入 SecurityContext
            // 第三个参数传 authorities，Spring Security 据此判断是否已认证
            UsernamePasswordAuthenticationToken authentication =
                    new UsernamePasswordAuthenticationToken(
                            userDetails, null, userDetails.getAuthorities()
                    );
            SecurityContextHolder.getContext().setAuthentication(authentication);
        }

        chain.doFilter(request, response);
        // 请求结束后清理，防止线程复用时数据污染
        SecurityContextHolder.clearContext();
    }

    private String extractToken(HttpServletRequest request) {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return header.substring(7);
        }
        return null;
    }
}
```

### 8.5 SecurityConfig 配置

```java
package com.example.config;

import com.example.security.JwtAuthenticationFilter;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
@EnableWebSecurity
@EnableMethodSecurity          // 开启 @PreAuthorize / @PostAuthorize 等方法级鉴权
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            // JWT 无状态，不创建 Session
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/login", "/auth/refresh", "/captcha/**").permitAll()
                .anyRequest().authenticated()
            )
            // 在 UsernamePasswordAuthenticationFilter 之前插入 JWT Filter
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

| 注解                    | 说明                                                           |

| `@EnableMethodSecurity` | 启用方法级鉴权，激活 `@PreAuthorize`、`@PostAuthorize` 等注解 |

### 8.6 @PreAuthorize 用法

开启 `@EnableMethodSecurity` 后，在 Controller 方法上直接标注所需权限：

```java
@RestController

@RequiredArgsConstructor

    }

    @PostMapping
    @PreAuthorize("hasAuthority('user:add')")
    public Result<Void> add(@RequestBody @Valid UserDTO dto) {
        userService.add(dto);
        return Result.success();
    }

    @DeleteMapping("/{id}")
    @PreAuthorize("hasAuthority('user:delete')")
    public Result<Void> delete(@PathVariable Long id) {
        userService.delete(id);
        return Result.success();
    }

    // 需要同时具备两个权限
    @PostMapping("/{id}/reset-password")

```

**常用 SpEL 表达式：**

| 表达式                                 | 含义                       |
| -------------------------------------- | -------------------------- |
| `hasAuthority('user:list')`            | 拥有指定权限               |
| `hasAnyAuthority('a', 'b')`           | 拥有任一权限               |
| `hasRole('ADMIN')`                     | 拥有角色（自动加 `ROLE_` 前缀） |
| `isAuthenticated()`                    | 已登录                     |
| `#userId == authentication.principal.userId` | 参数与当前用户匹配（数据级控制） |

### 8.7 完整认证链路

```
HTTP 请求
  → JwtAuthenticationFilter
      ├─ 解析 Token → 验签 → 查黑名单
      ├─ 调用 UserDetailsService.loadUserByUsername(userId)
      │     └─ 查 DB：user + permissions → 封装 LoginUser（含 authorities）
      └─ 写入 SecurityContextHolder
  → Spring Security 过滤器链（校验是否已认证）
  → DispatcherServlet → Controller
      └─ @PreAuthorize 触发
            └─ 从 SecurityContext 取 authorities → 判断是否包含所需权限
                  ├─ 通过 → 执行方法
                  └─ 不通过 → 抛出 AccessDeniedException → 返回 403
```

**与自定义方案的等价关系：**

| 自定义方案                  | Spring Security 方案             |
| --------------------------- | -------------------------------- |
| `UserContext.getUserId()`   | `((LoginUser) authentication.getPrincipal()).getUserId()` |
| `@RequirePermission("x:y")` | `@PreAuthorize("hasAuthority('x:y')")` |
| `PermissionAspect`（自定义 AOP） | Spring Security 框架内置 AOP     |
| `AuthInterceptor`           | `JwtAuthenticationFilter`        |

## 附录B：常见问题排查

| 问题                       | 可能原因                               | 解决方案                              |
| -------------------------- | -------------------------------------- | ------------------------------------- |
| **Token 无法解析**         | 密钥不一致                             | 确保生成和解析使用相同密钥            |
| **跨域请求返回 401**       | OPTIONS 预检被拦截                     | Filter/Interceptor 中放行 OPTIONS     |
| **ThreadLocal 内存泄漏**   | 请求结束未清理                         | afterCompletion 中调用 clear()        |
| **权限修改后不生效**       | 缓存未更新                             | 修改权限时清除相关缓存                |
| **BCrypt 结果每次不同**    | 正常现象（盐值随机）                   | 使用 matches() 验证，勿直接比较       |
| **Redis 连接超时**         | 配置或网络问题                         | 检查 Redis 配置和连接池设置           |
| **Token 过期时间不准**     | 服务器时间不同步                       | 使用 NTP 同步服务器时间               |
| **`@PreAuthorize` 不生效** | 配置类未加 `@EnableMethodSecurity`     | 在 `SecurityConfig` 上添加该注解      |
