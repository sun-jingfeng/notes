## 一、进程和线程

### 1. 基本概念

| 概念              | 说明                       | 类比     |
| --------------- | ------------------------ | ------ |
| **进程（Process）** | 操作系统中正在运行的一个程序           | 一个工厂   |
| **线程（Thread）**  | 进程中的一个执行单元，是 CPU 调度的最小单位 | 工厂里的工人 |

**关系**：

*   一个进程可以包含多个线程
*   一个进程至少有一个线程（主线程）
*   线程共享进程的资源（内存、文件等）

### 2. 图解

    ┌─────────────────────────────────────────────────────────────┐
    │                        操作系统                              │
    │  ┌─────────────────────┐    ┌─────────────────────┐         │
    │  │   进程1（QQ）        │    │   进程2（微信）      │         │
    │  │  ┌─────┐ ┌─────┐   │    │  ┌─────┐ ┌─────┐   │         │
    │  │  │线程1│ │线程2│   │    │  │线程1│ │线程2│   │         │
    │  │  └─────┘ └─────┘   │    │  └─────┘ └─────┘   │         │
    │  │  ┌─────┐           │    │  ┌─────┐           │         │
    │  │  │线程3│           │    │  │线程3│           │         │
    │  │  └─────┘           │    │  └─────┘           │         │
    │  └─────────────────────┘    └─────────────────────┘         │
    └─────────────────────────────────────────────────────────────┘

### 3. 并发与并行

| 概念                 | 说明                 | 图解               |
| ------------------ | ------------------ | ---------------- |
| **并发（Concurrent）** | 多个任务交替执行（CPU 快速切换） | 一个人同时做多件事（看起来同时） |
| **并行（Parallel）**   | 多个任务真正同时执行（多核 CPU） | 多个人同时做多件事（真正同时）  |

    并发（单核 CPU）：
    时间 →
    CPU:  [任务A][任务B][任务A][任务B][任务A]...
          交替执行，看起来像同时

    并行（多核 CPU）：
    时间 →
    CPU1: [任务A][任务A][任务A]...
    CPU2: [任务B][任务B][任务B]...
          真正同时执行

## 二、Java 开启线程的方式

### 1. 方式一：继承 Thread 类

```java
// 1. 定义类继承 Thread
public class MyThread extends Thread {
    
    // 2. 重写 run() 方法
    @Override
    public void run() {
        for (int i = 0; i < 100; i++) {
            System.out.println(getName() + "：" + i);
        }
    }
}

// 3. 创建对象，调用 start() 启动线程
public class Demo {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();
        
        t1.setName("线程1");
        t2.setName("线程2");
        
        t1.start();  // ✅ 启动线程
        t2.start();
        
        // t1.run();  // ❌ 错误！直接调用 run() 不会开启新线程
    }
}
```

**注意**：

*   调用 `start()` 方法启动线程，不是 `run()`
*   `run()` 中的代码才是线程要执行的任务

***

### 2. 方式二：实现 Runnable 接口（推荐）

```java
// 1. 定义类实现 Runnable 接口
public class MyRunnable implements Runnable {
    
    // 2. 重写 run() 方法
    @Override
    public void run() {
        for (int i = 0; i < 100; i++) {
            // Runnable 没有 getName()，需要通过 Thread.currentThread()
            System.out.println(Thread.currentThread().getName() + "：" + i);
        }
    }
}

// 3. 创建 Runnable 对象，传给 Thread
public class Demo {
    public static void main(String[] args) {
        MyRunnable mr = new MyRunnable();
        
        Thread t1 = new Thread(mr, "线程1");
        Thread t2 = new Thread(mr, "线程2");
        
        t1.start();
        t2.start();
    }
}
```

**Lambda 简化写法**：

```java
// 匿名内部类
new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("线程执行");
    }
}).start();

// Lambda 表达式（推荐）
new Thread(() -> {
    System.out.println("线程执行");
}).start();
```

***

### 3. 方式三：实现 Callable 接口（可以获取返回值）

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

// 1. 定义类实现 Callable 接口，指定返回值类型
public class MyCallable implements Callable<Integer> {
    
    // 2. 重写 call() 方法，可以有返回值
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        return sum;
    }
}

// 3. 使用 FutureTask 包装，获取返回值
public class Demo {
    public static void main(String[] args) throws Exception {
        MyCallable mc = new MyCallable();
        FutureTask<Integer> ft = new FutureTask<>(mc);
        
        Thread t = new Thread(ft);
        t.start();
        
        // 获取返回值（会阻塞，等待线程执行完毕）
        Integer result = ft.get();
        System.out.println("结果：" + result);  // 结果：5050
    }
}
```

***

### 4. 三种方式对比

| 方式              | 优点                          | 缺点         |
| --------------- | --------------------------- | ---------- |
| **继承 Thread**   | 编写简单，可直接使用 `this.getName()` | 单继承限制，扩展性差 |
| **实现 Runnable** | 扩展性强，可以继承其他类；适合多线程共享资源      | 无返回值       |
| **实现 Callable** | 可以有返回值，可以抛出异常               | 编写稍复杂      |

**推荐**：优先使用 **Runnable**（无返回值）或 **Callable**（有返回值）

## 三、线程常用方法与生命周期

### 1. 常用方法一览

| 方法                               | 说明                   |
| -------------------------------- | -------------------- |
| `void start()`                   | 启动线程                 |
| `void run()`                     | 线程要执行的任务             |
| `String getName()`               | 获取线程名称               |
| `void setName(String name)`      | 设置线程名称               |
| `static Thread currentThread()`  | 获取当前线程对象             |
| `static void sleep(long millis)` | 让当前线程休眠指定毫秒          |
| `void join()`                    | 等待该线程执行完毕            |
| `void join(long millis)`         | 等待该线程执行，最多等待指定毫秒     |
| `void setDaemon(boolean on)`     | 设置为守护线程              |
| `int getPriority()`              | 获取线程优先级              |
| `void setPriority(int priority)` | 设置线程优先级（1-10）        |
| `static void yield()`            | 让出 CPU 执行权           |
| `void interrupt()`               | 中断线程                 |
| `boolean isInterrupted()`        | 判断线程是否被中断            |
| `static boolean interrupted()`   | 判断当前线程是否被中断（会清除中断标志） |

***

### 2. 方法详解

#### sleep() - 线程休眠

```java
public class Demo {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("开始");
        
        Thread.sleep(3000);  // 休眠 3 秒
        
        System.out.println("结束");
    }
}
```

***

#### join() - 等待线程结束

```java
public class Demo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("子线程：" + i);
            }
        });
        
        t.start();
        t.join();  // 主线程等待 t 执行完毕
        
        System.out.println("主线程继续执行");
    }
}

// 输出：
// 子线程：0
// 子线程：1
// 子线程：2
// 子线程：3
// 子线程：4
// 主线程继续执行
```

***

#### setDaemon() - 守护线程

```java
public class Demo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("守护线程运行中...");
            }
        });
        
        t.setDaemon(true);  // 设置为守护线程（必须在 start 之前）
        t.start();
        
        // 主线程结束后，守护线程也会结束
        System.out.println("主线程结束");
    }
}
```

**守护线程特点**：

*   当所有非守护线程结束时，守护线程自动结束
*   典型应用：垃圾回收线程

***

#### setPriority() - 线程优先级

```java
public class Demo {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                System.out.println("t1：" + i);
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                System.out.println("t2：" + i);
            }
        });
        
        // 优先级范围：1-10，默认是 5
        t1.setPriority(Thread.MIN_PRIORITY);  // 1
        t2.setPriority(Thread.MAX_PRIORITY);  // 10
        
        t1.start();
        t2.start();
    }
}
```

**注意**：优先级高只是表示**抢到 CPU 的概率更大**，不保证一定先执行

***

#### interrupt() - 线程中断

```java
public class Demo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                System.out.println("线程运行中...");
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    // sleep 被中断会抛出异常，并清除中断标志
                    System.out.println("线程被中断，退出循环");
                    break;  // 或者重新设置中断标志：Thread.currentThread().interrupt();
                }
            }
            System.out.println("线程结束");
        });
        
        t.start();
        
        Thread.sleep(3000);  // 主线程等待 3 秒
        t.interrupt();       // 中断线程
        System.out.println("发送中断信号");
    }
}
```

**中断机制说明**：

| 方法                     | 说明                   |
| ---------------------- | -------------------- |
| `interrupt()`          | 设置中断标志（不会强制停止线程）     |
| `isInterrupted()`      | 判断是否被中断（不清除中断标志）     |
| `Thread.interrupted()` | 判断当前线程是否被中断（会清除中断标志） |

> 💡 **注意**：`interrupt()` 只是设置中断标志，线程需要自己检查并响应中断。如果线程正在 `sleep()`、`wait()`、`join()` 等阻塞状态，会抛出 `InterruptedException` 并清除中断标志。
>
> 实际开发里，捕获 `InterruptedException` 后通常有两种处理方式：
>
> 1. 当前方法决定结束任务：记录日志后 `break` / `return`
> 2. 当前方法不吞掉中断语义：重新设置中断标志 `Thread.currentThread().interrupt()`，让上层感知中断

### 3. 线程生命周期（6 种状态）

Java 线程有 **6 种状态**，定义在 `Thread.State` 枚举中：

                                         ┌──────────────────┐
                                         │     BLOCKED      │
                                         │   （阻塞-等待锁）  │
                                         └────────┬─────────┘
                                                  ↑ 等待锁
                                                  │
    ┌─────────┐     ┌───────────────┐     ┌───────┴───────┐     ┌─────────────┐
    │   NEW   │────→│   RUNNABLE    │←───→│   获取到锁    │────→│ TERMINATED  │
    │  新建   │     │  就绪/运行中   │     │               │     │    终止     │
    └─────────┘     └───────┬───────┘     └───────────────┘     └─────────────┘
      new Thread()          │ wait()/join()/sleep()
           ↓ start()        ↓
                      ┌─────────────────┐
                      │    WAITING      │  无限等待
                      │  （等待-无超时）  │  wait()、join()
                      └─────────────────┘
                      ┌─────────────────┐
                      │  TIMED_WAITING  │  有限等待
                      │  （等待-有超时）  │  sleep(n)、wait(n)、join(n)
                      └─────────────────┘

| 状态                 | 说明           | 触发条件                                   |
| ------------------ | ------------ | -------------------------------------- |
| **NEW**            | 新建状态         | `new Thread()` 后，未调用 `start()`         |
| **RUNNABLE**       | 可运行状态（就绪+运行） | 调用 `start()` 后                         |
| **BLOCKED**        | 阻塞状态         | 等待获取 synchronized 锁                    |
| **WAITING**        | 无限等待状态       | `wait()`、`join()`、`LockSupport.park()` |
| **TIMED\_WAITING** | 有限等待状态       | `sleep(n)`、`wait(n)`、`join(n)`         |
| **TERMINATED**     | 终止状态         | 线程执行完毕或异常终止                            |

```java
// 获取线程状态
Thread t = new Thread(() -> {});
System.out.println(t.getState());  // NEW

t.start();
System.out.println(t.getState());  // RUNNABLE

// ... 线程执行完毕
System.out.println(t.getState());  // TERMINATED
```

> 💡 **注意**：Java 线程状态枚举里没有单独的 **RUNNING** 状态，运行中的线程和就绪中的线程都统一记作 `RUNNABLE`。

## 四、线程安全和同步

### 1. 线程安全问题

当多个线程**同时访问共享资源**时，可能出现数据不一致的问题。

#### 问题演示：卖票

```java
public class Ticket implements Runnable {
    private int ticket = 100;  // 共享资源
    
    @Override
    public void run() {
        while (true) {
            if (ticket > 0) {
                try {
                    Thread.sleep(10);  // 模拟出票时间
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() 
                    + "卖出第" + ticket + "张票");
                ticket--;
            } else {
                break;
            }
        }
    }
}

// 测试
public class Demo {
    public static void main(String[] args) {
        Ticket t = new Ticket();
        
        new Thread(t, "窗口1").start();
        new Thread(t, "窗口2").start();
        new Thread(t, "窗口3").start();
    }
}

// 可能出现的问题：
// 窗口1卖出第100张票
// 窗口2卖出第100张票  ← 重复卖票
// 窗口3卖出第-1张票   ← 卖出负数票
```

***

### 2. 解决方案一：synchronized 同步代码块

```java
public class Ticket implements Runnable {
    private int ticket = 100;
    private Object lock = new Object();  // 锁对象
    
    @Override
    public void run() {
        while (true) {
            // synchronized (锁对象) { 需要同步的代码 }
            synchronized (lock) {
                if (ticket > 0) {
                    try {
                        Thread.sleep(10);
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                    System.out.println(Thread.currentThread().getName() 
                        + "卖出第" + ticket + "张票");
                    ticket--;
                } else {
                    break;
                }
            }
        }
    }
}
```

**锁对象的选择**：

*   可以是任意对象，但必须是**同一个对象**
*   常用 `this`（当前对象）或 `类名.class`（类的字节码对象）

```java
// 使用 this 作为锁
synchronized (this) {
    // ...
}

// 使用类的字节码对象作为锁（静态方法中常用）
synchronized (Ticket.class) {
    // ...
}
```

***

### 3. 解决方案二：synchronized 同步方法

```java
public class Ticket implements Runnable {
    private int ticket = 100;
    
    @Override
    public void run() {
        while (true) {
            if (!sellTicket()) {
                break;
            }
        }
    }
    
    // 同步方法：锁对象是 this
    public synchronized boolean sellTicket() {
        if (ticket > 0) {
            try {
                Thread.sleep(10);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println(Thread.currentThread().getName() 
                + "卖出第" + ticket + "张票");
            ticket--;
            return true;
        }
        return false;
    }
}
```

**同步方法的锁**：

*   非静态同步方法：锁是 `this`
*   静态同步方法：锁是 `类名.class`

***

### 4. 解决方案三：Lock 锁

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class Ticket implements Runnable {
    private int ticket = 100;
    private Lock lock = new ReentrantLock();  // 创建锁对象
    
    @Override
    public void run() {
        while (true) {
            lock.lock();  // 加锁
            try {
                if (ticket > 0) {
                    Thread.sleep(10);
                    System.out.println(Thread.currentThread().getName() 
                        + "卖出第" + ticket + "张票");
                    ticket--;
                } else {
                    break;
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock.unlock();  // 释放锁（必须在 finally 中）
            }
        }
    }
}
```

***

### 5. synchronized vs Lock

| 对比项        | synchronized      | Lock                   |
| ---------- | ----------------- | ---------------------- |
| **类型**     | 关键字               | 接口                     |
| **加锁/释放锁** | 自动                | 手动（lock/unlock）        |
| **灵活性**    | 较低                | 较高                     |
| **可中断**    | 不可中断              | 可中断（lockInterruptibly） |
| **公平锁**    | 非公平               | 可以设置公平锁                |
| **条件变量**   | 只有一个（wait/notify） | 可以有多个 Condition        |
| **性能**     | JDK 1.6 后优化，差异不大  | 差异不大                   |

***

### 6. 死锁

**死锁**：两个或多个线程互相持有对方需要的锁，导致所有线程都无法继续执行。

```java
public class DeadLockDemo {
    private static Object lockA = new Object();
    private static Object lockB = new Object();
    
    public static void main(String[] args) {
        // 线程1：先获取 lockA，再获取 lockB
        new Thread(() -> {
            synchronized (lockA) {
                System.out.println("线程1获取了lockA");
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {}
                
                synchronized (lockB) {
                    System.out.println("线程1获取了lockB");
                }
            }
        }).start();
        
        // 线程2：先获取 lockB，再获取 lockA
        new Thread(() -> {
            synchronized (lockB) {
                System.out.println("线程2获取了lockB");
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {}
                
                synchronized (lockA) {
                    System.out.println("线程2获取了lockA");
                }
            }
        }).start();
    }
}

// 输出：
// 线程1获取了lockA
// 线程2获取了lockB
// （程序卡死，发生死锁）
```

**死锁产生的四个条件**：

1.  **互斥条件**：资源只能被一个线程持有
2.  **持有并等待**：持有资源的同时等待其他资源
3.  **不可剥夺**：资源只能由持有者主动释放
4.  **循环等待**：线程之间形成循环等待链

**避免死锁的方法**：

*   按相同顺序获取锁
*   使用 `tryLock()` 设置超时
*   使用 `Lock.lockInterruptibly()` 响应中断

### 7. volatile 关键字

**作用**：保证变量的**可见性**，禁止**指令重排序**。

#### 可见性问题

```java
public class VolatileDemo {
    private static boolean flag = true;  // 不加 volatile
    
    public static void main(String[] args) throws InterruptedException {
        new Thread(() -> {
            while (flag) {
                // 空循环
            }
            System.out.println("线程结束");
        }).start();
        
        Thread.sleep(1000);
        flag = false;  // 主线程修改 flag
        System.out.println("flag 已设置为 false");
        
        // 问题：子线程可能永远不会结束！
        // 原因：子线程读取的是自己工作内存中的 flag 副本
    }
}
```

#### 使用 volatile 解决

```java
private static volatile boolean flag = true;  // 加上 volatile
// 修改后，子线程能立即看到 flag 的变化
```

**volatile vs synchronized**：

| 对比项      | volatile | synchronized |
| -------- | -------- | ------------ |
| **可见性**  | ✅ 保证     | ✅ 保证         |
| **原子性**  | ❌ 不保证    | ✅ 保证         |
| **性能**   | 较高       | 较低           |
| **适用场景** | 一写多读     | 多写多读         |

> ⚠️ **注意**：`volatile` 不保证原子性！`count++` 这样的操作仍然需要同步。

## 五、线程通信

### 1. wait/notify 机制

| 方法                   | 说明           |
| -------------------- | ------------ |
| `wait()`             | 让当前线程等待，并释放锁 |
| `wait(long timeout)` | 等待指定毫秒后自动唤醒  |
| `notify()`           | 唤醒一个等待的线程    |
| `notifyAll()`        | 唤醒所有等待的线程    |

**注意**：这些方法必须在 **synchronized** 块中调用，且调用对象必须是**锁对象**。

***

### 2. 生产者-消费者模式

```java
public class ProducerConsumerDemo {
    public static void main(String[] args) {
        DataBox box = new DataBox();
        
        // 生产者
        new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                box.put(i);
            }
        }, "生产者").start();
        
        // 消费者
        new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                box.take();
            }
        }, "消费者").start();
    }
}

class DataBox {
    private int data;
    private boolean hasData = false;  // 是否有数据
    
    // 生产数据
    public synchronized void put(int data) {
        // 有数据则等待
        while (hasData) {
            try {
                wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        this.data = data;
        hasData = true;
        System.out.println(Thread.currentThread().getName() + " 生产了：" + data);
        
        notifyAll();  // 唤醒等待线程，多个生产者/消费者场景更稳妥
    }
    
    // 消费数据
    public synchronized void take() {
        // 没有数据则等待
        while (!hasData) {
            try {
                wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        System.out.println(Thread.currentThread().getName() + " 消费了：" + data);
        hasData = false;
        
        notifyAll();  // 唤醒等待线程，避免错误唤醒后无人继续执行
    }
}
```

**输出**：

    生产者 生产了：1
    消费者 消费了：1
    生产者 生产了：2
    消费者 消费了：2
    ...

> 💡 **为什么用 `while` 而不是 `if`？**
> 防止虚假唤醒（spurious wakeup），线程可能在没有被 `notify` 的情况下醒来，需要重新检查条件。

> 💡 **补充**：只有单生产者 + 单消费者时，`notify()` 往往也能工作；一旦扩展到多个生产者或多个消费者，`notifyAll()` 更稳妥，否则可能唤醒到同类线程，导致所有线程重新等待。

## 六、线程池

### 1. 为什么需要线程池

**问题**：频繁创建和销毁线程，开销大，效率低。

**解决**：预先创建一组线程，放入"池"中，需要时取出使用，用完归还。

    ┌────────────────────────────────────────────────────┐
    │                      线程池                         │
    │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐           │
    │  │线程1 │  │线程2 │  │线程3 │  │线程4 │ ...       │
    │  └──────┘  └──────┘  └──────┘  └──────┘           │
    │                                                    │
    │              任务队列：[任务A] [任务B] [任务C]       │
    └────────────────────────────────────────────────────┘

    工作流程：
    1. 提交任务到任务队列
    2. 线程池中的线程从队列取任务执行
    3. 执行完毕后，线程归还到池中，等待下一个任务

### 2. 线程池的好处

| 好处         | 说明               |
| ---------- | ---------------- |
| **降低资源消耗** | 复用线程，减少创建和销毁的开销  |
| **提高响应速度** | 任务到达时，无需等待线程创建   |
| **便于管理**   | 统一管理线程，可以控制最大并发数 |

***

### 3. Executors 创建线程池（简单方式）

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Demo {
    public static void main(String[] args) {
        // 1. 创建固定大小的线程池
        ExecutorService pool = Executors.newFixedThreadPool(3);
        
        // 2. 提交任务
        pool.submit(() -> {
            System.out.println(Thread.currentThread().getName() + "执行任务1");
        });
        
        pool.submit(() -> {
            System.out.println(Thread.currentThread().getName() + "执行任务2");
        });
        
        pool.submit(() -> {
            System.out.println(Thread.currentThread().getName() + "执行任务3");
        });
        
        // 3. 关闭线程池
        pool.shutdown();
    }
}
```

### 4. Executors 提供的四种线程池

| 方法                          | 说明      | 特点           |
| --------------------------- | ------- | ------------ |
| `newFixedThreadPool(n)`     | 固定大小线程池 | 固定 n 个线程     |
| `newCachedThreadPool()`     | 缓存线程池   | 线程数量不固定，按需创建 |
| `newSingleThreadExecutor()` | 单线程线程池  | 只有 1 个线程     |
| `newScheduledThreadPool(n)` | 定时任务线程池 | 可以执行定时任务     |

```java

ExecutorService pool1 = Executors.newFixedThreadPool(5);

// 缓存线程池（线程数量可变）

// 单线程线程池
ExecutorService pool3 = Executors.newSingleThreadExecutor();

// 定时任务线程池
ScheduledExecutorService pool4 = Executors.newScheduledThreadPool(3);
pool4.schedule(() -> {
    System.out.println("延迟 3 秒执行");
}, 3, TimeUnit.SECONDS);
```

### 5. submit() vs execute()

| 方法                          | 返回值    | 异常处理         | 参数类型                |
| --------------------------- | ------ | ------------ | ------------------- |
| `execute(Runnable)`         | 无      | 直接抛出         | 只能是 Runnable        |
| `submit(Runnable/Callable)` | Future | 封装在 Future 中 | Runnable 或 Callable |

```java
// execute：无返回值
pool.execute(() -> {
    System.out.println("execute 执行");
});

// submit：有返回值
Future<String> future = pool.submit(() -> {
    return "submit 执行结果";
});
String result = future.get();  // 获取返回值
```

**结论**：

*   只关心执行，不关心结果，用 `execute()`
*   需要获取任务结果、异常或完成状态，用 `submit()`

### 6. 线程池任务返回值怎么拿

无论是 `ExecutorService` 还是 `ThreadPoolExecutor`，**拿返回值的核心都是：提交 `Callable`，接收 `Future`，再通过 `get()` 获取结果**。

```java
import java.util.concurrent.*;

public class Demo {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);

        Future<Integer> future = pool.submit(() -> {
            int sum = 0;
            for (int i = 1; i <= 100; i++) {
                sum += i;
            }
            return sum;
        });

        Integer result = future.get();  // 阻塞等待执行结果
        System.out.println("结果：" + result);

        pool.shutdown();
    }
}
```

| 方法 | 说明 |
| --- | --- |
| `submit(Callable<T>)` | 提交有返回值任务 |
| `Future<T>` | 代表异步计算结果 |
| `future.get()` | 获取结果，未完成时会阻塞 |
| `future.get(timeout, unit)` | 最多等待指定时间，避免无限阻塞 |

***

### 7. shutdown() vs shutdownNow()

| 方法                                | 说明                          |
| --------------------------------- | --------------------------- |
| `shutdown()`                      | 平缓关闭：不接受新任务，等待已提交任务执行完毕     |
| `shutdownNow()`                   | 立即关闭：尝试中断正在执行的任务，返回未执行的任务列表 |
| `isShutdown()`                    | 判断是否已调用 shutdown            |
| `isTerminated()`                  | 判断所有任务是否都已完成                |
| `awaitTermination(timeout, unit)` | 等待线程池终止，超时返回 false          |

```java
pool.shutdown();  // 平缓关闭

// 等待线程池完全终止，最多等 60 秒
if (pool.awaitTermination(60, TimeUnit.SECONDS)) {
    System.out.println("线程池已完全终止");
} else {
    System.out.println("超时，强制关闭");
    pool.shutdownNow();
}
```

### 8. JDK 原生自定义线程池（推荐）

#### 为什么需要自定义线程池

`Executors` 创建的线程池存在风险：

*   `newFixedThreadPool` 和 `newSingleThreadExecutor`：任务队列无限大，可能导致 OOM
*   `newCachedThreadPool`：线程数量无限大，可能导致 OOM

**阿里巴巴开发规范**：**禁止使用 Executors 创建线程池，推荐使用 ThreadPoolExecutor**

***

#### ThreadPoolExecutor 七大参数

```java
public ThreadPoolExecutor(
    int corePoolSize,           // 核心线程数
    int maximumPoolSize,        // 最大线程数
    long keepAliveTime,         // 空闲线程存活时间
    TimeUnit unit,              // 时间单位
    BlockingQueue<Runnable> workQueue,  // 任务队列

)
```

| 参数                  | 说明                   |
| ------------------- | -------------------- |
| **corePoolSize**    | 核心线程数（一直存活的线程）       |
| **maximumPoolSize** | 最大线程数（核心 + 临时线程）     |
| **keepAliveTime**   | 临时线程空闲后的存活时间         |
| **unit**            | 存活时间的单位（秒、毫秒等）       |
| **workQueue**       | 任务队列，存放等待执行的任务       |
| **threadFactory**   | 线程工厂，用于创建线程          |
| **handler**         | 拒绝策略，队列满且线程满时如何处理新任务 |

#### 工作流程图解

    提交任务
        │
        ↓
    ┌─────────────────────────────────────────────────────────────────┐
    │                        线程池                                    │
    │                                                                  │
    │  ┌─────────────────────┐    ┌─────────────────────┐             │
    │  │    核心线程区        │    │    任务队列          │             │
    │  │  ┌────┐ ┌────┐     │    │  [任务] [任务] ...   │             │
    │  │  │线程│ │线程│ ... │    │                      │             │
    │  │  └────┘ └────┘     │    └─────────────────────┘             │
    │  │  (corePoolSize)    │              │                          │
    │  └─────────────────────┘              │                          │
    │                                       ↓                          │
    │  ┌─────────────────────┐        队列满了？                       │
    │  │    临时线程区        │        ┌──────┐                        │
    │  │  ┌────┐ ┌────┐     │←───────│ 创建 │ 临时线程                │
    │  │  │线程│ │线程│ ... │        └──────┘                        │
    │  │  └────┘ └────┘     │                                         │
    │  │  (max - core)      │              │                          │
    │  └─────────────────────┘              ↓                          │
    │                                  临时线程也满了？                  │
    │                                  执行拒绝策略                      │
    └─────────────────────────────────────────────────────────────────┘

**任务处理流程**：

1.  提交任务，优先使用核心线程执行
2.  核心线程满了 → 放入任务队列等待
3.  任务队列满了 → 创建临时线程执行
4.  达到最大线程数且队列满 → 执行拒绝策略

#### 自定义线程池示例

```java
import java.util.concurrent.*;

public class Demo {
    public static void main(String[] args) {
        // 创建自定义线程池
        ThreadPoolExecutor pool = new ThreadPoolExecutor(
            2,                                  // 核心线程数
            5,                                  // 最大线程数
            60,                                 // 空闲线程存活时间
            TimeUnit.SECONDS,                   // 时间单位
            new ArrayBlockingQueue<>(10),       // 任务队列（容量 10）
            Executors.defaultThreadFactory(),   // 默认线程工厂
            new ThreadPoolExecutor.AbortPolicy()// 拒绝策略
        );
        
        try {
            // submit(Callable) 可以拿到 Future 结果
            Future<Integer> future = pool.submit(() -> {
                int sum = 0;
                for (int i = 1; i <= 100; i++) {
                    sum += i;
                }
                return sum;
            });

            Integer result = future.get();
            System.out.println("计算结果：" + result);  // 5050
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } catch (ExecutionException e) {
            e.printStackTrace();
        } finally {
            // 关闭线程池
            pool.shutdown();
        }
    }
}
```

**说明**：

*   `ThreadPoolExecutor` 是 `ExecutorService` 的实现类，因此同样通过 `submit()` + `Future.get()` 获取返回值
*   如果只写 `execute()`，那就只有“异步执行”，没有直接返回结果

***

#### 四种拒绝策略

| 拒绝策略                  | 说明                                        |
| --------------------- | ----------------------------------------- |
| `AbortPolicy`         | **默认策略**，抛出 RejectedExecutionException 异常 |
| `CallerRunsPolicy`    | 由提交任务的线程执行该任务                             |
| `DiscardPolicy`       | 直接丢弃任务，不抛异常                               |
| `DiscardOldestPolicy` | 丢弃队列中最老的任务，然后重新提交                         |

```java
// 默认：抛异常
new ThreadPoolExecutor.AbortPolicy()

// 由调用者线程执行
new ThreadPoolExecutor.CallerRunsPolicy()

// 直接丢弃
new ThreadPoolExecutor.DiscardPolicy()

// 丢弃最老的任务
new ThreadPoolExecutor.DiscardOldestPolicy()
```

#### 常用任务队列

| 队列                      | 说明                               |
| ----------------------- | -------------------------------- |
| `ArrayBlockingQueue`    | 有界队列，基于数组，需指定容量                  |
| `LinkedBlockingQueue`   | 无界队列（默认 Integer.MAX\_VALUE），基于链表 |
| `SynchronousQueue`      | 不存储任务，直接交给线程执行                   |
| `PriorityBlockingQueue` | 优先级队列，按优先级执行                     |

```java

// 无界队列（慎用，可能 OOM）
new LinkedBlockingQueue<>()

// 同步队列（任务直接交给线程）
new SynchronousQueue<>()
```

#### 线程池大小设置建议

核心思路：根据**任务类型**（CPU 密集型 / IO 密集型）决定线程数，避免线程过多导致上下文切换、或过少导致 CPU/IO 闲置。

| 任务类型         | 瓶颈       | 线程数估算                     | 原因简述 |
| ---------------- | ---------- | ------------------------------ | -------- |
| **CPU 密集型**   | CPU 算力   | 核数 N，或 N+1                 | 线程数超过核数会加剧上下文切换；N+1 可掩盖部分内存延迟 |
| **IO 密集型**     | 磁盘/网络  | N × (1 + IO/CPU)，或先取 2N～4N | 线程在等 IO 时不占 CPU，多线程可重叠等待与计算 |

**CPU 密集型**：任务绝大部分时间在运算，很少等待 IO。线程数 ≈ 核数即可；略多 1 个（N+1）有时能在一个线程等内存时让另一线程用上该核。

**IO 密集型**：任务经常等待磁盘、网络、数据库等。单任务若「CPU 计算时间 = C、IO 等待时间 = W」，则 **线程数 ≈ N × (1 + W/C) = N × (1 + IO/CPU)**。IO 等待越多，可重叠的任务越多，线程数可适当大于 N。若难以估算 W/C，可先取 **2N～4N**，再结合压测与监控调优。

> 💡 **瓶颈理解**：CPU 密集型压力在 CPU，磁盘相对空闲；IO 密集型压力在磁盘（或网络）。当磁盘/网络已被占满时，再增加线程只会排队等 IO，CPU 会闲置，此时应优化 IO 或扩容磁盘/网络，而非继续加线程。

```java
// 获取 CPU 核数
int cpuCores = Runtime.getRuntime().availableProcessors();

// CPU 密集型：N 或 N+1
int cpuIntensiveThreads = cpuCores + 1;

// IO 密集型：2N～4N，或按公式 N×(1+IO/CPU) 估算
int ioIntensiveThreads = cpuCores * 2;  // 保守起点，可调大
```

### 9. Spring 项目中的线程池

#### 1. `ThreadPoolTaskExecutor` 是什么

**`ThreadPoolTaskExecutor`** 是 Spring Framework 提供的线程池封装类，用于更方便地与 Spring 容器、Bean 管理和异步机制集成。

| 对比项 | JDK 原生线程池 | Spring 线程池封装 |
| --- | --- | --- |
| **典型类** | `ExecutorService`、`ThreadPoolExecutor` | `ThreadPoolTaskExecutor` |
| **所属体系** | JDK 并发包 | Spring Framework |
| **是否依赖 Spring** | ❌ 不依赖 | ✅ 依赖 |
| **适用场景** | 纯 Java 项目、底层并发控制 | Spring / Spring Boot 项目 |

> 💡 **注意**：`ThreadPoolTaskExecutor` 是 Spring 提供的公开 API，但它不会因为“是 Spring 的类”就自动成为 Bean。通常仍需要开发者显式声明，再由 Spring 注册进容器。

***

#### 2. Bean 的定义、注册与使用

在线程池进入 Spring 容器时，最容易混淆的是三个动作：

| 动作 | 含义 | 谁来做 |
| --- | --- | --- |
| **定义 Bean** | 声明容器里要有这样一个对象 | 开发者 |
| **注册 Bean** | 把对象真正放进 Spring 容器 | Spring |
| **使用 Bean** | 从容器里取出对象并在业务里使用 | 开发者 + Spring 注入机制 |

最常见的写法是通过 `@Bean` 手动声明线程池：

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

@Configuration
public class ExecutorConfig {

    @Bean("taskExecutor")
    public ThreadPoolTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("task-");
        executor.initialize();
        return executor;
    }
}
```

这段代码里发生了三件事：

1. 开发者通过 `@Bean("taskExecutor")` **定义** 了一个名字叫 `taskExecutor` 的 Bean。
2. Spring 启动时扫描到配置类，执行 `taskExecutor()` 方法，把返回对象**注册**到容器。
3. 后续业务类通过注入方式**使用**这个线程池 Bean。

***

#### 3. 多个线程池 Bean 的情况

如果项目里有多个不同用途的线程池，通常会定义多个不同名字的 Bean：

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

@Configuration
public class ExecutorConfig {

    @Bean("computeExecutor")
    public ThreadPoolTaskExecutor computeExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.initialize();
        return executor;
    }

    @Bean("ioExecutor")
    public ThreadPoolTaskExecutor ioExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(16);
        executor.initialize();
        return executor;
    }
}
```

| Bean 名称 | 常见用途 |
| --- | --- |
| **`computeExecutor`** | CPU 密集型计算任务 |
| **`ioExecutor`** | IO 密集型任务、消息发送、远程调用 |

这些线程池 Bean 不是 Spring 凭空创建出来的，而是开发者声明多个 `@Bean` 后，由 Spring 统一注册进容器。

***

#### 4. `@Qualifier` 的作用

**`@Qualifier`** 用于在同一种类型有多个 Bean 时，指定到底注入哪一个。

```java
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import org.springframework.stereotype.Service;

@Service
public class TaskService {

    private final ThreadPoolTaskExecutor taskExecutor;

    public TaskService(@Qualifier("taskExecutor") ThreadPoolTaskExecutor taskExecutor) {
        this.taskExecutor = taskExecutor;
    }

    public void runTask() {
        taskExecutor.execute(() -> {
            System.out.println("执行异步任务");
        });
    }

    public Future<Integer> calculateAsync() {
        return taskExecutor.submit(() -> {
            int sum = 0;
            for (int i = 1; i <= 100; i++) {
                sum += i;
            }
            return sum;
        });
    }
}
```

| 位置 | 作用 |
| --- | --- |
| **`@Qualifier("taskExecutor")`** | 指定注入名字叫 `taskExecutor` 的线程池 Bean |
| **`taskExecutor.execute(...)`** | 手动把任务提交给线程池异步执行 |
| **`taskExecutor.submit(...)`** | 手动提交可返回结果的任务，得到 `Future` |

如果容器里只有一个 `ThreadPoolTaskExecutor`，通常可以不写 `@Qualifier`；如果有多个，最好显式指定。

如果要获取结果，调用方再通过 `future.get()` 拿返回值：

```java
Future<Integer> future = taskService.calculateAsync();
Integer result = future.get();
System.out.println("结果：" + result);
```

***

#### 5. `@Async` 的作用

**`@Async`** 不负责创建线程池，也不负责注册线程池，它负责的是：**把某个方法声明为异步执行方法**。

```java
import org.springframework.scheduling.annotation.Async;
import java.util.concurrent.CompletableFuture;
import org.springframework.stereotype.Service;

@Service
public class NotifyService {

    @Async("taskExecutor")
    public CompletableFuture<String> sendMessage() {
        System.out.println("异步发送消息");
        return CompletableFuture.completedFuture("发送成功");
    }
}
```

这里的 `"taskExecutor"` 表示：调用 `sendMessage()` 时，使用名字叫 `taskExecutor` 的线程池 Bean。

调用方可以这样接收返回值：

```java
CompletableFuture<String> future = notifyService.sendMessage();
String result = future.get();
System.out.println(result);
```

要让 `@Async` 生效，还需要开启异步能力：

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableAsync;

@EnableAsync
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

**`@Async` 使用限制**：

*   只能作用在 Spring 容器管理的 Bean 上
*   方法调用必须经过 Spring 代理，`this.sendMessage()` 这类同类内部调用不会生效
*   一般用于 `public` 方法，便于代理拦截
*   返回 `void` 时，异常不会直接抛回调用方；返回 `Future` / `CompletableFuture` 时，可以通过 `get()` / `join()` 感知异常

***

#### 6. 手动 `execute()` 和 `@Async` 的区别

| 写法 | 特点 |
| --- | --- |
| **手动 `execute()` / `submit()`** | 自己明确提交任务，控制更直接 |
| **`@Async`** | 只声明方法异步，Spring 自动调线程池 |

如果代码已经手动调用线程池：

```java
taskExecutor.execute(() -> {
    System.out.println("执行异步任务");
});
```

这时异步逻辑已经显式写出来了，因此不需要再额外加 `@Async`。

***

#### 7. `ThreadPoolTaskExecutor` 和 `ThreadPoolExecutor` 选哪个

二者不是“谁替代谁”的关系，而是“场景不同”：

| 场景 | 更常见选择 |
| --- | --- |
| **Spring / Spring Boot 项目** | `ThreadPoolTaskExecutor` |
| **纯 Java 项目** | `ThreadPoolExecutor` |
| **需要特别底层、细粒度控制** | `ThreadPoolExecutor` |
| **需要与 `@Async`、Bean 管理联动** | `ThreadPoolTaskExecutor` |

| 对比项 | `ThreadPoolExecutor` | `ThreadPoolTaskExecutor` |
| --- | --- | --- |
| **来源** | JDK 原生 | Spring 封装 |
| **依赖 Spring** | ❌ 不需要 | ✅ 需要 |
| **控制粒度** | 更底层、更直接 | 更偏工程化封装 |
| **与 Spring Bean 管理集成** | 一般 | ✅ 很方便 |
| **与 `@Async` 集成** | 需要自己适配 | ✅ 天然适合 |

一句话理解：`ThreadPoolExecutor` 更像 JDK 原生发动机，`ThreadPoolTaskExecutor` 更像 Spring 给这台发动机包的一层适合 Spring 项目使用的外壳。

## 七、原子类

### 1. 什么是原子类

原子类提供**无锁**的线程安全操作，比 synchronized 性能更高。

```java
import java.util.concurrent.atomic.AtomicInteger;

public class Demo {
    private static AtomicInteger count = new AtomicInteger(0);
    
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> {
            for (int i = 0; i < 10000; i++) {
                count.incrementAndGet();  // 原子性自增
            }
        };
        
        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        t1.start();
        t2.start();
        t1.join();
        t2.join();
        
        System.out.println("count = " + count.get());  // 20000（正确）
    }
}
```

### 2. 常用原子类

| 类型   | 原子类                                          |
| ---- | -------------------------------------------- |
| 基本类型 | `AtomicInteger`、`AtomicLong`、`AtomicBoolean` |
| 引用类型 | `AtomicReference<V>`                         |
| 数组类型 | `AtomicIntegerArray`、`AtomicLongArray`       |

### 3. 常用方法

| 方法                              | 说明              |
| ------------------------------- | --------------- |
| `get()`                         | 获取当前值           |
| `set(newValue)`                 | 设置新值            |
| `getAndIncrement()`             | 先获取再自增（i++）     |
| `incrementAndGet()`             | 先自增再获取（++i）     |
| `getAndAdd(delta)`              | 先获取再加 delta     |
| `compareAndSet(expect, update)` | CAS 操作：期望值匹配则更新 |

## 八、ThreadLocal 线程本地变量

### 1. 什么是 ThreadLocal

`ThreadLocal` 为每个线程提供**独立的变量副本**，实现线程隔离。每个线程访问的都是自己的副本，互不干扰。

```
┌─────────────────────────────────────────────────────────────┐
│  主内存                                                      │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  ThreadLocal<String> name = new ThreadLocal<>();    │    │
│  └─────────────────────────────────────────────────────┘    │
│                          │                                   │
│          ┌───────────────┼───────────────┐                  │
│          ↓               ↓               ↓                  │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐             │
│   │  线程A   │    │  线程B   │    │  线程C   │             │
│   │ name="张三"│    │ name="李四"│    │ name="王五"│             │
│   └──────────┘    └──────────┘    └──────────┘             │
│   各线程拥有独立副本，互不干扰                                │
└─────────────────────────────────────────────────────────────┘
```

**ThreadLocal vs 普通变量：**

| 类型 | 线程访问 | 数据隔离 |
| ---- | -------- | -------- |
| 普通成员变量 | 所有线程共享同一个变量 | ❌ 不隔离 |
| ThreadLocal | 每个线程独立副本 | ✅ 完全隔离 |

***

### 2. 基本使用

#### 常用方法

| 方法 | 说明 |
| ---- | ---- |
| `set(T value)` | 设置当前线程的变量值 |
| `get()` | 获取当前线程的变量值 |
| `remove()` | 移除当前线程的变量值（防止内存泄漏）|
| `initialValue()` | 设置初始值（重写此方法或使用 withInitial）|

#### 基本示例

```java
public class ThreadLocalDemo {
    // 创建 ThreadLocal 变量
    private static ThreadLocal<String> threadLocal = new ThreadLocal<>();
    
    public static void main(String[] args) {
        // 线程1
        new Thread(() -> {
            threadLocal.set("线程1的数据");
            System.out.println(Thread.currentThread().getName() + "：" + threadLocal.get());
            threadLocal.remove();  // 用完记得移除
        }, "Thread-1").start();
        
        // 线程2
        new Thread(() -> {
            threadLocal.set("线程2的数据");
            System.out.println(Thread.currentThread().getName() + "：" + threadLocal.get());
            threadLocal.remove();
        }, "Thread-2").start();
        
        // 主线程
        threadLocal.set("主线程的数据");
        System.out.println(Thread.currentThread().getName() + "：" + threadLocal.get());
        threadLocal.remove();
    }
}

// 输出（顺序可能不同）：
// Thread-1：线程1的数据
// Thread-2：线程2的数据
// main：主线程的数据
```

#### 设置初始值

```java
// 方式一：重写 initialValue() 方法
ThreadLocal<Integer> count = new ThreadLocal<>() {
    @Override
    protected Integer initialValue() {
        return 0;
    }
};

// 方式二：使用 withInitial()（推荐，更简洁）
ThreadLocal<Integer> count = ThreadLocal.withInitial(() -> 0);

// 使用
System.out.println(count.get());  // 0（未 set 时返回初始值）
```

***

### 3. 实现原理

#### 数据结构

每个线程（Thread）内部维护一个 `ThreadLocalMap`，存储该线程的所有 ThreadLocal 变量：

```
Thread 对象
    └── ThreadLocalMap（类似 HashMap）
            ├── Entry(ThreadLocal<?> key, Object value)
            ├── Entry(ThreadLocal<?> key, Object value)
            └── ...

示例：
Thread-1
    └── ThreadLocalMap
            ├── Entry(nameLocal, "张三")
            └── Entry(ageLocal, 18)

Thread-2
    └── ThreadLocalMap
            ├── Entry(nameLocal, "李四")
            └── Entry(ageLocal, 20)
```

#### get() 方法原理（简化）

```java
public T get() {
    // 1. 获取当前线程
    Thread t = Thread.currentThread();
    // 2. 获取当前线程的 ThreadLocalMap
    ThreadLocalMap map = t.threadLocals;
    // 3. 以当前 ThreadLocal 对象为 key，获取 value
    if (map != null) {
        Entry e = map.getEntry(this);
        if (e != null) {
            return (T) e.value;
        }
    }
    // 4. 没有则返回初始值
    return setInitialValue();
}
```

***

### 4. 内存泄漏问题

#### 问题原因

`ThreadLocalMap` 的 Entry 使用**弱引用**指向 ThreadLocal 对象：

```java
static class Entry extends WeakReference<ThreadLocal<?>> {
    Object value;  // 强引用
    Entry(ThreadLocal<?> k, Object v) {
        super(k);  // key 是弱引用
        value = v; // value 是强引用
    }
}
```

**问题场景：**

```
ThreadLocal 对象 ←── 弱引用 ── Entry.key
                              Entry.value ──→ 实际数据（强引用）

当 ThreadLocal 对象没有外部强引用时：
1. GC 回收 ThreadLocal 对象
2. Entry.key 变成 null
3. 但 Entry.value 仍然存在（强引用）
4. 如果线程长期存活（如线程池），value 无法被回收 → 内存泄漏
```

#### 解决方案

**使用完毕后调用 `remove()` 方法：**

```java
ThreadLocal<User> userLocal = new ThreadLocal<>();

try {
    userLocal.set(currentUser);
    // 业务逻辑...
} finally {
    userLocal.remove();  // ✅ 必须调用，防止内存泄漏
}
```

> ⚠️ **特别注意**：在使用线程池时，线程会被复用，如果不调用 `remove()`，下次使用该线程时可能会获取到上次的数据！

***

### 5. Web 开发中的应用

在 Web 应用中，每个 HTTP 请求由一个线程处理。使用 ThreadLocal 存储用户信息，可以在整个请求链路中方便地获取当前用户。

#### UserContext 工具类

```java
public class UserContext {
    private static final ThreadLocal<Long> USER_ID = new ThreadLocal<>();
    private static final ThreadLocal<String> USERNAME = new ThreadLocal<>();
    
    public static void setUserId(Long userId) {
        USER_ID.set(userId);
    }
    
    public static Long getUserId() {
        return USER_ID.get();
    }
    
    public static void setUsername(String username) {
        USERNAME.set(username);
    }
    
    public static String getUsername() {
        return USERNAME.get();
    }
    
    /** 清理上下文（必须在请求结束时调用，防止内存泄漏）*/
    public static void clear() {
        USER_ID.remove();
        USERNAME.remove();
    }
}
```

#### 在拦截器中设置和清理

```java
@Component
public class AuthInterceptor implements HandlerInterceptor {
    
    @Override
    public boolean preHandle(HttpServletRequest request, 
                             HttpServletResponse response, 
                             Object handler) {
        // 解析 Token，获取用户信息
        String token = request.getHeader("Authorization");
        Long userId = parseUserId(token);
        String username = parseUsername(token);
        
        // 存入 ThreadLocal
        UserContext.setUserId(userId);
        UserContext.setUsername(username);
        return true;
    }
    
    @Override
    public void afterCompletion(HttpServletRequest request, 
                                HttpServletResponse response, 
                                Object handler, Exception ex) {
        // 请求结束，必须清理！
        UserContext.clear();
    }
}
```

#### 在业务代码中使用

```java
@Service
public class OrderService {
    
    public void createOrder(OrderDTO dto) {
        // 直接获取当前用户，无需参数传递
        Long userId = UserContext.getUserId();
        
        Order order = new Order();
        order.setUserId(userId);
        order.setCreateTime(LocalDateTime.now());
        // ...
    }
}
```

### 6. InheritableThreadLocal

普通 `ThreadLocal` 在父子线程间**不共享**数据。如果需要子线程继承父线程的数据，使用 `InheritableThreadLocal`：

```java
// 普通 ThreadLocal：子线程无法获取父线程的值
ThreadLocal<String> threadLocal = new ThreadLocal<>();
threadLocal.set("父线程数据");

new Thread(() -> {
    System.out.println(threadLocal.get());  // null
}).start();

// InheritableThreadLocal：子线程可以继承父线程的值
InheritableThreadLocal<String> inheritableLocal = new InheritableThreadLocal<>();
inheritableLocal.set("父线程数据");

new Thread(() -> {
    System.out.println(inheritableLocal.get());  // 父线程数据
}).start();
```

> ⚠️ **注意**：`InheritableThreadLocal` 在线程池场景下可能失效，因为线程池中的线程是复用的，不是每次都新建子线程。
