# 链表

## 一、题型认知

链表题的难点通常不在算法复杂度，而在于 **指针操作是否稳定**。写题前先想清楚三个角色：

| 角色                   | 作用                   |
| ---------------------- | ---------------------- |
| **当前节点 `current`** | 正在处理谁             |
| **前驱节点 `prev`**    | 反转、拼接时常用       |
| **快慢指针**           | 找中点、判环、对齐长度 |

面试里常见的链表套路：

- 双指针对齐长度差
- 迭代反转
- 快慢指针找中点/判环
- 虚拟头节点简化边界

## 二、相交链表

**链接**：[160. 相交链表](https://leetcode.cn/problems/intersection-of-two-linked-lists/)

**难度：** Easy

### 1. 核心思路

让两个指针分别走完 `A + B` 和 `B + A` 两段路径：

- 如果两链表相交，它们最终会在交点相遇。
- 如果不相交，它们最终都会走到 `null`，也会相等。

这个写法本质上是在自动“补齐长度差”。

### 2. 复杂度

| 维度           | 复杂度     |
| -------------- | ---------- |
| **时间复杂度** | `O(m + n)` |
| **空间复杂度** | `O(1)`     |

### 3. 参考实现

```typescript
class ListNode {
  val: number
  next: ListNode | null

  constructor(val?: number, next?: ListNode | null) {
    this.val = val ?? 0
    this.next = next ?? null
  }
}

function getIntersectionNode(
  headA: ListNode | null,
  headB: ListNode | null,
): ListNode | null {
  let pointerA = headA
  let pointerB = headB

  while (pointerA !== pointerB) {
    pointerA = pointerA === null ? headB : pointerA.next
    pointerB = pointerB === null ? headA : pointerB.next
  }

  return pointerA
}
```

## 三、反转链表

**链接**：[206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)

**难度：** Easy

### 1. 核心思路

反转链表的标准动作是“三指针”：

- `prev` 指向已经反转好的前半段。
- `current` 指向当前节点。
- `next` 暂存后继节点，防止断链。

### 2. 复杂度

| 维度           | 复杂度 |
| -------------- | ------ |
| **时间复杂度** | `O(n)` |
| **空间复杂度** | `O(1)` |

### 3. 参考实现

```typescript
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null
  let current = head

  while (current !== null) {
    const next = current.next
    current.next = prev
    prev = current
    current = next
  }

  return prev
}
```

## 四、环形链表

**链接**：[141. 环形链表](https://leetcode.cn/problems/linked-list-cycle/)

**难度：** Easy

### 1. 核心思路

使用快慢指针：

- 慢指针每次走一步。
- 快指针每次走两步。
- 如果有环，快指针最终一定会追上慢指针。
- 如果没有环，快指针会先走到 `null`。

### 2. 复杂度

| 维度           | 复杂度 |
| -------------- | ------ |
| **时间复杂度** | `O(n)` |
| **空间复杂度** | `O(1)` |

### 3. 参考实现

```typescript
function hasCycle(head: ListNode | null): boolean {
  let slow = head
  let fast = head

  while (fast !== null && fast.next !== null) {
    slow = slow?.next ?? null
    fast = fast.next.next

    if (slow === fast) {
      return true
    }
  }

  return false
}
```

## 五、回文链表

**链接**：[234. 回文链表](https://leetcode.cn/problems/palindrome-linked-list/)

**难度：** Easy

### 1. 核心思路

面试里更推荐的做法是：

- 用快慢指针找到链表中点。
- 反转后半段链表。
- 从头和中点同时向后比较。

这样能把额外空间优化到 `O(1)`，比把值全部放进数组更像链表题的标准解法。

### 2. 复杂度

| 维度           | 复杂度 |
| -------------- | ------ |
| **时间复杂度** | `O(n)` |
| **空间复杂度** | `O(1)` |

### 3. 参考实现

```typescript
function isPalindrome(head: ListNode | null): boolean {
  if (head === null || head.next === null) {
    return true
  }

  let slow = head
  let fast = head

  while (fast !== null && fast.next !== null) {
    slow = slow.next as ListNode
    fast = fast.next.next
  }

  let right = reverseList(slow)
  let left = head

  while (right !== null) {
    if (left.val !== right.val) {
      return false
    }

    left = left.next as ListNode
    right = right.next
  }

  return true
}
```

## 六、合并两个有序链表

**链接**：[21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)

**难度：** Easy

### 1. 核心思路

用一个虚拟头节点 `dummy` 来统一处理头节点拼接问题，每次把较小值接到结果链表末尾。

这种写法比递归更稳，更适合面试中手写。

### 2. 复杂度

| 维度           | 复杂度     |
| -------------- | ---------- |
| **时间复杂度** | `O(m + n)` |
| **空间复杂度** | `O(1)`     |

### 3. 参考实现

```typescript
function mergeTwoLists(
  list1: ListNode | null,
  list2: ListNode | null,
): ListNode | null {
  const dummy = new ListNode()
  let tail = dummy
  let left = list1
  let right = list2

  while (left !== null && right !== null) {
    if (left.val <= right.val) {
      tail.next = left
      left = left.next
    } else {
      tail.next = right
      right = right.next
    }

    tail = tail.next
  }

  tail.next = left ?? right
  return dummy.next
}
```

### 4. 易错点

| 易错点               | 说明                             |
| -------------------- | -------------------------------- |
| **忘记保存后继节点** | 反转链表时会直接断链             |
| **边界判断混乱**     | 链表为空时要先处理               |
| **不用虚拟头节点**   | 合并链表时会导致头节点逻辑变复杂 |
