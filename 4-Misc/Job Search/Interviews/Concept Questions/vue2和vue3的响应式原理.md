# Vue2 和 Vue3 的响应式原理

**一句话回答：** Vue2 通过 `Object.defineProperty` 劫持属性，Vue3 通过 `Proxy` 拦截对象操作；后者覆盖能力更强，初始化成本也更低。

***

## 一、核心对比

| 对比项 | **Vue2** | **Vue3** |
| --- | --- | --- |
| **实现基础** | `Object.defineProperty` | `Proxy` |
| **拦截粒度** | 逐个属性劫持 | 对整个对象统一拦截 |
| **新增 / 删除属性** | 不能天然监听，需要 `Vue.set` | 可以直接监听 |
| **数组下标与长度变化** | 需要特殊处理重写数组方法 | 可以更自然地监听 |
| **Map / Set** | 支持较弱 | 支持更好 |

***

## 二、Vue2 怎么做响应式

Vue2 会在初始化阶段递归遍历对象，为每个属性定义 getter 和 setter：

1. **getter 收集依赖。** 组件渲染时访问了哪些数据，就把对应 watcher 收集起来。
2. **setter 派发更新。** 数据变化后通知依赖重新执行。
3. **数组通过重写变更方法补齐。** 例如 `push`、`splice` 等。

缺点也很明显：初始化要深度遍历；新增属性和数组下标变更不够自然。

***

## 三、Vue3 为什么更优

Vue3 的核心对象是：

| API | 作用 |
| --- | --- |
| **`reactive()`** | 创建对象响应式 |
| **`ref()`** | 让基本类型和值包装成可追踪对象 |
| **`effect()`** | 建立副作用函数 |
| **`track()` / `trigger()`** | 分别负责依赖收集和触发更新 |

`Proxy` 的优势在于：**只有真正访问到的属性才会参与依赖追踪**，并且对新增、删除、集合类型支持更完整。

***

## 四、面试答题模板

可以直接答：**Vue2 响应式基于 `Object.defineProperty`，本质是给每个属性定义 getter/setter 来收集依赖和派发更新，所以初始化要深度遍历，而且新增属性、数组下标这些场景处理不够自然。Vue3 改成 `Proxy` 后，是对整个对象进行拦截，支持新增删除属性、数组和 `Map/Set`，覆盖能力更强，初始化成本也更低。**
