# Vue 中 nextTick 的原理

**一句话回答：** `nextTick` 的作用是把回调延后到“DOM 更新完成之后”再执行，本质上是利用异步任务队列等待本轮响应式更新刷完。

***

## 一、为什么需要 nextTick

Vue 更新数据后不会立刻同步修改真实 DOM，而是把多次更新合并，统一在下一轮调度里批量刷新。这样做的目的是：

1. **减少重复渲染。**
2. **提高批量更新效率。**
3. **保证同一轮数据变更只触发一次 DOM 刷新。**

所以如果你在改完数据后立刻读取 DOM，拿到的可能还是旧值，这时候就需要 `nextTick`。

***

## 二、原理可以怎么说

### 1. 更新流程

`数据变化 -> 依赖收集到的 watcher / effect 入队 -> 调度器去重 -> 异步刷新队列 -> DOM 更新完成`

### 2. nextTick 做的事

- 把用户回调放到更新队列刷新之后执行。
- 优先使用微任务，如 Promise。
- 退化情况下再使用 `setTimeout` 等宏任务。

因此它不是“延时 0ms”，而是“等当前这轮 DOM patch 完成后再执行”。

***

## 三、使用场景与误区

| 场景 | 是否适合用 `nextTick` |
| --- | --- |
| **更新后读取 DOM 尺寸 / 位置** | 适合 |
| **更新后立即聚焦输入框** | 适合 |
| **只是想等待接口返回** | 不适合，应该等 Promise |
| **能用计算属性 / 生命周期解决的逻辑** | 优先不用 `nextTick` |

**常见误区：** 不要把 `nextTick` 当万能异步工具；它只解决“等 Vue 把 DOM 更新完”这个问题。

***

## 四、面试答题模板

可以直接答：**Vue 为了提升性能，会把同一轮数据变更合并后异步更新 DOM，所以修改响应式数据后，真实 DOM 不一定马上变。`nextTick` 就是把回调放到本轮 DOM patch 完成之后再执行，底层通常优先借助 Promise 这样的微任务来调度。**
