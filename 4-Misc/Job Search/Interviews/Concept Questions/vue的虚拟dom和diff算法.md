# Vue 的虚拟 DOM 和 Diff 算法

**一句话回答：** 虚拟 DOM 是对真实 DOM 的 JavaScript 抽象，Diff 算法则负责比较前后两棵虚拟树，找出最小必要更新并同步到真实 DOM。

***

## 一、为什么需要虚拟 DOM

真实 DOM 操作成本高，而且浏览器渲染链路复杂。Vue 先把界面描述成虚拟节点树，可以先在 JavaScript 层完成比较和计算，再把真正需要变更的部分一次性落到真实 DOM。

| 价值 | 说明 |
| --- | --- |
| **跨平台抽象** | 不只可以映射到浏览器 DOM，也可以映射到其他渲染目标 |
| **便于声明式开发** | 开发者只关心状态和模板 |
| **降低无效 DOM 操作** | 通过 Diff 找出必要更新 |

***

## 二、Diff 的几个关键规则

1. **同层比较，不跨层暴力移动。**
2. **节点类型不同，直接卸载重建。**
3. **节点类型相同，复用节点，只更新属性和子节点。**
4. **列表更新依赖 `key`。** `key` 稳定时，Vue 更容易识别复用和移动关系。

### 列表为什么不能滥用 index 作为 key

如果用索引做 `key`，当列表插入、删除、排序时，旧节点可能被错误复用，导致状态错位或无效更新增多。

***

## 三、Vue2 和 Vue3 的差异

| 版本 | 特点 |
| --- | --- |
| **Vue2** | 以运行时 Diff 为主，优化粒度有限 |
| **Vue3** | 编译器会生成 Patch Flag、Block Tree，缩小 Diff 范围 |

所以 Vue3 的提升不只是“虚拟 DOM 更快”，而是 **编译阶段就告诉运行时哪些节点值得比较**。

***

## 四、面试答题模板

可以直接答：**Vue 的虚拟 DOM 是对真实 DOM 的对象化描述，更新时会生成新旧两棵虚拟树，通过 Diff 找出最小必要改动再 patch 到真实 DOM。Diff 的核心规则是同层比较、同类型复用、不同类型重建，列表场景要依赖稳定的 `key`。Vue3 进一步把编译优化和运行时 Diff 结合起来，所以更新更精准。**
