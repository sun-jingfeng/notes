# 浏览器的渲染过程

**一句话回答：** 浏览器渲染页面的核心链路是“解析 -> 构树 -> 布局 -> 绘制 -> 合成”，理解这条链路能解释很多性能问题。

***

## 一、渲染主流程

1. **解析 HTML，构建 DOM。**
2. **解析 CSS，构建 CSSOM。**
3. **合成 Render Tree。** 只包含可见节点。
4. **Layout。** 计算节点几何信息。
5. **Paint。** 把节点画成像素。
6. **Composite。** 多图层合成到屏幕。

***

## 二、为什么会有重排和重绘

| 行为 | 说明 | 常见触发 |
| --- | --- | --- |
| **重排** | 布局信息变化，必须重新计算位置和尺寸 | 改宽高、改定位、插入删除节点 |
| **重绘** | 几何不变，只是视觉变化 | 改颜色、背景、阴影 |
| **合成** | 图层变化，不一定重排或重绘 | `transform`、`opacity` |

理解这三者的区别，是做前端性能优化的基础。

***

## 三、与性能优化的关系

| 问题 | 建议 |
| --- | --- |
| **动画卡顿** | 优先用 `transform` 和 `opacity` |
| **频繁布局抖动** | 避免交替读写布局属性，合并 DOM 操作 |
| **首屏慢** | 减少阻塞脚本，优化关键 CSS 和静态资源加载 |
| **长列表卡顿** | 使用虚拟列表或分片渲染 |

***

## 四、面试答题模板

可以直接答：**浏览器渲染页面时会先解析 HTML 和 CSS，生成 DOM 和 CSSOM，再组合成渲染树，之后经过布局、绘制和图层合成把内容显示出来。前端里常说的重排、重绘，其实就是这条链路上的不同阶段，所以性能优化通常就是尽量减少重排和高成本绘制。**
