# 项目优化

**一句话回答：** 面试里的项目优化不要只说“我做了懒加载、压缩图片”，而要按“指标 -> 瓶颈 -> 手段 -> 结果”来讲，才有说服力。

***

## 一、先怎么定位问题

| 维度 | 常用工具 | 看什么 |
| --- | --- | --- |
| **性能瓶颈** | Chrome Performance、Lighthouse | 长任务、首屏、CLS、LCP |
| **包体积** | `rollup-plugin-visualizer`、`webpack-bundle-analyzer` | 大包、重复依赖、拆包效果 |
| **运行时渲染** | Vue DevTools / React DevTools | 重复渲染、组件更新热点 |
| **接口链路** | Network 面板、APM | 慢接口、重复请求、瀑布阻塞 |

***

## 二、常见优化方向

| 方向 | 典型做法 |
| --- | --- |
| **首屏速度** | 路由懒加载、关键资源优先、图片压缩、缓存优化 |
| **运行性能** | 避免长任务、虚拟列表、减少重排重绘、使用 `AbortController` |
| **包体积** | 按需加载、Tree Shaking、代码分割、Gzip / Brotli |
| **请求效率** | 请求合并、缓存、去重、预取 |
| **体验优化** | 骨架屏、加载态、错误兜底、空状态 |

***

## 三、答题时最容易加分的点

1. **说优化前的问题。** 例如首屏慢、打包体积大、用户切页卡顿。
2. **说怎么确认瓶颈。** 不要像拍脑袋优化。
3. **说为什么选这个方案。** 例如长列表用虚拟滚动而不是简单分页。
4. **说结果。** 哪怕没有精确数字，也要有“明显缩短”“减少重复请求”“用户投诉下降”这类结果描述。

### 一个简化回答结构

- 先用工具定位问题
- 再分为资源加载、渲染链路、接口请求三类治理
- 最后补效果和复盘

***

## 四、面试答题模板

可以直接答：**我做项目优化时一般先看指标和工具数据，不会先堆方案。比如首屏慢，我会先通过 Lighthouse 和 Performance 判断是资源体积、接口瀑布还是主线程长任务；如果是包体积问题，就做按需加载和拆包；如果是渲染问题，就检查长列表、重复渲染和重排重绘；如果是请求问题，就做缓存、去重和预取。这样回答会比单纯背优化名词更像真实项目经验。**
