## 二、逐题复盘（问题 → 我的答案 → 评价 → 参考答案 → 话术）

### 1. 自我介绍与 AI 相关经历【7 分】

**问题**：先做个自我介绍，重点突出自己，尤其是 AI 项目相关经验。

**我的答案要点**
- 吉林大学软件工程本科毕业，4 年左右 Web 开发经验。
- 最近一年在做 React + Java 全栈开发，有 AI Agent 落地经验。
- 具备从 0 到 1 的项目交付能力，也会用 AI 做开发提效。
- 做过 6 人小组组长、项目负责人，连续两年涨薪，被评为年度优秀员工。

**评价**
- 优点：学历背景、工作年限、技术栈、管理经历和 AI 关键词都交代到了，基础信息比较完整。
- 不足：整体更像履历罗列，没有快速回答“你为什么适合这个岗位”；优势点较散，AI 落地经验没有压缩成一句有辨识度的定位。

**参考答案要点**
- 开头先给个人定位：4 年 Web 开发，前端为主，近一年扩展到 React + Java 全栈，并有 AI 应用落地经验。
- 中间突出两类优势：一类是从 0 到 1 的交付能力，另一类是 AI 协作和项目推进能力。
- 结尾直接扣岗位：适合需要快速验证、强调业务落地和工程执行力的团队。

**话术示例**
我本科是吉林大学软件工程专业，做 Web 开发大概 4 年，前端是我的主方向，近一年开始做 React + Java 的全栈开发，也落地过 AI Agent 相关功能。我过去做过从 0 到 1 的项目交付，也担任过小组组长和项目负责人，所以我的优势不只是能写代码，还能把需求拆清楚、把方案推进下去。对 AI 相关岗位来说，我比较匹配的点在于既有前端和工程化基础，也有把 AI 功能真正接到业务里的落地经验。

### 2. 最近一家公司做了什么，你负责哪一块【7 分】

**问题**：你最近这家公司主要做什么？你做了哪些东西，负责哪一块？

**我的答案要点**
- 最近在红象科技工作了 3 年左右，公司主要做气象软件，客户多为国企或局方，项目偏定制化。
- 自己主要参与气象软件系统开发，很多项目都是从 0 到 1 的完整交付。
- 最近做的是气象雷达预警项目，这是自己第一个前后端全栈项目，后期嵌入了 AI 智能体功能。
- 技术栈是前端 React、后端 Java、智能体部分用 Python 微服务实现。

**评价**
- 优点：把公司业务、客户类型、项目形态和技术栈都交代清楚了，也说明了自己在做全栈和 AI 方向延展。
- 不足：对“你负责哪一块”回答得还不够深入，没有把自己负责的核心模块、职责边界、最终产出和业务价值说透。

**参考答案要点**
- 按“公司业务背景 → 项目场景 → 我的职责 → 技术栈 → 结果”来讲。
- 重点说清自己不是普通参与开发，而是在方案设计、核心模块、前后端联调、AI 功能接入中承担了什么职责。
- 如果能补充结果更好，比如上线情况、效率提升、对业务流程的改善。

**话术示例**
我最近这家公司主要做气象行业的软件，客户以国企和气象相关单位为主，很多项目是定制化交付。我这几年主要负责气象业务系统开发，参与过多个从 0 到 1 的项目。最近一个代表性项目是气象雷达预警系统，我在里面承担的职责比较完整，前端是 React，后端是 Java，后期还接入了 Python 写的 AI 智能体能力。这个项目对我最大的提升是让我从原来的前端主力，逐步转到可以独立推动前后端加 AI 功能落地的角色。

### 3. 开发工具、AI 提效方式和项目里的具体落地【7 分】

**问题**：你现在都用什么开发工具？气象雷达项目里这些 AI 相关东西具体是怎么做的？过程中遇到了什么问题？

**我的答案要点**
- 前端开发中大量使用 AI 工具提效，会先搭骨架、拆组件、写一个示例组件，再把重复工作交给 AI 生成，自己做审核后提交。
- 提到通过 MCP 连接设计和开发工具，先确定组件传参方式、组件拆分粒度，再让 AI 按既有示例扩展。
- 后端也是先搭基础骨架，再按 Controller、Service、Mapper 这样的分层先写一个示例，之后让团队按示例推进。
- 会沉淀持久化提示词，例如全局规则放在 `Rules`，某类任务的具体规范放在任务级配置里。
- 业务侧提到后来新增了智能体能力，用于辅助气象预警文案生成，替代早期偏硬编码的方式。
- 对“遇到了什么问题”这部分回答不完整，记录里没有展开具体难点和解决方式。

**评价**
- 优点：回答很有一线开发感，不是泛泛而谈“我会用 AI”，而是讲到了骨架先行、示例驱动、重复工作交给 AI、人工审核把关这些工程化做法。
- 不足：工具名、流程和难点没有讲成一个完整闭环，尤其“具体怎么做”和“遇到了什么问题”没有展开，导致面试官没能听到更有说服力的项目细节。

**参考答案要点**
- 先分层回答：开发工具怎么用，业务功能怎么落地，遇到的问题怎么解决。
- 工具层面可以讲清 AI 主要承担的工作：样板代码生成、重复接口生成、UI 还原辅助、规范继承；自己负责架构、示例、边界和验收。
- 业务落地层面要讲清智能体链路：输入是什么、处理流程是什么、输出是什么、最终如何嵌入系统。
- 难点可以从 3 个方向说：一是气象业务知识和提示词约束，二是结果可控性和结构化输出，三是接入现有系统时的接口编排和稳定性。
- 最后补一句你如何解决：用规则沉淀、样板约束、人工校验和逐步灰度接入来保证效果。

**话术示例**
我现在用 AI 工具已经比较深了，但我的原则一直很明确，就是我先把架构和边界定出来，AI 负责高重复、低歧义、容易验证的工作。前端这边我会先根据设计图把组件拆出来，确定传参方式和组件粒度，然后先写一个示例组件，再让 AI 去扩其他重复部分。后端也类似，我会先把分层、命名、接口结构这些定好，先写一个标准示例，再让 AI 或团队按这个模式扩展。

项目里的智能体落地，核心场景是辅助生成气象预警文案。以前更多是硬编码模板，现在是把气象要素、业务规则和上下文组织起来，由智能体生成候选内容，再回到系统里给业务人员确认。这个过程里比较难的是结果可控性和业务准确性，所以我的做法是把全局规则和任务规则沉淀下来，再加上人工审核和逐步上线，保证它不是一个完全不可控的黑盒。

### 4. LangChain、LangGraph 这类能力用了多久【4 分】

**问题**：像 LangChain、LangGraph 这些你大概用了多久，是去年刚开始吗？

**我的答案要点**
- 回答是用了半年左右。

**评价**
- 优点：回答比较真实，没有为了显得资深而夸大经验时长。
- 不足：只有时间，没有补充“这半年具体做了什么、做到什么程度、理解到了哪一层”，信息量明显不够。

**参考答案要点**
- 先直接给时长，再补实际使用场景。
- 强调自己虽然接触时间不算长，但已经做过业务接入，而不是只停留在 Demo 阶段。
- 可以顺带补一句自己的理解边界，比如更熟的是链路编排、提示词约束、工具调用，复杂图编排还在持续深化。

**话术示例**
这块我实际接触时间大概半年左右，确实是最近一年才开始深入的。不过我不是只停留在 Demo 或概念层面，而是已经把它用到了真实业务场景里，像智能体流程编排、提示词约束、结合业务数据生成内容这些我都实际做过。我的看法是这块更新很快，所以我会比较强调先把真实场景跑通，再逐步把复杂度往上加。

### 5. 你的技术路线是不是从前端再扩到 AI 和全栈【5 分】

**问题**：你本身是前端开始的，后来又做 AI 这些东西，是这样吗？

**我的答案要点**
- 回答了自己本身是前端开始，后来再往后扩展。
- 记录过简，未展开为什么会从前端延伸到全栈和 AI。

**评价**
- 优点：方向回答是对的，和你的真实经历一致。
- 不足：缺少成长路径和驱动力说明，没有把“为什么扩”和“扩完之后形成了什么能力”说出来。

**参考答案要点**
- 先确认前端是基本盘，再说明向后端和 AI 扩展是因为项目交付需要，而不是无目的转方向。
- 重点强调能力演进：前端主力 → 完整交付意识 → 后端补位 → AI 功能落地。
- 结尾要让面试官感受到你的核心竞争力不是“什么都懂一点”，而是“以业务交付为目标不断补齐能力栈”。

**话术示例**
对，我最早是以前端开发为主，这也是我的基本盘。后来因为项目越来越偏完整交付，我发现如果只停留在前端，很难把很多事情真正推进到落地，所以我开始补后端能力，再到后面接触 AI 应用落地。这个过程不是为了单纯转方向，而是为了把一个项目从界面、接口到智能能力接入都能更完整地接住，所以我现在更像是以前端为基础、面向业务交付扩展出来的全栈能力结构。

### 6. 反问：了解公司业务方向【5 分】

**问题**：你还有什么需要问我的吗？

**我的答案要点**
- 先试图补充智能体细节，但面试官表示大概了解。
- 随后主动询问了对方公司的业务方向。
- 对方介绍公司在做 AI 科技营销相关链路后，没有继续追问。

**评价**
- 优点：至少做了反问，而且是围绕业务本身展开，说明你在判断岗位和公司方向。
- 不足：反问深度偏浅，没有继续追问岗位职责、团队分工、当前阶段、成功标准等更关键的信息，错过了进一步判断岗位匹配度的机会。

**参考答案要点**
- 反问建议至少准备 2 到 3 个层次：业务方向、岗位职责、团队阶段或技术预期。
- 如果对方岗位偏 AI 应用落地，可以重点问“当前最核心的业务场景是什么”“这个岗位进去之后最先要解决的问题是什么”。
- 再追一个协作问题，会显得更成熟，比如“团队里产品、研发、AI 工程的分工方式是什么”。

**话术示例**
我有两个问题想了解一下。第一，咱们当前 AI 科技营销这条业务里，最核心、最优先的应用场景是什么，这个岗位进去之后主要是围绕哪一段链路做落地。第二，团队现在更看重这个岗位的人解决什么问题，是偏产品验证、业务交付，还是偏 AI 工程能力和系统搭建。这样我也能更准确判断自己的经验跟岗位的匹配度。

## 四、待改进与盲区

### 4.1 技术回答

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **项目职责回答** | 说了项目背景和技术栈，但没把自己负责的核心模块、关键决策和业务结果讲透 | 固定用“场景、职责、技术栈、结果”四段式来讲项目。 |
| **AI 落地细节** | 提到了工具和思路，但缺少完整链路说明 | 补清输入数据、智能体流程、输出结果、人工校验、上线方式。 |
| **遇到的问题** | 面试官问到了难点，但回答里基本没展开 | 准备 2 到 3 个真实问题，例如结果可控性、提示词稳定性、业务准确性、系统接入复杂度。 |
| **AI 框架使用深度** | LangChain、LangGraph 只回答了时长，没有体现深度 | 补具体场景、做过的能力边界、当前最熟和仍在深化的部分。 |

### 4.2 表达与结构

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **自我介绍** | 信息点很多，但岗位匹配点不够靠前 | 开头直接说“前端主力，近一年做全栈和 AI 应用落地”。 |
| **回答结构** | 有几段回答比较散，像边想边说 | 尽量按“结论、做法、结果”或“背景、职责、难点、解决”来组织。 |
| **专有名词表达** | 录音转写里很多专业词失真，口头表达也容易让对方听不稳 | 二面前统一标准说法，例如 LangChain、LangGraph、MCP、Cursor、AI Agent。 |
| **补充意识** | 面试官打断后你会停，但没有快速切到更核心的信息 | 遇到时间短的面试，更要优先讲最有辨识度的 1 到 2 个点。 |

### 4.3 反问与面试策略

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **反问深度** | 只问了业务方向，没有继续深入 | 继续追问岗位目标、团队分工、近期重点项目和成功标准。 |
| **AI 经验包装** | 有实际经验，但还没沉淀成统一方法论 | 整理成“我如何定义边界、如何让 AI 参与、如何验收结果”的固定话术。 |

## 五、后续行动

### 5.1 短期（针对二面或同类岗位）

1. 把自我介绍重写成 60 到 90 秒版本，开头直接突出“前端主力 + 全栈扩展 + AI 落地经验”。
2. 准备一套固定的项目介绍话术，严格按“背景、职责、难点、解决、结果”来讲气象雷达预警项目。
3. 单独准备“AI 在项目里怎么落地”的答案，把工具使用、智能体链路、难点和解决方式讲成闭环。
4. 给 LangChain、LangGraph 这类问题准备 30 秒和 90 秒两个版本，避免只答一句“用了半年”。

### 5.2 中期（知识补全）

1. 系统梳理 AI Agent 相关基础概念，包括工作流编排、工具调用、状态管理、结构化输出和结果校验。
2. 补一轮“AI 应用落地常见难点”的案例化总结，至少准备 3 个你自己做过或能讲透的问题。
3. 继续加强后端与微服务表达，避免在“前端出身转全栈”这类问题上只停留在经历层面。

### 5.3 简历与话术

1. 简历里把 AI Agent 落地经历写得更具体，最好体现一个明确场景、你的职责和结果。
2. 把“会用 AI 提效”改写成更专业的话术，例如“通过骨架先行、规则沉淀、示例驱动提升重复开发效率并保证代码一致性”。
3. 统一所有工具和框架名称的口头表达，避免因为名称模糊影响专业感。

***

## 六、小结

- 这场一面整体时长很短，面试官更多是在快速确认你的经历主线和 AI 方向的真实性，而不是深挖技术细节。
- 你的优势在于前端基础、项目交付经历、带人推进经历，以及已经开始把 AI 用到真实开发流程和业务功能里。
- 当前最大问题不是没做过，而是很多做过的内容没有被你讲成结构化、可追问、可放大的答案，所以显得信息价值没有完全打出来。
- 如果后续把项目职责、AI 落地链路、常见难点和反问策略再收一轮，这类偏 AI 应用落地的岗位会更容易打出区分度。
