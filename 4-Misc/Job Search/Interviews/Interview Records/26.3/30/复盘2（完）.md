## 二、逐题复盘（问题 → 我的答案 → 评价 → 参考答案 → 话术）

### 1. 自我介绍与个人标签【7 分】

**问题**：请做一下自我介绍，并概括你的背景和能力。

**我的答案要点**
- 介绍了学历背景，本科是吉林大学软件工程。
- 说明有 4 年开发经验。
- 提到前端技术栈是 Vue、React，后端是 Java，也会一点 Python。
- 说明自己具备前后端全栈交付能力。
- 提到有 AI 提效和智能体落地经验。
- 说明自己做过项目负责人和 6 人技术小组组长。

**评价**
- 优点：学历、年限、技术栈、管理经历、全栈能力和 AI 经验都覆盖到了，信息密度是够的。
- 不足：表达更像简历条目罗列，没有先把最有辨识度的标签打出来，比如“前端出身，近一年做全栈与 AI 落地，能独立交付项目”。另外中间一句“您看哪儿感兴趣我详细说”会把主动权交给面试官，不如自己直接接代表项目。

**参考答案要点**
- 开头先一句话给个人定位。
- 中间用一段代表项目证明“全栈交付 + AI 落地 + 负责人经历”。
- 结尾补一句和岗位的匹配方向。

**话术示例**
我本科是吉林大学软件工程专业，工作 4 年，起点是前端开发，主要用 Vue 和 React。近一年我逐步把能力扩展到了 Java 后端和 AI 应用落地，已经能承担前后端一体的项目交付。过去我做过项目负责人和 6 人技术小组组长，除了编码，也会做方案推进、任务拆分和关键问题收口。我的特点可以概括成一句话，就是前端出身，但现在能做全栈交付，也有实际的 AI 智能体落地经验。

### 2. 代表项目与 AI 落地经历【6.5 分】

**问题**：挑一段最能代表你的相关经历，结合实际项目展开讲讲你做了什么。

**我的答案要点**
- 面试官先让你展开代表性经历。
- 你先反问对方更想听传统前后端还是 AI 相关内容。
- 在对方选择 AI 相关后，你先讲了近一年使用 AI 开发提效，机械性代码让 AI 生成，效率大概提升到原来的 3 倍。
- 后续在面试官追问下，开始介绍雷达气象预警项目。

**评价**
- 优点：知道根据面试官兴趣切换讲述重点，后面也把 AI 提效和项目经历连上了。
- 不足：这一题本质上是在建立“你最值钱的经历是什么”，不适合先把球踢回给面试官。你前半段先讲 AI 提效比例，后半段才落到项目，导致主线有点散。更稳的方式是直接用一个代表项目把“业务、角色、技术、结果、AI 落地”串起来。

**参考答案要点**
- 直接选一个代表项目，不要先反问。
- 用“项目背景、我的角色、我负责的核心模块、AI 落地点、结果”五段式展开。
- AI 提效属于补充亮点，不应替代项目本身。

**话术示例**
我最近最有代表性的项目是一个雷达气象预警系统。我在里面既承担前端核心开发，也承担了较多后端工作，同时还负责智能体能力的接入。这个项目比较有代表性，因为它不是单纯做页面，而是既有原有系统复用、又有单体到微服务的演进，还新增了 AI 生成预警文案的能力。对我来说，这个项目能比较完整地体现我在传统 Web 交付和 AI 落地上的结合能力。

### 3. 雷达气象预警项目里你具体做了什么【7 分】

**问题**：结合最近的项目，具体讲一下项目结构、你的职责，以及智能体功能是怎么接进去的。

**我的答案要点**
- 项目是雷达气象预警项目。
- 前端因为要复用两个旧项目并新增功能，做成了父子项目结构，新功能拆成 3 个独立小项目，最后合并到一个主项目中。
- 后端一开始是单体，后来因为要做多省份版本，需要共性复用和差异化隔离，所以拆成了微服务。
- 每个省份有自己的定制服务，通用能力抽到公共微服务中。
- 后面新增了智能体生成功能，用于根据气象要素和时间生成预警文案。
- 前端只是点击生成，后端这块主要由你实现，用 Python 写了一个智能体微服务。
- 智能体服务会接收前端参数，查询整理气象数据，结合模板交给模型生成文案，再返回前端。

**评价**
- 优点：项目背景、前端结构、后端演进、AI 接入链路都讲到了，说明你确实做过全链路工作。
- 不足：信息量很多，但表达不够收束，口头里有不少重复和转写失真，导致结构感不强。最关键的是，你虽然讲了系统怎么搭，但“你自己具体写了哪些模块、承担了哪部分难点、产出结果是什么”还可以再更明确一点。

**参考答案要点**
- 先一句话定义项目和业务场景。
- 再按前端、后端、AI 接入三段说自己的职责。
- 补出为什么这么拆、拆完解决了什么问题。
- 最后落到自己的价值：不仅开发，还承担了跨技术栈串联工作。

**话术示例**
这个项目是一个雷达气象预警系统，服务的是气象预警业务场景。我在里面一方面负责前端核心功能开发，因为项目需要复用两个旧系统并新增能力，所以前端做成了主项目加多个子项目的结构；另一方面，我也参与了后端从单体向微服务的演进，把共性能力和省份差异化能力拆开，方便后续多版本维护。后面系统又新增了预警文案智能生成能力，这块是我自己用 Python 做了一个独立微服务，负责接收前端参数、查询整理气象数据、组装提示模板并调用内网模型返回结果。这个项目比较能体现我的点，是我能把前端交互、后端服务和 AI 能力接入整合到一条完整链路里。

### 4. 为什么选 LangChain / LangGraph 这类框架【4.5 分】【错】

**问题**：当时为什么选型用 LangChain、LangGraph 这类智能体框架？有没有针对业务做过评估和测试？

**我的答案要点**
- 一开始回答成“这是做智能体的主流厂家”。
- 后面补充说主要考虑使用人数和社区热度。
- 也提到当时对比过 Spring AI 和 Python 生态方案。
- 最终认为 Python 的 AI 生态更全、已有工具更多，所以用 Python 写独立微服务接入 Java 服务。

**错误点**：把 LangChain / LangGraph 这类开源框架说成了“厂家”，且选型理由停留在“主流、热度高”，没有直接回答业务适配性和评估过程。

**评价**
- 优点：后半段补出了 Java 与 Python 生态的取舍逻辑，方向是对的。
- 不足：这是本场最明显的失分点之一。面试官问的是“有没有做选型评估”，你最开始的回答既不准确，也没有体现评估过程。即使实际没有做完整实验，也应该从任务类型、框架能力、团队技术栈、演进成本几个角度来答，而不是只说“社区热度高”。

**参考答案要点**
- 明确这些是框架或生态方案，不是厂家。
- 从业务需求出发回答：是否需要工作流编排、工具调用、状态管理、多轮对话、后续扩展。
- 说明为什么没有直接用 Spring AI，为什么最终拆成 Python 微服务。
- 即使没有做完整压测，也可以说做过小范围原型验证和可行性评估。

**话术示例**
当时我们关注的不是哪个框架更热门，而是谁更适合当前任务。因为这个功能不只是简单调一次模型接口，后面还涉及参数整理、模板组装、工具链路和后续扩展，所以我们更看重的是框架在工作流编排和 AI 生态上的完整度。Java 侧我也考虑过 Spring AI，它和现有体系结合更自然，但当时在工具生态和扩展能力上没有 Python 方案成熟。综合团队现状和后续复用考虑，我最后把这块能力独立成 Python 微服务，用更成熟的 AI 框架承接，再通过接口接回原来的 Java 服务体系。

### 5. 你为什么离开上一家公司【6 分】

**问题**：这次换工作是出于什么考虑？是不是整个组都被动离职了？

**我的答案要点**
- 你回答是因为业务线不做了。
- 也提到公司提供了转岗机会。
- 后续补充说领导和同事都换了，所以决定重新看机会。
- 当面试官继续追问业务线不做原因时，你提到了领导之间关系问题。

**评价**
- 优点：第一句“业务线不做了”其实是稳的，也是真实且足够解释离职背景。
- 不足：后面把原因扩展到组织内部关系，这是高风险表达，会让面试官把注意力从你的职业判断转移到你对前公司的评价。离职原因题的原则是“真实但克制，客观但不带情绪”，这题你后半段说多了。

**参考答案要点**
- 保持客观中性，不展开组织矛盾细节。
- 强调“业务线调整、团队变化、岗位发展方向”这三个安全维度。
- 顺手把话题拉回自己想找什么机会。

**话术示例**
我这次换工作，核心原因是原来的业务线在调整，这条线后续不再继续投入了。公司其实也给了转岗机会，但结合团队变化和我自己的发展方向，我更希望继续找一个能稳定做 Web 应用交付、同时也能继续做 AI 落地的岗位。所以这次出来找机会，更多是基于业务变化和职业方向做的选择。

### 6. 你现在怎么定位自己【6.5 分】

**问题**：你现在更把自己定义成什么类型的开发？偏工程、偏 AI 应用、还是偏算法设计？

**我的答案要点**
- 你先说自己积极学习新技能，追随行业发展趋势。
- 在面试官继续追问后，补充说目前主要还是项目交付和 AI 智能体应用。

**评价**
- 优点：第二次回答比第一次更接近问题本身，已经开始落到“项目交付”和“AI 应用”了。
- 不足：第一次回答太虚，像价值观表达，不像能力定位。面试官其实是在判断你适合被放在哪类岗位上，你需要直接回答“我是什么类型的人”，而不是先说自己愿意学习。即使你的定位不是算法，也可以很清楚地说自己是“偏工程交付的全栈 / AI 应用开发”。

**参考答案要点**
- 先一句话明确当前定位。
- 再说明过去经历怎样支撑这个定位。
- 最后说你未来一两年的延伸方向，但不要把主定位说散。

**话术示例**
如果现在给自己做定位，我会把自己定义成偏工程交付的全栈开发，同时在 AI 应用落地这块有比较实际的经验。我不是偏模型算法研究那一类，强项还是把需求变成能交付的系统，包括前端、后端以及 AI 能力接入。对我来说，未来的发展方向也是继续沿着这个路线走，把 Web 工程能力和 AI 应用能力结合起来。

***

### 7. 你更擅长工程交付，还是 AI 设计与算法【7 分】

**问题**：你自己更擅长或者更愿意做的是工程上的事情，还是偏 AI 设计、算法上的事情？

**我的答案要点**
- 你回答目前主要还是项目交付和 AI 智能体应用。

**评价**
- 优点：回答方向是对的，至少没有把自己硬往不擅长的算法方向靠。
- 不足：太短，缺少支撑。更好的回答应该顺带说明你为什么更偏工程交付，比如你过去做的是系统建设、跨端协作、服务接入、项目推进，而不是模型训练和算法研究。

**参考答案要点**
- 明确自己偏工程交付与 AI 应用，不偏底层算法研究。
- 用过往项目经历证明这个定位。
- 顺手说明这和目标岗位是匹配的。

**话术示例**
我目前更擅长也更愿意做的，还是工程交付和 AI 应用落地这一类工作。因为我过去的经验主要集中在系统建设、前后端协作、微服务演进和 AI 能力接入上，这些都更偏工程实现，而不是底层算法研究。换句话说，我的优势不在于去训练模型，而在于把现有模型能力和业务系统真正结合起来，并且稳定交付出去。

***

### 8. 反问环节与岗位匹配判断【7 分】

**问题**：你对公司和岗位有什么想了解的？

**我的答案要点**
- 你先问了公司主要做什么业务。
- 在得知对方做出海 AI 应用、面向海外学生、是多端 Web 产品后，你判断这个方向和自己匹配。
- 继续追问了技术栈。
- 得知对方是 Next.js 为主的无服务器全栈架构后，你表示自己也有相关掌握，并说明自己虽然传统上更习惯 Java，但也具备前后端全栈能力。

**评价**
- 优点：反问是有效的，先问业务再问技术栈，说明你在判断岗位是否适合自己，而不是机械式发问。最后也能把自己的能力和对方需求连接起来。
- 不足：后半段表达稍乱，特别是在“Next 生态”“全栈能力”“以前更喜欢 Java”几个点之间切换较快。更好的做法是先确认理解，再用一句话总结自己的匹配点。

**参考答案要点**
- 反问顺序合理：先业务，再产品形态，再技术栈，再团队协作方式。
- 听完之后的回应要简洁，总结“为什么我匹配”。
- 不要在最后一段加入太多自我辩解式表述。

**话术示例**
我比较关心两件事，一是这边的核心业务和产品阶段，二是团队主要的技术栈和协作方式。因为我过去主要做的是 Web 应用交付，也做过 AI 能力接入，所以如果这边是多端 Web 产品、同时又是 AI 应用场景，我会觉得和我的背景是比较匹配的。技术上如果是 Next.js 这类全栈方案，我也能接受，因为我现在已经具备从前端到后端完整参与交付的能力。

## 四、待改进与盲区

### 4.1 技术回答

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **代表项目展开不够稳** | 先反问对方想听什么，再分别讲 AI 提效和项目，主线被打散。 | 固化成“项目背景、角色、职责、AI 落地点、结果”一版标准讲法。 |
| **项目职责虽多但个人产出不够聚焦** | 讲了系统结构和演进，但“我具体写了什么、负责了什么难点”不够突出。 | 准备 2 到 3 个自己实际负责的模块或链路，面试时优先讲具体动作。 |
| **框架选型题失分明显** | LangChain / LangGraph 的定位说错，选型理由也偏空。 | 统一一版“需求特征、对比维度、为什么选 Python 生态、如何接回 Java 体系”的答案。 |
| **技术定位回答偏虚** | “积极学习新技能”不等于岗位定位。 | 直接回答“偏工程交付的全栈 / AI 应用开发”，再补经历支撑。 |

### 4.2 表达与结构

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **结论前置不够** | 多数回答是先铺背景，再慢慢接近重点。 | 每题先用一句话给结论，再展开细节。 |
| **口头表达有重复和绕句** | 项目介绍部分重复较多，影响清晰度。 | 把代表项目压缩成 60 到 90 秒固定话术，减少临场拼接。 |
| **反问后的自我匹配总结不够利落** | 听完对方介绍后，回应里有些来回确认和自我解释。 | 练一版“这个方向和我匹配的原因有两点”式总结。 |

### 4.3 职业化表达

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **离职原因后半段说多了** | 提到前公司内部关系，会带来负面观感。 | 统一成“业务线调整、团队变化、职业方向选择”这类中性说法。 |
| **对自身定位容易先讲态度再讲能力** | 面试官要的是可归类的岗位画像，不是泛泛表态。 | 先说自己现在是什么类型的开发，再补学习能力和成长意愿。 |

### 4.4 专有名词与术语准确性

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **AI 框架名称转写和表述失真** | 录音里出现了 `logogriph`、`long drop` 这类失真词，现场口述如果也不稳，会削弱可信度。 | 正式表达统一使用 **LangChain**、**LangGraph**、**Spring AI** 等准确名称。 |
| **框架属性表述不准确** | 把框架说成“厂家”属于概念错误。 | 面试前把常用 AI 框架的定位、适用场景和对比点梳理清楚。 |
