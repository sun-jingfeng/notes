## 二、基础背景与求职动机

### 1. 自我介绍与个人标签

- 请先做一下自我介绍。
- 请脱离简历讲讲你自己。
- 你先简单介绍一下。
- 请做一个不超过四五分钟的自我介绍。
- 如果一句话总结你的定位，你会怎么说？

### 2. 工作经历与角色定位

- 你现在做了 4 年是吗，主要技术栈是什么？
- 你之前主要是前端多一点是吧？
- 你现在更把自己定义成什么类型的开发？
- 你是前端出身，后来又做 AI 和全栈，是这样吗？
- 你现在更偏前端、全栈，还是 AI 应用工程？

### 3. 离职原因与找工作诉求

- 现在是不是已经离职了？离职原因是什么？
- 为什么没有留在原公司内部其他业务线？
- 接下来想找什么样的机会？
- 你现在看机会一般会从哪些方向去看？
- 为什么会考虑我们这个岗位？

### 4. 职业规划与竞争力

- 你对自己未来的发展有什么规划？
- 你觉得自己最突出的亮点是什么？
- 换到别的业务线或 To B 系统，你的优势是什么？
- 你现在的经验和我们岗位的匹配度，你自己怎么看？
- 未来更想做前端、全栈，还是偏 AI 应用？

### 5. 稳定性、地点与协作适配

- 为什么本科时间比较长？
- 为什么 31 岁只有 4 年工作经验？
- 现在是在北京还是老家？地点是否有问题？
- 英语怎么样，能否适配海外团队？
- 如果有跨团队或跨时区协作，你的适配度怎么样？

## 三、项目与全栈交付

### 1. 最近项目总述

- 把最近做的主要项目简单讲一讲。
- 挑一个最能代表你的项目，结合实际展开讲讲你做了什么。
- 最近的项目是什么，是不是从 0 到 1？
- 项目到底解决什么问题？
- 这个项目为什么能代表你的能力边界？

### 2. 个人职责与团队分工

- 你在项目里担任什么角色？
- 前后端参与比例是多少？
- 团队配置怎样？
- 你这边也参与具体开发吗？比例大概多少？
- 你主导的是架构、关键模块，还是全链路推进？

### 3. 带人、分工与推进

- 你这个小组长带多少人，主要负责什么？
- 做需求分析、技术选型和工作安排时是怎么考虑的？
- 新项目到你这里后，你怎么分人、怎么拆任务？
- 绩效是不是你来打？
- 遇到技术分歧或排期压力时怎么推进？

### 4. 技术选型与架构理由

- 从 0 到 1 的技术选型、架构搭建是怎么做的？
- 为什么用了父子项目 / iframe / Module Federation，而不是别的方案？
- 为什么智能体选 Python，不选 Spring AI 或 Node.js？
- 为什么后端要从单体演进到微服务？
- 为什么某个能力做成工具调用，而不是放在普通业务代码里？

### 5. 微服务演进与拆分边界

- 单体是怎么拆成微服务的？
- 共性需求和各省差异化需求是怎么划边界的？
- 服务拆成了哪些部分，分别做什么？
- 服务间调用、注册发现、熔断降级怎么做？
- 分布式事务在什么场景下才有必要？

### 6. 业务落地与结果评估

- 这个项目落地后带来了什么实际价值？
- 覆盖了哪些省份、哪些业务场景、哪些用户？
- 你怎么定义项目做成了，而不是只是上线了？
- 项目里有没有明确的性能指标、准确率指标或用户采纳指标？
- 如果让你复盘这个项目，最关键的成败点是什么？

### 7. 全栈能力边界

- 你后端做了多长时间？
- Java 开发这部分你也做过吗？
- Java、Spring、MySQL、Redis、Python 这些能力是什么时候开始真正实践的？
- 服务器部署是不是也由你负责？
- 你会不会只是“会接一点后端”，还是能独立把完整链路做完？

## 四、AI 提效、工具链与工程实践

### 1. AI 提效方法论

- 平时怎么用 AI 做开发提效？
- AI 在前端、后端分别怎么帮助你？
- 大概多少代码由 AI 生成？为什么还有一部分必须自己写？
- 如果一行代码都不写，能否靠 AI 把项目端到端做完？
- 你是怎么把 AI 从“问答工具”变成“工程助手”的？

### 2. AI 工具与模型选择

- 平时主要用哪些 AI 编程工具？
- Cursor、Claude Code、Copilot、OpenCode 有什么区别？
- 你现在主要用什么模型？
- 最近有没有观察过这些工具上下文读取方式的变化？
- 你为什么在不同阶段切换不同工具或模型？

### 3. Rules / Skills / MCP / Prompt 沉淀

- Rules 和 Skills 分别放什么？
- 这些规则是怎么限制 AI 的？为什么有的放 Rules，有的放 Skills？
- Skills 通常在什么时候用？你写了多少类？
- MCP 你怎么理解，实际接过哪些？
- Skills 和 MCP 有什么区别？

### 4. AI 约束、幻觉与质量控制

- 上下文很多、AI 回答不稳定或者出现幻觉时怎么处理？
- 多人协作、大项目里 AI 容易跑偏，你怎么控住？
- AI 生成代码后你怎么 review、怎么验收？
- 如果 AI 帮你写完一段代码，你下一步怎么验证它是真的对的？
- 如果 AI 代码量变成人写的 3 到 5 倍，怎么保证长期质量？

### 5. AI 在完整研发链路里的角色

- 如果把需求分析、PRD、UI、技术方案、排期、联调、自测都尽量交给 AI，你怎么看？
- 测试阶段 AI 会怎么参与排查问题？
- 如果让 AI 参与部署到发布的链路，怎么保证准确性与安全性？
- AI 会怎么改变前端、后端、测试、产品这些角色？
- 你会把哪些事情明确留给人，而不是交给 AI？

### 6. AI 工程化沉淀与团队协作

- 团队里是怎么沉淀 AI 最佳实践的？
- 项目做久以后，Rules / Skills 怎么迭代？
- 如何让不同成员用 AI 产出的代码风格更一致？
- 你们有没有形成固定的提示词模板、评审标准或验收流程？

## 五、Agent 与大模型应用

### 1. 智能体项目介绍

- 智能体这块是什么时候开始做的？上线了吗？
- 你们这个智能体主要包含哪几部分？
- 主要完成什么业务功能？输入输出是什么？
- 最后是以什么方式交付到系统里的？
- 你在其中负责的是模型接入、工作流编排，还是整条交付链路？

### 2. 为什么不是简单调 API

- 这个场景为什么不能只靠提示词加单次模型调用解决？
- 你为什么判断这里需要智能体框架，而不是普通接口封装？
- 哪些能力必须通过工具调用实现，不能交给模型本身？
- 什么时候应该用工作流，什么时候单轮调用就够了？

### 3. LangChain / LangGraph / 工作流节点

- 基于 LangChain 做的能力具体怎么接的？
- 是不是用 LangGraph 之类的工作流来组织的？里面核心有几个节点？
- 路由节点是按什么条件分流的？
- 为什么说是不同分支节点，而不是不同模型？
- 最后的结构化输出节点是怎么设计的？

### 4. 工具调用、消息协议与边界

- 经纬度转地名为什么要做成工具，而不是提前在业务代码里算好？
- 哪些问题该交给模型，哪些该交给传统逻辑？
- 强约束提示词应该放在 message 的哪个角色位置？
- tool message 在 message 数组里有什么顺序要求？
- 输入风控、输出风控、流式撤回怎么设计？

### 5. 会话记忆、压缩与持久化

- 长对话场景下怎么做上下文管理？
- 压缩时机和压缩力度怎么控制？
- 只按阈值压缩，怎么避免上下文被切断后不连贯？
- session_id 是怎么生成、回传、续聊和过期的？
- 为什么 system 消息和 tool 消息通常不做压缩？

### 6. 指标、流式输出与平台选型

- 项目里有没有建立准确率指标、采纳率指标或响应时间指标？
- 当前为什么没有做流式输出？如果要支持流式，该怎么改？
- 为什么不用 Dify、Coze、n8n 这类现成平台，而是自己用 LangGraph 搭？
- 私有化部署、专网环境、垂直工具接入，对平台选型有什么影响？

### 7. Agent 工程化能力

- 你在 Agent 里面怎么设计 system prompt？
- 如果新建一个垂类 Agent 或 Sub-Agent，你会怎么设计说明文件和能力边界？
- 团队里有哪些 AI 工程实践和 rules / skills 沉淀？
- 如果让 AI 对产品文档评分、判断需求值不值得做，提示词结构怎么设计？
- 如果让你做一个公司内部可复用的 Agent 底座，你会怎么拆层？

## 八、现场手写与在线编码

### 3. 前端现场排查与思路题

### 4. 工程配置与实现题

- Vite 多入口怎么配置？
- Vue Router 异步守卫怎么写？
- 某个通用组件或 Hook / Composable 如何现场写核心骨架？
