### 3. 介绍一下最近做过的一个项目 / Could you introduce one project you worked on recently?

**中文版：**

我最近做过的一个项目，叫气象雷达预警系统。前端采用的是父子项目架构，子项目通过 iframe 的方式嵌入。基于这套架构，我们实现了父子应用之间的通信，以及统一登录、统一风格切换和统一权限控制。

后端一开始是单体架构，后来为了适配多省份需求、复用公共能力、解耦各省份的独有功能，我们把系统逐步拆成了微服务架构。

**English Version:**

One recent project I worked on was the Meteorological Radar Early Warning System. On the front end, we used a parent-child application architecture, where the child applications were embedded through iframes. We implemented communication between the parent and child applications, as well as unified login, theme switching, and permission control.

On the back end, the system was originally built as a monolithic application. Later, we refactored it into a microservice architecture to support different province-specific requirements, reuse shared capabilities, and decouple province-specific features.

Later, we also introduced AI agent capabilities by implementing the agent as an independent Python microservice and integrating it into the existing Java microservice system.

### 5. 这个项目里最大的技术挑战是什么 / What was the biggest technical challenge in that project?

**中文版：**

这个项目的技术挑战主要集中在前端、后端和智能体三个方面。

前端最大的难点是要复用之前两个已有项目，同时再开发三个新项目，并且最终要以一个统一系统的形式对外展示。为了解决这个问题，我设计了父子项目架构以及它们之间的通信机制，最终实现了统一登录、统一风格切换和统一权限控制。再就是一些性能优化问题。

后端最大的难点是微服务拆分。因为我们既要支持不同省份的差异化需求，又要复用原有的通用逻辑，所以我把原来的单体系统逐步拆成了微服务，把公共能力抽成共享微服务，同时为每个省份单独建立微服务来承载它自己的特定需求。再就是一些性能优化问题。

智能体这部分的难点在于，需要把新的能力接入到原有的 Java 微服务体系中。当时可以选 Spring AI，也可以选 Python 方案。最终考虑到 Python 生态更成熟，所以我选择用 Python 实现智能体微服务，再把它接入现有的 Java 微服务架构。

**English Version:**

The biggest technical challenges in this project were mainly on the front end, the back end, and the AI agent side.

On the front end, the biggest challenge was that we had to reuse two existing projects, build three new ones, and eventually present them as one unified system. To solve this, I designed the parent-child application architecture and the communication mechanism between the parent and child applications. Based on that architecture, we implemented unified login, theme switching, and permission control. There were also some performance optimization challenges.

On the back end, the biggest challenge was splitting the system into microservices. Because we needed to support province-specific requirements while still reusing the original shared logic, I refactored the original monolithic system into microservices, extracted common capabilities into shared services, and created dedicated microservices for each province to handle its specific requirements. There were also some performance optimization challenges.

For the AI agent part, the main challenge was integrating the new capability into the existing Java microservice system. At that time, we could choose either Spring AI or a Python-based solution. In the end, we chose Python because its ecosystem was more mature for this use case. We then implemented the agent as an independent Python microservice and integrated it into the existing Java microservice system.

### 6. 介绍一下你如何使用 AI 提效 / Could you explain how you use AI to improve development efficiency?

**中文版：**

我们公司从去年年初开始推动 AI 提效。前端主要使用 Cursor，后端主要使用 IntelliJ IDEA 里的 Copilot 插件。

除了直接使用这些 AI 编码工具之外，我也沉淀了一些提升和 AI 沟通效率与准确度的方法，比如 rules、skills 和 MCP。

在我理解里，rules 和 skills 主要是为了提高提示词的复用性。Rules 一般配置在全局层面，用来约束一些基础信息，比如 Vue 项目默认使用 Vue 3，Java 项目使用 Java 11。Skills 一般放在项目里，用来约束具体任务的生成规范，比如前端组件生成，或者后端接口生成。

在实际使用过程中，我们也会持续完善这些 AI skills。一个项目做得越久，这些规则和技能就会越完善，AI 生成的代码也会越接近团队的预期。

我对 MCP 的理解是，它是一种让 AI 接入外部工具的标准方式。我目前主要接入过 Figma MCP。接入之前，我们需要先把设计图截图发给 AI；接入之后，AI 就可以直接读取设计图里的节点信息，这样沟通会更准确。

**English Version:**

Our company started adopting AI to improve development efficiency in early last year. We mainly used Cursor for front-end development and the Copilot plugin in IntelliJ IDEA for back-end development.

Besides using AI coding tools directly, I also developed some practical methods to improve both the efficiency and accuracy of working with AI, such as rules, skills, and MCP.

In my understanding, both rules and skills are mainly intended to improve the reusability of prompts. Rules are usually defined at the global level to set baseline standards, such as using Vue 3 for Vue projects, and Java 11 for Java projects. Skills are usually defined at the project level to specify generation standards for specific tasks, such as front-end component generation, or back-end API generation.

In real projects, we keep refining rule files and skill templates over time. As a project evolves, they become more complete, and the code generated by AI gets closer to the team's expectations.

My understanding of MCP is that it is a standard way for AI to connect to external tools. The main MCP server I have used so far is the Figma MCP server. Before integrating it, we had to manually send screenshots of the design to AI. After integrating it, AI could directly read node information from the design, which made communication much more accurate.
