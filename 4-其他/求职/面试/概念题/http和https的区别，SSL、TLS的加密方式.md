# HTTP 和 HTTPS 的区别，SSL、TLS 的加密方式

**一句话回答：** HTTPS = HTTP + TLS，它在 HTTP 之下增加了一层安全传输协议，用来保证机密性、完整性和身份认证。

***

## 一、HTTP 和 HTTPS 的核心区别

| 对比项 | **HTTP** | **HTTPS** |
| --- | --- | --- |
| **是否加密** | 明文传输 | TLS 加密传输 |
| **默认端口** | 80 | 443 |
| **身份校验** | 无 | 通过证书校验服务端身份 |
| **防篡改** | 弱 | 通过 MAC / AEAD 校验完整性 |
| **SEO / 浏览器信任** | 较弱 | 更受浏览器和搜索引擎信任 |

***

## 二、TLS 为什么要混合加密

| 加密方式 | 特点 | 在 TLS 中的作用 |
| --- | --- | --- |
| **对称加密** | 速度快 | 真正用于后续数据传输 |
| **非对称加密** | 速度慢，但适合安全交换信息 | 用于身份校验、密钥交换 |
| **摘要 / 消息认证** | 校验内容是否被篡改 | 保证完整性 |

TLS 并不是“全程都用 RSA 加密所有内容”，而是先通过证书和密钥交换建立安全会话，再用对称密钥高效传输数据。

***

## 三、TLS 握手在做什么

1. **协商版本和加密套件。**
2. **服务端返回证书。** 浏览器校验证书是否合法、是否过期、是否被可信 CA 签发。
3. **密钥交换。** 现代 TLS 通常使用 ECDHE，生成会话密钥。
4. **之后的 HTTP 数据都走加密通道。**

### 常见追问

| 问题 | 回答要点 |
| --- | --- |
| **SSL 和 TLS 的关系？** | SSL 是早期协议，现网基本已淘汰；现在通常说 HTTPS，实际指的是 TLS。 |
| **HTTPS 一定完全安全吗？** | 不是，还要防 XSS、CSRF、弱口令、证书误配、明文存储等问题。 |
| **为什么 HTTPS 更慢？** | 主要多了 TLS 握手和加解密成本，但现代硬件和会话复用已经把成本降得很低。 |

***

## 四、面试答题模板

可以直接答：**HTTP 是明文传输，HTTPS 则是在 HTTP 下面加了 TLS。TLS 通过证书认证服务端身份，再结合非对称加密、对称加密和摘要算法建立安全通信。握手阶段解决“你是谁”和“密钥怎么安全交换”，真正传输阶段主要靠对称加密来保证性能。**
