# 之前项目的难点、亮点

**一句话思路：** 这类题不要只罗列做过什么，要按“业务背景 -> 难点 -> 方案 -> 结果 -> 复盘”来回答，重点体现自己的判断和推动作用。

***

## 一、推荐回答结构

| 环节 | 重点要说什么 |
| --- | --- |
| **背景** | 项目类型、目标用户、业务目标 |
| **难点** | 为什么难，卡在哪，常规方案为什么不够 |
| **方案** | 你主导或核心参与的设计与取舍 |
| **结果** | 性能、效率、稳定性、体验上的量化收益 |
| **复盘** | 如果重做一遍，会如何进一步优化 |

***

## 二、可以重点展开的项目亮点

### 1. 组件库与样式隔离

- **难点：** 多业务线复用组件时，样式污染和主题差异容易互相影响。
- **方案：** 从工程层面统一组件规范、样式命名和隔离策略，减少跨项目冲突。
- **亮点表达：** 我不是只写了组件，而是把“复用能力 + 稳定性”一起做了工程化设计。

### 2. Vue3 基础框架搭建

- **难点：** 新项目初始化阶段要同时考虑目录结构、状态管理、请求封装、权限与构建规范。
- **方案：** 统一项目骨架、插件机制、环境配置和公共能力沉淀。
- **亮点表达：** 提前把规范和公共能力打平，后续业务接入成本更低。

### 3. 性能优化

- **难点：** 复杂 JS 计算、图片加载与缓存策略会影响首屏和交互流畅度。
- **方案：** 针对长任务、图片缓存和静态资源更新机制做专项治理。
- **亮点表达：** 不是泛泛做“性能优化”，而是定位瓶颈后分模块治理。

### 4. iframe 跨边界截图

- **难点：** 跨 iframe 通信、层叠上下文、鼠标移出浏览器、拼接坐标都比普通截图复杂。
- **方案：**
  - 父子页面通信同步截图状态
  - 使用 `transform` 移动截图窗口，避免频繁重排
  - 在渲染函数中挂载，规避层叠上下文影响
  - 处理鼠标移出浏览器和跨区域拼接逻辑
- **亮点表达：** 这个点能体现你解决复杂交互和边界条件的能力。

***

## 三、答题时怎么避免“像背稿”

1. **每个亮点都说一个业务目标。** 例如“为了降低多项目接入成本”“为了避免用户清缓存”。
2. **每个亮点都说一个具体难点。** 不要只说“我做了组件库”。
3. **尽量给结果。** 即使没有精确数字，也要说“减少回归成本”“提升发布稳定性”“降低用户刷新失败率”。
4. **突出你的角色。** 是主导设计、推进落地，还是承担关键模块实现。

***

## 四、面试答题模板

可以直接答：**我之前项目里比较有代表性的亮点有三类。第一类是工程化建设，比如组件库和 Vue3 基础框架搭建，解决的是多人协作和跨项目复用问题；第二类是性能优化，我会先定位长任务、缓存和静态资源更新这些具体瓶颈，再做针对性治理；第三类是复杂交互场景，比如跨 iframe 截图，这个场景涉及父子通信、层叠上下文和边界坐标处理，能体现我在复杂前端问题上的拆解和落地能力。**
