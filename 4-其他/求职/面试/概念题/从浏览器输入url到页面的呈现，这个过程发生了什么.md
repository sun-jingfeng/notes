# 从浏览器输入 URL 到页面的呈现，这个过程发生了什么

**一句话回答：** 这道题本质上是把“网络请求链路 + 浏览器渲染链路”完整串起来，从 URL 解析、DNS、连接建立，到资源下载、解析、布局、绘制和合成。

***

## 一、主流程总览

```text
URL 解析
  -> DNS 解析
  -> TCP 三次握手
  -> HTTPS 场景再做 TLS 握手
  -> 发送 HTTP 请求
  -> 服务端处理并返回响应
  -> 浏览器解析 HTML / CSS / JS
  -> 构建 DOM、CSSOM、Render Tree
  -> Layout -> Paint -> Composite
  -> 页面显示并继续处理后续资源与交互
```

***

## 二、网络侧要说清什么

| 阶段 | 重点 |
| --- | --- |
| **URL 解析** | 拆出协议、域名、端口、路径、查询参数 |
| **DNS** | 浏览器缓存、系统缓存、hosts、递归查询 |
| **TCP** | 三次握手建立可靠连接 |
| **TLS** | 证书校验、密钥交换、建立加密通道 |
| **HTTP** | 请求行、请求头、请求体；响应状态、响应头、响应体 |

***

## 三、渲染侧要说清什么

1. **解析 HTML，构建 DOM。** 遇到外链资源会继续请求。
2. **解析 CSS，构建 CSSOM。**
3. **DOM + CSSOM 组合成 Render Tree。**
4. **Layout。** 计算元素位置和尺寸。
5. **Paint。** 把内容画成像素。
6. **Composite。** 图层合成后显示到屏幕。

### 高频追问

| 问题 | 回答要点 |
| --- | --- |
| **CSS 会阻塞什么？** | CSS 不阻塞 DOM 解析，但会阻塞渲染，也会影响后续 JS 执行时机。 |
| **JS 为什么会阻塞解析？** | 普通脚本执行前浏览器要保证 DOM 状态可预测，所以会暂停 HTML 解析。 |
| **怎么优化？** | `defer/async`、预加载、缓存、减少重排重绘、关键资源优先。 |

***

## 四、面试答题模板

可以直接答：**输入 URL 后，浏览器先解析地址并通过 DNS 拿到 IP，然后建立 TCP 连接；如果是 HTTPS，还要完成 TLS 握手。接着浏览器发送 HTTP 请求，服务端返回 HTML、CSS、JS 等资源。浏览器在拿到资源后会构建 DOM 和 CSSOM，再生成渲染树，之后经历布局、绘制和合成把页面显示出来。面试里如果再往下追，一般就会问缓存、脚本阻塞、重排重绘和性能优化。**
