# 屏幕分辨率适配方案

**一句话回答：** 屏幕适配不是只选一个单位，而是结合视口、弹性布局、相对单位和设备特性，保证页面在不同尺寸、不同 DPR、不同安全区域下都可用。

***

## 一、先区分几个概念

| 概念 | 含义 |
| --- | --- |
| **物理像素** | 设备硬件真实像素点 |
| **CSS 像素** | 浏览器布局使用的逻辑像素 |
| **DPR** | 设备像素比，`物理像素 / CSS 像素` |
| **视口（viewport）** | 浏览器用来布局页面的可视区域 |

移动端适配常见问题本质上都和这几个概念有关。

***

## 二、常见适配方案

| 方案 | 适用场景 | 特点 |
| --- | --- | --- |
| **弹性布局（Flex / Grid）** | 大多数页面结构 | 首选，结构响应能力强 |
| **百分比 / `vw` / `vh`** | 随视口变化的尺寸 | 对整屏比例场景友好 |
| **`rem`** | 有设计稿比例体系的项目 | 通过根字体统一缩放 |
| **媒体查询** | 断点明显的页面 | 精细控制不同屏宽布局 |
| **`max-width` + 居中容器** | PC / 大屏页面 | 防止内容无限拉伸 |

### 推荐理解

- **布局层面：** 先用 Flex / Grid。
- **尺寸层面：** 需要等比缩放时用 `rem` 或 `vw`。
- **断点层面：** 差异明显时用媒体查询补充。

***

## 三、高频细节问题

### 1. 1px 问题

高 DPR 设备上，`1px` 可能看起来更粗，可以通过以下方式处理：

- 使用 `transform: scale()` 缩放伪元素边框
- 使用半透明边框或阴影模拟
- 某些场景直接接受系统渲染效果，避免过度优化

### 2. 刘海屏与安全区域

iOS 全面屏设备需要考虑安全区域：

- 使用 `env(safe-area-inset-top)` 等变量
- 底部固定按钮、顶部吸顶区域要特别留白

### 3. 图片与字体适配

- 图片尽量 `max-width: 100%`
- 字体不要完全依赖等比缩放，避免小屏不可读
- 大图优先做响应式裁切或多尺寸资源

***

## 四、面试答题模板

可以直接答：**屏幕适配一般分三层处理：先用 Flex 或 Grid 做弹性布局，再根据设计稿体系选择 `rem` 或 `vw` 这类相对单位，最后通过媒体查询处理关键断点。移动端还要关注 DPR 带来的 1px 问题，以及刘海屏的安全区域。**
