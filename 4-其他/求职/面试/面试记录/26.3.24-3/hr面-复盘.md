## 二、逐题复盘（问题 → 我的答案 → 评价 → 参考答案 → 话术）

### 1. 自我介绍

**问题**：请做一个简单的自我介绍。

**我的答案要点**
- 吉林大学本科，软件工程专业。
- 从事 Web 开发 4 年。
- 前端技术栈以 Vue、React 为主，后端是 Java。
- 对 AI 开发提效比较熟练。
- 做过项目负责人和 6 人技术小组组长。
- 具备全栈交付能力。
- 提到之前了解过岗位需求，认为和自己的技能匹配度较高。

**评价**
- 优点：学历、年限、技术栈、带团队经历、全栈交付能力都提到了，信息覆盖比较完整；也顺手表达了对岗位的兴趣和匹配度。
- 不足：转写里有一些口误和用词不稳，比如“技术障碍”这类表述会影响专业感；整体偏信息堆叠，没有先打出一个清晰定位，例如“前端出身、近一年扩展到全栈交付”。

**参考答案要点**
- 开头先给定位：前端出身，近一年扩展到 Java 全栈和 AI 提效落地。
- 中间讲 2 到 3 个最有价值标签：项目负责人、小组长、能做实际交付。
- 结尾再扣岗位：你的能力结构为什么和这个岗位匹配。

**话术示例**
我本科是吉林大学软件工程专业，做 Web 开发大概 4 年，前端是我的主方向，主要做过 Vue 和 React，近一年也在持续补强 Java 后端和 AI 提效相关能力。过去我做过项目负责人和技术小组组长，不只是参与编码，也负责技术方案、任务拆分和推进交付。现在我的优势更偏向前端出身、但已经具备全栈交付能力，这一点和咱们这个岗位的要求是比较匹配的。

### 2. 目前状态、上一家公司组织情况和你的角色

**问题**：你现在是离职状态吗？上一家公司所在组织大概是什么情况？你在团队里的角色是什么？

**我的答案要点**
- 目前是离职状态。
- 上家公司是红橡科技，在研发部门。
- 最初团队十几人，前后端都有；后来民用和军用相关部门合并，形成更大的研发中心。
- 大部门下前端有 3 个小组，后端也有多个小组。
- 自己是其中一个小组的组长，对应雷达预警业务线。
- 组内除自己外，还有 1 个后端和 4 个前端。
- 自己前后端都做。

**评价**
- 优点：组织背景、团队规模、业务线归属和个人角色都交代到了，说明你不是只在单点写代码，而是在真实业务组织里承担核心职责。
- 不足：表述略绕，部门名、合并背景、业务线信息比较多，HR 更关注的是“你带什么团队、负责什么事情、角色级别如何”，可以更收敛一点。

**参考答案要点**
- 先说当前状态，再用两三句话讲清楚组织层级。
- 团队信息聚焦在和自己最相关的部分：业务线、团队人数、自己负责什么。
- 角色表达要直接：技术小组组长 + 项目负责人 + 核心开发。

**话术示例**
我现在是离职状态。上一家公司是做定制化软件交付的，我所在的是研发体系下的一条雷达预警业务线。我们当时属于一个技术小组，我是组长，团队里有前端和后端同事，我自己也同时参与前后端开发。对我来说，这段经历的核心不是简单待过一个团队，而是我确实在项目推进、任务拆分和核心开发上承担了比较关键的角色。

### 3. 作为组长你主要负责什么

**问题**：你身为组长主要负责什么？

**我的答案要点**
- 主要工作仍然是参与开发，少部分精力用于任务分配。
- 新项目到自己这里后，会先分人，再自己参与开发。
- 会根据谁手里有没有活、谁做过类似功能、谁适合做核心任务来分配。
- 需求基础框架和整体结构通常由自己先搭。
- 页面、组件、后端接口等再拆分给具体成员。
- 目标是降低沟通成本，提高交付效率。
- 自己不是纯管理岗，仍承担了大量产出。
- 最近项目里，前端约贡献 1/3，后端约贡献一半，核心架构由自己搭建。

**评价**
- 优点：这题答得比较扎实，既讲了任务分配逻辑，也讲了自己如何参与核心开发，能体现你是真的在带小团队做交付，不是挂名组长。
- 不足：对 HR 来说，这题除了“怎么分活”，还可以补一句“你带团队的结果是什么”，比如项目数量、交付节奏、是否按时上线，这样更像管理闭环。

**参考答案要点**
- 回答结构可以固定成“职责范围 → 分工原则 → 自己承担的核心工作 → 结果”。
- 强调你不是行政管理，而是项目内的技术负责人和推进者。
- 补充结果导向：保证项目按时交付、降低沟通成本、提升复用效率。

**话术示例**
我这个组长角色本质上更偏技术负责人。一方面我会负责新项目进来之后的任务拆分、人员安排和技术骨架搭建，另一方面我自己也会参与核心开发。分工时我会结合成员当前工作量、历史经验和任务特点来安排，尽量把沟通成本降到最低，把关键模块抓在自己手里。对我来说，带组不是只分活，而是要把项目稳定往前推，确保最后能按节奏交付。

### 4. 上一家公司主营业务是什么

**问题**：红橡科技的主营业务是什么？

**我的答案要点**
- 公司主营业务是定制化软件系统开发和交付。
- 母公司是航天宏图，拥有气象相关数据能力。
- 红橡主要负责用这些数据做软件开发和项目交付。
- 项目来源主要是招投标和业务资源。
- 客户多为国企、事业单位。
- 产品形态偏气象预报、预警、复盘类系统。

**评价**
- 优点：回答把公司业务模式、上游资源、客户类型和产品形态讲清楚了，说明你对所在公司的业务逻辑是理解的。
- 不足：HR 场景下不用展开太多背景信息，重点说清“行业 + 商业模式 + 你的业务场景”即可，否则容易显得冗长。

**参考答案要点**
- 用一句话定义公司业务。
- 再补一句你所在业务线的具体方向。
- 如果有行业特点，比如政企定制、项目制交付，可以点到为止。

**话术示例**
这家公司主要做的是定制化软件系统开发和交付，行业方向偏气象相关。它依托母公司的数据能力，去承接国企和事业单位这类客户的软件项目，我所在的业务线主要就是做气象预警和相关系统交付。所以我过去的经历比较偏项目制、政企类、强调交付落地的场景。

### 5. 离职原因

**问题**：你从上一家公司离开的原因是什么？

**我的答案要点**
- 原来的业务线不再继续做了。
- 这条业务线以前每年能接到四五个项目，但后来甲方不再合作。
- 小组因此取消。
- 公司给过转岗机会，但过去后同事和领导都会变化，相当于重新开始。
- 自己判断不如直接寻找新的、更有发展空间的平台。

**评价**
- 优点：主线是业务变化，不是个人问题，风险相对较低；也说明你有认真评估过转岗方案，不是冲动离职。
- 不足：最后一句“发展好的平台”略泛，可以更职业化一些，改成“希望寻找和自己能力结构更匹配、发展方向更清晰的机会”。

**参考答案要点**
- 保持客观、中性、可验证。
- 强调这是业务线收缩，不是绩效或人际原因。
- 结尾自然过渡到你现在的求职方向。

**话术示例**
我离职的核心原因是原来负责的业务线后面不再继续做了，这属于业务层面的客观变化。公司当时也给过转岗机会，但对应团队、业务方向和我的既有积累差异比较大，我评估下来相当于重新开始。所以我更希望借这个时间点，去找一个和自己技术结构、职业方向更匹配的机会。

### 6. 这三年最大的成长是什么

**问题**：你在这三年的时间里，最大的成长是什么？

**我的答案要点**
- 最大成长是技术成长，以及对公司运作和业务的理解。
- 刚入职时以前端身份为主，后来补充了地图、Canvas、组件库等气象行业相关能力。
- 去年开始在公司推动 AI 提效的大背景下，转向前后端一起做。
- 这一年主要学习 Java，并成功交付了前后端项目。
- 现在具备全栈交付能力。
- 也更理解公司制度、项目来源和业务运作方式。

**评价**
- 优点：技术成长线比较完整，从前端深度到全栈扩展，再到 AI 提效，逻辑上是成立的；同时补到了对组织和业务的理解，维度比较全。
- 不足：答案稍微有点散，信息点很多，但缺少一个更强的总结句。HR 更容易记住的是“我从单一前端成长为能完整交付项目的全栈负责人”。

**参考答案要点**
- 用一句总结先概括成长主题。
- 再分成两个维度展开：技术能力提升、业务视角提升。
- 每个维度都给出一个代表性例子，不要罗列太多点。

**话术示例**
如果总结成一句话，我觉得我这三年最大的成长，是从一个以前端为主的开发，成长成了能从技术和业务两个维度去推动项目交付的人。技术上，我补强了行业相关能力，也在去年把 Java 后端和 AI 提效真正落到了项目里，具备了全栈交付能力。业务上，我不只是写代码，也更理解项目是怎么来的、团队怎么运转、为什么有些制度会那样设计，这些理解会让我看问题更完整。

### 7. 你们的 AI 落地主要是怎么推进的

**问题**：你们可以落地 AI，主要是通过什么方式来推进这种事情？

**我的答案要点**
- 公司主要通过技术分享来推动。
- 同时增加工作要求，希望大家通过 AI 提高效率。
- 会推荐一些工具和使用方式。
- 本质上是工作变多但不加人，所以需要靠 AI 提效。
- 自己也因此在 AI 提效方面成长比较快。

**评价**
- 优点：回答比较真实，说明这件事在公司内不是概念层，而是和实际工作要求绑定的。
- 不足：直接说“加活不加人”虽然真实，但语气略硬，不适合在 HR 面直接展开。更稳的说法应该是“公司在推动效率提升，AI 是其中一个明确方向”。

**参考答案要点**
- 先说组织层面的推动方式：培训、分享、工具引入、项目试点。
- 再说个人层面的落地：把 AI 用在机械性工作、代码生成、效率提升上。
- 保持表达中性，少用抱怨式措辞。

**话术示例**
我们当时推进 AI 落地，主要还是通过技术分享、工具引入和实际项目试点来推进。公司层面会鼓励大家把一些重复性的工作交给 AI 去辅助完成，比如代码生成、方案整理、文档处理这类场景。对我个人来说，这个过程最大的价值是让我把 AI 真正用进了开发流程里，不只是停留在尝试层面，而是形成了稳定的提效习惯。

### 8. 你对未来发展的规划是什么

**问题**：你对自己未来的发展，有什么规划或者预期？

**我的答案要点**
- 希望做全栈 Web 开发。
- 认为 AI 时代只做前端会偏窄。
- 未来趋势是一个人能覆盖更多能力，再借助 AI 放大效率。
- 去年已经在主动提升 Java 能力。
- 现在已经具备前后端全栈交付能力。
- 未来希望继续提升全栈能力，并持续使用和学习 AI。
- 如果岗位涉及新东西，也愿意快速学习。

**评价**
- 优点：方向明确，和你过去一年的成长路径是一致的；也体现了主动学习和持续扩展能力边界的意识。
- 不足：像“一人成军”这种说法在 HR 面里容易显得过猛，建议换成更稳的表达，比如“覆盖更完整的交付链路”；同时要避免让对方误以为你未来会频繁转方向。

**参考答案要点**

- 补一句你希望在业务复杂度、项目 ownership 或技术深度上继续提升。

**话术示例**
我未来几年的主线还是会放在全栈 Web 交付能力上。因为我现在的积累本身就是前端出身，逐步扩展到 Java 后端和 AI 提效，所以我希望把这条路继续走深，让自己不仅能完成单点开发，也能覆盖更完整的项目交付链路。AI 这块我也会持续用和持续学，因为我觉得它已经不是加分项，而是未来开发效率的一部分。

### 9. 你现在看机会主要关注哪些方面

**问题**：你现在看机会一般会从哪些方向去看？

**我的答案要点**
- 首先看岗位匹配度，这是最核心的。
- 希望是 Web 全栈开发岗位。
- 前端希望是 Vue 或 React，后端希望是 Java。
- 如果岗位重视 AI 接入或 AI 提效，会更匹配自己的经历。
- 其次看岗位稳定性，不考虑太初创或刚成立不久的小团队。
- 还会看预算是否达到预期。

**评价**
- 优点：标准比较清晰，能体现你不是海投，而是在有选择地看机会。
- 不足：排序上可以更职业一些。除了匹配度和稳定性，还可以补一句“希望看重真实业务价值和长期成长空间”，这样会比单讲预算更平衡。

**参考答案要点**
- 回答维度建议是：匹配度、成长空间、稳定性、薪酬。
- 技术栈要求可以说，但不要太像“限定条件清单”。
- 重点表达你在找长期可投入的岗位。

**话术示例**
我现在看机会，最核心还是岗位匹配度，也就是这个岗位是不是能把我现阶段的能力真正用起来。对我来说，比较理想的是 Web 全栈方向，前端和后端都有发挥空间，同时如果团队也重视 AI 提效或者新能力接入，那会和我的经历更贴合。除此之外，我也会看团队稳定性和成长空间，薪酬当然也会综合考虑，但我更希望找的是一个能长期投入、方向清晰的机会。

### 11. 你有什么想了解的吗

**问题**：你这边有什么想和我交流的吗？

**我的答案要点**
- 表示之前已经和业务面试官了解过岗位职责和技术使用情况。
- 这次主要想了解组织规模。
- 追问了大部门人数、技术团队人数、所在组规模，以及新产品和现有部门的关系。
- 最后表达了自己认为岗位匹配度和整体情况都符合预期。

**评价**
- 优点：反问方向是对的，没有问福利、假期这类低价值问题，而是问组织规模和产品归属，说明你在判断岗位稳定性和组织成熟度。
- 不足：还可以更进一步，比如问清楚这个岗位的汇报线、试用期预期、团队当前最急的目标。这样能为后续谈 offer 和入职预期做铺垫。

**参考答案要点**
- HR 面的反问重点可以放在组织稳定性、汇报关系、招聘背景、后续流程。
- 问题不宜多，但要精准。
- 结尾可以顺手表达对岗位的认可，增强正向信号。

**话术示例**
我这边主要想再确认两个点。一个是这个岗位所在团队目前的大概规模和组织形态，另一个是这个岗位后续更偏新产品孵化，还是已经进入比较稳定的推进阶段。因为对我来说，我比较看重的是岗位和我能力的匹配度，以及团队后续发展的清晰度。从我目前了解的信息来看，这个机会整体还是比较符合我预期的。

## 三、表现好的地方

| 点 | 说明 |
| --- | --- |
| **整体状态比较稳** | HR 面全程语气平稳，回答比较顺，没有明显慌乱或卡壳。 |
| **角色信息比较完整** | 能讲清楚自己是项目负责人、组长、核心开发，不是只做单点执行。 |
| **离职原因风险较低** | 主线是业务线变化，表达也比较客观，没有明显负面情绪。 |
| **职业方向比较明确** | 明确表达想走全栈 Web 交付方向，并持续结合 AI 提效。 |
| **地点配合度高** | 北京到岗、可搬家、通勤可调整，这些信息对 HR 是加分项。 |
| **反问比较聚焦** | 关注组织规模和产品归属，说明你在判断岗位稳定性和匹配度。 |

## 四、待改进与盲区

### 4.1 表达与话术

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **自我介绍的核心定位不够突出** | 信息很多，但缺少一句让 HR 快速记住你的总结。 | 固化成“前端出身，近一年扩展到 Java 全栈和 AI 提效落地”的开场。 |
| **部分措辞不够职业化** | 像“技术障碍”“一人成军”“加活不加人”等说法偏口语，容易降低正式感。 | 统一替换成更职业、更中性的表达。 |
| **答案偶尔偏长偏散** | 组织背景、技术成长等题目里，信息点比较多，但收口不够强。 | 练习“先总结一句，再分 2 到 3 点展开”的回答结构。 |

### 4.2 HR 关注点匹配

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **带团队结果导向不够强** | 讲了怎么分活，但没有强调交付结果、效率提升和项目成果。 | 补一句“我负责把项目按节奏推进并落地”。 |
| **职业规划可以再稳一些** | 强调能力扩展是对的，但表达过猛时容易让 HR 觉得你目标太发散。 | 统一聚焦为“全栈交付能力持续增强，AI 作为长期效率工具”。 |
| **看机会标准可更平衡** | 提到了预算和稳定性，但成长空间、业务价值表达稍弱。 | 固化为“匹配度、成长空间、稳定性、薪酬”四维。 |

### 4.3 可继续补强的反问

| 问题 | 不足 | 可补内容 |
| --- | --- | --- |
| **反问还可以更精准** | 只问了组织规模，没有继续问汇报关系、岗位目标和后续流程。 | 可补问“这个岗位当前最希望我入职后解决什么问题”“汇报给谁”“后续流程和时间点”。 |

## 五、后续行动

1. 把自我介绍压缩成 60 秒版本，固定成“定位 + 代表经历 + 岗位匹配”三段式。
2. 单独整理一版 HR 面常见题话术，包括离职原因、职业规划、看机会标准、地点稳定性。
3. 把“技术小组组长”这段经历补成结果导向版本，加入项目数量、交付职责、核心产出占比等信息。
4. 统一修正高风险口语表达，避免在后续面试中出现过于随意或带情绪的措辞。
5. 准备 3 个通用 HR 反问模板，分别针对组织稳定性、岗位目标和后续流程。
6. 如果进入下一轮，提前准备“为什么选择 360”“为什么这个岗位适合你”的精简版本，增强收口能力。

## 六、小结

这场 HR 面整体风险不高，核心信息基本都传达到了，尤其是你的背景、角色层级、离职原因和发展方向，整体是成立的。主要问题不在内容真假，而在话术收敛度和职业化表达上，少数表述还可以再稳一些。下一步重点不是补知识，而是把已有经历压缩成更清晰、更利于 HR 记忆的标准答案。
