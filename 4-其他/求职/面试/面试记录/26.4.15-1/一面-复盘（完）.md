### 3. 快速连续提交时的防重处理 【7 分】

**问题**
如果用户很快速地发了两条消息，前端是怎么处理的？

**我的答案要点**
- 做了节流处理
- 生成按钮在请求返回之前保持 loading + 禁用状态
- 接口返回后才解除禁用，允许再次提交

**评价**
- 优点：思路正确，与表单防重提交逻辑一致，描述准确。
- 不足：将"防抖/节流"和"按钮禁用"混用表述，逻辑上这里用的是"请求 pending 期间禁用按钮"而不是严格意义的节流；面试官追问"你定时了两秒吗"时说明未完全理解你的方案，可更精准表述。

**参考答案要点**

- 不是定时禁用，而是与请求生命周期绑定，无论接口快慢都精准生效

**话术示例**

你有做过组件功能上的优化吗？比如 Tooltip 默认悬浮就显示，如何优化成只在文字溢出时才显示？

**我的答案要点**
- 封装过该功能（在 Vue 2 时期）
- 思路：比较容器宽度和文字实际宽度（scrollWidth vs offsetWidth），有差值说明溢出
- 通过动态绑定 disabled 属性控制 Tooltip 是否显示

**评价**
- 优点：思路正确，`scrollWidth > offsetWidth` 是判断溢出的标准方式；提到动态绑定属性控制显示也是正确方向。

**参考答案要点**
- 判断溢出：通过 `el.scrollWidth > el.offsetWidth` 判断文字是否溢出容器
- 控制 Tooltip：将判断结果绑定到 Tooltip 的 `:disabled` 属性（Element Plus / AntDV 均支持），`true` 时不弹出
- 可封装为指令（`v-overflow-tooltip`）或组件（包裹 `<el-tooltip>`），提高复用性
- 时机：在 `onMounted` + `ResizeObserver` 中监听宽度变化，保证动态内容也能正确响应

**话术示例**

### 8. 响应式缩放布局方案 【6.5 分】

**问题**
有一个信息栏布局，分三个区域（名称+状态、基本信息、路径信息）。容器缩小时，先把"基本信息"缩成图标，继续缩再把"路径信息"缩成图标；放大时反向。当容器右边界与最右侧内容间距 ≤ 16px 时触发。初始进入页面时也需根据当前宽度自动响应最佳展示状态，你会怎么做？

**我的答案要点**
- 先考虑容器宽度是否写死，若写死可用媒体查询
- 数量固定、内容不固定，需动态判断
- 用侦听器（或计算属性）监听整体内容宽度与容器宽度差
- 设两个标志位：`middleCollapsed`、`rightCollapsed`，控制中间和右侧的展示状态
- 16px 为临界值，先折叠中间，中间已折叠再折叠右侧
- 初始时额外加一个同步判断函数，在挂载时立即执行一次

**评价**
- 优点：能想到用标志位拆分状态控制顺序，初始判断的补充思路也正确。
- 不足：初期思路把侦听器与计算属性混用导致表述乱；面试官提示"应该监听的是尺寸变化"才修正，说明对 ResizeObserver 的主动使用经验不足；总体方案可行但需要被引导才能收拢。

**参考答案要点**
- 使用 **ResizeObserver** 监听外层容器尺寸变化（优于侦听响应式数据）
- 获取容器 `clientWidth` 和内容整体 `scrollWidth` 的差值，与 16px 对比
- 维护两个 ref 标志位：`middleCollapsed`、`rightCollapsed`
- 折叠顺序：差值 ≤ 16px 且中间未折叠 → 折叠中间；差值仍 ≤ 16px 且中间已折叠 → 折叠右侧
- 展开顺序（放大时）：反向，先展开右侧，再展开中间
- 初始化：`onMounted` 后立即执行一次判断函数，保证初始状态正确
- 完整代码思路：

```js
const middleCollapsed = ref(false)
const rightCollapsed = ref(false)

function updateLayout(containerEl) {
  const gap = containerEl.clientWidth - contentEl.scrollWidth
  if (gap <= 16) {
    if (!middleCollapsed.value) {
      middleCollapsed.value = true
    } else {
      rightCollapsed.value = true
    }
  } else {
    if (rightCollapsed.value) {
      rightCollapsed.value = false
    } else {
      middleCollapsed.value = false
    }
  }
}

onMounted(() => {
  updateLayout(containerEl)
  const ro = new ResizeObserver(() => updateLayout(containerEl))
  ro.observe(containerEl)
})
```

**话术示例**
我会用 ResizeObserver 监听外层容器的宽度变化，每次触发时计算容器 clientWidth 和内容 scrollWidth 的差值，与 16px 比较。同时维护两个 ref 标志位，middleCollapsed 和 rightCollapsed，控制中间和右侧区域分别显示完整内容还是图标。折叠时先看中间是否已折叠，没有就先折叠中间；已折叠了再折叠右侧。放大时反过来，先展开右侧再展开中间。页面初始加载时，在 onMounted 里立即执行一次这个判断函数，保证一进来就能响应到当前容器的实际宽度，不需要等到用户拖动窗口才触发。

### 9. Modal.confirm 异步结果处理 【6.5 分】

**问题**
在同步代码中如何拿到 Modal.confirm 的选择结果（确定/取消），再执行后续操作？

**我的答案要点**
- 有一点印象，当时用的是回调函数方式
- 传入一个回调，弹窗点击后把结果传回来，再根据结果执行后续逻辑

**评价**
- 优点：方向基本正确。
- 不足：对 Ant Design Vue 的 `Modal.confirm` 返回 Promise 的特性不熟悉，只记得回调而不记得 Promise 方式；说"记得不太清楚"表述给人不扎实的感觉。

**参考答案要点**
- Ant Design Vue 的 `Modal.confirm()` 返回一个对象，包含 `update` 和 `destroy` 方法，**不直接返回 Promise**
- 正确做法是通过 `onOk` / `onCancel` 回调（或返回 Promise）处理：

```js
Modal.confirm({
  title: '确认操作',
  onOk: async () => {
    await doSomething()
  },
  onCancel: () => {
    // 用户取消
  }
})
```

- 若希望 `await` 式写法，可封装成：

```js
function confirm(options) {
  return new Promise((resolve) => {
    Modal.confirm({
      ...options,
      onOk: () => resolve(true),
      onCancel: () => resolve(false)
    })
  })
}
// 使用
const result = await confirm({ title: '确认？' })
if (result) { /* 确定 */ }
```

**话术示例**
Ant Design Vue 的 Modal.confirm 本身不直接返回 Promise，但它接受 onOk 和 onCancel 两个回调，我们可以在 onOk 里写确认后的逻辑，在 onCancel 里写取消逻辑。如果希望用 await 的方式写得更顺，可以自己封装一层，把 Modal.confirm 包成一个返回 Promise 的函数，onOk 时 resolve(true)，onCancel 时 resolve(false)，这样外面就可以用 await 拿到用户的选择结果，代码也更清晰。

### 10. Teleport 的使用与自实现方案 【7.5 分】

**我的答案要点**

- 主要使用场景：弹窗需要脱离深层 stacking context，渲染到 body 下
- 实际使用前自己用渲染函数（h 函数 + render）实现过相同效果，将组件挂载到 body 直接子节点

**评价**
- 优点：结合 z-index stacking context 说明了使用场景，有深度；提到了自己实现方案，说明理解了底层原理。
- 不足："泰利炮"系口误，应说"Teleport"；对 Teleport 的 to 属性、disabled 属性等 API 细节未展开。

**参考答案要点**
- Teleport 作用：将组件渲染到 `<teleport to="body">` 指定的 DOM 节点，脱离当前组件树的 stacking context
- 使用场景：全屏弹窗、Toast、抽屉等需要最高层级的 UI
- 核心属性：`to`（目标 DOM 选择器）、`disabled`（禁用传送，回归常规渲染）
- 自实现方式：`createApp(Component).mount(document.body)` 或 `render(h(Component, props), document.body)`，用完后手动 `unmount` / `render(null, el)` 清理

**话术示例**
Teleport 我理解它的作用是把组件渲染到指定的 DOM 节点，常见的是渲染到 body 下，这样不管组件在多深的层级里，弹窗都能脱离父级的 stacking context，保证 z-index 有效。我之前没有直接用 Teleport，用的是渲染函数的方式，手动 render 到 document.body，效果是一样的。后来了解到 Teleport 之后发现语法更简单，只需要 `<teleport to="body">` 包裹内容就可以，还有 disabled 属性可以动态控制是否传送，比手写渲染函数优雅很多。
